# S6 — 식 언어 `chk-expr`와 템플릿

**물음:** C14가 「안전한 식 언어」라고만 적어 둔 것을 무엇으로 구현하고, 도우미 함수 목록을 어떻게 정하는가 (M3 로드맵의 「식 도우미 목록 확정」).

**결론:** 직접 만든 AST 검사기. 결정과 이유는 [ADR-0025](../../docs/decisions/0025-expression-language.md).

## 어떻게 재었나

업무 예제 50개에서 **식이 실제로 쓰이는 자리를 전부** 뽑았다 (`collect.py` → `corpus.json`). 정규식이 아니라 제품 reader(`chaeksas.contracts.bpmn_ext`)로 읽는다 — 식이 `chk:*`의 JSON 속에도 있다.

| 자리 | 곳 |
| --- | --- |
| `scriptTask`의 스크립트 | 74 |
| 흐름 조건 | 36 |
| `serviceCall.input` | 50 |
| `rule.input` (DMN) | 16 |
| `call.input` | 12 |
| `dataOutput` (`path`·`template`) | 13 |
| **합계** | **201** |

세 가지를 재었다 (`run.py`): ① 그 후보가 201곳을 **파싱하는가**, ② 손으로 쓴 평가 시험 14개(사전 점 접근·내포·조건식·도우미·`None`)를 **맞히는가**, ③ 막아야 할 7가지(`__import__`·`open`·던더·`eval`)를 **막는가**.

## 재어 본 결과

| 후보 | 문법 받아들임 | 값 내기 | 막음 | 비고 |
| --- | --- | --- | --- | --- |
| **직접 만든 AST 검사기** (`walker.py`) | **193/201** | **14/14** | **7/7** | 못 읽은 8곳은 식이 아니라 템플릿이다 (아래) |
| `simpleeval` | 119/127 | 14/14 | 7/7 | **대입문을 다루지 않는다** — 스크립트 74곳을 쓸 수 없다 |
| `asteval` | (못 잼) | 8/14 | 6/7 | 내포·조건식 미지원, **`open('/etc/passwd')`가 새어 나갔다** |

재현: `uv run --with simpleeval --with asteval python spikes/s6-expr/run.py`

## 재면서 알게 된 것

1. **식이 아닌 자리가 섞여 있었다 — 템플릿이다.** 못 읽은 8곳은 모두 `dataOutput.path`로, `대사표/대사표_{대상월}.md`처럼 **텍스트에 `{변수}`를 끼운** 것이다. 식으로 파싱될 수 없다.
   예제 전체에서 중괄호가 쓰인 자리는 86곳(`email.subject`·`email.to`·`email.body`·`dataOutput.path`·`dataOutput.template`)이고 **중괄호 안은 전부 변수 이름 하나**였다 — 식이 들어온 곳은 없다. 그래서 템플릿은 식과 **다른, 더 작은 것**으로 둔다.
2. **사전을 점으로 읽는다.** 예제가 `결과.지급`처럼 쓴다(`결과`는 사전). 파이썬 의미로는 오류라서 평가기가 그 뜻을 바꿔 줘야 한다 — `asteval`은 여기서 바로 막혔다.
3. **스크립트는 대입문이다.** 74곳이 `대상월 = 대상월 or 지난달()` 꼴이다. 식만 보는 평가기는 쓸 수 없다.
4. **도우미 함수에 순수하지 않은 것이 섞여 있다.** 예제가 `파일목록(…)`(디스크 읽기)·`설정(…)`(환경 읽기)·`대사규칙(…)`·`전표자료(…)`(업무 로직)·`…양식(…)`(서식 만들기)을 식에서 부른다. 식은 **순수 함수만** 둬야 재생(결정 수행)이 같은 값을 낸다 — 어디로 보낼지는 ADR-0025 §4의 표에 적었다.

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `collect.py` | 예제에서 식 자리를 모은다 → `corpus.json` |
| `walker.py` | 후보 ① 직접 만든 AST 검사기 (제품 구현의 뼈대가 됐다) |
| `run.py` | 세 후보를 corpus로 재고 표를 찍는다 |
