# S7 — AI 태스크가 LLM에 닿는 길

**물음:** `core`의 AI 태스크(`chk:aiTask`)가 모델을 어떻게 부르는가. 벤더 SDK인가, 에이전트 프레임워크인가, 우리가 들고 있는 루프인가 (M3 로드맵의 「AI 태스크: LLM 호출, 도구 화이트리스트, 결과 필드 검증」).

**결론:** OpenAI 호환 HTTP를 우리 루프로 직접 부른다. 결정과 이유는 [ADR-0027](../../docs/decisions/0027-llm-connection.md).

## 1. 먼저 예제가 무엇을 요구하는지 재었다

S6와 같은 방식이다 — 추측하지 않고 업무 예제 50개의 AI 태스크 **31곳**을 제품 reader로 읽어 세었다 (`collect.py`).

| 잰 것 | 결과 |
| --- | --- |
| `domain` | `llm` 18, `doc` 7, `api` 4, `desktop` 2 (`web` 0) |
| `tools` | **6종, 쓰인 자리는 12곳뿐.** `pdf_text_tool` 4, `http_request_tool` 4, `excel_parser_tool`·`csv_parser_tool`·`image_ocr_tool`·`excel_writer_tool` 각 1 |
| `results` 개수 | 1개가 22곳, 2개 7곳, 3개 1곳, 4개 1곳 |
| 결과 타입 | `string` 19, `dict` 10, `list` 6, `number` 4, `int` 2, `bool`·`date` 각 1 |
| 반복이 붙은 AI 태스크 | 7곳 |
| `goal` 길이 | 96~279자 (중앙 176) |

**읽은 것:** ① 18곳은 **도구가 아예 없다** — 「물어보고 구조화된 답을 받는다」 한 번이다. ② 도구는 6종뿐이고 **전부 우리가 만들 로컬 도구**다 (PDF·엑셀·CSV·OCR·HTTP). 바깥 생태계의 도구 묶음이 필요하지 않다. ③ 결과는 거의 늘 **필드 1~2개의 JSON**이다 — 긴 대화가 아니라 **한두 번 왕복**이다.

## 2. 후보를 스텁에 붙여 재었다

진짜 모델 없이 재려고 OpenAI 호환 `/v1/chat/completions`를 흉내 내는 최소 서버를 두었다 (`stub.py`, 표준 라이브러리만). 대본대로 「도구를 불러라」 → 「최종 JSON」을 답한다.

재현: `uv run python spikes/s7-llm/run.py` (후보 B까지 보려면 `uv run --with openai python …`)

| | A. 직접 HTTP (httpx) | B. 벤더 SDK (`openai`) | C. 에이전트 프레임워크 |
| --- | --- | --- | --- |
| 도구 루프 한 바퀴 | **O** | O | (재지 않음 — 아래 무게에서 떨어졌다) |
| 도구 화이트리스트 | **O** (우리가 고른다) | O (우리가 고른다 — SDK는 안 막는다) | |
| 결과 필드 검증 (C14 `results`) | **O** (우리가 한다) | 우리가 따로 해야 한다 | |
| **재생 — 모델 없이 같은 결과** | **O** (모델 호출 0회) | **X** — SDK가 궤적을 주지 않아 결국 우리가 적어 둬야 한다 | |

## 3. 무게를 재었다 (설치 파일이 걸린 문제다 — ADR-0024는 PyInstaller onedir)

빈 가상환경에 하나씩 깔아 보았다 (Linux x86_64 기준).

| | 패키지 수 | 크기 |
| --- | --- | --- |
| `httpx`만 (**지금 `core`가 이미 쓴다**) | 7 | **4 MB** |
| `openai` | 14 | 47 MB |
| `anthropic` | 15 | 45 MB |
| `langchain` | 39 | 63 MB |
| `pydantic-ai` | **99** | **219 MB** |

벤더를 둘 이상 붙이면 SDK는 90 MB가 넘고, 프레임워크는 그 자체로 설치 파일을 두 배로 만든다. **얻는 것은 우리가 어차피 직접 해야 하는 일**(도구 선택·화이트리스트·결과 검증·궤적 기록)이다.

## 4. 재면서 알게 된 것

1. **재생(결정 수행)이 선택을 갈랐다.** ADR-0010이 「결정 수행은 LLM을 쓰지 않거나 최소」라고 못 박았으므로, 자율 수행에서 **도구 순서와 마지막 답을 우리가 적어 둬야** 한다. 루프를 프레임워크에 맡기면 그 안을 들여다봐야 하고, 판이 바뀌면 적어 둔 것이 쓸모없어진다.
2. **「LLM을 서비스 앱으로 빼면 안 되나」 — 모델 호출만 뺄 수 있다.** 도구 루프까지 서버로 보내면 `domain: desktop`·`web` 태스크가 성립하지 않는다 (도구가 현장 PC의 화면·파일을 만진다. 도구 한 번마다 서버 왕복이고, 서버가 끊기면 못 돈다). 반면 **모델 호출만** 사내 게이트웨이로 보내는 것은 `base_url` 하나를 바꾸는 일이라 A가 그대로 된다.
3. **OpenAI 호환이 사실상의 공통 창구다.** vLLM·Ollama·Azure OpenAI·OpenRouter·사내 게이트웨이가 모두 같은 경로를 연다. 벤더 네이티브(Anthropic Messages 등)가 필요해지면 **어댑터를 하나 더** 두면 된다 — 보내기(`core.senders`)·서비스 앱(`core.services`)과 같은 모양이다.
4. **스텁이 쓸모 있었다.** 키 없이도 도구 루프·사용량 집계·화이트리스트·재생을 전부 잴 수 있었다. 이 스텁은 제품 시험에도 같은 꼴로 들어간다 (`RecordingLlm`).
