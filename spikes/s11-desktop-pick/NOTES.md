# s11 데스크톱 「직접 고르기」·「표시」

결론 → [ADR-0072](../../docs/decisions/0072-desktop-pick-without-hooks.md) (수락)

## 확인하려 한 것

BUI-06의 데스크톱 창에서 사람이 요소를 **눌러 담고**(직접 고르기), 고른 줄을 **창 위에 테두리로**(표시) 보일 수 있는가 (09-gaps §7-3). 브라우저는 덧씌운 스크립트가 클릭을 받는데 데스크톱에는 그런 자리가 없다. 누른 자리를 알려고 **전역 마우스 훅**을 걸면 다른 앱의 입력을 가로채게 된다 — 그것 없이 되는가.

## 환경

| 항목 | 값 |
| --- | --- |
| OS | Windows 11 Education 10.0.26200, 일반 사용자 |
| 화면 | 1920×1080 한 대, **배율 100%** |
| 라이브러리 | `uiautomation` 2.0.29, PySide6 (제품과 같은 판) |
| 시험 창 | `tests/fake_desktop_apps.py taxbook` (Qt) |

```bash
uv run --no-sync python spikes/s11-desktop-pick/probe.py
```

## 본 것 (`outputs/result.json`)

**A. 고르기 — 훅 없이 된다.** 커서를 요소 가운데에 두고 `ControlFromCursor()`를 읽으면 입력(`nextRow`)·단추(`saveMenu`)·표(`sheet`) 셋 다 **그 요소**가 온다(`same: true`). Ctrl은 `IsKeyPressed`(GetAsyncKeyState)로 **누른 동안 참, 뗀 뒤 거짓**으로 읽힌다. 창 밖 한 점은 프로세스·조상 대조로 **걸러진다**. 셋 다 **읽기만** 한다 — 입력을 가로채거나 막지 않는다.

**B. 표시 — Qt 테두리 창이 그 자리에 그려진다.** UIA 사각형 `[745, 317, 1229, 343]`(물리 픽셀)을 `devicePixelRatio`(1.0)로 나눠 테두리 창을 띄우고 화면을 캡처하니, 테두리 위 점이 `#ff0000`, 요소 안쪽은 `#ffffff`(가리지 않는다)였다. 창에 `WindowTransparentForInput`이 걸려 클릭이 아래 앱으로 간다.

## 못 본 것

- **배율 125%·150%, 모니터 여럿** — 화면 설정을 바꿔야 해서 보지 않았다. 나눗셈은 Qt가 그 화면의 `devicePixelRatio`를 주므로 맞아야 하고(S2가 UIA 좌표 = 물리 픽셀임을 125%·150%에서 확인했다, ADR-0021), 어긋나면 테두리가 몇 픽셀 밀리는 것으로 끝난다(업무를 건드리지 않는다).
- **표 안의 칸** — 시험 창의 표가 비어 있어 칸 위를 짚어 보지 못했다. 칸이 오면 **조상으로 올라가** 등록할 만한 종류(표)에 닿게 했다(`registrable`) — 제품 시험이 칸 있는 표로 본다.
- **누르고 있는 시간** — 고른 것은 화면이 비워 가져갈 때(BUI-06 `PICK_POLL_MS` = 400ms) 읽으므로, Ctrl을 그보다 짧게 누르면 놓친다. 「올려 두고 Ctrl을 누르세요」로 말한다.
