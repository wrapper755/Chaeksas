## FX-01. API AI 태스크

| 항목 | 값 |
| --- | --- |
| 분야 | 기능 예제 |
| 출처 | 프로토타입 example_api |
| 실행 위치 | **서버 (서버 Bot)** |
| 시작 | 수동 실행 |
| 서비스 앱·키 참조 | 없음 |
| 확장 | 없음 (플랫폼 기본 태스크만) |
| 마일스톤 | **M3** Studio 시험 실행에서 처음 통과 → M5 Center 배포 → M7 서버 실행기 |
| 파일 | [BPMN](bpmn/fx01_api_call.bpmn) · [시험 케이스](cases/fx01_api_call.cases.json) |

**업무 배경과 목표**

공개 API 한 번 호출해 값을 꺼낸다. 업무 파라미터로 주소를 두면 재생 때 그대로 쓰인다.

**왜 서버에서 도는가**

서버 기본 (ADR-0016).

**흐름 (노드)**

| id | 이름 | 종류 | 핵심 속성 | 다음 |
| --- | --- | --- | --- | --- |
| `Start` | 시작 | 시작 이벤트 | — | Task_Api |
| `Task_Api` | API 호출 | AI 태스크 | api · 결과 `원화`:number · 도구 http_request_tool · 파라미터 주소 | End |
| `End` | 끝 | 끝 이벤트 | — |  |

<details><summary>AI 태스크 목표 전문</summary>

**`Task_Api` API 호출**

```markdown
## 상황
업무 파라미터 `주소`가 JSON API다.

## 할 일
GET으로 한 번 불러 `rates.KRW`를 꺼낸다.

## 판단하지 않는 것
값을 지어내지 않는다. 응답에 없으면 실패한다.

## 반환
- `원화`: number
```

</details>

**시험 케이스**

| 케이스 | 입력 | 기대 결과 | 결재 자동 응답 · 보내는 메시지 |
| --- | --- | --- | --- |
| 기본 | {} | {"원화": {"$gt": 0}} | — |

**이 예제로 확인하는 것**

- `domain: api`
- 업무 파라미터
- 결정 수행 재생

**주의**

- 결과 타입을 적지 않으면 문자열 `"1380.5"`가 와서 뒤 비교가 틀렸다 — 결과에 타입을 적는다.

| 파일 | [BPMN](bpmn/fx02_business_rule.bpmn) · [시험 케이스](cases/fx02_business_rule.cases.json) · [DMN](bpmn/discount_policy.dmn) |

**업무 배경과 목표**

금액·등급으로 할인율과 사유를 정한다.

**왜 서버에서 도는가**

서버 기본 (ADR-0016).

**입력** (`chk:process.inputs` — 작업 지시·메시지 본문·케이스가 채운다)

| 이름 | 타입 | 필수 | 기본값 | 뜻 |
| --- | --- | --- | --- | --- |
| `금액` | int | ✓ |  |  |
| `등급` | string | ✓ |  |  |

**흐름 (노드)**

| id | 이름 | 종류 | 핵심 속성 | 다음 |
| --- | --- | --- | --- | --- |
| `Start` | 시작 | 시작 이벤트 | — | Task_Rule |
| `Task_Rule` | 할인 정하기 | 규칙(DMN) | DMN `discount_policy` → 할인율, 사유 | Task_Price |
| `Task_Price` | 최종가 | 스크립트 | `최종가 = round(금액 * (1 - 할인율))` | End |
| `End` | 끝 | 끝 이벤트 | — |  |

**규칙 `discount_policy` (할인 정책, 적중 정책 FIRST)**

| 금액 | 등급 | → discount | discount_reason | 설명 |
| --- | --- | --- | --- | --- |
| >= 1000000 | "VIP" | 0.2 | "VIP 대량 주문" |  |
| >= 1000000 | - | 0.1 | "대량 주문" |  |
| - | "VIP" | 0.05 | "VIP" |  |
| - | - | 0 | "할인 없음" |  |

**시험 케이스**

| 케이스 | 입력 | 기대 결과 | 결재 자동 응답 · 보내는 메시지 |
| --- | --- | --- | --- |
| VIP 대량 | {"금액": 1500000, "등급": "VIP"} | {"할인율": 0.2, "최종가": 1200000} | — |
| 일반 소량 | {"금액": 50000, "등급": "일반"} | {"할인율": 0} | — |

**이 예제로 확인하는 것**

- `businessRuleTask` + `chk:rule` 입력·출력 매핑
- 다중 출력 DMN

**주의**

- 프로토타입은 DMN 입력 이름(amount)과 변수 이름(금액)이 같아야 했다 — 새 형식은 `input` 매핑으로 잇는다.

## FX-04. 폴더 감시 (조건 시작 대체)

| 항목 | 값 |
| --- | --- |
| 분야 | 기능 예제 |
| 출처 | 프로토타입 example_conditional_start |
| 실행 위치 | **서버 (서버 Bot)** |
| 시작 | 타이머 — 5분마다 |
| 서비스 앱·키 참조 | 없음 |
| 확장 | 없음 (플랫폼 기본 태스크만) |
| 마일스톤 | **M3** Studio 시험 실행에서 처음 통과 → M5 Center 배포 → M7 서버 실행기 |
| 파일 | [BPMN](bpmn/fx04_folder_poll.bpmn) · [시험 케이스](cases/fx04_folder_poll.cases.json) |

**업무 배경과 목표**

받은 폴더에 파일이 있으면 처리한다. 프로토타입은 조건 시작 이벤트를 썼지만 엔진이 조건을 계속 평가하지 못했다 → **타이머 + 게이트웨이**로 바꾼다.

**왜 서버에서 도는가**

서버 기본 (ADR-0016).

**입력** (`chk:process.inputs` — 작업 지시·메시지 본문·케이스가 채운다)

| 이름 | 타입 | 필수 | 기본값 | 뜻 |
| --- | --- | --- | --- | --- |
| `감시폴더` | string |  |  |  |

**흐름 (노드)**

| id | 이름 | 종류 | 핵심 속성 | 다음 |
| --- | --- | --- | --- | --- |
| `Start` | 5분마다 | 시작 이벤트 | 타이머 `*/5 * * * *` | Task_List |
| `Task_List` | 파일 목록 | 스크립트 | `파일 = 파일목록(감시폴더 + '/*')` … | Gw_Any |
| `Gw_Any` | 있음? | 배타 게이트웨이 | — | Approve_Confirm (`건수 > 0`), End_None (기본) |
| `Approve_Confirm` | 처리 확인 | 결재 | 「받은 파일 처리」 · 보임 파일 · 칸 `처리`(bool*) · Center 결재함 | End |
| `End_None` | 없음 | 끝 이벤트 | — |  |
| `End` | 끝 | 끝 이벤트 | — |  |

**시험 케이스**

| 케이스 | 입력 | 기대 결과 | 결재 자동 응답 · 보내는 메시지 |
| --- | --- | --- | --- |
| 빈 폴더 | {"감시폴더": "samples/inbox-empty"} | {"건수": 0} | — |
| 2건 | {"감시폴더": "samples/inbox"} | {"건수": 2} | `Approve_Confirm`: {"처리": true} |

**이 예제로 확인하는 것**

- 조건 시작 이벤트는 지원하지 않음 (C14) → 타이머 폴링
- 끝 이벤트 둘

**주의**

- 조건 시작은 「무엇이 바뀌면 다시 평가하나」가 정의되지 않아 프로토타입에서 한 번만 돌았다.
- 폴링은 실행이 자주 생긴다 — 「없음」 실행은 이력에서 접어 보이게(CON-04 필터).

## FX-13. 신호 던지기·받기

| 항목 | 값 |
| --- | --- |
| 분야 | 기능 예제 |
| 출처 | 프로토타입 example_signal |
| 실행 위치 | **서버 (서버 Bot)** |
| 시작 | 수동 실행 |
| 서비스 앱·키 참조 | 없음 |
| 확장 | 없음 (플랫폼 기본 태스크만) |
| 마일스톤 | **M3** Studio 시험 실행에서 처음 통과 → M5 Center 배포 → M7 서버 실행기 |
| 파일 | [BPMN](bpmn/fx13_signal.bpmn) · [시험 케이스](cases/fx13_signal.cases.json) |

**업무 배경과 목표**

가지 A가 준비되면 `ready` 신호를, 검사에서 문제가 나오면 `abort` 신호를 던진다. 가지 B는 `ready`를 기다렸다가 일하고, 일하는 중 `abort`가 오면 정리한다.

**왜 서버에서 도는가**

서버 기본 (ADR-0016).

**입력** (`chk:process.inputs` — 작업 지시·메시지 본문·케이스가 채운다)

| 이름 | 타입 | 필수 | 기본값 | 뜻 |
| --- | --- | --- | --- | --- |
| `검사결과` | string |  | "ok" |  |
| `작업번호` | string |  | "W-1" |  |

**흐름 (노드)**

| id | 이름 | 종류 | 핵심 속성 | 다음 |
| --- | --- | --- | --- | --- |
| `Start` | 시작 | 시작 이벤트 | — | Gw_Fork |
| `Gw_Fork` |  | 병렬 게이트웨이 | — | Wait_A, Wait_Ready |
| `Wait_A` | 1초 뒤 | 중간 받기 | 타이머 `PT1S` | Task_Prepare |
| `Task_Prepare` | 준비 (A) | 스크립트 | `준비 = True` | Thr_Ready |
| `Thr_Ready` | ready | 중간 던지기 | 신호 `ready` | Task_Inspect |
| `Task_Inspect` | 검사 (A) | 스크립트 | `result = 검사결과` | Gw_Problem |
| `Gw_Problem` | 문제? | 배타 게이트웨이 | — | Thr_Abort (`result != 'ok'`), End_A (기본) |
| `Thr_Abort` | abort | 중간 던지기 | 신호 `abort` | End_A |
| `End_A` | A 끝 | 끝 이벤트 | — |  |
| `Wait_Ready` | ready 대기 | 중간 받기 | 신호 `ready` | Recv_Work |
| `Recv_Work` | 본 작업 완료 받기 | 메시지 받기 | 메시지 `work_done` · 상관 `작업번호` | Task_Work |
| `Task_Work` | 본 작업 기록 (B) | 스크립트 | `작업 = '완료'` | End_B |
| `Task_Cleanup` | 정리 (B) | 스크립트 | `작업 = '중단'` | End_B |
| `End_B` | B 끝 | 끝 이벤트 | — |  |
| `Bnd_Abort` | abort | 경계(신호) | `Recv_Work`에 붙음 · `abort` | Task_Cleanup |

**시험 케이스**

| 케이스 | 입력 | 기대 결과 | 결재 자동 응답 · 보내는 메시지 |
| --- | --- | --- | --- |
| 정상 | {} | {"작업": "완료"} | —<br>4초 뒤 `work_done` {} |
| 문제<br><small>abort가 1초쯤 오므로 4초 뒤 완료 메시지는 받을 곳이 없다</small> | {"검사결과": "bad"} | {"작업": "중단"} | —<br>4초 뒤 `work_done` {} |

**이 예제로 확인하는 것**

- 중간 던지기 신호 / 중간 받기 신호 / 경계 신호
- 한 실행 안의 가지 사이 신호 (C14 범위)
- 중간 받기 타이머로 순서 잡기
- 받기 태스크의 신호 경계

**주의**

- 신호는 **한 실행 안의 가지 사이**에서만 오간다 (C14). 다른 실행·외부 시스템에 알리려면 메시지를 쓴다 (BX-11).
- 받는 쪽이 아직 기다리지 않을 때 던진 신호는 사라진다. 가지 A 앞에 1초 대기를 두어 B가 먼저 `ready 대기`에 서게 한다 — 시험용 순서 잡기이며, 실제 업무에서는 신호에 순서를 기대지 않는다.
- `abort` 경계는 바깥 작업 완료를 기다리는 받기 태스크에 붙였다. 경계는 태스크에만 붙는다(이벤트에는 못 붙임). 순간에 끝나는 스크립트에 붙이면 신호가 닿기 전에 끝나 버린다.

| `Start` | 시작 | 시작 이벤트 | — | Task_Make |

| `Bnd_Fail` | 실패 | 경계(오류) | `Task_Hook`에 붙음 · `SEND_FAILED` | Task_Fail |

- `chk:webhook` body `fields:[…]`
- `SEND_FAILED`

**주의**

- body `all`은 모든 변수를 보낸다 — 비밀이 섞일 수 있어 `fields`를 권장 (실행 전 검사 경고).
