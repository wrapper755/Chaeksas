# 08. BPM 업무 예제

| 항목 | 값 |
| --- | --- |
| 상태 | **초안** (2026-10-01) — 코드 작업 전 준비물 |
| 형식 | [C14 BPMN 확장 속성](../03-contracts/C14-bpmn-extensions.md) |
| 쓰는 곳 | M3 엔진 회귀 시험, M4 UI 태스크, M5 결재·확장, M7 서버 실행 — 각 마일스톤의 **인수 시험 묶음** ([05-roadmap](../05-roadmap.md)). Studio 「예제 BPM 프로세스 가져오기...」(STU-01), 사용자 교육 |
| 작성 규칙 | [writing-guide.md](writing-guide.md) — 프로토타입에서 시나리오 쓰기가 어려웠던 이유와 규칙 |

프로토타입에서 BPM Studio를 만들며 가장 애먹은 것은 화면이 아니라 **돌릴 업무 시나리오**였다. 시나리오가 없으니 기능이 맞는지 판단할 수 없었고, 그때그때 만든 예제는 목표 문구·파라미터·케이스가 서로 어긋났다. 이 폴더는 그 일을 코드보다 먼저 해 둔다.

- **업무 예제(BX)** — 실제 부서 업무 하나를 처음부터 끝까지. 왜 서버(또는 PC)에서 도는지, 어떤 확장·키가 필요한지, AI 태스크 목표 전문, 결재 폼, 시험 케이스, 프로토타입에서 배운 주의점까지 적었다.
- **기능 예제(FX)** — BPMN 요소·플랫폼 기능 하나씩. 프로토타입 `processes/example_*.bpmn`을 새 형식으로 옮기고 빈 곳(병렬 반복, 포함 게이트웨이, 외부 확장 등)을 메웠다. 엔진 회귀 시험의 최소 단위다.

## 파일

| 위치 | 내용 |
| --- | --- |
| `finance.md`, `scm.md`, `hr.md`, `ops.md` | 분야별 업무 예제 카드 |
| `feature-examples.md` | 기능 예제 카드 |
| `bpmn/*.bpmn` | 실행할 BPMN (C14 확장 속성 + 그림 정보). bpmn-js로 열린다 |
| `bpmn/*.dmn` | 규칙 태스크가 쓰는 결정표 |
| `cases/*.cases.json` | 시험 케이스 (C14 형식, STU-07이 읽는다) |
| `_source/` | **유일한 원본.** `spec_*.py`(예제 정의) → `build.py`가 위 파일을 모두 만든다 |

```bash
python docs/08-business-examples/_source/build.py          # 다시 만들기 (표준 라이브러리만)
python docs/08-business-examples/_source/build.py --check  # CI: 정의와 생성물이 다르면 실패
```

`build.py`는 만들기 전에 C14 검사 규칙 중 정의만 보고 할 수 있는 것을 검사한다: B2·B3(포함 짝)·B4·B5·B6·B7·B8(결과 타입)·B9·B12·B14, 그리고 B11의 일부(메일·웹훅·결재 `show`가 읽는 변수의 출처). 케이스도 대조한다: 입력이 선언됐는지, 필수 입력이 있는지, 기대 변수를 만드는 곳이 있는지, 결재 자동 응답의 칸·타입, 보내는 메시지를 받는 곳. **스크립트·조건식 안의 「경로에 따라 없는 변수」는 아직 검사하지 못한다** — 식 해석기가 생기는 M3에서 B11을 온전히 구현한다. **생성된 파일을 직접 고치지 않는다** — 카드·BPMN·케이스가 서로 어긋나는 것이 프로토타입의 실패 원인이었다.

## 검증한 것 (2026-10-01)

| 검사 | 결과 |
| --- | --- |
| `build.py` 정의 검사 | 50개 모두 통과 |
| XML 파싱 | BPMN 50, DMN 7 통과 |
| bpmn-js 17 가져오기 (Chromium, Playwright) | 50개 모두 경고 없이 열림, 그림 육안 확인 |
| SpiffWorkflow 3 파서 | BPMN 43개 통과. **규칙 태스크가 있는 7개는 실패** — 기본 파서가 `camunda:decisionRef`를 기대한다. M3에서 `chk:rule`을 읽는 파서 확장이 필요하다. DMN 7개는 모두 통과 |
| 실행 | 아직 없음 (엔진은 M3). 케이스 기대값은 설계값이다 |

## 아직 정하지 않은 것 (예제가 드러낸 공백)

| 공백 | 예제 | 갈 곳 |
| --- | --- | --- |
| 서버 BPM 프로세스가 PC 작업을 만드는 요소 | BX-16 (사내 확장으로 임시로 메움) | [ADR-0016](../decisions/0016-server-first.md) §3 「PC 위임」 제안 (Call Activity로 표현, schema 1은 C1 R3가 거부) → M7 |
| 받는 곳이 아직 없을 때 온 메시지 — C12는 `no_receiver`로 거부해 잃는다 | BX-05, BX-11, BX-13, BX-34 | C12 메시지 보관(TTL) 검토 → M7 |
| 식 언어의 업무 도우미 함수 (`지난달()`, `기간()`, `합계()`, `표를사전()` …) | 스크립트가 있는 예제 대부분 | C14 규칙 6, M3에서 목록 확정 |
| 다중 인스턴스 하위 프로세스 | BX-22 (실행 하나 = 한 사람으로 우회) | M3 엔진 확인 |
| 병렬 가지에서 같은 목록 변수에 덧붙이기 | BX-22 | M3 결정 (가지별 변수 → 합류 뒤 합치기 권장) |
| 말일 cron(`L`) | BX-05 | M3 일정 해석기 |
| 결재자 배정 규칙 (누가 결재하나) | BX-21, BX-33 | C6 결재 배정 (BPMN에 사람 이름을 쓰지 않음) |
| 시험용 모의 서비스 앱 (ERP, 신용, 헬프데스크 등) | 확장을 쓰는 예제 전부 | M5 `samples/mock-*` |
