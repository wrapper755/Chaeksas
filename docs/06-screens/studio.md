# Studio 화면 설계

Windows 데스크톱 앱 (PySide6 + bpmn-js in QtWebEngine). 사용자: BPM 프로세스 설계자.
공통 원칙·상태 표기는 [README.md](README.md) §2·§3.

## STU-01 메인 창

기본 크기 1400×860. 시작하면 마지막으로 연 BPM 프로세스를 다시 연다. 없으면 빈 캔버스 + 로그에 안내 + 탐색기를 앞으로.

```
+----------------------------------------------------------------------+
| [T] title bar                                                        |
| [M] menu bar                                                         |
| [B] toolbar                                                          |
+---------------+--------------------------------------+---------------+
|               |                                      |               |
|      [E]      |                [C]                   |      [P]      |
|  explorer     |            BPMN canvas      [mini]   |   property    |
|  docks (tabs) |                                      |   panel       |
|               |                                      |               |
+---------------+--------------------------------------+---------------+
|                        [L] bottom tabs                               |
+----------------------------------------------------------------------+
| [S] status bar                                                       |
+----------------------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [T] 제목 | 아무것도 없을 때 「Chaeksas Studio - (BPM 프로세스를 선택하거나 새로 만드세요)」. 열려 있으면 「Chaeksas Studio - <BPM 프로세스 이름> (v<버전>) - <정의 이름>」, 저장 안 한 변경이 있으면 끝에 「 *」. 공유 BPM 프로세스를 열면 「[공유 BPM 프로세스] <이름> <버전> (읽기 전용)」 |
| [M] 메뉴 | 아래 표 |
| [B] 도구 모음 | 「저장」 \| 「실행 취소」「다시 실행」 \| 「실행 전 검사」「실행...」 \| 「속성 패널 접기」. 실행 중에는 「실행...」이 강조색으로 바뀌고 글자가 「자율 수행 중지」/「결정 수행 중지」가 된다 (U5) |
| [E] 탐색기 독 | 탭 두 개: 「BPM 프로세스」(STU-02), 「리소스」(STU-03). 왼쪽 기본, 오른쪽으로 옮길 수 있음 |
| [C] 캔버스 | bpmn-js 편집기 + 오른쪽 위 미니맵(노드 상태 색 포함). 「리소스」 탭의 「캔버스에 추가」나 끌어다 놓기로 해당 태스크가 생긴다 (STU-03, [ADR-0044](../decisions/0044-canvas-drag-and-drop.md)) |
| [P] 속성 패널 | STU-04. 캔버스와 가로 분할 (3:1) |
| [L] 아래 탭 | 「로그」(읽기 전용, 문맥 메뉴 「로그 지우기」), 「검사」(실행 전 검사 — F6·STU-08이 같은 표를 채운다), 「UI 태스크」(그 실행의 UI 세션 한 줄씩 — STU-09), 「변수」(이름/값/타입 트리) |
| [S] 상태 줄 | 색 + 글자 한 줄. 시작은 「대기 중」 |

모든 영역은 접을 수 있고 크기·위치를 기억한다. 도구 → 「레이아웃 초기화」로 되돌린다.

> 상태: **돈다** (`apps/studio/layout.py`). 창 크기·위치, 독의 자리, 분할자 비율, 「속성 패널
> 접기」가 **설정과 따로 `layout.json`**에 담긴다 — 사람이 읽고 고치는 설정(주소·참조 이름)에
> Qt의 바이트 뭉치를 섞지 않고, 지워도 되는 파일이라 「초기화」가 **파일 지우기 + 지금 창
> 되돌리기**로 끝난다. **깨진 파일은 없는 것으로 보고** 기본 배치로 뜬다 (배치 하나 때문에
> Studio가 뜨지 않으면 안 된다). 담아 둔 판이 맞지 않으면 Qt가 거부하고, 되돌리지 못한 자리는
> 기본값으로 남는다.

파일을 직접 여는 메뉴는 없다 (U1). BPM 프로세스는 탐색기에서 연다.

- **「다른 이름으로 저장...」의 단위는 BPM 프로세스다** — 파일 메뉴의 단위가 BPM 프로세스이고(U1),
  정의 하나만 복사하면 그림 안의 BPMN process id가 겹쳐 `callActivity`가 어느 것을 부를지
  모호해진다 (바꾸려면 XML을 파이썬이 만져야 하고 [ADR-0022](../decisions/0022-studio-canvas.md)가
  그것을 막는다). 받는 칸은 STU-05와 같고(id·이름·버전·그룹, id만 비워 둔다), 정의·케이스·
  학습(`memory/`)·받아 둔 공유 BPM 프로세스가 함께 간다. **실행 기록·산출물은 두고 간다** —
  그 실행의 것이다. 복사한 뒤에는 **복사한 쪽을 편집한다**(진입 정의를 연다).
- 「저장」은 **열린 정의**를, 「다른 이름으로 저장...」은 **BPM 프로세스 한 벌**을 쓴다. 복사는
  디스크의 것을 옮기므로 저장 안 한 편집이 있으면 **먼저 저장**을 거친다.
- 실행 메뉴의 「결정 수행 (재생)...」은 「실행...」과 **같은 창(STU-08)**을 열고 수행 모드만
  미리 골라 둔다 — 학습 안 된 AI 태스크가 있으면 창이 그 모드를 끄고 까닭을 보이므로(U3)
  **메뉴는 끄지 않는다**.

### 닫기·전환 보호

- 창 닫기·다른 정의로 전환 시 저장 안 한 변경이 있으면 「저장하지 않은 변경사항」: 「저장」/「저장 안 함」/「취소」 (U11).
- 속성 패널에 적용 안 한 편집이 있으면 먼저 STU-04의 확인을 거친다.

## STU-02 BPM 프로세스 탐색기

```
+---------------------------------------------+
| [H] column header                           |
| [G] group                                   |
|   [P] process                               |
|     [D] definition                          |
+---------------------------------------------+
```

| 열 | 내용 |
| --- | --- |
| 「BPM 프로세스 / 정의」 | 그룹(폴더 아이콘) → BPM 프로세스 → 정의(BPMN). 「기본」 그룹은 항상 맨 위, 지울 수 없음. 열려 있는 BPM 프로세스·정의는 굵게 |
| 「버전」 | BPM 프로세스 버전 |
| 「학습·검증」 | BPM 프로세스 줄: 「AI 태스크 N개 · 학습 a/N · 재생 검증 v/N · 케이스 통과 p/S」. 정의 줄: 「진입」 또는 「진입에서 호출되지 않음」 |

- 더블클릭·Enter: BPM 프로세스 줄 → 진입 정의를 연다. 정의 줄 → 그 정의를 연다.
- BPM 프로세스를 다른 그룹으로 끌어 옮긴다.
- 빈 상태: 「BPM 프로세스가 없습니다. 파일 → 새 BPM 프로세스...로 만드세요.」
- 버튼 줄은 없다 (메뉴와 겹침).

문맥 메뉴 (고른 줄의 종류에 따라, U4):

| 줄 | 항목 |
| --- | --- |
| 정의 | 「열기」, 「정의 삭제...」, 「공유 BPM 프로세스로 내보내기...」, 「공유 BPM 프로세스 Center로 올리기」 |
| BPM 프로세스 | 「열기」, 「BPM 프로세스 정보...」, 「다른 그룹으로 이동...」, 「BPM 프로세스 삭제...」, 「Center로 올리기」 |
| 그룹·빈 곳 | 「새 BPM 프로세스...」, 「예제 BPM 프로세스 가져오기...」, 「새 그룹...」, 「그룹 삭제」(비었을 때만), 「새로 고침」 |

삭제 확인:
- 「BPM 프로세스 삭제」: 지워지는 것(정의, 케이스, 학습 자료)을 나열, 되돌릴 수 없음, 기본 단추 「아니요」.
- 「정의 삭제」: 진입 정의이거나 다른 정의가 부르는 정의면 거부하고 이유를 보인다. 아니면 함께 지워지는 케이스를 나열.

## STU-03 리소스 탐색기

> 상태: **돈다** (`apps/studio/resources.py`). 뿌리 셋, 둘째 단계(「서비스 앱 → 작업」), 문맥 메뉴, 「캔버스에 추가」, **끌어다 놓기**, 공유 BPM 프로세스의 **부르기·보기·복사**가 돈다.
>
> - **끌어다 놓기와 「캔버스에 추가」는 같은 길이다** ([ADR-0044](../decisions/0044-canvas-drag-and-drop.md)) — 둘 다 캔버스 명령 하나(`createTask`)로 만들어 **실행 취소가 한 걸음**이고, 다른 것은 **자리뿐**이다(놓은 점이 노드의 가운데가 된다. 메뉴·더블클릭은 보이는 자리의 빈 곳을 찾는다). **만들 것이 없는 줄은 아예 끌리지 않는다** — 끌고 가서 놓았는데 아무 일도 없는 것보다 낫다. 열린 정의가 없으면 메뉴와 **같은 한 줄**을 말한다.
> - 캔버스는 `QWebEngineView`라 드롭을 **내부 렌더 위젯에서 가로챈다** (뷰의 `dropEvent`는 불리지 않는다 — ADR-0044, 스파이크 `spikes/s9-canvas-drop/`). **우리 MIME 형식일 때만** 받으므로 페이지 안의 bpmn-js 팔레트 드래그와 바깥에서 끌어 온 파일은 그대로 간다. **캔버스는 무엇이 떨어졌는지 모른다** — 글과 자리만 올려 보내고 뜻은 메인 창이 푼다.
> - **기여 뿌리는 한 단계다 — 둘째 단계를 「두지 않는다」** ([ADR-0045](../decisions/0045-contributed-resource-children.md), 아직이 아니라 **하지 않는다**). 둘째 단계(요소)는 항목의 `data`인데 **플랫폼은 그것을 해석하지 않는다** (C13 §5 — 그래서 코드에 「UI 화면」이라는 말이 없다). 요소 수는 항목의 `summary`가 말해 주고, **요소를 고르는 자리는 STU-13의 스텝 표 하나다** (그 확장이 공개 카탈로그를 직접 읽는다 — 선언으로 걷게 하면 같은 목록이 두 길로 와 `revision`·「오프라인인가」가 어긋난다). 그래서 「요소 보기」·「요소를 끌어다 스텝 추가」가 **없다** — 요소를 훑어보려면 문맥 메뉴 「관리 콘솔에서 보기」(UIA-02)가 그 길이다.
> - **쓸 수 없는 줄은 끄고 까닭을 적는다** (U3): 「공유 BPM 프로세스」 뿌리의 「설치...」·「제거...」는 **여기서 하지 않는다** — 설치는 **열린 BPM 프로세스 하나에** 하는 일이라 ([ADR-0048](../decisions/0048-installing-shared-packages.md)) 문맥 메뉴의 **「Center 공유 자원...」**(STU-11)이 그 자리다.
> - **공유 BPM 프로세스의 셋은 설치된 판에서만 켜진다** ([ADR-0051](../decisions/0051-shared-process-conveniences.md)) — 뿌리의 **멤버십은 Center 목록 그대로**이고(줄이 늘거나 줄지 않는다) 「이 BPM 프로세스에 받아 둔 판」은 **줄에 덧붙인다**. 설치 여부를 읽는 함수는 **STU-11과 하나**다(`install.installed_of` — 베끼면 한 화면은 「설치됨」이라 하고 다른 화면은 「—」라 하는 날이 온다). **설치되지 않은 것으로 Call Activity를 만들어 주지 않는다** — C14 B14가 그 그림을 막고 시험 실행이 부를 수 없어 「왜 안 되나」가 된다. **Center 목록에서 빠졌는데 설치돼 있는 것(「로컬만」)은 STU-11의 일이다** — 이 뿌리는 그것을 지어내 그리지 않는다(둘째 단계와 「받는 것·내놓는 것」은 매니페스트의 `provides`가 주는 것이다, C1).

BPM 프로세스 밖에서 가져다 쓰는 것을 보여 준다. 「공유 BPM 프로세스」·「서비스 앱」은 고정 뿌리이고, 그 밖의 뿌리는 **확장이 기여한다** (`studio.resource_views`, 예: UI 자동화 확장의 「UI 화면」) — 뿌리 이름·자원 갈래·만들 태스크 종류가 모두 선언에서 오고, 기여 뿌리는 **라벨 순**으로 그린다.

목록은 Center에서 온다. 서비스 앱은 STU-14가 받아 둔 것을 그대로 쓰고(같은 것을 두 번 받지 않는다), 기여 자원은 **리소스 목록(C7)**을, 공유 BPM 프로세스는 **패키지 표(C5 `?kind=process_lib`)**를 뿌리마다 한 번씩 읽는다 — C7에 그 갈래가 없다. **들고 있지 않는다** — 닿지 못하면 그 자리에서 「받지 못했습니다 — <까닭>」과 「새로 고침」을 보인다. Studio는 현장이 아니라 개발 도구다 (들고 있는 쪽은 Bot UI다, [ADR-0007](../decisions/0007-client-initiated-communication.md)). Center 주소·키가 없으면 **두드리지 않고** 뿌리만 그린다.

열은 셋이다: 「리소스」 / 「구분」 / 「설명」.

| 뿌리 | 하위 | 「캔버스에 추가」 | 문맥 메뉴 |
| --- | --- | --- | --- |
| 「공유 BPM 프로세스」 | 공유 BPM 프로세스(이름, 버전, 「정의 N개」 + 받아 둔 판) → 정의 | 정의 → Call Activity 생성 (`calledElement`만). **설치된 판의 정의에서만** 켜진다 | 「캔버스에 추가」, 「열기 (읽기 전용)」, 「내 BPM 프로세스로 복사」 — 셋 다 설치된 정의에서만. 「설치...」·「제거...」는 끄고 「Center 공유 자원...」(STU-11)으로 보낸다 |
| 「UI 화면」 (UI 자동화 확장 기여) | 화면(이름 + `summary`의 요소 수) | 그 화면의 UI 태스크(STU-13) 생성 — 자원 id는 확장이 선언한 칸(`creates_task_field`)에만 넣는다 | 「캔버스에 추가」, 「관리 콘솔에서 보기」(그 확장의 서버 부분 콘솔, C7 `console_url`이 있을 때만) |
| 「서비스 앱」 (신규) | 앱(이름, 구분·확장 등급, 상태 — 외부 확장의 HTTP 어댑터 작업도 여기) → 작업 | 작업 → 서비스 앱 태스크(STU-14) 생성. **키 참조는 넣지 않는다** (BPM 프로세스에서 상속) | 「캔버스에 추가」, 「작업 설명 보기」, 「관리 콘솔에서 보기」 |

- 더블클릭: 만들 수 있는 항목이면 「캔버스에 추가」. 만들 수 없는 줄이면 **까닭을 로그에 한 줄** 말한다 (조용히 아무 일도 없지 않다). 열린 정의가 없으면 「열린 정의가 없습니다 — 먼저 BPM 프로세스를 여세요」.
- **끌어다 놓기**: 만들 수 있는 줄을 캔버스로 끌면 **놓은 자리에** 그 노드가 생긴다 (가운데가 그 점이다). 만들 수 없는 줄은 끌리지 않고, 열린 정의가 없으면 더블클릭과 같은 한 줄을 말한다. 「스텝 사이에 끼우기」(연결선 위에 놓기)는 없다 ([ADR-0044](../decisions/0044-canvas-drag-and-drop.md) — bpmn-js의 `dragging`에 들어가야 한다).
- 「작업 설명 보기」는 읽기만 하는 창이고 **manifest·정의가 말해 준 것만** 보인다 — `input_schema`·`output_schema`가 없으면 「정의가 알려 주지 않았습니다」라고 한다 (없는 칸을 지어내지 않는다, C11).
- **공유 BPM 프로세스 줄에 덧붙는 말** ([ADR-0051](../decisions/0051-shared-process-conveniences.md)): 받아 둔 판이 있으면 「설명」 끝에 「· 설치됨」, 판이 다르면 「· 다른 판 설치됨 (1.0.0)」이 붙는다. 받아 둔 것이 없으면 **아무 말도 붙지 않는다**(없음이 그 뜻이다). 셋이 꺼지는 까닭은 말풍선에 붙고 **STU-11로 보낸다**: 「이 BPM 프로세스에 설치되지 않았습니다 — 「Center 공유 자원...」(STU-11)에서 설치합니다」 / 「다른 판이 설치되어 있습니다 (1.0.0) — STU-11에서 갱신합니다」 / 「설치된 판이 이 정의를 주지 않습니다」(읽지 못한 정의 — 실행 전 검사가 말한다). 공유 BPM 프로세스 줄(첫 단계)에서는 「정의를 고르면 Call Activity를 만듭니다」다.
- **「캔버스에 추가」가 만드는 것은 `calledElement`뿐이다** — `chk:call`의 입력·출력 짝은 **내 변수 이름**을 알아야 하는 일이라 지어내지 않고 속성 패널(STU-04)에서 적는다. 그 공유 BPM 프로세스가 선언한 「받는 것·내놓는 것」은 줄의 「설명」과 말풍선이 말해 준다.
- **「열기 (읽기 전용)」은 받아 둔 `libs/`의 그 파일을 띄운다** — 창은 **정말 못 고치는 뷰어**다 (bpmn-js 뷰어 배포본, ADR-0051 — 팔레트를 가린 편집기가 아니다). 머리에 「<패키지>@<판> / <정의 id> — 읽기 전용입니다」 한 줄, 아래에 「닫기」. 확대·이동만 되고 **Center를 부르지 않는다**(보는 것과 실행이 같은 파일이다).
- **「내 BPM 프로세스로 복사」**는 그 정의를 **내 `process/`로** 가져와 편집 대상으로 만들고 바로 연다. 묻는 창이 **만들 파일 이름을 적어** 보이고(이름이 겹치면 새 이름이 거기 적힌다 — **덮어쓰지 않는다**), 복사한 뒤로는 **내 것이 이기고**(같은 id면 `process/`가 `libs/`를 가린다) 내보낼 때 `requires.libs`에서 빠진다. **같은 BPMN 프로세스 id의 정의가 이미 있으면 복사하지 않고 그렇게 말한다.** 저장 안 한 편집이 있으면 **먼저 묻는다** (열기와 같은 관문, U11).
- 「새로 고침」은 단추와 문맥 메뉴 둘 다에 있고, 받는 일은 **메인 창**이 한다 (STU-14의 고를 거리와 같은 한 번의 읽기다).
- 확장을 끄고 켜면(STU-15) 그 자리에서 뿌리가 사라지거나 생긴다 ([ADR-0043](../decisions/0043-turned-off-extensions.md)).

툴팁: 공유 BPM 프로세스 정의는 읽는/쓰는 변수, 기여 자원은 id와 바뀐 때, 서비스 앱 작업은 입력·출력 필드.

## STU-04 속성 패널

> 실행 위치가 「서버」인 BPM 프로세스에서는 캔버스 팔레트의 UI 태스크가 꺼지고(이유 툴팁 대신 팔레트 아래 한 줄: 「서버 실행 — UI 태스크를 쓸 수 없습니다」), AI 태스크 「대상 환경」에서 웹·데스크톱이 꺼진다 (U3).

캔버스에서 고른 요소를 편집한다.

```
+------------------------------------------+
| [H] name + type + (faint id)             |
| [K] tabs: form | JSON                    |
| [F] editor sections                      |
| [E] error line                    [Apply]|
+------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [H] 머리 | 굵은 이름 + 한국어 종류 + 흐린 id (U2) |
| [K] 탭 | 「폼」 \| 「JSON」. 그 요소가 우리 설정 문서를 가질 때만 탭 줄을 보인다 |
| [F] 편집기 | 아래 표 |
| [E] 오류·적용 | 빨간 오류 한 줄 + 「적용」 단추. 실제 변경이 있을 때만 켜진다 |

- 빈 상태: 「캔버스에서 요소를 선택하면 속성을 편집할 수 있습니다.」
- 적용 안 한 편집이 있는데 다른 요소를 고르거나 저장·실행하면: 「적용하지 않은 변경사항」 「적용」/「버리기」/「머무르기」. 지금 적용할 수 없는 상태면 「적용」을 빼고 이유를 보인다.
- 빈 캔버스를 눌러도 패널을 BPM 프로세스로 바꾸지 않는다 (편집 중단 방지).

## STU-06 BPM 프로세스 정보

> 상태: **돈다** (`apps/studio/process_dialog.py`). 파일 메뉴 「BPM 프로세스 정보...」로 연다.
>
> **고치는 것이 두 곳에 산다.** 이름·버전·설명·담당자·태그는 작업 폴더 기록(`process.json` — Studio 안에서만 쓰는 기록이라 계약이 아니다)이고, **실행 위치·키 참조는 그림**(`chk:process`, C14)이다. 그림은 **캔버스를 거쳐야** 고칠 수 있으므로([ADR-0022](../decisions/0022-studio-canvas.md) — XML을 파이썬이 만지면 실행 취소와 「저장 안 한 변경」이 깨진다) **진입 정의가 열려 있을 때만** 그 두 칸이 켜지고, 아니면 끄고 까닭을 적는다 (U3). 켜져 있으면 「저장」이 `chk:process`를 **한 걸음**으로 적용한다(실행 취소도 한 걸음). **외부 확장의 「정의 고정」은 여기서 하지 않는다** — 해시를 보여 주는 자리가 STU-15이고, 같은 값을 고치는 자리를 두 곳에 두지 않는다 ([ADR-0060](../decisions/0060-pinning-external-definitions.md)).
>
> - **설명만 패키지로 간다** (C1 `description`) — 담당자·태그는 매니페스트에 칸이 없어 설계자가 보는 메모로 남는다. 빈 값은 기록에 적지 않는다(「아직 안 적었다」와 「비웠다」를 가르지 않는다).
> - **읽고 쓰는 것은 진입 정의 하나다.** 하위 정의가 적은 `service_keys`를 섞어 보이면 저장이 그것을 진입으로 옮기는 셈이 된다. 저장할 때 **읽은 `chk:process`를 통째로 되돌려 쓴다** — `inputs`·`outputs`·`extensions`처럼 창이 다루지 않는 칸이 사라지지 않게.
> - **「서버에서 실행할 수 없는 태스크」는 그림 검사와 같은 함수로 센다** (`contracts.server_blockers` — B6이 쓰는 것). 어긋나면 창이 「바꿔도 된다」고 하고 F6이 막는 일이 생긴다. **확장 태스크(UI 태스크 등)도 센다** — 실행 위치는 확장 정의만 아니(C13 `task_types[].run_locations`, [ADR-0018](../decisions/0018-extensions.md)) 메인 창이 확장 호스트의 표를 넘긴다. **F6·패키지 매니페스트가 같은 표를 쓴다.** 표에 없는 종류(그 확장을 깔지 않았거나 꺼 뒀다 — [ADR-0043](../decisions/0043-turned-off-extensions.md))는 **세지 않는다**: 모르는 것을 막으면 올바른 그림이 「서버에서 안 된다」가 된다.
> - **그림 쪽은 캔버스에만 적용된다** — 파일로 가는 것은 「저장」(Ctrl+S)이다 (STU-04의 「적용」과 같은 결). 상태 줄이 그렇게 말한다.
> - **「이 부분을 PC BPM 프로세스로 나누기...」가 돈다** ([ADR-0071](../decisions/0071-splitting-a-task-into-a-pc-bot.md), `apps/studio/split_actions.py`·`split_dialog.py`) — 단위는 **서버에서 못 하는 노드 하나**다. 그 노드를 새 PC Bot(시작 → 노드 → 끝)으로 옮기고 원래 자리는 **위임 호출로 바뀐다**(흐름·경계 이벤트는 그대로, 실행 취소 한 걸음). 그림은 둘 다 **캔버스가 짓는다**(`appendChain`·`delegateNode`). 아래 「STU-06a」.

읽기 전용: id, 폴더, 학습 상태 요약. 편집: 이름(중복 검사), 버전, 설명, 담당자, 태그(쉼표), **「실행 위치」**(PC / 서버, 신규). 「저장」/「취소」.

「실행 위치」를 「서버」로 바꾸면 서버에서 쓸 수 없는 태스크(UI 태스크, 웹·데스크톱 환경 AI 태스크, 「현장」 결재 위치)를 바로 세어 「서버에서 실행할 수 없는 태스크 N개 — 실행 전 검사에서 오류로 표시됩니다」를 보인다 (저장은 막지 않음). 같은 줄에 단추 「실행 위치를 PC로 바꾸기」. 서버에 둬야 할 업무라면 같은 줄의 「이 부분을 PC BPM 프로세스로 나누기...」 — 이 창을 닫고 STU-06a를 연다(이 창에서 고친 것은 저장되지 않는다 — 그렇게 묻는다). [ADR-0015](../decisions/0015-run-location.md) §3, [ADR-0016](../decisions/0016-server-first.md)

**「서비스 앱 키」 섹션 (신규, [ADR-0013](../decisions/0013-api-keys.md) 안 C):** 이 BPM 프로세스가 서비스 앱을 부를 때 쓸 **키 참조 이름**. 키 값은 여기에 넣지 않는다 (패키지에 비밀이 들어가지 않게).

| 열 | 내용 |
| --- | --- |
| 「서비스 앱」 | 이 BPM 프로세스의 UI 태스크·서비스 앱 태스크가 쓰는 앱 (자동으로 채움, 「추가」로 더 넣을 수 있음) |
| 「키 참조 이름」 | 예: `finance-invoice`. 영문 소문자·숫자·`-`, 1~40자. 기본값은 BPM 프로세스 id에서 `.`·`_`를 `-`로 바꾼 것 (C1) |
| 「이 PC의 값」 | 읽기 전용: 「정상」 / 「없음 — 설정 → 서비스 앱 키」 (Studio 설정 기준) |
| 「태스크에서 바꾼 곳」 | 이 참조를 쓰지 않고 다른 참조로 바꾼 태스크 수 (누르면 목록) |

- 태스크(STU-13·STU-14)는 기본으로 이 표의 참조를 **상속**한다.
- 「실행 전 검사」(F6)는 참조 이름이 빠진 서비스 앱을 오류로 보인다. **값이 이 PC에 없는 참조도** 사전 점검이 오류로 보인다 — 「설정 → 「서비스 앱 키」에 넣으세요」 (ADR-0013 §사전 점검).
- 실행 위치가 「서버」면 키 값은 서버 실행기가 가진다 (Bot UI가 아님). 「이 PC의 값」은 Studio 개발 실행 기준이다.
- 같은 내용이 속성 패널(STU-04)의 BPM 프로세스(정의 바깥) 항목에 요약으로 보인다.


### STU-06a PC BPM 프로세스로 나누기

> 상태: **돈다** ([ADR-0071](../decisions/0071-splitting-a-task-into-a-pc-bot.md)). STU-06 「이 부분을 PC BPM 프로세스로 나누기...」로 연다. 진입 정의가 열려 있고 실행 위치가 「서버」이며 서버에서 못 하는 노드가 있을 때만 켜진다(아니면 끄고 까닭을 적는다).

```
+-------------------------------------------------------------+
| [N] node to move (combo)                                    |
| [B] new PC Bot: id / name                                   |
| [I] inputs table  (use | name | type)       [+ add row]     |
| [O] outputs table (use | name)              [+ add row]     |
| [H] hint line                                               |
|                                  [Split]  [Cancel]          |
+-------------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [N] 「옮길 노드」 | 서버에서 못 하는 노드(`server_blockers` — B6과 같은 함수) 중 하나. 줄은 `<이름> (<id>) — <까닭>` |
| [B] 「새 PC Bot」 | id(기본 `<서버 id>-pc`, 작업 폴더 id 규칙 — 이미 있으면 막는다)·이름(기본 `<서버 이름> PC`). 같은 그룹에 만든다 |
| [I] 「입력」 | 그 노드가 읽는 변수 — **플랫폼이 아는 것만 미리 채운다**(`read_vars`). 줄마다 「쓸 것」·이름·타입(C14 값 타입, 기본 `string`). 위임 호출의 `input`은 `{이름: 이름}`, PC Bot의 `inputs`는 필수로 간다 |
| [O] 「출력」 | 그 노드가 만드는 변수(`produced_vars`). 위임 호출의 `output`은 `{이름: 이름}`, PC Bot의 `outputs`로 간다 |
| [H] 안내 | 확장 태스크면 「이 태스크가 읽고 쓰는 변수는 확장만 압니다 — 입력·출력을 직접 적으세요」(플랫폼이 `data`를 해석하지 않는다, C13 §5). 이름이 비거나 겹치면 빨간 한 줄 |

흐름:

1. 「나누기」를 누르면 **먼저 서버 정의를 저장한다**(적용 안 한 편집이 있으면 STU-04처럼 묻는다).
2. 새 작업 폴더를 만들고 캔버스에 PC 그림을 짓는다 — 시작 → **옮긴 노드(본문 그대로)** → 끝, `chk:process`는 `run_location: pc`·입력·출력과 **그 노드의 확장에 해당하는** 서버의 키 참조·확장 고정만. 그 정의를 **저장한다**.
3. 서버 그림을 다시 띄워 그 노드를 **위임 호출로 바꾼다**(`chk:call.delegate.bpm_process_id` = 새 id, `calledElement` = PC 그림의 process id). 서버 쪽은 **캔버스에만** 적용된다 — 「저장」(Ctrl+S)으로 쓴다.
4. 안내 줄: 「나눴습니다 — <노드>를 PC Bot <id>로 옮겼습니다. 서버 그림은 「저장」으로 쓰세요. 위임이 실패하면 `DELEGATION_FAILED`가 옵니다 — 오류 경계를 다세요. 시험 케이스에 이 호출의 `delegations`를 적어야 시험 실행이 지납니다. PC Bot은 따로 올리고 배포합니다.」 — **경계·케이스를 지어 넣지 않는다**.
5. 2에서 실패하면 서버 그림은 **디스크의 것 그대로** 돌아오고 만든 폴더는 지운다(빈 폴더를 남기지 않는다). 3에서 실패하면 PC Bot은 남기고 그렇게 말한다.

## STU-07 시험 케이스

880×620. 왼쪽 케이스 목록 + 「추가」/「삭제」, 오른쪽 편집.

| 섹션 | 내용 |
| --- | --- |
| 기본 | 이름, 대상 정의(진입은 「— 진입」 표시), 설명, 「사람이 직접 답함 (수동 케이스)」 체크 — 켜면 결재 자동 응답을 쓰지 않고 실제 창을 띄운다 |
| 「입력 변수」 | 이름/값/타입(string, number, bool, 목록·객체, 「지금부터」(기간 → `$now_plus`)) 표, 「입력 추가」, 「선택 줄 삭제」. BPM 프로세스 정보의 입력(`chk:process.inputs`)이 이름 콤보에 미리 나온다 |
| 「기대 결과」 | 이름/비교/값 표. 비교 콤보: 「같음」 / 「값이 있음」(`*`) / 「이상」·「이하」·「초과」·「미만」 / 「포함」. 객체는 적은 키만 비교 (C14 비교 규칙) |
| 「결재 자동 응답」 | 결재 노드(그 정의의 결재 이름 콤보)/필드(그 폼의 키 콤보)/값/타입(폼을 따름). 결재가 없으면 「이 정의에는 결재가 없습니다.」 응답을 비운 결재는 기다린다(기한 초과 시험) |
| 「보낼 메시지」 | 몇 초 뒤/메시지 이름(그 정의가 받는 메시지 콤보)/상관 값/본문 표. 받기 태스크·메시지 경계를 시험할 때. 받는 곳이 없는 메시지는 결과에 「받는 곳 없음」으로 남는다 (C14 `messages`) |

- 「저장」은 창을 닫지 않고 「저장됨 — 케이스 N개」를 보인다. 저장 시 **모든 케이스**를 검증한다 (이름 중복, 값 타입, 결재 답은 엔진과 같은 검증기).
- 「닫기」 시 저장 안 한 변경이 있으면 U11.
- JSON 입력 상자를 쓰지 않는다 (괄호 하나로 저장이 막혔다).

## STU-08 실행 대화상자

폭 460.

| 요소 | 내용 |
| --- | --- |
| 실행 위치 줄 (신규, 읽기 전용) | 「실행 위치: PC」 / 「실행 위치: 서버 — 이 시험 실행은 Studio에서 돌지만, 서버에서 쓸 수 없는 태스크가 있으면 「실행」이 꺼집니다」 |
| 「케이스」 콤보 | 「(케이스 없음)」, 케이스들, 2개 이상이면 「(모든 케이스 차례로)」. 아래 한 줄 설명: 「입력 2개 · 기대 결과 없음 — 비교하지 않습니다」 |
| 수행 모드 (라디오) | 「자율 수행 — AI가 방법을 찾고, 성공하면 학습한다」 / 「결정 수행 (재생) — 학습된 대로 LLM 없이 수행한다. Bot과 같은 방식」. 고를 수 없는 방식은 **바로 아래에 빨간 글자로 이유** (예: 학습 안 된 AI 태스크 이름) (U3). Worker·서비스 앱에도 이 모드가 그대로 전달된다. **감시 모드는 없다** — 일정(cron)을 읽는 자리는 현장 하나이고, 트리거가 깨우는 그림은 시험 케이스의 `messages`로 본다 ([ADR-0053](../decisions/0053-no-watch-mode-in-studio.md)) |
| 「Worker」 줄 (신규) | UI 태스크가 있을 때만: 「Bot UI의 Worker 프로세스: 실행 중」 / 「Bot UI가 꺼져 있습니다 — Bot UI를 실행하세요」 / 「Worker 프로세스가 멈춰 있습니다 — Bot UI → 「로컬 런타임」 탭에서 다시 시작하세요」 / 「Worker 사용 중 — Bot 실행 중(<Bot>) 또는 셀렉터 등록 중」(이때 「실행」 단추는 꺼진다). Studio는 Worker 프로세스를 띄우지 않는다 ([ADR-0012](../decisions/0012-bot-ui.md)) |
| 「서비스 앱」 줄 (신규) | 서비스 앱·UI 태스크가 있을 때만: 앱마다 「정상」 / 「응답 없음」 / 「키 참조 `<이름>`의 값이 없음 — 설정 → 서비스 앱 키」 / 「이 키는 자율 수행을 허용하지 않음」 |
| 단추 | 「실행」 / 「취소」 |

실행 순서: 적용 안 한 편집 확인 → 저장 안 했으면 자동 저장 → 사전 점검(실행 불가 항목이 있으면 중단하고 창으로 알림) → 표시 초기화 → 시작.

사전 점검은 **「실행 전 검사」와 같은 관문**이다 — 그림 검사(B1~B15)와 「이 PC에서 돌 수 있나」(`core.preflight` — Bot UI의 BUI-04 「준비」가 쓰는 것과 **같은 러너**)를 한 표에 모아 보이고, **막는 것이 하나라도 있으면 실행하지 않는다**. 사전 점검 줄은 「규칙」 칸이 「사전 점검」이라 그림의 흠과 갈라 보인다. 요구 사항은 **저장된 파일**에서 모으므로, 저장하지 않은 편집이 있으면 그렇게 경고한다 (방금 더한 키 참조는 세지 않았다는 뜻이다).

### 「UI 태스크」 탭 — 스크린샷을 두지 않는다

| 「케이스」 | 어느 케이스의 줄인가. **C3에 없는 칸이다** — 돌리는 쪽이 넣는다 (`run_started`의 `case_id`와 같은 것). Center의 실행 하나는 케이스 하나지만 Studio는 **차례로** 돌리므로 (STU-08 「모든 케이스 차례로」) 이것이 없으면 표를 읽을 수 없다. 케이스 없이 돌리면 「—」 |
| 「노드」 | 그 UI 태스크의 노드 id (`node_id`) |
| 「화면」 | `page_id`. **글자뿐이다** — 아래 「링크를 두지 않는다」 |
| 「결과」 | `status_map`의 「UI 세션」에 있는 표기만: 「성공」 / 「전환」 / 「실패」. 모르는 값은 **그대로** 보인다 (계약 원칙 10) |
| 「스텝 수」 | `steps` |
| 「폴백 깊이 최대」 | `fallback_depth_max`. 0이면 첫 로케이터로 됐다는 뜻이다 (C8) |
| 「치유」 | `healed` → 「예」 / 「아니오」 |

- 재료는 **C3 `ui_session` 한 줄**이다 ([ADR-0041](../decisions/0041-extension-run-events.md)) — UI 태스크가 끝날 때 확장이 주고 엔진이 쓴다. 「로그」·「변수」 탭과 **같은 길**로 온다 (시험 실행이 받는 C3 이벤트).
- **「진행 중」은 없다.** 줄은 세션이 끝날 때 생긴다 — 도는 동안 무엇을 하고 있나는 BUI-09가 아는 것이다 (UIA-03도 같은 규칙).
- **「실행」 한 번에 한 번만 비운다** — 「로그」 탭과 같다. 케이스마다 비우면 세 번째 케이스의 전환을 마지막 케이스가 덮는다.
- 빈 상태: 「이 실행에는 UI 태스크가 없습니다.」 (U12)

**스크린샷을 두지 않는다.** 이 탭은 「화면」이라는 이름으로 「실행 중 스크린샷」을 보이기로 적혀 있었다. 셋 때문에 걷었다.

1. **아무도 그림을 만들지 않는다.** C10 `StepResult`에 이미지 칸이 없고, C8이 치유에 싣는 것은 **가린 글**(`aria_snapshot`·`sub_dom`)이다. 「화면을 밖에 무엇으로 보이나」를 이 저장소는 **픽셀이 아니라 가린 글로** 이미 정해 두었다 — 그 결을 탭 하나 때문에 뒤집지 않는다.
2. **C3가 스크린샷을 금한다** — `data`는 「업무 값·결재 답·비밀·**스크린샷** 없음」이다. 실행 기록으로 들어올 길이 없으니 Studio가 받을 길도 없다.
3. **그림은 가릴 수 없다.** 원칙 6의 가리기는 글에 거는 것이다. 화면 한 장은 거래처 이름·금액을 통째로 담아, 보이고 버린다 해도 개발 PC에 남는 길만 늘어난다.

그래서 「화면」은 **글자 하나**(`page_id`)로 남고 탭 이름도 그 열이 아니라 **무엇의 표인지**로 바꿨다 (CON-01·BUI-02가 이미 「UI 태스크」라고 부른다). 다시 그림을 보이려면 **Worker가 그림을 만드는 일부터** 정해야 한다 — C10에 칸을 더하고 가리기를 정하는 계약 변경이고, 이 탭의 일이 아니다.

**확장이 기여한 칸이 아니다** ([ADR-0042](../decisions/0042-extension-contributed-panels.md)). BUI-09 「최근 UI 세션」을 확장이 그리는 것은 재료가 **C10**(확장이 소유한 계약)이고 열이 **확장의 말**이어서다. 여기 재료는 **C3**(플랫폼 계약)이고 열 이름도 C3가 정한 칸이라, 플랫폼이 그려도 Studio가 UI 자동화를 알게 되지 않는다 — CON-01이 같은 것을 같은 열로 그린다.

**링크를 두지 않는다.** CON-01은 「화면」을 그 앱의 관리 콘솔(UIA-03)로 잇는데, 그것은 BFF가 C7 기여 자원을 조인해서 되는 일이다. **STU-01은 실행 중에 Center를 두드리지 않는다** (STU-03과 같은 결 — 창은 Center를 부르지 않는다). 화면을 훑어보는 길은 STU-03 문맥 메뉴 「관리 콘솔에서 보기」다.

## STU-11 Center 공유 자원

> 상태: **돈다 — 남은 기능이 없다** (`apps/studio/center_resources.py` + `install.py`). 열 다섯·「새로 고침」·아래 상태 줄과 **공유 BPM 프로세스 설치·갱신·제거**가 돈다. 목록은 **C5 패키지 표**에서 온다 (`GET /packages?kind=process_lib`) — C7 리소스 목록에 `process_lib` 갈래가 없고, 「상태」가 **패키지 상태**라서다 (CON-06이 같은 것을 읽는다).
>
> - **공유 BPM 프로세스의 「설치」·「갱신」·「제거」가 돈다** (`install.py` + `workspace.py`, [ADR-0048](../decisions/0048-installing-shared-packages.md)). 받은 것은 **그 BPM 프로세스 작업 폴더의 `libs/`**로 가고 거기서 호출이 찾는다 — 실행기(`libs/*.bpmn`)와 **같은 자리**라 시험 실행·F6과 현장이 같은 파일을 본다. 「설치본」·「(갱신 있음)」·「로컬만」도 돈다.
> - **설치는 BPM 프로세스 하나에 하는 일이다** — 그래서 「설치본」은 **열린 BPM 프로세스 기준**이고, 열린 것이 없으면 표는 그대로 보이고 **단추만** 꺼진다 (읽기는 되는 자리다). 판은 작업 폴더 기록(`process.json`)에 남고 **패키지로는 가지 않는다**(내보낼 때 `requires.libs`에 `<id>@<version>`으로 적힌다).
> - **툴팩 탭은 없다** — 도구 묶음은 패키지가 아니다 ([ADR-0050](../decisions/0050-no-toolpack-kind.md)). 도구는 확장이 기여하고, 확장은 STU-15에서 본다.
> - **결정표(DMN)도 함께 설치된다** — 정의가 쓰는 결정표를 `libs/`에 같이 풀고 **Studio와 실행기가 둘 다** `libs/*.dmn`을 읽는다 (한쪽만 고치면 「Studio에서는 되는데 현장에서 안 된다」가 된다). **내 `process/`의 결정이 이긴다** — 같은 결정 id면 내 것을 쓴다.
> - **개수는 매니페스트의 `provides`가 말한다** (C1). `provides`가 없으면 **0이 아니라 「매니페스트에 없음」**이다 (CON-06과 같은 규칙).
> - **들고 있지 않는다** — 닿지 못하면 그 자리에서 「받지 못했습니다 — <까닭>」이고 주소·키가 없으면 두드리지 않는다.

## STU-12 공유 BPM 프로세스 내보내기·올리기

> 상태: **내보내기와 올리기가 모두 돈다** (`dialogs.py`의 `ShareDefinitionsDialog` + `packaging.export_lib` + `apps/studio/upload.py`). 고른 정의가 `kind=process_lib` 패키지가 되고 **매니페스트의 `provides.processes`를 그림에서 모은다** (C1 — CON-06 「제공 정의」가 읽는다). 창에 「만들 폴더」 대신 파일 고르기를 쓴다 (「패키지로 내보내기...」와 같은 모양).
>
> **「올리기」는 내보내는 것과 같은 zip을 보낸다** — 새로 짓지 않고 `export`·`export_lib`가 만든 것을 그대로 올리므로 둘이 다른 것을 낼 일이 없다. 파일은 남기지 않는다(올리기는 내보내기가 아니다 — 파일이 필요하면 「내보내기」가 그 일을 한다). **설정을 먼저 묻는다** — 패키지를 만든 뒤에 「Center 설정이 없습니다」라고 하면 사람이 한 일이 버려진다. 「설명」·「올리기 안내」는 창에 아직 없다.
>
> **담는 것은 저장된 파일이다** — 저장하지 않은 편집이 있으면 먼저 저장한다. 결정(DMN)은 가려내지 않고 모두 담는다. **고르지 않은 형제 정의를 부르면 막는다**: 그대로 두면 `requires.libs`에 같은 작업 폴더의 id가 「바깥 패키지」로 적혀 받는 쪽이 없는 패키지를 찾는다.

| 요소 | 내용 |
| --- | --- |
| 설명 | 내보내기 / 올리기 차이 |
| 「BPM 프로세스」 | 이름·버전 (읽기 전용) |
| 「공유할 정의」 | 체크 목록 (하나 이상 필수) |
| 「만들 폴더」 + 「찾아보기...」 | 내보내기일 때만 |
| 안내 | 올리기: 「후보 상태로 올라갑니다. 같은 버전은 다시 올릴 수 없으니 버전을 올리세요.」 |
| 단추 | 「내보내기」 또는 「올리기」 / 「취소」 |

## STU-13 UI 태스크 편집기 (신규)

> UI 자동화 확장(내장)이 기여하는 편집기다 (`task_types` `ui_task`, `studio.editors`, [ADR-0018](../decisions/0018-extensions.md)).
>
> 상태: **화면·옵션·스텝 표·경고가 돈다.** 고를 것은 **공개 카탈로그**(C9 `GET /v1/catalog`)에서 오고 거기엔 셀렉터가 없다 — 그래서 Studio에는 키가 필요 없다. 리소스 탐색기(STU-03)의 「캔버스에 추가」가 **화면이 채워진 UI 태스크**를 만들어 준다 (자원 id는 확장이 선언한 칸으로 간다, C13 `creates_task_field`). 아직인 것: 「이 스텝까지 시험」(Bot UI의 BUI-08에서 돌린다), 자율 수행에서 세운 계획을 스텝으로 굳히기. **「요소를 끌어다 스텝 추가」는 하지 않는다** ([ADR-0045](../decisions/0045-contributed-resource-children.md) — 스텝의 모양은 이 확장의 것이라 플랫폼이 만들 수 없고, **요소를 고르는 자리는 아래 스텝 표 하나다**. 표의 콤보가 그 요소의 가능한 동작만 채우고 선행 입력을 경고하는데, 끌어다 놓아 생긴 스텝은 동작이 비어 결국 표로 돌아온다). Center 리소스 목록이 생기면(M5) 주소의 출처만 그쪽으로 바뀐다 (C13 `service.base_url`).

속성 패널에서 UI 태스크를 골랐을 때의 편집기. 등록된 화면의 요소를 시맨틱 키로 조작하는 스텝을 만든다. 셀렉터는 여기서 보이지 않는다 (ADR-0008).

```
+------------------------------------------------------+
| [S] screen picker                     [Reload]       |
| [O] options                                          |
| [T] steps table                                      |
|                        [+] [-] [Up] [Down] [Test]    |
| [G] goal mode (optional)                             |
| [W] warnings                                         |
+------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [S] 화면 | 「화면」 콤보: Center 리소스의 UI 화면 목록(「<이름> — 요소 N개」). 서버에 닿지 못하면 마지막 목록 + 「(오프라인)」. 「다시 읽기」 단추 |
| [O] 옵션 | 「시작 주소」(비우면 화면의 기본 주소 / 이미 열린 화면에서 이어서), 「브라우저 프로필」, 「자가 치유 사용」(기본 켬 — 켜 두면 결정 수행 Bot도 실패한 요소에 한해 UI 자동화 앱의 LLM 치유를 쓴다. 「실행 전 검사」가 이를 알린다), 「실행 후 브라우저 닫기」, 「UI 자동화 앱 키」: 「BPM 프로세스 설정을 따름 (`<참조>`)」(기본) / 「이 태스크만 다른 참조: [ ]」. 실행 때 Bot·Studio가 참조를 풀어 Worker 세션 요청에 키를 실어 보낸다 |
| [T] 스텝 표 | 열: 「#」 / 「요소」(그 화면의 시맨틱 키 콤보, 이름·종류 함께) / 「동작」(그 요소가 가능한 동작만) / 「값」(변수 또는 식, fill·press·select만) / 「결과 변수」(읽기 동작만) / 「화면 이동」(체크: 이 스텝 뒤 다른 화면으로 넘어감) |
| 단추 | 「스텝 추가」, 「삭제」, 「위로」, 「아래로」, 「이 스텝까지 시험」(Bot UI가 관리하는 Worker 프로세스로 지금 열린 브라우저에서 실행, 결과는 로그) |
| [G] 목표로 계획 | 체크 「스텝 대신 목표로 실행」 + 목표 한 줄 + 「결과 변수」(쉼표로 여럿). 켜면 스텝 표가 흐려지고, 실행 때 UI 자동화 앱이 계획을 세운다 (LLM 사용, [ADR-0035](../decisions/0035-ui-goal-planning.md)). 쓸 값은 목표 안에 `{이름}`으로 적는다 — 그 **이름만** 모델에 간다. 도움말: 「자율 수행(Studio 시험)에서만 돕니다. Bot(결정 수행)에서는 실패합니다」. 목표를 켰는데 비었으면 오류(적용 막음), 목표에 `{이름}`이 없으면 경고(값을 넣는 스텝을 세울 수 없다) |
| [W] 경고 | 등록되지 않은 요소, 「대체됨」만 남은 요소, 선행 입력(depends_on)이 앞 스텝에 없음 → 경고(막지 않음). 값이 필요한 동작에 값 없음, 읽기 동작에 결과 변수 없음 → 오류(적용 막음) |

요소는 **스텝 표에서 고른다** — 리소스 탐색기(STU-03)에서 끌어다 놓는 길은 두지 않는다 ([ADR-0045](../decisions/0045-contributed-resource-children.md)). 탐색기가 주는 것은 **화면이 채워진 UI 태스크**까지다 (「캔버스에 추가」·끌어다 놓기, [ADR-0044](../decisions/0044-canvas-drag-and-drop.md)).

## STU-14 서비스 앱 태스크 편집기 (신규)

> 상태: **돈다** (`apps/studio/service_editor.py` + 고를 거리 `service_catalog.py`). 확장이 기여한 편집기(STU-13)와 **같은 규약**이라 속성 패널은 어느 쪽인지 모른다. 리소스 탐색기(STU-03)의 「서비스 앱」 뿌리에서 작업을 **캔버스에 추가**해 태스크를 만들고, 「작업 설명 보기」 창도 그쪽에 있다. 탐색기에서 **끌어다 놓아도** 같은 태스크가 생긴다 (「캔버스에 추가」와 같은 명령이다, [ADR-0044](../decisions/0044-canvas-drag-and-drop.md)).

속성 패널에서 서비스 앱 태스크를 골랐을 때의 편집기. 서비스 앱의 manifest(C11) 또는 외부 확장 정의의 어댑터 작업(C13 §4)을 읽어 입력·출력 칸을 자동으로 만든다. 확장이 자기 편집기를 기여하지 않은 작업은 모두 이 편집기를 쓴다.

| 섹션 | 필드 |
| --- | --- |
| 「서비스 앱」 | 콤보: 「<앱 이름> (<구분>) — 정상 / 응답 없음」. 응답 없는 앱도 고를 수 있지만 경고 |
| 「작업」 | 콤보: 그 앱의 작업 이름. 아래에 작업 설명 |
| 「API 키」 | 「BPM 프로세스 설정을 따름 (`<참조>`)」(기본) / 「이 태스크만 다른 참조: [ ]」. 다른 참조는 예외일 때만 (예: 권한이 다른 작업). 키 값은 넣지 않는다 |
| 「입력」 | 표: 입력 필드(manifest) / 필수 / 타입 / 값(변수 또는 식). 단추 「기대 입력 채우기」(같은 이름의 변수로 채움) |
| 「출력」 | 표: 작업 출력 필드 / 저장할 변수. 단추 「모두 같은 이름으로」 |
| 「실행 제한」 | 제한 시간(초) — 비우면 「작업 기본값을 따름」. 재시도 횟수. 아래에 「다시 부를 상태 코드」(읽기 전용 — 외부 앱은 정의의 `retry_on`이 정한다) |

> 「실패하면」 칸은 **두지 않는다.** `chk:serviceCall`에 그런 필드가 없고(C14), 실패를 업무가 받느냐는 **그 태스크에 오류 경계 이벤트가 붙어 있는가**로 정해진다. 캔버스에서 경계 이벤트를 붙이는 일이지 편집기의 칸이 아니다.

검증: 필수 입력이 비면 적용 불가. manifest가 바뀌어 없는 필드가 남으면 그 줄을 빨갛게 표시하고 「작업 정의가 바뀌었습니다」를 보인다.

- 고를 거리는 **Center 리소스 목록**에서 온다 (C7) — 정의를 열 때와 설정을 저장한 뒤에 받는다. 등록된 앱이 없으면 콤보가 「(Center에 등록된 서비스 앱이 없습니다)」라고 말한다.
- 「API 키」의 기본 줄은 BPM 프로세스가 적어 둔 참조를 함께 보인다 (`chk:process.service_keys`). 적혀 있지 않으면 「이 앱의 참조가 적혀 있지 않습니다」 — 실행할 때 B7로 막히는 자리다.
- `input_schema`·`output_schema`는 **선택 칸**이다 (C11). 없으면 입력·출력 표는 그림에 적힌 줄만 보이고 사람이 「줄 더하기」로 적는다 — 없는 칸을 지어내지 않는다.

「지원 수행 모드」 줄(읽기 전용): manifest의 모드 목록. 결정 수행을 지원하지 않는 작업이면 경고 「이 작업은 Bot(결정 수행)에서 실행할 수 없습니다」 — 배포 전 사전 점검에서도 실행 불가로 표시된다.

## STU-15 확장 (신규)

> 상태: **돈다** (`apps/studio/extension_dialog.py`). 목록·상세·「켜기」/「끄기」·「새로 고침」·「정의 파일 열기...」가 모두 돈다. 끈 목록은 **Studio 설정**에 있다 ([ADR-0043](../decisions/0043-turned-off-extensions.md)) — Bot UI(BUI-11)는 제 설정에 따로 둔다. 외부 확장은 여기서 끄지 않는다 (Center에 등록된 정의다, C13 E6).

Studio에 켜진 확장과 각 확장이 더한 것을 본다 ([ADR-0018](../decisions/0018-extensions.md), C13). 「도구」 → 「확장...」. 600×480.

| 영역 | 내용 |
| --- | --- |
| 목록 | 확장 / 등급(내장·사내·외부) / 버전 / 상태(켜짐·꺼짐·호환 안 됨) / 기여 요약 |
| 상세 | 기여 지점별: 태스크 종류(팔레트 이름·아이콘·실행 위치), 편집기, 리소스 탐색기 뿌리, 서비스 앱 작업, 필요한 키 |
| 단추 | 「켜기」/「끄기」(내장·사내), **「정의 고정」/「고정 해제」**(외부 확장 — 아래), 「새로 고침」(Center의 외부 확장 정의), 「정의 파일 열기...」(외부 확장을 Center에 올리기 전에 시험 — 검사 결과를 보여 줌) |

- 확장을 끄면 그 확장의 태스크가 있는 BPM 프로세스에서 「실행 전 검사」가 「확장 <이름>이 꺼져 있습니다」 오류를 보인다. **「그 확장이 없다」와 다른 오류다** — 고치는 길이 「켜세요」와 「그 확장이 깔린 판으로 올리세요」로 갈린다 (`core.preflight`의 `extension_turned_off`).
- 끄면 **그 자리에서** 기여가 빠진다 (태스크 종류·편집기·리소스 뿌리·점검). 「저장」이 없다 — 누르는 순간 설정에 적힌다.
- 외부 확장 정의를 시험할 때 어댑터 검사(C13 E3)를 Studio에서 먼저 돌려, 허용 호스트·템플릿 오류를 바로 보여 준다. **등록하지 않는다** — 서명해 올리는 일은 Admin의 몫이다 (C2).
- 「새로 고침」으로 받은 외부 확장은 **이 창에만** 담긴다 — 팔레트·시험 실행이 보는 확장 호스트를 건드리지 않는다. 봉투는 받을 때마다 **다시 검증한다** (C13 E6) — Studio도 Admin 서명을 직접 본다. Center에 닿지 못하면 **그 자리에서 말한다** (들고 있지 않는다 — 개발 도구다).
- **「정의 고정」은 지금 보고 있는 그 해시를 그림에 적는다** ([ADR-0060](../decisions/0060-pinning-external-definitions.md)) — 자리는 `chk:process.extensions[].definition_hash`(C14)이고, 빌드가 C1으로 옮기면 받는 쪽이 **승인받은 그 정의인지** 대조한다(다르면 시작조차 하지 않는다). 사람이 해시를 손으로 옮겨 적지 않는다.
  - **외부 확장만**이고(내장·사내는 정의가 설치 파일에 있다) **「새로 고침」으로 받아 봉투를 검증한 것만**이다 (C13 E6 — 검증되지 않은 정의의 해시를 고정하면 고정이 거짓이 된다).
  - **그림을 고치는 일이라 진입 정의가 열려 있을 때만** 켜진다 (STU-06과 같은 규칙, [ADR-0022](../decisions/0022-studio-canvas.md)). 적용되는 곳은 **캔버스**이고 파일로 가는 것은 「저장」(Ctrl+S)이다.
  - **그림이 쓴다고 적지 않은 확장은 고정할 수 없다** — `chk:process.extensions`에 줄이 없으면 그렇게 말한다(버전 범위를 지어내지 않는다).
  - 「고정 해제」는 그 칸을 **지운다**. 정의가 바뀌면 지우고 다시 누른다 — 그러면 승인·배포를 다시 받는다 (C1의 뜻).
  - **고정하지 않아도 막지 않는다** — 「실행 전 검사」가 **경고** 한 줄로 말한다(「외부 확장 N개가 고정되지 않았습니다」).
- 켜지지 않은 확장은 **까닭을 상세 맨 위에** 보인다. 정의를 **읽지도 못한** 것은 id가 없어 목록에 줄을 만들 수 없으니 표 아래 한 줄로 말한다.
