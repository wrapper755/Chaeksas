# PC 실행기 화면 설계

**PC 실행기는 항상 떠 있는 트레이 기반 GUI 프로그램**이다. 현장 PC와 설계자 PC에 하나씩 설치한다 ([ADR-0012](../decisions/0012-bot-ui.md)).

| 기능 | 화면 |
| --- | --- |
| ① BPM 프로세스 다운로드 및 실행 — Center가 배포한 BPM 프로세스를 받아 결정 수행으로 실행 | BUI-01 트레이, BUI-02 「BPM 프로세스」 탭, BUI-04 |
| 확장 목록·켜기·끄기 | BUI-11 (BUI-01 메뉴 7·BUI-02 [M] 「도구」 → 「확장...」) |
| 설정 (Center 주소·등록 요청) — 키는 Center가 내려 준다 | BUI-03 |

- **실행 자리는 하나다.** 실행 중인 BPM 프로세스는 PC 한 대에 최대 1개이고, 나머지 실행 요청(Center 작업, 수동 실행, 감시 트리거, 일정, 메시지)은 대기열에서 들어온 순서대로 기다린다 ([ADR-0014](../decisions/0014-one-bot-per-pc.md)).
- **확장:** PC 실행기는 특정 확장을 모른다. 설치된 확장 정의(C13)를 읽어 태스크 종류·설정 칸·사전 점검을 끼워 넣는다 (VS Code가 확장을 붙이듯이, [ADR-0018](../decisions/0018-extensions.md)). 지금 깔린 내장 확장은 없다 — 로컬 런타임·도구 바로가기·화면 칸 기여 지점은 UI 자동화 확장과 함께 걷었다 ([ADR-0114](../decisions/0114-remove-ui-automation.md)).
- 로그인 세션에서 실행한다 (Windows 서비스 모드는 나중에 검토).
- 공통 원칙·상태 표기는 [README.md](README.md) §2·§3. 스레딩 규칙: 화면은 보여 주기만, Qt 슬롯에서 동기 I/O 금지, 배경 작업은 하나의 실행 함수로 시작해 예외를 드러냄, 위젯은 GUI 스레드에서만.

## BUI-02 메인 창

제목 「Chaeksas PC 실행기」, 1000×720. 창을 닫아도 PC 실행기는 트레이에서 계속 돈다.

```
+----------------------------------------------------------+
| [M] menu: File | Tools                                   |
+----------------------------------------------------------+
| [K] tabs: Bots | Runs                                    |
|                                                          |
|                 [W] tab content                          |
|                                                          |
+----------------------------------------------------------+
| [S] status bar                                           |
+----------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [M] 메뉴 | 「파일」 → 「설정...」, 「로그 폴더 열기」, 구분선, 「종료」(Ctrl+Q) · 「도구」 → 「확장...」(BUI-11) |
| [K] 탭 | 「BPM 프로세스」(BUI-04) / 「실행 기록」(로그) |
| [S] 상태 줄 | 「<상태> · Center <주소> · 오류: <앞부분>」 (오류는 `failed` 색 글자). 해당할 때만 뒤 항목을 붙인다 |

「실행 기록」 탭: 최대 5000줄. 줄 형식 「<시각> [<BPM 프로세스>] <노드> <내용>」. 실패는 한 줄 요약 먼저 (U13). 문맥 메뉴: 복사, 「화면 지우기」.

> 상태: **돈다** — `runs/<run_id>.jsonl`을 읽어 그린다 (`run_log_view.py`). **원본은 파일이다**(ADR-0031·C3)라서 PC 실행기를 닫았다 열어도 같은 것이 보이고, **새 실행이 위**다. 「화면 지우기」는 **화면만** 비운다 — 파일을 지우면 Center로 보낼 기록이 사라진다. 「파일 → 로그 폴더 열기」가 그 폴더를 연다. 스크롤이 맨 아래가 아니면 자리를 지킨다. **업무 값은 없다** — `data`에서 **아는 칸만** 글로 옮긴다 (원칙 6).

## BUI-03 설정·등록

> 상태: 「Center」 탭이 **이 모양으로 돈다** ([ADR-0092](../decisions/0092-keys-are-issued-and-delivered-by-center.md), `settings_dialog.py`·`agent.enroll_step()`). 승인을 기다리는 동안 트레이 아이콘의 글은 「승인 대기 — 코드 ABCD-EFGH」이고, 누르면 이 창의 「Center」 탭이 열린다.

처음 실행하면 등록이 안 되어 있으므로 이 창이 먼저 뜬다. 칸은 **탭으로 나눈다** — 아래 표의 한 줄이 탭 하나이고 순서도 표와 같다. 창은 「Center」 탭으로 열린다(첫 실행에 할 일이 거기 있다).

| 탭 | 필드 | 비고 |
| --- | --- | --- |
| 「Center」 | **주소 하나**와 상태 줄, 「연결 테스트」. **키 칸은 없다** — 주소를 저장하면 PC 실행기가 등록 요청을 보내고(C4 §등록 요청과 승인), 승인되면 키를 받아 OS 비밀 저장소에 둔다. 사람은 키를 보지 않는다 | 상태 줄(하나만): 「승인을 기다립니다 — 관리자에게 요청 코드 **ABCD-EFGH**를 알려 주세요 (<만료 시각>까지)」 — 코드는 크게, 「복사」 단추와 함께 / 「연결됨 — 이 PC는 <PC 실행기 이름>으로 등록됨」 / 「거절되었습니다: <사유>」 + 「다시 요청」 / 「요청이 만료되었습니다」 + 「다시 요청」 / 「Center가 지금 등록 요청을 받지 않습니다 — 잠시 뒤 다시 요청합니다」 / 「키가 거부되었습니다 — 「다시 요청」으로 새로 승인받으세요」 / 「닿지 못함 — <이유>」. 환경변수로 키가 오면(`BPM_BOT_UI__CENTER_API_KEY`, 개발·CI) 「환경변수의 키를 씁니다」라고만 말하고 요청하지 않는다 |
| 「실행」 | 「로그인할 때 자동 시작」(기본 켬. 이 사용자의 로그온 작업으로 등록 — 관리자 권한 없음. 등록에 실패하면 경고 「자동 시작을 등록하지 못했습니다: <이유>」를 보이고 칸을 **실제 상태로 되돌려** 저장한다), 「결재를 Center로 올리기」(원격 결재 — BPM 프로세스의 결재 위치가 「PC 실행기 설정을 따름」인 결재에만 적용, STU-04가 정한 것이 우선), 「서명된 패키지만 설치」(기본 켬), 「대기열 크기」(기본 20, `BPM_BOT_UI__QUEUE__MAX`) | 실행 자리는 하나로 고정 (설정 없음) |
| 「모델」 (신규) | 주소(OpenAI 호환 `/v1`을 여는 곳 — 사내 게이트웨이·Ollama·vLLM. 비우면 **AI 태스크가 돌지 않는다**), 모델 이름, **API 키**(값 가림, 키가 필요 없는 로컬 모델이면 비워 둔다 — 비우면 `Authorization`을 아예 보내지 않는다). 「연결 테스트」 | 주소·키는 **실행하는 쪽만 안다** — BPM 프로세스에는 들어가지 않는다 ([ADR-0013](../decisions/0013-api-keys.md)·[ADR-0027](../decisions/0027-llm-connection.md)). 키는 OS 비밀 저장소 |
| 「파일」 (신규) | 「읽기 허용 폴더」 목록 + 「쓰기 허용 폴더」 목록 (각각 「추가...」/「삭제」). 출력 폴더는 `<데이터 폴더>/outputs/<BPM 프로세스>`로 고정이고 보여 주기만 한다 | BPM 프로세스가 읽을 수 있는 곳은 **여기 적은 폴더뿐**이다 ([ADR-0026](../decisions/0026-file-paths-and-file-list-task.md)). 비어 있으면 파일을 읽는 태스크는 **조용히 넘어가지 않고 실패한다**. 쓰기 허용 폴더는 **비어 있는 것이 기본**이고, 적으면 **그 안의 파일을 BPM 프로세스가 고칠 수 있다**고 화면이 말한다 ([ADR-0032](../decisions/0032-writable-dirs.md)) |
| 「보내기」 (신규) | **SMTP**: 주소, 포트(비우면 보안에 맞는 기본 — `starttls` 587·`ssl` 465·`none` 25), 보안(`starttls` 기본 / `ssl` / `none`), 사용자, **비밀번호**(값 가림 → OS 비밀 저장소), 보내는 주소(`from`), 첨부 합계 상한(MB, 기본 10). **웹훅**: 「허용 호스트」 목록(「추가...」/「삭제」). 「연결 테스트」 | 비우면 `bpm:email`이 **보내지 않고 실패한다**(`SEND_FAILED`) — 조용히 넘어가지 않는다 ([ADR-0059](../decisions/0059-sending-mail-and-webhooks.md)). 보안을 `none`으로 고르면 **「암호화하지 않고 보냅니다」**라고 말한다. 웹훅 허용 호스트는 **비어 있는 것이 기본**이고 비면 어디에도 보내지 않는다(쓰기 허용 폴더와 같은 결 — ADR-0032). **사설·루프백 주소는 적어도 열리지 않는다** (C13 §4-3과 같은 관문) |
| 확장별 설정 (확장의 `configuration` 기여) | **확장마다 탭 하나**이고 탭 이름은 확장 이름이다. 확장이 선언한 칸으로 **그 자리에서** 만든다. `scope: bot_ui`인 칸만. 확장이 주는 칸이 없으면 탭도 없다 | **비밀 칸은 설정 파일에 들어가지 않는다** |
| 「나중에」 | 아직 없는 칸(메시지 수신 포트, 툴팩 비밀)을 **끈 채로** 이유와 함께 보인다 (U3) | 메시지 수신 포트(기본 8790, 「다른 PC에서도 받기」 기본 끔)는 ReceiveTask·메시지 시작 이벤트용 |

단추: 「저장」/「취소」 — **탭 밖**에 있어 어느 탭에서 눌러도 모든 탭의 칸을 함께 저장한다. 탭의 내용이 창보다 크면(예: 1920×1080을 150%로 쓰면 화면 높이가 672) **그 탭의 내용만 스크롤되고 탭과 단추는 항상 보인다.** 창은 처음 열 때 화면 높이를 넘지 않게 뜬다.

## BUI-04 BPM 프로세스 탭 (실행·대기열·설치된 BPM 프로세스)

탭 위쪽에 실행 자리와 대기열, 아래쪽에 설치된 BPM 프로세스 목록을 둔다.

```
+----------------------------------------------------------+
| [R] running now: bot @ node | elapsed | [Stop]           |
| [Q] queue table                    [To front] [Cancel]   |
+----------------------------------------------------------+
| [L] installed bots table                                 |
+----------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [R] 지금 실행 | 「<BPM 프로세스> <버전> @ <노드> · <경과> · 출처 <Center 작업/수동/감시/일정/메시지>」 + 「중지」(확인 창, 기본 「취소」). 결재·확인을 기다리는 중이면 「결재 창 열기」(CMN-01). 비었으면 「실행 중인 BPM 프로세스가 없습니다」 |
| [Q] 대기열 | 열: 「#」 / 「BPM 프로세스」 / 「출처」 / 「요청 시각」 / 「만료」(Center 작업만) / 「입력 키」(값은 접음, U10). 단추: 「맨 앞으로」(수동 실행 항목만), 「취소...」(확인 창, 기본 「취소」. Center 작업이면 「Center에 '현장에서 취소함'으로 알립니다」 — C4 `rejected` + `cancelled_on_pc`). 빈 상태: 「기다리는 실행이 없습니다. 「지금 실행...」이나 Center 작업 지시로 실행됩니다.」 위 제목에 「대기 N/20」 |
| [L] 설치된 BPM 프로세스 | 아래 표 |


| 열 | 내용 |
| --- | --- |
| 「BPM 프로세스」 | 이름 (id는 툴팁) |
| 「버전」 | |
| 「출처」 | 「Center 배포」 / 「수동 설치」 / 「알 수 없음」(설치할 때 남긴 표식이 없다 — **둘 중 어느 쪽인지 모르면 고르지 않는다**) |
| 「서명」 | 「확인됨」 / 「서명 없음」 / 「서명 불일치」 |
| 「준비」 | 「준비됨」 / 「확장 꺼짐」(BUI-11에서 켜면 된다) / 「확장 없음」(판을 올려야 한다) / 「배포 철회」(Center 목록에 이 판의 배포가 없다 — 다시 배포받아야 한다) / 「배포 만료」(배포의 유효 기간이 지났다) / 「사전 점검 실행 불가」 — 사전 점검 결과. 막은 점검의 사유·고칠 방법은 툴팁 |
| 「상태」 | 대기 / 실행 중 / 대기열 N번째 / 감시 중 / 수동 실행 전용 / 비활성 |
| 「최근 실행」 | 시각 + 결과 (「완료」·「실패」·「취소됨」·「실행 중」, 끝 기록이 없으면 「—」). 시각은 기록 그대로(UTC)이고 BUI-02와 같다 |

단추 (고른 줄 기준): 「지금 실행...」(입력 변수 입력 창 → 실행 자리가 비었으면 바로 실행, 차 있으면 「대기열에 넣었습니다 (N번째)」. 입력 창에 체크 「맨 앞에 넣기」. 「준비」가 「배포 철회」·「배포 만료」면 넣지 않고 그 까닭을 경고 창으로 말한다 — PC에서 고칠 수 없다. 다른 막힘은 띄울 때 본다), 「감시 시작/중지」, 「제거...」(Center 배포분은 「Center에서 배포를 철회해야 다시 설치되지 않습니다」 안내).
위쪽 단추: 「패키지 파일에서 설치...」(서명 확인), 「새로 고침」.
「준비」에 「서비스 앱 키 받지 못함」은 없다 — 서비스 앱 키가 없다 ([ADR-0102](../decisions/0102-calling-outside-is-pull.md)). BPM 프로세스는 바깥 기능을 Center의 외부 작업으로 부르고 불러도 되는가는 Center가 배포로 가린다 (C15).
빈 상태: 「설치된 BPM 프로세스가 없습니다. Center에서 이 PC에 배포하거나 「패키지 파일에서 설치...」로 설치하세요.」

> 상태: 「준비」까지 돈다 — 사전 점검(`core.preflight`)이 **갖춰야 할 설정**·**확장 태스크 종류**·**AI 환경**(`web`·`desktop` AI 태스크는 이 판에서 돌릴 수 없어 `missing_agent_environment`로 막는다 — [ADR-0114](../decisions/0114-remove-ui-automation.md))과 확장이 기여한 점검(C13)을 보고, 결과를 하트비트 `readiness`로 올린다 (C4 → CON-03). **「꺼 뒀다」와 「없다」를 가른다** — 확장이 깔려 있는데 사람이 BUI-11에서 껐으면 「확장 꺼짐」이고 고치는 길은 「켜기」다 ([ADR-0043](../decisions/0043-turned-off-extensions.md)). **준비되지 않은 BPM 프로세스는 시작하지 않는다** — Center 작업이면 `rejected`·`not_ready`로 ack한다. **「배포 철회」·「배포 만료」는 배포가 정한다** ([ADR-0113](../decisions/0113-field-follows-withdrawn-deployments.md)) — Center가 **답한** 하트비트의 배포 목록에 이 판을 덮는 봉투가 없으면 「Center 배포」 설치의 표식(`DEPLOYMENT`)에 적고, 기한은 그 표식으로 현장 시각에 본다(Center가 닿지 않아도). 닿지 못한 주기에는 바꾸지 않는다. 파일은 지우지 않고 도는 실행은 멈추지 않는다. 「수동 설치」·「알 수 없음」은 다루지 않는다. 「출처」는 **설치할 때 남긴 표식**(`INSTALL_SOURCE`)에서 읽는다 — 배포가 설치한 것은 「Center 배포」(`deploy.py`), 「패키지 파일에서 설치...」가 설치한 것은 「수동 설치」다. **표식이 없으면 「알 수 없음」이다** — 푸는 것만으로는 어느 쪽인지 알 수 없고(`bots.install`은 적지 않는다), 표식을 남기기 전에 설치된 폴더일 수 있다. 「최근 실행」은 **BUI-02와 같은 파일**(`runs/<run_id>.jsonl`)에서 그 BPM 프로세스의 마지막 실행 하나를 읽는다 — 시각은 `run_started`, 결과는 `run_finished`의 `status`를 「실행·노드」 표기(「완료」·「실패」·「취소됨」)로 옮긴다. **끝 줄이 없으면** 지금 도는 그 실행이면 「실행 중」이고, 아니면 결과를 지어내지 않고 「—」(툴팁: 실행기가 도중에 멈췄을 수 있다)다. 한 번도 안 돌았으면 빈칸이다.

규칙:
- **알릴 거리를 아는 쪽과 띄우는 쪽을 가른다** — 실행·배포·대기열을 아는 것은 `agent.py`이고, 풍선을 띄우는 것은 트레이다. 그래서 알림 판단은 Qt를 모르는 자리(`notices.py`)에 있다.
- **같은 말을 주기마다 띄우지 않는다.** 연결 끊김은 **바뀔 때만** 알리고, 아직 띄우지 않은 같은 알림은 두 번 넣지 않는다. 켜자마자 닿지 못하면 그것은 알리지만(기록이 쌓인다), 잘 닿은 첫 바퀴는 「복구」가 아니다.
- **쌓이기만 하지 않는다** — 창을 오래 닫아 둔 PC에서 알림이 수백 개가 되면 한꺼번에 띄우게 된다. 상한을 넘으면 오래된 것부터 버린다.
- 「사람이 볼 때까지」는 **알림 센터에 남는 것**으로 지킨다 — Windows는 표시 시간을 제 설정대로 쓴다 (우리가 주는 밀리초는 참고값이다).
- 누르면 가는 자리는 **그 알림이 가리키는 것**이고, 창은 메인 창이 쥔다 (결재는 CMN-01, Center 키는 BUI-03).

> 상태: **표가 다 돈다** (`notices.py` + `agent.py`의 자리들). 붙이면서 **기다리는 동안 만료된 작업을 버리는 일**도 함께 생겼다 — C4의 `expired` ack를 아무도 보내지 않아 지난 작업이 그대로 돌고 있었다.
>
> **「Center API 키 만료 임박」은 Center가 말해 준 값으로 알린다** (C4 `key_expires_at`) — 만료일은 Center만 알아서 등록·하트비트 응답에 싣는다. **14일 전부터 하루 한 번**이고(주기마다 띄우면 30초에 한 번 같은 말을 한다), **이미 만료된 키는 알리지 않는다**(그때는 Center가 거부하고 「키 거부」가 할 일을 말한다). 기간을 늘려 주면 들고 있던 「알렸다」를 버려 다음에 또 알린다. 값이 **없으면 「만료 없음」**이고 「모른다」가 아니다.
>
> **서비스 앱 키 알림은 없다** ([ADR-0102](../decisions/0102-calling-outside-is-pull.md) — 서비스 앱 키가 없다). 바깥 기능이 거절·실패하면 그 실행의 실패(「<BPM 프로세스> 실패 — <한 줄>」)로 알린다.

## BUI-06 ~ BUI-09 — 폐기

UI 셀렉터 등록·요소 계획 정보·셀렉터 시험(BUI-06~08)과 로컬 런타임 탭(BUI-09)은 UI 자동화 확장과 함께 없어졌다 ([ADR-0114](../decisions/0114-remove-ui-automation.md)). PC 실행기는 로컬 런타임을 띄우지 않는다.

## BUI-10 서비스 앱 키 — 없어졌다

서비스 앱 키가 없어 화면이 없다 ([ADR-0102](../decisions/0102-calling-outside-is-pull.md)) — BPM 프로세스는 바깥 기능을 Center의 외부 작업(C15)으로 부른다. 실행 프로세스는 PC 실행기가 제 Center API 키로 청한 **호출 토큰**(24시간)으로 올리고, 「불러도 되나」는 Center가 배포로 가린다. 「도구」 메뉴의 「서비스 앱 키...」도 없다. 사람이 넣을 것은 없다. 옛 설정 파일의 `service_keys`(참조 이름 목록)는 **읽지 않고** 다음 저장에서 빠진다 — OS 비밀 저장소에 남은 옛 키 값은 PC 실행기가 지우지 않는다(목록을 뽑을 수 없는 저장소라 이름을 잃으면 찾을 길이 없다 — 지우려면 그 OS의 자격 증명 관리자에서 사람이 지운다).

## BUI-11 확장

이 PC에 설치된 확장 목록 ([ADR-0018](../decisions/0018-extensions.md), C13). 「도구」 → 「확장...」.

| 열 | 내용 |
| --- | --- |
| 「확장」 | 이름 (id는 툴팁) |
| 「등급」 | 내장 / 사내 / 외부 |
| 「버전」 | |
| 「기여」 | 짧게: 「태스크 1 · 설정 칸 2」 (누르면 상세) |
| 「상태」 | 「켜짐」 / 「꺼짐」 / 「호환 안 됨 — 확장 API <범위> 필요」 / 「필요하지만 없음」(설치된 BPM 프로세스가 요구, C1 `requires.extensions`) |
| 「쓰는 BPM 프로세스」 | 이 확장을 요구하는 설치된 BPM 프로세스 수 |

상세: 기여 지점별 목록, 서버 부분(있나 — 주소는 보이지 않는다. 바깥 기능의 주소는 일꾼만 안다, ADR-0102). 「필요한 키」 줄은 없다 (서비스 앱 키가 없다).

> 상태: 코드(`extension_dialog.py`)는 아직 「필요한 키」 줄(`PURPOSE_LABEL` — 「넣을 키 없음」만 말한다)과 서버 부분의 「주소」 줄을 보인다. 이 문서대로 걷을 일이다.

단추: 「끄기」/「켜기」(내장·사내만. 쓰는 BPM 프로세스가 있으면 「<BPM 프로세스> N개가 실행 불가가 됩니다」 확인), 「새로 고침」(Center에서 외부 확장 정의 다시 받기).

- 끈 목록은 **PC 실행기 설정**에 둔다 ([ADR-0043](../decisions/0043-turned-off-extensions.md)) — Studio(STU-15)의 것과 **다른 자리**다. 개발 도구에서 끈 것이 현장 BPM 프로세스를 멈추면 안 된다.
- **「저장」이 없다** — 누르는 그 자리에서 설정에 적고 확장을 다시 읽는다. 그러면 기여(태스크 종류·칸·점검)가 한꺼번에 빠지고 **사전 점검 결과도 다시 잰다**.
- 「상태」의 「꺼짐」은 C4 `ExtensionState.off`로 Center에도 올라간다 — CON-03이 「호환 안 됨」과 가른다.
- 꺼진 확장을 쓰는 BPM 프로세스는 BUI-04 「준비」에 **「확장 꺼짐」**으로 보인다 — 「확장 없음」과 다른 말이다(고치는 길이 「켜기」와 「다시 깔기」로 갈린다).
- 끄기는 **쓰는 BPM 프로세스가 있으면 몇 개가 실행 불가가 되는지 말하고** 확인 창의 기본은 「취소」다. 켜기는 잃을 것이 없어 묻지 않는다.

- 외부 확장은 코드가 없으므로 여기서는 「정의만 — 서비스 앱 태스크로 씀」으로 보인다. 서명(C2 — Center가 짓는다)이 검증되지 않은 외부 정의는 「서명 확인 안 됨 — 쓰지 않음」으로 보인다.
- 확장을 설치·제거하는 것은 PC 실행기 설치 파일을 바꾸는 일이다 (사내 확장의 코드 배포는 ADR-0018 §5).

> 상태: **돈다** (`apps/bot_ui/extension_dialog.py`). 목록·상세·「켜기」/「끄기」·「새로 고침」이 모두 돈다. 외부 확장은 **들고 있는 명부**(`core.app_directory.DirectoryCache` — 서버 실행기와 같은 코드다)에서 오고 「새로 고침」만 Center를 부른다 — **닿지 못하면 들고 있던 것을 쓴다**(ADR-0007. Studio는 그 자리에서 말한다 — 현장이 아니라 개발 도구다). 받은 정의는 **봉투를 다시 검증한다** (C13 E6). 「쓰는 BPM 프로세스」는 `requires.extensions`로 센다. 상세의 서버 부분은 **주소만** 말한다 — 서비스 앱이 살아 있나는 Center가 보고 CON-07에 있다.
