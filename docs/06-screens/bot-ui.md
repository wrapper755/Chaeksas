# Bot UI 화면 설계

**Bot UI는 항상 떠 있는 트레이 기반 GUI 프로그램**이다. 현장 PC와 설계자 PC에 하나씩 설치한다 ([ADR-0012](../decisions/0012-bot-ui.md)).

| 기능 | 화면 |
| --- | --- |
| ① Bot(BPM 프로세스) 다운로드 및 실행 — Center가 배포한 Bot을 받아 결정 수행으로 실행 | BUI-01 트레이, BUI-02 「Bot」 탭, BUI-04 |
| ② 확장의 로컬 런타임 실행 관리 — 화면 없는 프로세스(지금은 Worker 프로세스)를 띄우고 감시·재시작 | BUI-09 |
| ③ 「도구」 — 확장이 더한 도구(기본 제공: UI 셀렉터 등록)를 **Tool UI로 여는 바로가기**. 도구 화면은 [tool-ui.md](tool-ui.md) ([ADR-0077](../decisions/0077-tool-ui.md)) | BUI-01 메뉴 7, BUI-02 [M] |
| 확장 목록·켜기·끄기 | BUI-11 |
| 설정·키 (Center API 키, 서비스 앱 키) | BUI-03, BUI-10 |

- **실행 자리는 하나다.** 실행 중인 Bot은 PC 한 대에 최대 1개이고, 나머지 실행 요청(Center 작업, 수동 실행, 감시 트리거, 일정, 메시지)은 대기열에서 들어온 순서대로 기다린다 ([ADR-0014](../decisions/0014-one-bot-per-pc.md)).
- 실행 중인 Bot은 UI 자동화가 필요하면 Worker 프로세스에 REST로 요청한다. Bot은 Worker를 띄우지 않는다. Worker 기동은 Bot UI의 일이다.
- **확장:** Bot UI는 특정 확장을 모른다. 설치된 확장 정의(C13)를 읽어 「도구」 메뉴의 바로가기, 화면의 칸(`bot_ui.panels`), 로컬 런타임, 설정 칸을 끼워 넣는다 (VS Code가 확장을 붙이듯이, [ADR-0018](../decisions/0018-extensions.md)). 아래의 Worker(BUI-09)는 **UI 자동화 확장이 기여한 런타임**이다. 확장이 더한 **도구의 창은 Bot UI가 갖지 않는다** — Tool UI가 띄우고 Worker는 Bot UI가 띄운 것을 빌려 쓴다 ([ADR-0077](../decisions/0077-tool-ui.md)).
- 로그인 세션에서 실행한다 (Windows 서비스 모드는 나중에 검토).
- 공통 원칙·상태 표기는 [README.md](README.md) §2·§3. 스레딩 규칙: 화면은 보여 주기만, Qt 슬롯에서 동기 I/O 금지, 배경 작업은 하나의 실행 함수로 시작해 예외를 드러냄, 위젯은 GUI 스레드에서만.

## BUI-01 트레이

| 항목 | 내용 |
| --- | --- |
| 아이콘 | 앱 아이콘 + 상태 점(색). 툴팁 「Chaeksas Bot UI · <상태>」 (U7) |
| 상태 | 「대기」 / 「실행 중 · 대기 N건」 / 「셀렉터 등록 중 · 대기 N건」 / 「결재 대기」 / 「확인 대기」 / 「오류」 / 「연결 끊김」(Center에 닿지 못함, 실행은 계속) / 「등록 전」(Center API 키 없음) / 「키 폐기됨」·「키 만료」(Center가 403 — 실행 중 Bot은 끝까지, 기록은 쌓음) / 「비활성」(Center가 새 작업·배포를 보내지 않음, C4 `disabled`) |

| 8 | 「감시 시작」 ↔ 「감시 중지」 | 감시 모드 Bot이 있을 때 |

시스템 트레이가 없는 환경이면 메인 창을 띄우고 창 메뉴에 같은 항목을 둔다 (U15).

> 상태: 「도구」의 항목이 **트레이에서도 열린다** — 기여의 이름(`label`)을 확장 이름순으로 그린다. 누르면 메인 창과 **같은 길**(`main_window.open_tool` → `tool_launch.py`)로 런타임을 띄우고 Tool UI를 띄운다. Tool UI는 **감시하지 않는 따로 뜬 프로세스**이고(Job Object에 넣지 않는다), 「같은 것을 두 번 열지 않는다」는 Tool UI가 지킨다(한 세션에 하나). 종료 순서의 「Worker 프로세스 종료」는 **먼저 곱게 끄기를 부른다**(C13 `shutdown` → C10 `POST /v1/admin/shutdown`) — 런타임이 열린 세션을 닫고 밀린 보고를 저장할 틈을 준다. **답하지 않아도 기다리지 않는다**(그대로 끈다, ADR-0023). 「확장...」(BUI-11)도 **창은 메인 창이 쥔다** — 트레이는 열어 달라고만 한다.

## BUI-02 메인 창

제목 「Chaeksas Bot UI」, 1000×720. 창을 닫아도 Bot UI는 트레이에서 계속 돈다.

```
+----------------------------------------------------------+
| [M] menu: File | Tools                                   |
+----------------------------------------------------------+
| [K] tabs: Bots | Runs | Local runtimes | (ext tabs)    |
|                                                          |
|                 [W] tab content                          |
|                                                          |
+----------------------------------------------------------+
| [S] status bar                                           |
+----------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [M] 메뉴 | 「파일」 → 「설정...」, 「로그 폴더 열기」, 구분선, 「종료」(Ctrl+Q) · 「도구」 → 확장이 기여한 도구들(Tool UI로 연다 — 트레이 7과 같다), 구분선, 「서비스 앱 키...」(BUI-10), 「확장...」(BUI-11) |
| [K] 탭 | 「Bot」(BUI-04) / 「실행 기록」(로그) / 「로컬 런타임」(BUI-09). 확장의 도구는 여기 붙지 않는다 — Tool UI의 탭이다 (TOL-01) |
| [S] 상태 줄 | 「<상태> · Center <주소> · Worker 127.0.0.1:<포트> · 밀린 기록 N건 · 오류: <앞부분>」 (오류는 `failed` 색 글자). 해당할 때만 뒤 항목을 붙인다 |

「실행 기록」 탭: 최대 5000줄. 줄 형식 「<시각> [<Bot>] <노드> <내용>」. 실패는 한 줄 요약 먼저 (U13). 문맥 메뉴: 복사, 「화면 지우기」.

> 상태: **돈다** — `runs/<run_id>.jsonl`을 읽어 그린다 (`run_log_view.py`). **원본은 파일이다**(ADR-0031·C3)라서 Bot UI를 닫았다 열어도 같은 것이 보이고, **새 실행이 위**다. 「화면 지우기」는 **화면만** 비운다 — 파일을 지우면 Center로 보낼 기록이 사라진다. 「파일 → 로그 폴더 열기」가 그 폴더를 연다. 스크롤이 맨 아래가 아니면 자리를 지킨다. **업무 값은 없다** — `data`에서 **아는 칸만** 글로 옮긴다 (원칙 6).

## BUI-03 설정·등록

처음 실행하면 등록이 안 되어 있으므로 이 창이 먼저 뜬다. 칸은 **탭으로 나눈다** — 아래 표의 한 줄이 탭 하나이고 순서도 표와 같다. 창은 「Center」 탭으로 열린다(첫 실행에 할 일이 거기 있다).

| 탭 | 필드 | 비고 |
| --- | --- | --- |
| 「Center」 | 주소, **Center API 키**(Center 콘솔 CON-11에서 발급받아 붙여 넣음, 값 가림. 모양이 `chk_ctr_` + 40자가 아니면 저장하지 않고 「Center API 키는 「chk_ctr_」로 시작하는 48자입니다 …」를 보인다), 「연결 테스트」 | 결과 한 줄: 「연결됨 — 이 PC는 <Bot UI 이름>으로 등록됨」 / 「키가 거부되었습니다 — 콘솔에서 키 상태를 확인하세요」 / 「닿지 못함 — <이유>」. 키는 OS 비밀 저장소 |
| 「실행」 | 「로그인할 때 자동 시작」(기본 켬. 이 사용자의 로그온 작업으로 등록 — 관리자 권한 없음. 등록에 실패하면 경고 「자동 시작을 등록하지 못했습니다: <이유>」를 보이고 칸을 **실제 상태로 되돌려** 저장한다), 「결재를 Center로 올리기」(원격 결재 — BPM 프로세스의 결재 위치가 「Bot UI 설정을 따름」인 결재에만 적용, STU-04가 정한 것이 우선), 「서명된 패키지만 설치」(기본 켬), 「대기열 크기」(기본 20, `CHK_BOT_UI__QUEUE__MAX`) | 실행 자리는 하나로 고정 (설정 없음) |
| 「모델」 (신규) | 주소(OpenAI 호환 `/v1`을 여는 곳 — 사내 게이트웨이·Ollama·vLLM. 비우면 **AI 태스크가 돌지 않는다**), 모델 이름, **API 키**(값 가림, 키가 필요 없는 로컬 모델이면 비워 둔다 — 비우면 `Authorization`을 아예 보내지 않는다). 「연결 테스트」 | 주소·키는 **실행하는 쪽만 안다** — BPM 프로세스에는 들어가지 않는다 ([ADR-0013](../decisions/0013-api-keys.md)·[ADR-0027](../decisions/0027-llm-connection.md)). 키는 OS 비밀 저장소 |
| 「파일」 (신규) | 「읽기 허용 폴더」 목록 + 「쓰기 허용 폴더」 목록 (각각 「추가...」/「삭제」). 출력 폴더는 `<데이터 폴더>/outputs/<Bot>`로 고정이고 보여 주기만 한다 | Bot이 읽을 수 있는 곳은 **여기 적은 폴더뿐**이다 ([ADR-0026](../decisions/0026-file-paths-and-file-list-task.md)). 비어 있으면 파일을 읽는 태스크는 **조용히 넘어가지 않고 실패한다**. 쓰기 허용 폴더는 **비어 있는 것이 기본**이고, 적으면 **그 안의 파일을 Bot이 고칠 수 있다**고 화면이 말한다 ([ADR-0032](../decisions/0032-writable-dirs.md)) |
| 「보내기」 (신규) | **SMTP**: 주소, 포트(비우면 보안에 맞는 기본 — `starttls` 587·`ssl` 465·`none` 25), 보안(`starttls` 기본 / `ssl` / `none`), 사용자, **비밀번호**(값 가림 → OS 비밀 저장소), 보내는 주소(`from`), 첨부 합계 상한(MB, 기본 10). **웹훅**: 「허용 호스트」 목록(「추가...」/「삭제」). 「연결 테스트」 | 비우면 `chk:email`이 **보내지 않고 실패한다**(`SEND_FAILED`) — 조용히 넘어가지 않는다 ([ADR-0059](../decisions/0059-sending-mail-and-webhooks.md)). 보안을 `none`으로 고르면 **「암호화하지 않고 보냅니다」**라고 말한다. 웹훅 허용 호스트는 **비어 있는 것이 기본**이고 비면 어디에도 보내지 않는다(쓰기 허용 폴더와 같은 결 — ADR-0032). **사설·루프백 주소는 적어도 열리지 않는다** (C13 §4-3과 같은 관문) |
| 「로컬 런타임」 | 런타임마다: 포트(Worker 기본 8899), 「시작」: 「필요할 때」(기본 — 설치된 Bot이 그 확장을 요구하거나 「도구」에서 그 런타임을 쓰는 도구를 열 때) / 「항상」 | 포트를 바꾸면 다시 띄운다 |
| 확장별 설정 (확장의 `configuration` 기여) | **확장마다 탭 하나**이고 탭 이름은 확장 이름이다. 확장이 선언한 칸으로 **그 자리에서** 만든다. `scope: bot_ui`인 칸만 — 도구가 쓰는 칸(`scope: tool_ui`, 예: UI 자동화의 등록 담당자 키)은 **Tool UI 설정(TOL-02)**에 있다. 확장이 주는 칸이 없으면 탭도 없다 | **비밀 칸은 설정 파일에 들어가지 않는다** |
| 「나중에」 | 아직 없는 칸(메시지 수신 포트, 툴팩 비밀)을 **끈 채로** 이유와 함께 보인다 (U3) | 메시지 수신 포트(기본 8790, 「다른 PC에서도 받기」 기본 끔)는 ReceiveTask·메시지 시작 이벤트용 |

단추: 「저장」/「취소」 — **탭 밖**에 있어 어느 탭에서 눌러도 모든 탭의 칸을 함께 저장한다. 탭의 내용이 창보다 크면(예: 1920×1080을 150%로 쓰면 화면 높이가 672) **그 탭의 내용만 스크롤되고 탭과 단추는 항상 보인다.** 창은 처음 열 때 화면 높이를 넘지 않게 뜬다.

## BUI-04 Bot 탭 (실행·대기열·설치된 Bot)

탭 위쪽에 실행 자리와 대기열, 아래쪽에 설치된 Bot 목록을 둔다.

```
+----------------------------------------------------------+
| [R] running now: bot @ node | elapsed | [Stop]           |
| [Q] queue table                    [To front] [Cancel]   |
+----------------------------------------------------------+
| [L] installed bots table                                 |
+----------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [R] 지금 실행 | 「<Bot> <버전> @ <노드> · <경과> · 출처 <Center 작업/수동/감시/일정/메시지>」 + 「중지」(확인 창, 기본 「취소」). 결재·확인을 기다리는 중이면 「결재 창 열기」(CMN-01). 비었으면 「실행 중인 Bot이 없습니다」. 셀렉터 등록이 Worker를 쓰는 중이면 「셀렉터 등록 중 — 대기열은 등록을 마치면 이어집니다」 |
| [Q] 대기열 | 열: 「#」 / 「Bot」 / 「출처」 / 「요청 시각」 / 「만료」(Center 작업만) / 「입력 키」(값은 접음, U10). 단추: 「맨 앞으로」(수동 실행 항목만), 「취소...」(확인 창, 기본 「취소」. Center 작업이면 「Center에 '현장에서 취소함'으로 알립니다」 — C4 `rejected` + `cancelled_on_pc`). 빈 상태: 「기다리는 실행이 없습니다. 「지금 실행...」이나 Center 작업 지시로 실행됩니다.」 위 제목에 「대기 N/20」 |
| [L] 설치된 Bot | 아래 표 |


| 열 | 내용 |
| --- | --- |
| 「Bot」 | 이름 (id는 툴팁) |
| 「버전」 | |
| 「출처」 | 「Center 배포」 / 「수동 설치」 / 「알 수 없음」(설치할 때 남긴 표식이 없다 — **둘 중 어느 쪽인지 모르면 고르지 않는다**) |
| 「서명」 | 「확인됨」 / 「서명 없음」 / 「서명 불일치」 |
| 「준비」 | 「준비됨」 / 「서비스 앱 키 없음: <참조>」 / 「확장 꺼짐」(BUI-11에서 켜면 된다) / 「확장 없음」(판을 올려야 한다) / 「사전 점검 실행 불가」 — 사전 점검 결과. 막은 점검의 사유·고칠 방법은 툴팁 |
| 「상태」 | 대기 / 실행 중 / 대기열 N번째 / 감시 중 / 수동 실행 전용 / 비활성 |
| 「최근 실행」 | 시각 + 결과 (「완료」·「실패」·「취소됨」·「실행 중」, 끝 기록이 없으면 「—」). 시각은 기록 그대로(UTC)이고 BUI-02와 같다 |

단추 (고른 줄 기준): 「지금 실행...」(입력 변수 입력 창 → 실행 자리가 비었으면 바로 실행, 차 있으면 「대기열에 넣었습니다 (N번째)」. 입력 창에 체크 「맨 앞에 넣기」), 「감시 시작/중지」, 「제거...」(Center 배포분은 「Center에서 배포를 철회해야 다시 설치되지 않습니다」 안내).
위쪽 단추: 「패키지 파일에서 설치...」(서명 확인), 「새로 고침」.
「준비」가 키 없음이면 줄에 「키 등록...」 단추 → BUI-10.
빈 상태: 「설치된 Bot이 없습니다. Center에서 이 PC에 배포하거나 「패키지 파일에서 설치...」로 설치하세요.」

> 상태: 「준비」까지 돈다 — 사전 점검(`core.preflight`)이 **서비스 앱 키 참조**·**확장 태스크 종류**·**AI 환경**과 확장이 기여한 점검(C13)을 보고, 결과를 하트비트 `readiness`로 올린다 (C4 → CON-03). **「꺼 뒀다」와 「없다」를 가른다** — 확장이 깔려 있는데 사람이 BUI-11에서 껐으면 「확장 꺼짐」이고 고치는 길은 「켜기」다 ([ADR-0043](../decisions/0043-turned-off-extensions.md)). **준비되지 않은 Bot은 시작하지 않는다** — Center 작업이면 `rejected`·`not_ready`로 ack한다. 「출처」는 **설치할 때 남긴 표식**(`INSTALL_SOURCE`)에서 읽는다 — 배포가 설치한 것은 「Center 배포」(`deploy.py`), 「패키지 파일에서 설치...」가 설치한 것은 「수동 설치」다. **표식이 없으면 「알 수 없음」이다** — 푸는 것만으로는 어느 쪽인지 알 수 없고(`bots.install`은 적지 않는다), 표식을 남기기 전에 설치된 폴더일 수 있다. 「최근 실행」은 **BUI-02와 같은 파일**(`runs/<run_id>.jsonl`)에서 그 Bot의 마지막 실행 하나를 읽는다 — 시각은 `run_started`, 결과는 `run_finished`의 `status`를 「실행·노드」 표기(「완료」·「실패」·「취소됨」)로 옮긴다. **끝 줄이 없으면** 지금 도는 그 실행이면 「실행 중」이고, 아니면 결과를 지어내지 않고 「—」(툴팁: 실행기가 도중에 멈췄을 수 있다)다. 한 번도 안 돌았으면 빈칸이다.

규칙:
- **알릴 거리를 아는 쪽과 띄우는 쪽을 가른다** — 실행·배포·대기열을 아는 것은 `agent.py`이고, 풍선을 띄우는 것은 트레이다. 그래서 알림 판단은 Qt를 모르는 자리(`notices.py`)에 있다.
- **같은 말을 주기마다 띄우지 않는다.** 연결 끊김·런타임 멈춤은 **바뀔 때만** 알리고, 아직 띄우지 않은 같은 알림은 두 번 넣지 않는다. 켜자마자 닿지 못하면 그것은 알리지만(기록이 쌓인다), 잘 닿은 첫 바퀴는 「복구」가 아니다.
- **쌓이기만 하지 않는다** — 창을 오래 닫아 둔 PC에서 알림이 수백 개가 되면 한꺼번에 띄우게 된다. 상한을 넘으면 오래된 것부터 버린다.
- 「사람이 볼 때까지」는 **알림 센터에 남는 것**으로 지킨다 — Windows는 표시 시간을 제 설정대로 쓴다 (우리가 주는 밀리초는 참고값이다).
- 누르면 가는 자리는 **그 알림이 가리키는 것**이고, 창은 메인 창이 쥔다 (결재는 CMN-01, 키는 BUI-10, Center 키는 BUI-03).
- 런타임 이름은 **확장이 준 것**을 쓴다 (C13 `label`) — 플랫폼 코드에 「Worker」라고 적지 않는다 ([ADR-0018](../decisions/0018-extensions.md)).

> 상태: **표가 다 돈다** (`notices.py` + `agent.py`의 자리들). 붙이면서 **기다리는 동안 만료된 작업을 버리는 일**도 함께 생겼다 — C4의 `expired` ack를 아무도 보내지 않아 지난 작업이 그대로 돌고 있었다.
>
> **「Center API 키 만료 임박」은 Center가 말해 준 값으로 알린다** (C4 `key_expires_at`) — 만료일은 Center만 알아서 등록·하트비트 응답에 싣는다. **14일 전부터 하루 한 번**이고(주기마다 띄우면 30초에 한 번 같은 말을 한다), **이미 만료된 키는 알리지 않는다**(그때는 Center가 거부하고 「키 거부」가 할 일을 말한다). 기간을 늘려 주면 들고 있던 「알렸다」를 버려 다음에 또 알린다. 값이 **없으면 「만료 없음」**이고 「모른다」가 아니다.
>
> **「서비스 앱 키」는 반쪽이 둘이고 묻는 때가 다르다** ([ADR-0052](../decisions/0052-service-app-key-notices.md)).
> - **거부는 묻지 않는다 — 실행이 이미 물었다.** 실행 기록의 `service_call` 중 **앱이 분명히 거부한 것**(`status`가 401·403)을 읽어 `app_id`·`key_ref`로 알린다. **값이 이 PC에 없는 것(`key_missing`)은 거부가 아니다** — 그것은 「준비」가 할 말이다(「서비스 앱 키 없음: `<참조>`」). 뭉치면 키를 넣으면 될 일에 「앱이 거부했다」고 한다. 같은 실행의 재시도는 한 번이고, **새 실행이 또 거부당하면 다시 알린다**(방금 실패한 업무다). 어댑터가 같은 자리에 들어가므로 **외부 앱도 같이 덮인다**.
> - **만료 임박만 하루 한 번 묻는다.** `GET /v1/keys/self`(C11)를 **점검 밖에서** 부른다 — `core.preflight`는 그대로 「값이 있나」까지만 본다. 좁히는 것 다섯: **설치된 Bot이 실제로 쓰는 참조만**(BUI-10에 등록만 해 둔 키는 묻지 않는다), **들고 있는 주소만**(주소를 모르면 묻지 않는다 — 이것 때문에 Center를 두드리지 않는다), **주기마다 많아야 하나**(하트비트가 화면과 같은 자리에서 돈다), **닿지 못한 것은 알릴 거리가 아니다**(ADR-0007 — 조용히 다음 날 다시 묻는다), **이미 만료된 키는 알리지 않는다**(그때는 앱이 거부하고 위의 줄이 할 일을 말한다 — Center 키와 같은 규칙).

## BUI-09 로컬 런타임 탭 (Worker 프로세스 등)

확장이 기여한 로컬 런타임(`bot_ui.local_runtimes`)을 Bot UI가 띄우고 감시한다. 런타임마다 아래 영역이 하나씩 있다. 지금은 UI 자동화 확장의 **Worker 프로세스** 하나다. 아래 「지금 하는 일」·「최근 UI 세션」·「밀린 보고」는 Worker가 상태 API(C10 `/v1/status`)로 주는 내용이다.

| 영역 | 내용 |
| --- | --- |
| 상태 | 「실행 중」 / 「꺼 둠 (필요할 때 시작)」 / 「다시 띄우는 중」 / 「멈춤」 + PID, 포트, 버전, 가동 시간 |
| 예약 | 「예약됨 — <Bot> (<실행 id>)」 / 「예약 없음」 (C10 `reserved_for`) |
| 지금 하는 일 | 「대기」 / 「Bot 요청 처리 중: <Bot> @ <노드>」 / 「Studio 요청 처리 중」 / 「셀렉터 등록 중」 |
| 최근 UI 세션 | 시각 / 요청한 쪽(Bot·Studio) / 화면 / 결과(성공·전환·실패) / 폴백 깊이 / 치유 |
| 밀린 보고 | UI 자동화 앱에 아직 못 보낸 보고 N건 |
| 단추 | 「시작」(꺼져 있을 때), 「다시 시작」(실행 중인 UI 세션이 있으면 확인 창, 기본 「취소」), 「로그 보기」. 「시작」 설정(필요할 때 / 항상)은 BUI-03 「로컬 런타임」 |

> 상태: 전부 돈다. 상태·PID·포트·가동 시간·다시 띄운 횟수·「지금 하는 일」(런타임이 `health`로 말해 준다)과 **「예약」·「밀린 보고」**는 런타임의 상태를 **확장 정의의 선언대로**(C13 `status`) 물어 보인다. **본문에서 뜻을 아는 칸만 읽는다**(`reserved_for`·`unsent_reports`) — 「최근 UI 세션」의 열(화면·폴백 깊이·치유)은 **확장의 말**이라 플랫폼이 그리면 Bot UI가 UI 자동화를 알게 된다 ([ADR-0018](../decisions/0018-extensions.md)). 그래서 **그 표는 확장이 그린다** — C13 `bot_ui.panels`로 기여한 칸이 이 영역 아래에 들어오고, Bot UI는 자리만 준다 ([ADR-0042](../decisions/0042-extension-contributed-panels.md)). **Worker가 떠 있을 때만 보인다**(꺼져 있을 때 빈 표를 보이는 것보다 칸이 없는 것이 정직하다). 칸을 그리지 못하면 **그 칸만 접고 사유를 보인다.** 예약은 **런타임이 말하는 것**이 원본이다 — 다시 뜨면 예약이 사라지므로 우리가 걸어 둔 것을 믿지 않는다.

규칙:
- Worker가 죽으면 Bot UI가 자동으로 다시 띄운다 (최대 3회 연속, 그 뒤 「멈춤」).
- Worker는 UI 세션을 한 번에 하나만 연다 (Bot 실행 / Studio 시험 실행 / Tool UI의 셀렉터 등록 중 하나). 다른 쪽 요청은 「사용 중 — <누가>」로 거절된다.

## BUI-10 서비스 앱 키

BPM 프로세스(Bot)가 쓰는 **서비스 앱 키 참조 이름 ↔ 키 값**을 이 PC에 등록한다 ([ADR-0013](../decisions/0013-api-keys.md) §3). 키 값은 각 서비스 앱의 관리 콘솔(SVC-02)에서 발급받는다. 「도구」 → 「서비스 앱 키...」.

| 열 | 내용 |
| --- | --- |
| 「참조 이름」 | BPM 프로세스 속성에 적힌 이름 (예: `finance-invoice`) |
| 「서비스 앱」 | 앱 id (매니페스트가 적은 그대로 — 화면이 이름을 짓지 않는다) |
| 「키」 | 값 가림, 앞자리 16자만. 어디서 오는지도 적는다 (「저장됨」 / 「환경변수」) |
| 「상태」 | 「정상 — 허용: 자율·결정, 만료 <날짜>」 / 「만료됨」 / 「키가 틀림」 / 「폐기됨」 / 「앱에 닿지 못함」 / 「주소를 모름」 / 「확인 전」 |
| 「쓰는 Bot」 | 이 참조를 쓰는 설치된 Bot 목록 (없으면 「쓰는 Bot 없음」) |

단추: 「추가...」, 「값 바꾸기...」, 「삭제...」(쓰는 Bot이 있으면 「<Bot> N개가 실행 불가가 됩니다」 확인, 기본 「취소」), 「확인」(앱에 키 상태 조회).
설치된 Bot이 요구하지만 없는 참조는 표 맨 위에 빨간 줄로 「등록 필요」.

규칙:
- **「저장」이 없다.** 키 관리창이라 추가·변경·삭제가 그 자리에서 일어나고, 그때마다 사전 점검을 다시 재게 한다 — 빠진 키를 넣으면 **다음 하트비트에 「준비됨」이 올라가야 한다** (C4 `readiness`).
- 참조 이름은 설정 파일에, **값은 OS 비밀 저장소**에 (`chaeksas-bot-ui`의 `svc:<참조>`). 비밀 저장소는 목록을 뽑을 수 없으므로 이름을 설정에 남긴다 — 그러지 않으면 쓰는 Bot이 없는 키는 보이지도, 지워지지도 않는다.
- 참조 이름은 **매니페스트와 같은 규칙**이어야 한다 (C1 R4) — 아니면 「적용」을 막는다.
- 환경변수(`CHK_BOT_UI__SVC__<참조>`)로 오는 키는 **여기서 바꾸거나 지울 수 없다** (읽기는 환경변수가 이겨서, 저장소에 덮어써도 그대로다). 그렇게 말해 준다.
- **표를 그릴 때는 앱을 부르지 않는다** — 「확인」을 누를 때만 `GET <앱 주소>/v1/keys/self`로 묻는다 (C11). 주소는 Center에서 받아 둔 명부(C7)에 있고, 없으면 「주소를 모름」이다.
- **창 밖에서도 같은 것을 묻는다 — 하루 한 번, 쓰는 키만** ([ADR-0052](../decisions/0052-service-app-key-notices.md)). 만료 임박을 BUI-05로 알리려면 창이 닫혀 있을 때도 알아야 한다. 「확인」과 **같은 함수**를 쓰고, 묻는 때와 범위만 좁다 (설치된 Bot이 쓰는 참조·들고 있는 주소·주기마다 하나).

> 상태: **돈다.** 값은 `credentials.py`를 거쳐 OS 비밀 저장소로 가고(없으면 **분명히 실패한다**), 「확인」은 진짜 앱에 묻는다. 「서비스 앱」 열에 사람이 읽을 **앱 이름**을 쓰려면 Center 리소스 목록을 봐야 해서 지금은 id를 적는다.

## BUI-11 확장

이 PC에 설치된 확장 목록 ([ADR-0018](../decisions/0018-extensions.md), C13). 「도구」 → 「확장...」.

| 열 | 내용 |
| --- | --- |
| 「확장」 | 이름 (id는 툴팁) |
| 「등급」 | 내장 / 사내 / 외부 |
| 「버전」 | |
| 「기여」 | 짧게: 「태스크 1 · 도구 1 · 로컬 런타임 1」 (누르면 상세) |
| 「상태」 | 「켜짐」 / 「꺼짐」 / 「호환 안 됨 — 확장 API <범위> 필요」 / 「필요하지만 없음」(설치된 Bot이 요구, C1 `requires.extensions`) |
| 「쓰는 Bot」 | 이 확장을 요구하는 설치된 Bot 수 |

상세: 기여 지점별 목록, 서버 부분(서비스 앱 주소·상태), 필요한 키(`requires_keys` — 실행용은 BUI-10, 도구용은 Tool UI 설정 TOL-02), 로컬 런타임 상태.

단추: 「끄기」/「켜기」(내장·사내만. 쓰는 Bot이 있으면 「<Bot> N개가 실행 불가가 됩니다」 확인), 「새로 고침」(Center에서 외부 확장 정의 다시 받기).

- 끈 목록은 **Bot UI 설정**에 둔다 ([ADR-0043](../decisions/0043-turned-off-extensions.md)) — Studio(STU-15)의 것과 **다른 자리**다. 개발 도구에서 끈 것이 현장 Bot을 멈추면 안 된다.
- **「저장」이 없다** (BUI-10과 같은 결) — 누르는 그 자리에서 설정에 적고 확장을 다시 읽는다. 그러면 기여(태스크 종류·도구·칸·점검)가 한꺼번에 빠지고 **사전 점검 결과도 다시 잰다**. 「도구」 메뉴의 그 항목도 그 자리에서 사라진다. **Tool UI도 이 목록을 따른다**(제 켜기·끄기가 없다, TOL-01) — Tool UI는 뜰 때 읽으므로 떠 있는 Tool UI의 탭은 다음에 뜰 때 사라진다.
- 「상태」의 「꺼짐」은 C4 `ExtensionState.off`로 Center에도 올라간다 — CON-03이 「호환 안 됨」과 가른다.
- 꺼진 확장을 쓰는 Bot은 BUI-04 「준비」에 **「확장 꺼짐」**으로 보인다 — 「확장 없음」과 다른 말이다(고치는 길이 「켜기」와 「다시 깔기」로 갈린다).
- 끄기는 **쓰는 Bot이 있으면 몇 개가 실행 불가가 되는지 말하고** 확인 창의 기본은 「취소」다. 켜기는 잃을 것이 없어 묻지 않는다.

- 외부 확장은 코드가 없으므로 여기서는 「정의만 — 서비스 앱 태스크로 씀」으로 보인다. Admin 서명이 검증되지 않은 외부 정의는 「서명 확인 안 됨 — 쓰지 않음」으로 보인다.
- 확장을 설치·제거하는 것은 Bot UI 설치 파일을 바꾸는 일이다 (사내 확장의 코드 배포는 ADR-0018 §5).

> 상태: **돈다** (`apps/bot_ui/extension_dialog.py`). 목록·상세·「켜기」/「끄기」·「새로 고침」이 모두 돈다. 외부 확장은 **들고 있는 명부**(`core.app_directory.DirectoryCache` — 서버 실행기와 같은 코드다)에서 오고 「새로 고침」만 Center를 부른다 — **닿지 못하면 들고 있던 것을 쓴다**(ADR-0007. Studio는 그 자리에서 말한다 — 현장이 아니라 개발 도구다). 받은 정의는 **봉투를 다시 검증한다** (C13 E6). 「쓰는 Bot」은 `requires.extensions`와 `requires.domains`의 AI 환경 주인을 함께 센다 (ADR-0037 — 그림에 확장을 적지 않아도 끄면 멈춘다). 상세의 서버 부분은 **주소만** 말한다 — 서비스 앱이 살아 있나는 Center가 보고 CON-07에 있다.
