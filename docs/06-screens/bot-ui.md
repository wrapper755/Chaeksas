# Bot UI 화면 설계

**Bot UI는 항상 떠 있는 트레이 기반 GUI 프로그램**이다. 현장 PC와 설계자 PC에 하나씩 설치한다 ([ADR-0012](../decisions/0012-bot-ui.md)).

| 기능 | 화면 |
| --- | --- |
| ① Bot(BPM 프로세스) 다운로드 및 실행 — Center가 배포한 Bot을 받아 결정 수행으로 실행 | BUI-01 트레이, BUI-02 「Bot」 탭, BUI-04 |
| ② 확장의 로컬 런타임 실행 관리 — 화면 없는 프로세스(지금은 Worker 프로세스)를 띄우고 감시·재시작 | BUI-09 |
| ③ 확장이 더한 유틸리티 — 기본 제공: UI 셀렉터 등록 (UI 자동화 확장) | BUI-06 ~ BUI-08 |
| 확장 목록·켜기·끄기 | BUI-11 |
| 설정·키 (Center API 키, 서비스 앱 키) | BUI-03, BUI-10 |

- **실행 자리는 하나다.** 실행 중인 Bot은 PC 한 대에 최대 1개이고, 나머지 실행 요청(Center 작업, 수동 실행, 감시 트리거, 일정, 메시지)은 대기열에서 들어온 순서대로 기다린다 ([ADR-0014](../decisions/0014-one-bot-per-pc.md)).
- 실행 중인 Bot은 UI 자동화가 필요하면 Worker 프로세스에 REST로 요청한다. Bot은 Worker를 띄우지 않는다. Worker 기동은 Bot UI의 일이다.
- **확장:** Bot UI는 특정 확장을 모른다. 설치된 확장 정의(C13)를 읽어 「도구」 메뉴의 유틸리티, 메인 창의 탭, 로컬 런타임, 설정 칸을 끼워 넣는다 (VS Code가 확장을 붙이듯이, [ADR-0018](../decisions/0018-extensions.md)). 아래의 UI 셀렉터 등록(BUI-06~08)과 Worker(BUI-09)는 **UI 자동화 확장이 기여한 화면**이다.
- 로그인 세션에서 실행한다 (Windows 서비스 모드는 나중에 검토).
- 공통 원칙·상태 표기는 [README.md](README.md) §2·§3. 스레딩 규칙: 화면은 보여 주기만, Qt 슬롯에서 동기 I/O 금지, 배경 작업은 하나의 실행 함수로 시작해 예외를 드러냄, 위젯은 GUI 스레드에서만.

## BUI-02 메인 창

제목 「Chaeksas Bot UI」, 1000×720. 창을 닫아도 Bot UI는 트레이에서 계속 돈다.

```
+----------------------------------------------------------+
| [M] menu: File | Tools                                   |
+----------------------------------------------------------+
| [K] tabs: Bots | Runs | Local runtimes | (ext tabs)    |
|                                                          |
|                 [W] tab content                          |
|                                                          |
+----------------------------------------------------------+
| [S] status bar                                           |
+----------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [M] 메뉴 | 「파일」 → 「설정...」, 「로그 폴더 열기」, 구분선, 「종료」(Ctrl+Q) · 「도구」 → 확장이 기여한 유틸리티들, 구분선, 「서비스 앱 키...」(BUI-10), 「확장...」(BUI-11) |
| [K] 탭 | 고정: 「Bot」(BUI-04) / 「실행 기록」(로그) / 「로컬 런타임」(BUI-09) · 확장 기여: 유틸리티는 기본으로 별도 창으로 열리고, 유틸리티 창의 「메인 창 탭으로 열기」를 켜 두면 여기 탭으로 붙는다 (예: 「UI 셀렉터 등록」 BUI-06·08) |
| [S] 상태 줄 | 「<상태> · Center <주소> · Worker 127.0.0.1:<포트> · 밀린 기록 N건 · 오류: <앞부분>」 (오류는 `failed` 색 글자). 해당할 때만 뒤 항목을 붙인다 |

「실행 기록」 탭: 최대 5000줄. 줄 형식 「<시각> [<Bot>] <노드> <내용>」. 실패는 한 줄 요약 먼저 (U13). 문맥 메뉴: 복사, 「화면 지우기」.

## BUI-03 설정·등록

처음 실행하면 등록이 안 되어 있으므로 이 창이 먼저 뜬다.

| 섹션 | 필드 | 비고 |
| --- | --- | --- |
| 「Center」 | 주소, **Center API 키**(Center 콘솔 CON-11에서 발급받아 붙여 넣음, 값 가림. 모양이 `chk_ctr_` + 40자가 아니면 저장하지 않고 「Center API 키는 「chk_ctr_」로 시작하는 48자입니다 …」를 보인다), 「연결 테스트」 | 결과 한 줄: 「연결됨 — 이 PC는 <Bot UI 이름>으로 등록됨」 / 「키가 거부되었습니다 — 콘솔에서 키 상태를 확인하세요」 / 「닿지 못함 — <이유>」. 키는 OS 비밀 저장소 |
| 「실행」 | 「로그인할 때 자동 시작」(기본 켬. 이 사용자의 로그온 작업으로 등록 — 관리자 권한 없음. 등록에 실패하면 경고 「자동 시작을 등록하지 못했습니다: <이유>」를 보이고 칸을 **실제 상태로 되돌려** 저장한다), 「결재를 Center로 올리기」(원격 결재 — BPM 프로세스의 결재 위치가 「Bot UI 설정을 따름」인 결재에만 적용, STU-04가 정한 것이 우선), 「서명된 패키지만 설치」(기본 켬), 「대기열 크기」(기본 20, `CHK_BOT_UI__QUEUE__MAX`) | 실행 자리는 하나로 고정 (설정 없음) |
| 「모델」 (신규) | 주소(OpenAI 호환 `/v1`을 여는 곳 — 사내 게이트웨이·Ollama·vLLM. 비우면 **AI 태스크가 돌지 않는다**), 모델 이름, **API 키**(값 가림, 키가 필요 없는 로컬 모델이면 비워 둔다 — 비우면 `Authorization`을 아예 보내지 않는다). 「연결 테스트」 | 주소·키는 **실행하는 쪽만 안다** — BPM 프로세스에는 들어가지 않는다 ([ADR-0013](../decisions/0013-api-keys.md)·[ADR-0027](../decisions/0027-llm-connection.md)). 키는 OS 비밀 저장소 |
| 「파일」 (신규) | 「읽기 허용 폴더」 목록 + 「쓰기 허용 폴더」 목록 (각각 「추가...」/「삭제」). 출력 폴더는 `<데이터 폴더>/outputs/<Bot>`로 고정이고 보여 주기만 한다 | Bot이 읽을 수 있는 곳은 **여기 적은 폴더뿐**이다 ([ADR-0026](../decisions/0026-file-paths-and-file-list-task.md)). 비어 있으면 파일을 읽는 태스크는 **조용히 넘어가지 않고 실패한다**. 쓰기 허용 폴더는 **비어 있는 것이 기본**이고, 적으면 **그 안의 파일을 Bot이 고칠 수 있다**고 화면이 말한다 ([ADR-0032](../decisions/0032-writable-dirs.md)) |
| 「로컬 런타임」 | 런타임마다: 포트(Worker 기본 8899), 「시작」: 「필요할 때」(기본 — 설치된 Bot이 그 확장을 요구하거나 유틸리티를 열 때) / 「항상」 | 포트를 바꾸면 다시 띄운다 |
| 확장별 설정 (확장의 `configuration` 기여) | 확장이 선언한 칸으로 **그 자리에서** 만든다. 「UI 자동화」: 등록 담당자 **서비스 앱 API 키**(`registry_write` 권한, 비밀 칸 → OS 비밀 저장소). UI 자동화 앱 주소는 여기 두지 않고 Center 리소스 목록에서 받는다 (주소 출처는 하나, C13 예약 키 `service.base_url`) | 그 확장의 유틸리티를 쓰는 PC에서만. **비밀 칸은 설정 파일에 들어가지 않는다** |
| 「메시지 수신」 | 포트(기본 8790), 「다른 PC에서도 받기」(기본 끔) | ReceiveTask·메시지 시작 이벤트용 |
| 「툴팩 비밀」 | 이름/값 표(값 가림) | 툴팩이 쓰는 비밀. OS 비밀 저장소 |

단추: 「저장」/「취소」. 창이 화면보다 크면(예: 1920×1080을 150%로 쓰면 화면 높이가 672) **내용만 스크롤되고 단추는 항상 창 아래에 보인다.** 창은 처음 열 때 화면 높이를 넘지 않게 뜬다.

## BUI-04 Bot 탭 (실행·대기열·설치된 Bot)

탭 위쪽에 실행 자리와 대기열, 아래쪽에 설치된 Bot 목록을 둔다.

```
+----------------------------------------------------------+
| [R] running now: bot @ node | elapsed | [Stop]           |
| [Q] queue table                    [To front] [Cancel]   |
+----------------------------------------------------------+
| [L] installed bots table                                 |
+----------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [R] 지금 실행 | 「<Bot> <버전> @ <노드> · <경과> · 출처 <Center 작업/수동/감시/일정/메시지>」 + 「중지」(확인 창, 기본 「취소」). 결재·확인을 기다리는 중이면 「결재 창 열기」(CMN-01). 비었으면 「실행 중인 Bot이 없습니다」. 셀렉터 등록이 Worker를 쓰는 중이면 「셀렉터 등록 중 — 대기열은 등록을 마치면 이어집니다」 |
| [Q] 대기열 | 열: 「#」 / 「Bot」 / 「출처」 / 「요청 시각」 / 「만료」(Center 작업만) / 「입력 키」(값은 접음, U10). 단추: 「맨 앞으로」(수동 실행 항목만), 「취소...」(확인 창, 기본 「취소」. Center 작업이면 「Center에 '현장에서 취소함'으로 알립니다」 — C4 `rejected` + `cancelled_on_pc`). 빈 상태: 「기다리는 실행이 없습니다. 「지금 실행...」이나 Center 작업 지시로 실행됩니다.」 위 제목에 「대기 N/20」 |
| [L] 설치된 Bot | 아래 표 |


| 열 | 내용 |
| --- | --- |
| 「Bot」 | 이름 (id는 툴팁) |
| 「버전」 | |
| 「출처」 | 「Center 배포」 / 「수동 설치」 / 「알 수 없음」(설치할 때 남긴 표식이 없다 — **둘 중 어느 쪽인지 모르면 고르지 않는다**) |
| 「서명」 | 「확인됨」 / 「서명 없음」 / 「서명 불일치」 |
| 「준비」 | 「준비됨」 / 「서비스 앱 키 없음: <참조>」 / 「확장 없음」 / 「사전 점검 실행 불가」 — 사전 점검 결과. 막은 점검의 사유·고칠 방법은 툴팁 |
| 「상태」 | 대기 / 실행 중 / 대기열 N번째 / 감시 중 / 수동 실행 전용 / 비활성 |
| 「최근 실행」 | 시각 + 결과 |

단추 (고른 줄 기준): 「지금 실행...」(입력 변수 입력 창 → 실행 자리가 비었으면 바로 실행, 차 있으면 「대기열에 넣었습니다 (N번째)」. 입력 창에 체크 「맨 앞에 넣기」), 「감시 시작/중지」, 「제거...」(Center 배포분은 「Center에서 배포를 철회해야 다시 설치되지 않습니다」 안내).
위쪽 단추: 「패키지 파일에서 설치...」(서명 확인), 「새로 고침」.
「준비」가 키 없음이면 줄에 「키 등록...」 단추 → BUI-10.
빈 상태: 「설치된 Bot이 없습니다. Center에서 이 PC에 배포하거나 「패키지 파일에서 설치...」로 설치하세요.」

> 상태: 「준비」까지 돈다 — 사전 점검(`core.preflight`)이 **서비스 앱 키 참조**·**확장 태스크 종류**·**AI 환경**과 확장이 기여한 점검(C13)을 보고, 결과를 하트비트 `readiness`로 올린다 (C4 → CON-03). **준비되지 않은 Bot은 시작하지 않는다** — Center 작업이면 `rejected`·`not_ready`로 ack한다. 「출처」는 **설치할 때 남긴 표식**(`INSTALL_SOURCE`)에서 읽는다 — 배포가 설치한 것은 「Center 배포」(`deploy.py`), 「패키지 파일에서 설치...」가 설치한 것은 「수동 설치」다. **표식이 없으면 「알 수 없음」이다** — 푸는 것만으로는 어느 쪽인지 알 수 없고(`bots.install`은 적지 않는다), 표식을 남기기 전에 설치된 폴더일 수 있다. 「최근 실행」은 아직 없다 — **모르는 것을 적지 않는다.**

## BUI-06 UI 셀렉터 등록

> UI 자동화 확장(내장)이 기여하는 유틸리티다 (`bot_ui.utilities`, [ADR-0018](../decisions/0018-extensions.md)). 화면 코드는 `extensions/ui_automation/client/`에 있다.
>
> 상태: **BUI-06~08이 돈다** — 담기·직접 고르기·표시·검증·등록·불러오기·등록 취소·시험. 창 하나에 「등록」·「시험」 탭 둘이다. Worker는 Bot UI가 유틸리티를 열 때 띄우고(`needs_runtime`), 어디 있는지는 **호스트가 설정으로 알려 준다** (C13 예약 키 `runtime.worker.*`·`service.base_url`). 서버에 닿지 못하면 **등록을 큐에 쌓고**(확장 폴더, C13 `storage.dir`) 창을 열 때·등록·삭제 뒤에 다시 올린다. 「표시」는 **CSS 후보가 있을 때만** 된다 (없으면 그렇게 말한다).

Bot UI의 유틸리티. Worker의 UI 세션을 쓰므로 **Bot 실행과 겹치지 않는다**: Bot 실행 중에는 창은 열리지만 브라우저 동작 단추가 꺼지고 안내 줄에 「Bot 실행 중 — 끝나면 쓸 수 있습니다」. 등록 중에 Bot 차례가 오면 Bot은 기다리고, 창을 닫으면 바로 실행된다 ([ADR-0014](../decisions/0014-one-bot-per-pc.md) §4). 새 화면의 요소를 담아 검증하고 UI 자동화 앱에 등록한다 (계약 C9). 브라우저 조작은 Worker 프로세스 API(C10)를 통해 한다. 등록 담당자 개인 키(BUI-03 「확장별 설정 › UI 자동화」)로 UI 자동화 앱에 쓴다. 기존 화면에 요소를 더하거나 지울 수도 있다.

```
+------------------------------------------------------------------+
| [P] page row: page-id picker [Load]  [state]  [Del elem][Del page]|
+------------------------------------------------------------------+
| [C] collector group (browser now, desktop later)                 |
|     row 1: start url  [Open] [Pick] [Analyze] [Close browser]    |
|     row 2: scope  max [n]  [x] include read targets              |
+------------------------------------------------------------------+
| [H] hint line (progress, results, errors)                        |
+------------------------------------------------------------------+
| [E] elements table                    [Delete sel] [Delete all]  |
|------------------------------------------------------------------|
| [V] checks table                                      [Validate] |
+------------------------------------------------------------------+
| [Reset]                                              [Register]  |
+------------------------------------------------------------------+
```

### 영역

| 영역 | 내용 |
| --- | --- |
| [P] 화면 줄 | 「화면 ID」 편집 콤보(목록에서 고르거나 새로 적음, 처음엔 빈 칸) + 「불러오기」 + 등록 상태 글 + 「요소 등록 취소」 + 「화면 등록 취소」 |
| [P] 등록 상태 | 「**기존 화면** — 요소 N개가 등록돼 있습니다 (여기에 더합니다)」 / 「**새 화면** — 등록하면 만들어집니다」 / 「서버에 닿지 못해 **기존 여부를 알 수 없습니다**」 (U8) |
| [C] 「브라우저에서 담기」 | 1행: 「시작 주소」 + 「브라우저 열기」(연 뒤에는 「주소로 이동」) + 「직접 고르기」(토글, 켜지면 「고르는 중… (누르면 종료)」) + 「분석」 + 「브라우저 닫기」. 2행: 「분석 범위」(CSS, 비우면 전체) + 「최대」(10~2000, 50 단위) + 「읽기 대상 포함」 |
| [C] (나중) 「데스크톱 창에서 담기」 | S1 스파이크 뒤 추가. 같은 자리에 창 고르기·UIA 분석·직접 고르기 |
| [H] 안내 줄 | 진행·결과·오류의 유일한 통로. 굵게 표시 가능 |
| [E] 요소 표 | 열: 「시맨틱 키」(체크 + 편집) / 「종류」(조작·목록·표·글자) / 「가능한 동작」 / 「태그」 / 「역할」 / 「접근성 이름」 / 「id」 / 「CSS 후보」. 체크된 키가 겹치면 빨간 바탕. 줄 툴팁: 등록된 사다리, 선행 입력, 업무 개념, 이동 |
| [V] 검증 표 | 사다리 한 칸에 한 줄. 열: 「시맨틱 키」 / 「순위」 / 「전략」 / 「셀렉터」 / 「결과」(통과·실패) / 「사유」 |
| 아래 | 왼쪽 「초기화」(표·검증·화면 ID 비움, 브라우저는 유지), 오른쪽 「등록」 |

### 단추 켜짐 규칙

| 단추 | 켜지는 조건 |
| --- | --- |
| 「직접 고르기」, 「분석」, 「브라우저 닫기」 | 브라우저가 열려 있음 |
| 「검증」 | 분석·고르기·불러오기로 표에 줄이 있음 |
| 「등록」 | 「검증」을 마침 (그 뒤 표를 바꾸면 다시 꺼짐) |
| 「선택 삭제」/「전체 삭제」 | 표에 줄이 있음 |
| 「불러오기」 | 등록 상태가 「기존 화면」 |
| 「화면 등록 취소」 | 화면 ID가 있고 상태가 「새 화면」이 아님 |
| 「요소 등록 취소」 | 위 조건 + 표에서 줄 하나를 고름 |

서버 조회는 일을 시작할 때만 한다: 화면 ID 입력이 끝났을 때(포커스 이동·Enter), 분석이 끝났을 때, 검증을 시작할 때, 등록·삭제 뒤. 고를 때마다 묻지 않는다.

### 흐름

1. **브라우저 열기** — 「브라우저를 띄우는 중…」 → 「열렸습니다 — <주소>. 등록할 화면까지 브라우저에서 직접 이동한 뒤 **분석**을 누르세요. 새 탭이 열려도 따라갑니다.」 주소는 시작점일 뿐이다.
2. **분석** — 지금 열린 화면에서 보이는 요소를 표로 가져온다 (표를 바꾼다).
   - 범위 선택자가 아무것도 찾지 못하면 「범위 선택자가 아무것도 찾지 못했습니다 — <범위>」 (전체로 몰래 넓히지 않는다).
   - 잘리면 「…중 K개만 가져왔습니다. **범위를 좁히거나 최대치를 올리세요**」 + 「최대」 칸 노란 표시.
   - 화면 ID가 비어 있으면 주소에서 채운다 (사용자가 고친 뒤에는 건드리지 않음).
3. **직접 고르기** — 브라우저에서 누른 요소가 표에 체크된 채 추가된다. 조작 대상은 빨강, 읽기 대상은 주황 테두리. Shift+클릭은 둘러싼 표. 고르는 동안 링크 이동은 막는다. Esc로 끝. 「골랐습니다 — <이름> → `<키>`」 / 「이미 표에 있습니다 — <이름>」.
4. **시맨틱 키** — 자동 제안(test_id → id → name → 영문 접근성 이름 → 역할 순, 한글 이름은 음역하지 않음, 겹치면 번호). 쓸 줄만 체크하고 필요한 키만 의미 있게 고친다. 키를 고치면 자동 체크, 지우면 체크 해제.
5. **표시** — 표에서 줄을 고르면 브라우저에서 그 요소를 파란 테두리로 보인다. 「화면에 표시했습니다」 / 「화면에서 찾지 못했습니다」 / 「**N개가 잡힙니다** — 모호해서 실패합니다」.
6. **요소 계획 정보** — 줄을 더블클릭하면 BUI-07.
7. **검증** — 먼저 등록 초안을 만든다. 초안 거부: 키 겹침, 고른 요소 없음, 서로 다른 화면의 요소가 섞임. 그다음 지금 열린 화면에서 사다리 전체를 시험한다. 요약:
   - 「잡히지 않는 요소가 있습니다 — … 자가 치유로 넘어갑니다」
   - 「모두 잡힙니다 — 다만 **X**는 쓸 수 있는 로케이터가 하나뿐입니다」
   - 「모두 잡히고 대체 로케이터도 살아 있습니다. 등록해도 좋습니다.」
   - 덧붙임: 「선행 입력 N건 · 업무 개념 M건을 함께 올립니다.」, 선행 입력을 찾을 수 없으면 **경고**(막지 않음).
8. **등록** — 「서버에 등록하는 중…」.
   - 성공: 「등록했습니다 — <화면> (새 로케이터 N개, 그대로 둔 것 K개)」 + 「새 로케이터는 **검증 전**으로 들어가 3회 연속 성공하면 사용 중으로 올라갑니다.」 바뀐 것이 없으면 「이미 등록된 것과 같습니다」.
   - 아직 없는 화면을 이동 대상으로 가리키면 경고: 「**아직 등록되지 않은 화면을 가리켰습니다** — 오타라면 지금 보이는 이 이름이 틀린 것입니다.」
   - 서버가 거부(4xx): 「서버가 거부했습니다 (<코드>) — <내용>. 보낸 내용을 고쳐야 합니다. 다시 눌러도 같은 답이 옵니다.」 큐에 쌓지 않는다.
   - 서버에 닿지 못함: 「서버에 닿지 못해 **등록을 큐에 쌓았습니다.** 서버가 돌아오면 저절로 올라갑니다.」
9. **불러오기** — 표에 줄이 있으면 먼저 「표에 N개 행이 있습니다. <화면>에 등록된 것으로 **바꿉니다.** 담아 둔 것은 사라집니다.」 불러온 줄은 체크되어 있고 서버의 사다리를 그대로 가진다 (다시 등록해도 정의가 바뀌지 않음).
10. **등록 취소 (삭제)** — 경고 창, 기본 단추 「취소」 (U9).
    - 화면: 「<화면>을 레지스트리에서 통째로 지웁니다. 쌓아 온 통계·승격·치유 이력이 함께 사라지고 되돌릴 수 없습니다. 화면이 바뀐 것이라면 지우지 말고 다시 등록하세요.」
    - 요소: 「<화면>의 `<키>`를 지웁니다. 그 요소의 사다리와 통계가 사라집니다.」
    - 화면 ID는 **입력한 값만** 쓴다 (주소에서 추정하지 않음).
    - 서버가 409(다른 화면이 가리킴): 두 번째 확인 「다른 화면이 가리키고 있습니다 — <내용>. 지우면 그 경로가 끊깁니다. 그래도 지울까요?」 → 예면 강제 삭제.
    - 결과: 「지웠습니다 — <범위> (요소 N개, 로케이터 M개)」 + 끊긴 경로 + 「큐에 남아 있던 등록과 계획 캐시도 함께 버렸습니다.」 삭제는 큐에 쌓지 않는다.

## BUI-08 셀렉터 시험

등록된 화면에 대해 계획을 받아 실행해 본다 (Worker 프로세스 경유). Bot 실행과는 별개의 시험이다. 들어가는 곳: 「도구」 → 「UI 셀렉터 등록」 창의 「시험」 탭. 결과 보고는 「시험」으로 표시되고 승격 통계에 들어가지 않는다 (C8 `origin: test`).

> 상태: **결정 수행으로 돈다** — 「가져오기」가 등록된 요소로 스텝 표를 채우고 사람이 동작·값을 고친다. 자연어 **목표로 계획**(자율 수행)은 Studio UI 태스크(STU-13)에서 쓴다 — 셀렉터 시험은 등록된 요소의 스텝으로만 하므로 칸을 꺼 두었다. **「결과를 서버에 보고」가 꺼져 있으면 아예 보내지 않는다** (C10 `report`). 시험은 자기 세션을 열기 때문에 **「등록」 탭이 쥔 브라우저를 놓는다** (세션은 한 번에 하나다) — 같은 세션을 이어 쓰는 것은 아직이다. BUI-06 요소 표의 「시험...」 진입도 아직이다.

| 요소 | 내용 |
| --- | --- |
| 1행 | 「화면」(목록에서 고름, 고르면 바로 조회) + 「목표」(예: 공급자 등록번호를 넣고 상신) + 「가져오기」 |
| 2행 | 「시작 주소」(비우면 계획의 값) |
| 3행 | 「자가 치유 사용」(켬), 「결과를 서버에 보고」(끔), 「끝나도 브라우저 열어 두기」(켬) · 오른쪽 「브라우저 닫기」, 「실행」 |
| 출력 | 읽기 전용 글 상자 |

출력 내용:
- 「[계획 출처: 서버 | 로컬 캐시 (오프라인)] <화면> · N스텝」 + 번호 붙은 스텝.
- 결과: 「성공 / 사람에게 전환 / 실패 — x/y 스텝」, 요소별 시도(「O/X 로케이터 (사유)」), 「자가 치유:」, 「읽어온 값:」(표는 줄 단위), 「사람에게 전환:」, 「서버에 보낼 보고: N bytes」.
- 끝: 「브라우저를 열어 두었습니다」 / 「보고 전송됨」 / 「보고를 큐에 쌓았습니다 (서버에 닿지 못함)」.
- 셀렉터 등록과 같은 브라우저 세션을 쓴다.


## BUI-09 로컬 런타임 탭 (Worker 프로세스 등)

확장이 기여한 로컬 런타임(`bot_ui.local_runtimes`)을 Bot UI가 띄우고 감시한다. 런타임마다 아래 영역이 하나씩 있다. 지금은 UI 자동화 확장의 **Worker 프로세스** 하나다. 아래 「지금 하는 일」·「최근 UI 세션」·「밀린 보고」는 Worker가 상태 API(C10 `/v1/status`)로 주는 내용이다.

| 영역 | 내용 |
| --- | --- |
| 상태 | 「실행 중」 / 「꺼 둠 (필요할 때 시작)」 / 「다시 띄우는 중」 / 「멈춤」 + PID, 포트, 버전, 가동 시간 |
| 예약 | 「예약됨 — <Bot> (<실행 id>)」 / 「예약 없음」 (C10 `reserved_for`) |
| 지금 하는 일 | 「대기」 / 「Bot 요청 처리 중: <Bot> @ <노드>」 / 「Studio 요청 처리 중」 / 「셀렉터 등록 중」 |
| 최근 UI 세션 | 시각 / 요청한 쪽(Bot·Studio) / 화면 / 결과(성공·전환·실패) / 폴백 깊이 / 치유 |
| 밀린 보고 | UI 자동화 앱에 아직 못 보낸 보고 N건 |
| 단추 | 「시작」(꺼져 있을 때), 「다시 시작」(실행 중인 UI 세션이 있으면 확인 창, 기본 「취소」), 「로그 보기」. 「시작」 설정(필요할 때 / 항상)은 BUI-03 「로컬 런타임」 |

> 상태: 상태·PID·포트·가동 시간·다시 띄운 횟수와 「지금 하는 일」(런타임이 `health`로 말해 준다)까지 돈다. 「예약」·「최근 UI 세션」·「밀린 보고」는 Worker 상태 API(C10 `/v1/status`)를 봐야 해서 M5다 — **모르는 것을 적지 않는다.**

규칙:
- Worker가 죽으면 Bot UI가 자동으로 다시 띄운다 (최대 3회 연속, 그 뒤 「멈춤」).
- Worker는 UI 세션을 한 번에 하나만 연다 (Bot 실행 / Studio 시험 실행 / 셀렉터 등록 중 하나). 다른 쪽 요청은 「사용 중 — <누가>」로 거절된다.

## BUI-10 서비스 앱 키

BPM 프로세스(Bot)가 쓰는 **서비스 앱 키 참조 이름 ↔ 키 값**을 이 PC에 등록한다 ([ADR-0013](../decisions/0013-api-keys.md) §3). 키 값은 각 서비스 앱의 관리 콘솔(SVC-02)에서 발급받는다. 「도구」 → 「서비스 앱 키...」.

| 열 | 내용 |
| --- | --- |
| 「참조 이름」 | BPM 프로세스 속성에 적힌 이름 (예: `finance-invoice`) |
| 「서비스 앱」 | 앱 id (매니페스트가 적은 그대로 — 화면이 이름을 짓지 않는다) |
| 「키」 | 값 가림, 앞자리 16자만. 어디서 오는지도 적는다 (「저장됨」 / 「환경변수」) |
| 「상태」 | 「정상 — 허용: 자율·결정, 만료 <날짜>」 / 「만료됨」 / 「키가 틀림」 / 「폐기됨」 / 「앱에 닿지 못함」 / 「주소를 모름」 / 「확인 전」 |
| 「쓰는 Bot」 | 이 참조를 쓰는 설치된 Bot 목록 (없으면 「쓰는 Bot 없음」) |

단추: 「추가...」, 「값 바꾸기...」, 「삭제...」(쓰는 Bot이 있으면 「<Bot> N개가 실행 불가가 됩니다」 확인, 기본 「취소」), 「확인」(앱에 키 상태 조회).
설치된 Bot이 요구하지만 없는 참조는 표 맨 위에 빨간 줄로 「등록 필요」.

규칙:
- **「저장」이 없다.** 키 관리창이라 추가·변경·삭제가 그 자리에서 일어나고, 그때마다 사전 점검을 다시 재게 한다 — 빠진 키를 넣으면 **다음 하트비트에 「준비됨」이 올라가야 한다** (C4 `readiness`).
- 참조 이름은 설정 파일에, **값은 OS 비밀 저장소**에 (`chaeksas-bot-ui`의 `svc:<참조>`). 비밀 저장소는 목록을 뽑을 수 없으므로 이름을 설정에 남긴다 — 그러지 않으면 쓰는 Bot이 없는 키는 보이지도, 지워지지도 않는다.
- 참조 이름은 **매니페스트와 같은 규칙**이어야 한다 (C1 R4) — 아니면 「적용」을 막는다.
- 환경변수(`CHK_BOT_UI__SVC__<참조>`)로 오는 키는 **여기서 바꾸거나 지울 수 없다** (읽기는 환경변수가 이겨서, 저장소에 덮어써도 그대로다). 그렇게 말해 준다.
- **표를 그릴 때는 앱을 부르지 않는다** — 「확인」을 누를 때만 `GET <앱 주소>/v1/keys/self`로 묻는다 (C11). 주소는 Center에서 받아 둔 명부(C7)에 있고, 없으면 「주소를 모름」이다.

> 상태: **돈다.** 값은 `credentials.py`를 거쳐 OS 비밀 저장소로 가고(없으면 **분명히 실패한다**), 「확인」은 진짜 앱에 묻는다. 「서비스 앱」 열에 사람이 읽을 **앱 이름**을 쓰려면 Center 리소스 목록을 봐야 해서 지금은 id를 적는다.

## BUI-11 확장

이 PC에 설치된 확장 목록 ([ADR-0018](../decisions/0018-extensions.md), C13). 「도구」 → 「확장...」.

| 열 | 내용 |
| --- | --- |
| 「확장」 | 이름 (id는 툴팁) |
| 「등급」 | 내장 / 사내 / 외부 |
| 「버전」 | |
| 「기여」 | 짧게: 「태스크 1 · 유틸리티 1 · 로컬 런타임 1」 (누르면 상세) |
| 「상태」 | 「켜짐」 / 「꺼짐」 / 「호환 안 됨 — 확장 API <범위> 필요」 / 「필요하지만 없음」(설치된 Bot이 요구, C1 `requires.extensions`) |
| 「쓰는 Bot」 | 이 확장을 요구하는 설치된 Bot 수 |

상세: 기여 지점별 목록, 서버 부분(서비스 앱 주소·상태), 필요한 키(`requires_keys` — 실행용은 BUI-10, 유틸리티용은 BUI-03), 로컬 런타임 상태.

단추: 「끄기」/「켜기」(내장·사내만. 쓰는 Bot이 있으면 「<Bot> N개가 실행 불가가 됩니다」 확인), 「새로 고침」(Center에서 외부 확장 정의 다시 받기).

- 외부 확장은 코드가 없으므로 여기서는 「정의만 — 서비스 앱 태스크로 씀」으로 보인다. Admin 서명이 검증되지 않은 외부 정의는 「서명 확인 안 됨 — 쓰지 않음」으로 보인다.
- 확장을 설치·제거하는 것은 Bot UI 설치 파일을 바꾸는 일이다 (사내 확장의 코드 배포는 ADR-0018 §5).
