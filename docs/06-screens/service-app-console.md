# 서비스 앱 관리 콘솔 화면 설계

**서비스 앱마다 자기 관리 콘솔(웹)을 가진다** ([ADR-0013](../decisions/0013-api-keys.md)). 서비스 앱 API 키는 여기서 발급한다. 공통 화면(SVC)은 `packages/service_kit`이 제공하고, 앱 고유 화면은 앱이 더한다. 첫 사례는 UI 자동화 앱(UIA)이다.

Center 콘솔은 서비스 앱 키를 다루지 않는다. Center 리소스 목록(CON-07)에서 각 관리 콘솔로 링크만 건다.

> 구현: `service_kit`(Python)은 **관리 API**(`/admin/v1/status`·`keys`·`usage`)를 제공하고, 화면은 Next.js 앱 `web/apps/svc-console` 한 벌이 그린다. 서비스 앱마다 같은 콘솔을 설정만 바꿔 띄우고(포트 = API + 1), 접속한 앱의 `app_id`에 맞는 고유 화면(예: UIA)만 켠다 ([ADR-0017](../decisions/0017-web-nextjs-design-system.md)).
공통 원칙·상태 표기는 [README.md](README.md) §2·§3.

## SVC-00 공통 틀

```
+----------------------------------------------------------------+
| [N] nav    | [A] top bar: app name | version | status | [Refresh]|
|            +---------------------------------------------------+
|            | [B] page body                                      |
+----------------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [N] 탐색 | 공통: 「상태」(SVC-01) / 「API 키」(SVC-02) / 「사용 기록」(SVC-03) · 그 아래 앱 고유 메뉴 (UI 자동화 앱: 「개요」·「셀렉터」·「모니터링」) |
| [A] 위 막대 | 앱 이름, 버전, 상태(정상·저하), 「새로 고침」 |

**로그인:** 관리자 토큰(앱 설정)으로 들어간다 (OIDC는 나중). 키 발급·폐기는 로그인한 관리자만.

## SVC-02 API 키

이 서비스 앱을 호출할 때 쓰는 키를 발급·폐기한다.

필터: 「상태」(사용 중 / 만료 / 폐기됨), 「허용 모드」.

| 열 | 내용 |
| --- | --- |
| 「이름」 | 사람이 알아볼 이름. BPM 프로세스의 **키 참조 이름**과 맞추기를 권장 (예: `finance-invoice`) |
| 「허용 작업」 | 「모든 작업」 또는 작업 목록 |
| 「허용 모드」 | 「결정 수행」(운영 Bot용) / 「자율·결정 수행」(Studio 개발용) |
| 「앞자리」 | 앞 16자 (`chk_svc_` + 무작위 8자) |
| 「만든 날」 / 「만료」 / 「마지막 사용」 | |
| 「상태」 | 사용 중 / 만료 / 폐기됨 |

- 「새 키」 → 창: 이름, 허용 작업, 허용 모드, 만료(기본 1년), 메모. 「발급」을 누르면 **원문을 한 번만** 보여 준다: 「이 키는 다시 볼 수 없습니다. 지금 복사해 Bot UI 「서비스 앱 키」(또는 Studio 설정)에 참조 이름 <이름>으로 넣으세요」 + 「복사」.
- 「폐기」(확인 창, 기본 「취소」): 「이 키를 쓰는 Bot의 호출이 바로 거부됩니다.」
- UI 자동화 앱은 추가로 「레지스트리 쓰기」 권한을 고를 수 있다 (UI 셀렉터 등록 담당자용).

## SVC-03 사용 기록

| 열 | 내용 |
| --- | --- |
| 시각 / 키 이름 / 작업 / 수행 모드 / 결과(성공·실패·거부) / 소요 / Bot·실행 id(있으면) | 업무 값은 기록하지 않는다 (키·작업·결과만) |

## UI 자동화 앱 고유 화면 (UIA)

> UI 자동화 확장이 기여하는 콘솔 화면이다 (`console.pages`, [ADR-0018](../decisions/0018-extensions.md)). 화면에서 읽어 온 업무 값은 보고에 없으므로(C8) 여기에도 보이지 않는다. 「셀렉터 시험」(BUI-08) 보고는 「시험」으로 따로 표시하고 승격 통계에 넣지 않는다. 코드는 `extensions/ui_automation/console/`. 외부 확장(외부 앱)은 이 콘솔을 쓰지 않고 자기 콘솔 링크만 CON-07에 보인다.
>
> 상태: **셋 다 돈다.** 탐색 줄은 기여에서 오고(콘솔이 확장 정의의 `console.pages`를 빌드 시점 레지스트리로 읽어 접속한 앱의 `extension.id`로 고른다, [ADR-0042](../decisions/0042-extension-contributed-panels.md) §2), 자료는 **C9 §관리 콘솔이 읽는 길**에서 오며 **관리자 토큰**으로만 열린다 (콘솔은 서비스 앱 키를 갖지 않는다, ADR-0013). 세 화면 모두 **보기 전용**이고 좁히기·경로 탐색·상세는 **JS 없이** 돈다 (일반 `<form method="get">`·`<details>`).

### UIA-01 개요

> 상태: **돈다** (`app/ext/ui-automation/overview`). 읽는 길은 C9 §관리 콘솔이 읽는 길(`GET /admin/v1/overview`)이다.

| 섹션 | 내용 |
| --- | --- |
| 「관리 중인 셀렉터」 | 화면 수, 요소 수, 로케이터 전체, 「검증 전」 수, 「대체됨」 수. 안내: 「검증 전 로케이터는 연속 3회 정상 동작하면 자동으로 사용 중으로 올라갑니다」 |
| 「LLM」 | 연결 여부, 모델, 마지막 호출 결과, 치유 최대 횟수. **주소·키는 보이지 않는다** (C11 §모델 연결). 계획과 치유가 **같은 모델 하나**를 쓴다 (앱 설정이 하나다) |
| 「최근 UI 세션」 | 오늘, 전체(보고받은 것), 사람에게 전환, 실패, 자가 치유. 「셀렉터 시험(BUI-08) 보고 N건은 위 수에 들어가지 않습니다」 |
| 「배포 전 확인」 | 「정상」/「경고」 배지 항목: 모델 연결, 등록 담당자 키(`registry_write`), 등록된 화면. **경고가 있어도 앱은 돈다** — 무엇이 안 되는지 알려 주는 줄이다 |

- **「진행 중」은 없다.** C8 보고는 세션이 **끝날 때** 오므로 앱은 도는 세션을 모른다 — 지금 무엇이 도는지는 현장 Bot UI의 BUI-09가 보여 준다. 화면이 그렇게 말한다.
- 「배포 전 확인」에 **허용 주소 목록·인증 설정은 두지 않는다** — 외부 확장 어댑터의 개념이고(C13 §4) C11을 따르는 이 앱에는 없다. 이 앱이 **자기 힘으로 볼 수 있는 것만** 본다.

### UIA-02 셀렉터

> 상태: **돈다** (`app/ext/ui-automation/selectors`). 읽는 길은 C9 `GET /admin/v1/pages`·`pages/{page_id}`·`path`다.

화면을 골라 그 화면의 로케이터 전부를 본다 (대체된 것 포함).

- 「화면」 고르기: 「<id> — <이름>」. 빈 상태: 「등록된 화면이 없습니다. Bot UI 「도구」 → 「UI 셀렉터 등록」(BUI-06)으로 등록하세요.」 / 「이 화면에 등록된 로케이터가 없습니다. BUI-06에서 요소를 더하세요.」
- 경고 띠 (C8 강등 규칙): 「최근 10회 실패율이 50%를 넘은 사용 중 로케이터 N개 — 화면이 바뀌었을 수 있습니다」 + 해당 요소로 이동
- 「좁히기」(접힘): 상태(사용 중/검증 전/대체됨), 시맨틱 키, 셀렉터 검색(셀렉터·접근성 이름 일부). 켜져 있으면 「전체 N건 중 **M건** — 좁히기가 켜져 있습니다.」 화면을 바꾸면 좁히기를 초기화.
- 표 열: 시맨틱 키 / 순위 / 전략 / 셀렉터 / 접근성 이름 / 상태 / 성공 / 실패 / 성공률(막대) / 연속 성공 / 「자가 치유」(치유가 더한 것인지와 그것이 밀어낸 수). 통계 열은 **늘 있다** — `LocatorStats`가 성공·실패·연속 성공을 들고 있다 ([ADR-0040](../decisions/0040-registry-storage-sqlite.md)). **성공률은 센 적이 없으면 「—」**다 (0%와 다르다).
  - 「순위」는 사다리 순서(`rank`)다. **「0」이 치유를 뜻하지 않는다** — 레지스트리에 그런 표시가 없어서, 치유가 더한 것인지는 **보고**(C8 `healed`)에서 알아내 따로 열로 보인다.
- 「대체 관계 N건」(접힘): 무엇이 무엇을 밀어냈는지. **보고가 적어 둔 것**이라 세션 기록이 있어야 보인다.
- 내용이 있을 때만 보이는 섹션: 「전략별 성공·실패」 차트, 「선행 조건·화면 이동」 표(시맨틱 키 / 역할 / 설명 / 업무 개념 / 선행 입력 / 이동하는 화면 / 가능한 동작, 빈 열은 접고 이름만 표시), 「화면 간 경로 탐색」(출발·도착 → `a → b`, 없으면 「두 화면을 잇는 경로가 없습니다 — 등록의 화면 이동을 확인하세요.」 — 간선은 요소의 `navigates_to`이고 **최단 하나**를 앱이 너비 우선으로 찾는다, ADR-0040).

### UIA-03 모니터링

> 상태: **돈다** (`app/ext/ui-automation/monitoring`). 읽는 길은 C9 `GET /admin/v1/sessions`다. 「Bot」·「Bot UI」·「요청 쪽」·「수행 모드」는 **C11 호출 봉투**에서 온다 (C8 보고에 없다).

UI 세션(= UI 태스크 한 번) 기록. 출처는 Worker가 보낸 보고.

| 섹션 | 내용 |
| --- | --- |
| 요약 | 전체 / 성공 / 전환 / 실패 (상태 배지, 시험 보고는 따로 「시험」). 설명: 「**전환** = 자가 치유가 한도를 넘어 현장 PC(Bot UI)의 확인으로 넘어간 것 (오류가 아닙니다)」. 치유 수. **「진행 중」은 없다** — UIA-01과 같은 이유다 (보고는 세션이 끝날 때 온다) |
| 「폴백 깊이 분포」 | 차트 + 「1순위 로케이터로 바로 성공한 비율 X%」. 없으면 「아직 성공한 실행 기록이 없습니다.」 |
| 「UI 세션 이력」 | 상태 / 화면 / 실행 id(`business_key`) / Bot / Bot UI / 요청 쪽(Bot·Studio·Worker) / 수행 모드 / 진행(x/y) / 치유 / 받은 시각 / 오류. 최근 100건까지 (시험 보고 포함, 상태 배지가 「시험」이다) |
| 상세 | 「자가 치유 내역」, 「전환됨」 경고와 시도한 로케이터·실패 사유 표, 「감사 로그」(접힌 JSON) |

전환은 Bot UI가 현장에서 확인으로 처리하므로, 이 페이지는 **보기 전용**이다 (프로토타입의 「BPM이 받아감」 단추는 없앤다).

- 「실행 id」에 **CON-01 링크는 아직 걸지 않는다** — 콘솔 둘의 주소가 서로를 모른다 (서비스 앱 콘솔은 자기 앱 주소만 설정으로 받는다). 링크를 걸려면 Center 콘솔 주소를 어디서 받을지 정해야 한다.
- 「폴백 깊이 분포」의 깊이는 **성공한 요소만** 센다 — 끝까지 실패한 것은 깊이가 아니라 전환·실패다.
