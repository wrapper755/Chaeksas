# 서비스 앱 관리 콘솔 화면 설계

**서비스 앱마다 자기 관리 콘솔(웹)을 가진다** ([ADR-0013](../decisions/0013-api-keys.md)). 서비스 앱 API 키는 여기서 발급한다. 공통 화면(SVC)은 `packages/service_kit`이 제공하고, 앱 고유 화면은 앱이 더한다. 첫 사례는 UI 자동화 앱(UIA)이다.

Center 콘솔은 서비스 앱 키를 다루지 않는다. Center 리소스 목록(CON-07)에서 각 관리 콘솔로 링크만 건다.

> 구현: `service_kit`(Python)은 **관리 API**(`/admin/v1/status`·`keys`·`usage`)를 제공하고, 화면은 Next.js 앱 `web/apps/svc-console` 한 벌이 그린다. 서비스 앱마다 같은 콘솔을 설정만 바꿔 띄우고(포트 = API + 1), 접속한 앱의 `app_id`에 맞는 고유 화면(예: UIA)만 켠다 ([ADR-0017](../decisions/0017-web-nextjs-design-system.md)).
공통 원칙·상태 표기는 [README.md](README.md) §2·§3.

## SVC-02 API 키

이 서비스 앱을 호출할 때 쓰는 키를 발급·폐기한다.

필터: 「상태」(사용 중 / 만료 / 폐기됨), 「허용 모드」.

| 열 | 내용 |
| --- | --- |
| 「이름」 | 사람이 알아볼 이름. BPM 프로세스의 **키 참조 이름**과 맞추기를 권장 (예: `finance-invoice`) |
| 「허용 작업」 | 「모든 작업」 또는 작업 목록 |
| 「허용 모드」 | 「결정 수행」(운영 Bot용) / 「자율·결정 수행」(Studio 개발용) |
| 「앞자리」 | 앞 16자 (`chk_svc_` + 무작위 8자) |
| 「만든 날」 / 「만료」 / 「마지막 사용」 | |
| 「상태」 | 사용 중 / 만료 / 폐기됨 |

- 「새 키」 → 창: 이름, 허용 작업, 허용 모드, 만료(기본 1년), 메모. 「발급」을 누르면 **원문을 한 번만** 보여 준다: 「이 키는 다시 볼 수 없습니다. 지금 복사해 Bot UI 「서비스 앱 키」(또는 Studio 설정)에 참조 이름 <이름>으로 넣으세요」 + 「복사」.
- 「폐기」(확인 창, 기본 「취소」): 「이 키를 쓰는 Bot의 호출이 바로 거부됩니다.」
- UI 자동화 앱은 추가로 「레지스트리 쓰기」 권한을 고를 수 있다 (UI 셀렉터 등록 담당자용).

## UI 자동화 앱 고유 화면 (UIA)

> UI 자동화 확장이 기여하는 콘솔 화면이다 (`console.pages`, [ADR-0018](../decisions/0018-extensions.md)). 화면에서 읽어 온 업무 값은 보고에 없으므로(C8) 여기에도 보이지 않는다. 「셀렉터 시험」(BUI-08) 보고는 「시험」으로 따로 표시하고 승격 통계에 넣지 않는다. 코드는 `extensions/ui_automation/console/`. 외부 확장(외부 앱)은 이 콘솔을 쓰지 않고 자기 콘솔 링크만 CON-07에 보인다.

### UIA-01 개요


| 섹션 | 내용 |
| --- | --- |
| 저장소 표시 | > 미정: 애초 계획은 「지식 그래프 (Neo4j)」/「YAML 레지스트리」 구분이었는데 구현은 SQLite 한 파일이다 — 이 줄이 무엇을 보일지는 ADR 뒤에 정한다 ([09-gaps](../09-gaps.md) §2-3) |
| 「관리 중인 셀렉터」 | 화면 수, 요소 수, 로케이터 전체, 「검증 전」 수, 「대체됨」 수. 안내: 「검증 전 로케이터는 연속 3회 정상 동작하면 자동으로 사용 중으로 올라갑니다」 |
| 「LLM」 | 공급자, 계획 모델, 치유 모델, 치유 최대 횟수 |
| 「최근 UI 세션」 | 진행 중, 오늘 누적, 전환 수 |
| 「배포 전 확인」 | 「정상」/「경고」 배지 항목: 허용 주소 목록, 인증 설정 |

### UIA-02 셀렉터

화면을 골라 그 화면의 로케이터 전부를 본다 (대체된 것 포함).

- 「화면」 고르기: 「<id> — <이름>」. 빈 상태: 「등록된 화면이 없습니다. Bot UI 「도구」 → 「UI 셀렉터 등록」(BUI-06)으로 등록하세요.」 / 「이 화면에 등록된 로케이터가 없습니다. BUI-06에서 요소를 더하세요.」
- 경고 띠 (C8 강등 규칙): 「최근 10회 실패율이 50%를 넘은 사용 중 로케이터 N개 — 화면이 바뀌었을 수 있습니다」 + 해당 요소로 이동
- 「좁히기」(접힘): 상태(사용 중/검증 전/대체됨), 시맨틱 키, 셀렉터 검색(셀렉터·접근성 이름 일부). 켜져 있으면 「전체 N건 중 **M건** — 좁히기가 켜져 있습니다.」 화면을 바꾸면 좁히기를 초기화.
- 표 열: 시맨틱 키 / 순위(「0」 = 자가 치유로 추가됨) / 전략 / 셀렉터 / 접근성 이름 / 상태 / 성공 / 실패 / 성공률(막대) / 연속 성공 / 대체한 로케이터. 통계는 지금 구현(SQLite)이 `LocatorStats`로 들고 있다.
- 「대체 관계 N건」(접힘): 무엇이 무엇을 밀어냈는지.
- 내용이 있을 때만 보이는 섹션: 「전략별 성공·실패」 차트, 「선행 조건·화면 이동」 표(시맨틱 키 / 역할 / 설명 / 업무 개념 / 선행 입력 / 이동하는 화면 / 가능한 동작, 빈 열은 접고 이름만 표시), 「화면 간 경로 탐색」(출발·도착 → `a → b`, 없으면 「두 화면을 잇는 경로가 없습니다 — 등록의 화면 이동을 확인하세요.」).

### UIA-03 모니터링

UI 세션(= UI 태스크 한 번) 기록. 출처는 Worker가 보낸 보고.

| 섹션 | 내용 |
| --- | --- |
| 요약 | 전체 / 성공 / 전환 / 실패 / 진행 중 (상태 배지, 시험 보고는 따로 「시험」). 설명: 「**전환** = 자가 치유가 한도를 넘어 현장 PC(Bot UI)의 확인으로 넘어간 것 (오류가 아닙니다)」. 치유 수 |
| 「폴백 깊이 분포」 | 차트 + 「1순위 로케이터로 바로 성공한 비율 X%」. 없으면 「아직 성공한 실행 기록이 없습니다.」 |
| 「UI 세션 이력」 | 세션 id / 상태 / 화면 / 실행 id(business_key, 누르면 Center 콘솔 CON-01, 새 탭) / Bot / Bot UI / 요청 쪽(Bot·Studio·셀렉터 등록) / 수행 모드 / 진행(x/y) / 치유 / 시작 / 오류 |
| 상세 | 「자가 치유 내역」, 「전환됨」 경고와 시도한 로케이터·실패 사유 표, 「감사 로그」(접힌 JSON) |

전환은 Bot UI가 현장에서 확인으로 처리하므로, 이 페이지는 **보기 전용**이다 (프로토타입의 「BPM이 받아감」 단추는 없앤다).
