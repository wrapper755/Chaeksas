# Tool UI 화면 설계

**Tool UI는 확장이 기여한 도구를 띄우는 데스크톱 프로그램**이다 ([ADR-0077](../decisions/0077-tool-ui.md)). 첫 도구는 UI 자동화 확장의 **UI 셀렉터 등록**(TOL-03~05)이다. Bot UI 설치에 함께 들어가므로 Bot UI가 있는 PC(현장 PC·설계자 PC)에 있다.

> 상태: **돈다** (`apps/tool_ui` — 창 `window.py`, 설정 `settings_dialog.py`, 판단은 Qt를 모르는 `host.py`). 묶은 앱에서는 Bot UI 실행 파일이 `--tool-ui`로 Tool UI가 되고(`packaging/botui_main.py`), 소스 실행은 `uv run chk-tool-ui`다. 한 세션에 하나는 `QLocalServer`가 지킨다.

| 기능 | 화면 |
| --- | --- |
| 도구를 열고 탭으로 늘어놓기 | TOL-01 |
| 도구 설정 (확장이 선언한 `scope: tool_ui` 칸) | TOL-02 |
| UI 셀렉터 등록 (UI 자동화 확장) | TOL-03 ~ TOL-05 |

- **Bot UI와 나눈 일:** Bot UI는 Bot을 받아 돌리고 Worker 프로세스를 띄워 감시한다. Tool UI는 **도구의 창**만 가진다 — 트레이가 없고 항상 떠 있지 않으며 **Center에 등록하지 않고 Center를 부르지 않는다.**
- **로컬 런타임은 빌려 쓴다.** Tool UI는 Worker를 띄우지 않는다 — 같은 PC의 Bot UI가 띄운 것을 Studio와 같은 길(런타임 폴더의 `runtime.json`·토큰 파일)로 찾는다. 그래서 Worker를 쓰는 도구는 **Bot UI가 떠 있어야** 열린다.
- **Bot 실행과의 차례는 Worker가 가른다** (세션은 한 번에 하나, [ADR-0014](../decisions/0014-one-bot-per-pc.md) §4). 도구가 세션을 쥐고 있으면 Bot은 대기열에서 기다리고, Bot이 Worker를 예약해 두었으면 도구가 「Bot 실행 중 — 끝나면 쓸 수 있습니다」라고 말한다.
- **확장:** Tool UI는 특정 확장을 모른다. 설치된 확장 정의(C13)의 `tool_ui.tools`로 도구를, `configuration`의 `scope: tool_ui` 칸으로 설정을 짓는다. **확장을 켜고 끄는 자리는 Bot UI(BUI-11) 하나**다 — Tool UI는 그 목록을 읽기만 하고, 끈 확장의 도구는 보이지 않는다.
- 공통 원칙·상태 표기는 [README.md](README.md) §2·§3. 스레딩 규칙은 Bot UI와 같다 (화면은 보여 주기만, Qt 슬롯에서 동기 I/O 금지, 위젯은 GUI 스레드에서만).

## TOL-01 Tool UI 창

제목 「Chaeksas Tool UI」, 1100×760. **한 로그인 세션에 하나만** 뜬다 — 다시 실행하면 떠 있는 창을 앞으로 부르고, 열어 달라는 도구(`--open <확장>:<도구>`)가 있으면 그 탭을 연다.

```
+----------------------------------------------------------+
| [M] menu: File | Tools                                   |
+----------------------------------------------------------+
| [K] tabs: (one per open tool)                    [x]     |
|                                                          |
|                 [W] tool content                         |
|                                                          |
+----------------------------------------------------------+
| [S] status bar                                           |
+----------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [M] 메뉴 | 「파일」 → 「설정...」(TOL-02), 구분선, 「닫기」(Ctrl+Q) · 「도구」 → 확장이 기여한 도구 목록(확장 이름순, 기여의 `label`) |
| [K] 탭 | 연 도구마다 탭 하나, 탭마다 닫기 단추. 같은 도구는 두 번 열지 않고 그 탭으로 간다 |
| [W] 빈 상태 | 연 도구가 없으면 「「도구」 메뉴에서 열 도구를 고르세요」와 도구마다 단추 하나. 도구가 하나도 없으면 「이 PC의 확장이 더한 도구가 없습니다」 |
| [S] 상태 줄 | 도구가 쓰는 런타임마다 「<런타임 이름> 127.0.0.1:<포트> · 실행 중」 / 「<런타임 이름> 꺼짐 — Bot UI 「도구」에서 열면 Bot UI가 띄웁니다」 (5초마다 `health`를 묻는다). 런타임 이름은 확장이 준 `label`이다 |

들어오는 길은 둘이다.

| 길 | 하는 일 |
| --- | --- |
| 시작 메뉴 「Chaeksas Tool UI」 | 그냥 뜬다. 런타임이 필요한 도구는 런타임이 떠 있을 때만 연다 |
| Bot UI 「도구」 ▸ 도구 이름 (BUI-01 7, BUI-02 [M]) | Bot UI가 `needs_runtime`을 **먼저 띄운 뒤** Tool UI를 `--open`으로 띄운다. Tool UI는 Bot UI의 자식이 아니다 — Bot UI를 다시 띄워도 창은 남는다 |

규칙:
- **런타임이 없으면 도구를 열지 않는다** (「없는데 된 척」하지 않는다). 그 자리에 까닭과 길을 쓴다 (U3): 「<런타임 이름>가 답하지 않습니다 (127.0.0.1:<포트>) — Bot UI를 켜고 Bot UI 「도구」에서 이 도구를 열면 Bot UI가 <런타임 이름>를 띄웁니다」. 「떠 있나」는 그 런타임의 `health`로만 본다 — Bot UI가 꺼진 것과 런타임만 꺼진 것을 가르지 않는다(가를 길이 Bot UI를 부르는 것뿐이고, 고치는 길이 같다).
- 도구를 연 뒤 Worker가 다시 뜨면 도구는 그대로 있다 — 토큰은 부를 때마다 다시 읽는다. 쥐고 있던 세션은 사라지므로 도구가 그렇게 말한다.
- 탭을 닫으면 도구의 `closed()`를 부른다 (쥔 UI 세션을 놓는다). 창을 닫으면 모든 탭을 그렇게 닫고 끝난다 — 트레이에 남지 않는다.
- 도구를 만들다 실패하면 **그 탭만** 사유를 보이고 창은 이어 그린다.
- 끈 확장 목록(Bot UI 설정)은 **뜰 때 읽는다** — 떠 있는 동안 BUI-11에서 끈 확장의 탭은 닫지 않고, 다음에 뜰 때 사라진다.

## TOL-02 Tool UI 설정

「파일」 → 「설정...」. 확장이 선언한 `scope: tool_ui` 칸만 있다 — **확장마다 탭 하나**이고 탭 이름은 확장 이름이다. 쓰는 곳이 없는 칸은 두지 않는다 ([ADR-0073](../decisions/0073-studio-settings-only-what-is-used.md)과 같은 결).

- 지금 기본 제공 확장(UI 자동화)은 Tool UI 칸을 선언하지 않는다 — 창은 「이 PC의 확장이 Tool UI 설정을 선언하지 않았습니다」만 보인다. 확장이 `scope: tool_ui` 칸을 선언하면 확장마다 탭 하나가 생긴다.
- 단추: 「저장」/「취소」 — 탭 밖에 있고 「저장」 전에는 아무것도 바뀌지 않는다.
- **비밀 칸은 설정 파일에 들어가지 않는다** — OS 비밀 저장소(`chaeksas-tool-ui`)로 간다. 저장소가 없으면 저장이 **분명히 실패**하고 창을 닫지 않는다. 읽기는 환경변수가 먼저다(`CHK_TOOL_UI__EXT__<확장>__<칸>`, 개발·CI).
- 칸이 하나도 없으면 「이 PC의 확장이 Tool UI 설정을 선언하지 않았습니다」.

> **「등록 담당자 키」 칸이 없다** — 서비스 앱 키가 없어졌다 ([ADR-0102](../decisions/0102-calling-outside-is-pull.md)). 셀렉터 등록도 Center에 **등록 작업**으로 올라가고(C15 §올리기), Tool UI는 이 PC Bot UI가 청해 둔 **호출 토큰**(C15)을 **읽기만** 한다(Bot UI 데이터 폴더를 읽기만 하는 것과 같은 결 — Tool UI는 Center에 들어오지 않는다. `credentials.ToolSecrets`가 예약 비밀 `call_token`을 Bot UI 비밀 저장소에서 읽는다 — 이름 규칙은 Bot UI와 같고 시험이 대조한다). 환경변수 `CHK_TOOL_UI__EXT__<확장>__CALL_TOKEN`(자동화·CI)이 먼저다. Center는 **CON-03에서 「셀렉터 등록」을 켠 PC**에서 온 등록 작업만 받는다. 다른 칸이 없어 「UI 자동화」 탭도 없다.
>
> - 등록이 허락되지 않았으면 TOL-03이 안내 줄 하나로 말한다: 「이 PC는 셀렉터 등록이 허락되지 않았습니다 — 관리자에게 Center 콘솔 「Bot UI 현황」에서 이 PC(<Bot UI 이름>)의 「셀렉터 등록」을 켜 달라고 하세요」. 등록·삭제 단추는 꺼지고, **시험(TOL-05)은 그대로 된다**(시험은 등록 권한이 필요 없다 — 지금과 같다).

## TOL-03 UI 셀렉터 등록 (구 BUI-06)

> UI 자동화 확장(내장)이 기여하는 **도구**다 (`tool_ui.tools`, [ADR-0018](../decisions/0018-extensions.md)·[ADR-0077](../decisions/0077-tool-ui.md)). 화면 코드는 `extensions/ui_automation/client/`에 있다.
>
> 상태: **TOL-03~05가 돈다** — 담기·직접 고르기·표시·검증·등록·불러오기·등록 취소·시험. 창 하나에 「등록」·「시험」 탭 둘이다. Worker는 **Bot UI가 띄운 것을 빌려 쓰고**(`needs_runtime` — Tool UI는 띄우지 않는다, TOL-01), 어디 있는지는 **호스트가 설정으로 알려 준다** (C13 예약 키 `runtime.worker.*`·`center.url`, 호출 토큰은 예약 비밀 `call_token`). 서버에 닿지 못하면 **등록을 큐에 쌓고**(Tool UI 데이터 폴더의 확장 자리, C13 `storage.dir`) 창을 열 때·등록·삭제 뒤에 다시 올린다. 「표시」는 **CSS 후보가 있을 때만** 된다 (없으면 그렇게 말한다).
>
> **데스크톱 창에서 담기도 돈다** — 창 고르기·붙기·UIA 분석·검증·등록. 데스크톱도 「직접 고르기」·「표시」가 된다 — **고를 요소 위에 마우스를 올리고 Ctrl**을 누르면 담긴다(입력을 가로채지 않는다), 표시는 Tool UI가 그 자리에 **잠깐 빨간 테두리**를 띄운다 ([ADR-0072](../decisions/0072-desktop-pick-without-hooks.md)).

Tool UI의 도구. Worker의 UI 세션을 쓰므로 **Bot 실행과 겹치지 않는다**: Bot 실행 중에는 창은 열리지만 브라우저 동작 단추가 꺼지고 안내 줄에 「Bot 실행 중 — 끝나면 쓸 수 있습니다」. 등록 중에 Bot 차례가 오면 Bot은 기다리고, 창을 닫으면 바로 실행된다 ([ADR-0014](../decisions/0014-one-bot-per-pc.md) §4). 새 화면의 요소를 담아 검증하고 UI 자동화 앱에 등록한다 (계약 C9). 브라우저 조작은 Worker 프로세스 API(C10)를 통해 한다. 등록은 Center에 등록 작업으로 올리고 UI 자동화 앱(일꾼)이 가져가 쓴다 (C15 — 이 PC의 「셀렉터 등록」이 켜져 있어야 한다, TOL-02). 기존 화면에 요소를 더하거나 지울 수도 있다.

```
+------------------------------------------------------------------+
| [P] page row: page-id picker [Load]  [state]  [Del elem][Del page]|
+------------------------------------------------------------------+
| [C] collector group  mode: (browser | desktop window)           |
|     row 1: start url  [Open] [Pick] [Analyze] [Close browser]    |
|     (desktop) window [Refresh] [Attach] [Pick] [Analyze] [Release]|
|     row 2: scope  max [n]  [x] include read targets              |
+------------------------------------------------------------------+
| [H] hint line (progress, results, errors)                        |
+------------------------------------------------------------------+
| [E] elements table                    [Delete sel] [Delete all]  |
|------------------------------------------------------------------|
| [V] checks table                              [Try...] [Validate] |
+------------------------------------------------------------------+
| [Reset]                                              [Register]  |
+------------------------------------------------------------------+
```

### 영역

| 영역 | 내용 |
| --- | --- |
| [P] 화면 줄 | 「화면 ID」 편집 콤보(목록에서 고르거나 새로 적음, 처음엔 빈 칸) + 「불러오기」 + 등록 상태 글 + 「요소 등록 취소」 + 「화면 등록 취소」 |
| [P] 등록 상태 | 「**기존 화면** — 요소 N개가 등록돼 있습니다 (여기에 더합니다)」 / 「**새 화면** — 등록하면 만들어집니다」 / 「서버에 닿지 못해 **기존 여부를 알 수 없습니다**」 (U8) |
| [C] 「화면에서 담기」 | 「방식」이 「브라우저」일 때 1행: 「시작 주소」 + 「브라우저 열기」(연 뒤에는 「주소로 이동」) + 「직접 고르기」(토글, 켜지면 「고르는 중… (누르면 종료)」) + 「분석」 + 「브라우저 닫기」. 2행: 「분석 범위」(CSS, 비우면 전체) + 「최대」(10~2000, 50 단위) + 「읽기 대상 포함」 |
| [C] 「데스크톱 창에서 담기」 | 줄 맨 앞 「방식」 콤보(「브라우저」 / 「데스크톱 창」)로 고른다. 데스크톱이면 1행이 「창」 콤보(지금 떠 있는 창 — `제목 — 프로세스`) + 「새로 고침」 + 「창에 붙기」 + 「직접 고르기」(토글) + 「분석」 + 「놓기」로 바뀐다. 2행의 「분석 범위(CSS)」는 꺼진다(창 하나가 범위다). 「직접 고르기」를 켜면 「고르는 중… 담을 요소 위에 마우스를 올리고 Ctrl을 누르세요 (Esc로 끝)」. 요소 표의 「태그」는 컨트롤 종류(UIA ControlType), 「id」는 AutomationId, 「CSS 후보」는 클래스 이름이다 |
| [H] 안내 줄 | 진행·결과·오류의 유일한 통로. 굵게 표시 가능 |
| [E] 요소 표 | 열: 「시맨틱 키」(체크 + 편집) / 「종류」(조작·목록·표·글자) / 「가능한 동작」 / 「태그」 / 「역할」 / 「접근성 이름」 / 「id」 / 「CSS 후보」. 체크된 키가 겹치면 빨간 바탕. 줄 툴팁: 등록된 사다리, 선행 입력, 업무 개념, 이동 |
| [V] 검증 표 | 사다리 한 칸에 한 줄. 열: 「시맨틱 키」 / 「순위」 / 「전략」 / 「셀렉터」 / 「결과」(통과·실패) / 「사유」. 「검증」 옆 「시험...」은 「시험」 탭으로 가 화면 ID와 **고른 줄**(없으면 전부)을 스텝 표에 채운다 (TOL-05) |
| 아래 | 왼쪽 「초기화」(표·검증·화면 ID 비움, 브라우저는 유지), 오른쪽 「등록」 |

### 단추 켜짐 규칙

| 단추 | 켜지는 조건 |
| --- | --- |
| 「직접 고르기」, 「분석」, 「브라우저 닫기」 | 브라우저가 열려 있음 |
| 「검증」 | 분석·고르기·불러오기로 표에 줄이 있음 |
| 「등록」 | 「검증」을 마침 (그 뒤 표를 바꾸면 다시 꺼짐) |
| 「시험...」 | 등록된 화면이다 (계획은 레지스트리에서 온다 — 아니면 「먼저 등록하세요」 툴팁) |
| 「선택 삭제」/「전체 삭제」 | 표에 줄이 있음 |
| 「불러오기」 | 등록 상태가 「기존 화면」 |
| 「화면 등록 취소」 | 화면 ID가 있고 상태가 「새 화면」이 아님 |
| 「요소 등록 취소」 | 위 조건 + 표에서 줄 하나를 고름 |

서버 조회는 일을 시작할 때만 한다: 화면 ID 입력이 끝났을 때(포커스 이동·Enter), 분석이 끝났을 때, 검증을 시작할 때, 등록·삭제 뒤. 고를 때마다 묻지 않는다.

### 흐름

1. **브라우저 열기** — 「브라우저를 띄우는 중…」 → 「열렸습니다 — <주소>. 등록할 화면까지 브라우저에서 직접 이동한 뒤 **분석**을 누르세요. 새 탭이 열려도 따라갑니다.」 주소는 시작점일 뿐이다.
1-1. **창에 붙기** (데스크톱) — 「창」 콤보에서 등록할 화면을 띄운 창을 고르고 「창에 붙기」. 「붙었습니다 — <창 제목>. 등록할 화면을 띄워 둔 채 「분석」을 누르세요.」 같은 제목·프로세스의 창이 여럿이면 「같은 조건의 창이 여럿입니다 — 하나만 남기세요」, 그 사이 창이 닫혔으면 「그 창이 없습니다 — 「새로 고침」으로 다시 고르세요」. **창을 닫지 않는다** — 사용자의 업무 앱이다 (「놓기」는 붙은 것을 놓기만 한다). 화면 ID가 비어 있으면 채우지 않고 「화면 ID를 적으세요」라고 말한다(창 제목에는 문서 이름이 섞인다).
2. **분석** — 지금 열린 화면에서 보이는 요소를 표로 가져온다 (표를 바꾼다).
   - 데스크톱: 붙은 창의 UIA 트리에서 조작 요소(입력·단추·고르기·체크)를, 「읽기 대상 포함」이면 글·표까지 가져온다. 사다리는 C8 데스크톱 순서다 — `automation_id` → `class_name`(종류로 좁힘) → `control_name`(종류로 좁힘, **화면 언어에 따라 달라진다**).
   - 범위 선택자가 아무것도 찾지 못하면 「범위 선택자가 아무것도 찾지 못했습니다 — <범위>」 (전체로 몰래 넓히지 않는다).
   - 잘리면 「…중 K개만 가져왔습니다. **범위를 좁히거나 최대치를 올리세요**」 + 「최대」 칸 노란 표시.
   - 화면 ID가 비어 있으면 주소에서 채운다 (사용자가 고친 뒤에는 건드리지 않음).
3. **직접 고르기** — 브라우저에서 누른 요소가 표에 체크된 채 추가된다. 조작 대상은 빨강, 읽기 대상은 주황 테두리. Shift+클릭은 둘러싼 표. 고르는 동안 링크 이동은 막는다. Esc로 끝. **데스크톱 창**은 누르지 않고 **요소 위에 마우스를 올린 채 Ctrl** — 표 안의 칸이면 그 표가 담기고, 붙은 창 밖이면 담기지 않는다. 「골랐습니다 — <이름> → `<키>`」 / 「이미 표에 있습니다 — <이름>」.
4. **시맨틱 키** — 자동 제안(test_id → id → name → 영문 접근성 이름 → 역할 순, 한글 이름은 음역하지 않음, 겹치면 번호). 쓸 줄만 체크하고 필요한 키만 의미 있게 고친다. 키를 고치면 자동 체크, 지우면 체크 해제.
5. **표시** — 표에서 줄을 고르면 브라우저에서 그 요소를 파란 테두리로 보인다. 데스크톱 창은 Tool UI가 그 요소 위에 **1.5초 동안 빨간 테두리 창**을 띄운다(입력은 통과한다). 「화면에 표시했습니다」 / 「화면에서 찾지 못했습니다」 / 「**N개가 잡힙니다** — 모호해서 실패합니다」.
6. **요소 계획 정보** — 줄을 더블클릭하면 TOL-04.
7. **검증** — 먼저 등록 초안을 만든다. 초안 거부: 키 겹침, 고른 요소 없음, 서로 다른 화면의 요소가 섞임. 그다음 지금 열린 화면에서 사다리 전체를 시험한다. 요약:
   - 「잡히지 않는 요소가 있습니다 — … 자가 치유로 넘어갑니다」
   - 「모두 잡힙니다 — 다만 **X**는 쓸 수 있는 로케이터가 하나뿐입니다」
   - 「모두 잡히고 대체 로케이터도 살아 있습니다. 등록해도 좋습니다.」
   - 덧붙임: 「선행 입력 N건 · 업무 개념 M건을 함께 올립니다.」, 선행 입력을 찾을 수 없으면 **경고**(막지 않음).
8. **등록** — 「서버에 등록하는 중…」. 데스크톱 화면은 `platform: desktop`과 **창 조건**(붙은 창의 제목을 정확히 맞추는 정규식 + 프로세스 이름)으로 올라간다 (C9).
   - 성공: 「등록했습니다 — <화면> (새 로케이터 N개, 그대로 둔 것 K개)」 + 「새 로케이터는 **검증 전**으로 들어가 3회 연속 성공하면 사용 중으로 올라갑니다.」 바뀐 것이 없으면 「이미 등록된 것과 같습니다」.
   - 아직 없는 화면을 이동 대상으로 가리키면 경고: 「**아직 등록되지 않은 화면을 가리켰습니다** — 오타라면 지금 보이는 이 이름이 틀린 것입니다.」
   - 서버가 거부(4xx): 「서버가 거부했습니다 (<코드>) — <내용>. 보낸 내용을 고쳐야 합니다. 다시 눌러도 같은 답이 옵니다.」 큐에 쌓지 않는다.
   - 서버에 닿지 못함: 「서버에 닿지 못해 **등록을 큐에 쌓았습니다.** 서버가 돌아오면 저절로 올라갑니다.」
9. **불러오기** — 표에 줄이 있으면 먼저 「표에 N개 행이 있습니다. <화면>에 등록된 것으로 **바꿉니다.** 담아 둔 것은 사라집니다.」 불러온 줄은 체크되어 있고 서버의 사다리를 그대로 가진다 (다시 등록해도 정의가 바뀌지 않음).
10. **등록 취소 (삭제)** — 경고 창, 기본 단추 「취소」 (U9).
    - 화면: 「<화면>을 레지스트리에서 통째로 지웁니다. 쌓아 온 통계·승격·치유 이력이 함께 사라지고 되돌릴 수 없습니다. 화면이 바뀐 것이라면 지우지 말고 다시 등록하세요.」
    - 요소: 「<화면>의 `<키>`를 지웁니다. 그 요소의 사다리와 통계가 사라집니다.」
    - 화면 ID는 **입력한 값만** 쓴다 (주소에서 추정하지 않음).
    - 서버가 409(다른 화면이 가리킴): 두 번째 확인 「다른 화면이 가리키고 있습니다 — <내용>. 지우면 그 경로가 끊깁니다. 그래도 지울까요?」 → 예면 강제 삭제.
    - 결과: 「지웠습니다 — <범위> (요소 N개, 로케이터 M개)」 + 끊긴 경로 + 「큐에 남아 있던 등록과 계획 캐시도 함께 버렸습니다.」 삭제는 큐에 쌓지 않는다.

## TOL-04 요소 계획 정보 (구 BUI-07)

제목 「<키> — 계획에 줄 정보」.

| 필드 | 설명 |
| --- | --- |
| 「선행 입력」 | 이 요소를 조작하기 전에 채워야 하는 요소의 시맨틱 키 (쉼표 구분) |
| 「업무 개념」 | 이 요소를 가리키는 업무 용어 (쉼표 구분). 자연어 목표 계획에 쓰인다 |

설명 한 줄 + 「확인」/「취소」. 채우면 그 줄이 자동 체크된다. 화면 이동(triggers)은 여기서 묻지 않는다.

## TOL-05 셀렉터 시험 (구 BUI-08)

등록된 화면에 대해 계획을 받아 실행해 본다 (Worker 프로세스 경유). Bot 실행과는 별개의 시험이다. 들어가는 곳: Tool UI의 「UI 셀렉터 등록」 탭 안의 「시험」 탭. 결과 보고는 「시험」으로 표시되고 승격 통계에 들어가지 않는다 (C8 `origin: test`).

> 상태: **결정 수행으로 돈다** — 「가져오기」가 등록된 요소로 스텝 표를 채우고 사람이 동작·값을 고친다. 자연어 **목표로 계획**(자율 수행)은 Studio UI 태스크(STU-13)에서 쓴다 — 셀렉터 시험은 등록된 요소의 스텝으로만 하므로 칸을 꺼 두었다. **「결과를 서버에 보고」가 꺼져 있으면 아예 보내지 않는다** (C10 `report`). **「등록」 탭에 열린 화면이 있으면 그것을 이어 쓴다** (C10 `…/plan` — 세션은 한 번에 하나다, ADR-0014). 그때는 시험이 **그 화면을 닫지 않는다** — 「끝나도 브라우저 열어 두기」·「브라우저 닫기」는 시험이 연 화면에만 듣고, 보고는 등록 탭에서 화면을 닫을 때 간다(그렇게 말한다). 등록 탭에 열린 것이 없으면 시험이 제 세션을 연다. **TOL-03 「시험...」**(검증 줄)으로 들어오면 화면 ID와 **고른 줄**(없으면 전부)이 스텝 표에 채워진다 — 등록된 화면이어야 한다(계획은 레지스트리에서 온다).

| 요소 | 내용 |
| --- | --- |
| 1행 | 「화면」(목록에서 고름, 고르면 바로 조회) + 「목표」(예: 공급자 등록번호를 넣고 상신) + 「가져오기」 |
| 2행 | 「시작 주소」(비우면 계획의 값) |
| 3행 | 「자가 치유 사용」(켬), 「결과를 서버에 보고」(끔), 「끝나도 브라우저 열어 두기」(켬) · 오른쪽 「브라우저 닫기」, 「실행」 |
| 출력 | 읽기 전용 글 상자 |

출력 내용:
- 「[계획 출처: 서버 | 로컬 캐시 (오프라인)] <화면> · N스텝」 + 번호 붙은 스텝.
- 결과: 「성공 / 사람에게 전환 / 실패 — x/y 스텝」, 요소별 시도(「O/X 로케이터 (사유)」), 「자가 치유:」, 「읽어온 값:」(표는 줄 단위), 「사람에게 전환:」, 「서버에 보낼 보고: N bytes」.
- 끝: 「브라우저를 열어 두었습니다」 / 「보고 전송됨」 / 「보고를 큐에 쌓았습니다 (서버에 닿지 못함)」.
- 셀렉터 등록과 같은 브라우저 세션을 쓴다.
