# 06. 화면 설계서

> 상태: **검토 완료 (2026-10-01, 독립 검토 22건 반영).** 프로토타입에서 실제로 쓰며 다듬은 화면을 바탕으로, 새 용어·새 구조(서비스 앱, UI 태스크)에 맞게 다시 설계했다. "신규" 표시는 프로토타입에 없던 화면이다.
> 화면이 바뀌면 **코드보다 이 문서를 먼저** 고친다 ([ADR-0002](../decisions/0002-docs-first-and-adr.md)).

## 0. 구현 기술과 모양

- 웹 화면(Center 콘솔, 서비스 앱 관리 콘솔)은 **Next.js**, 데스크톱(Studio, Bot UI)은 **PySide6**. 둘 다 같은 디자인 토큰(`design/tokens.json`)과 [스타일 가이드](../07-style-guide.md)를 따른다 ([ADR-0017](../decisions/0017-web-nextjs-design-system.md)).
- 이 폴더의 화면 설계서는 **무엇을 어디에 보이는가**를 정하고, **어떻게 보이는가**(색·글자·구성요소)는 스타일 가이드가 정한다.

### 표기 규칙

- **화면 ID:** `<앱>-<두 자리 번호>`. 번호는 재사용하지 않는다. 화면을 없애면 "폐기"로 남긴다.
- **배치도:** 영문 글자 영역 표시(`[A]`, `[B]`…)로 그리고, 영역 내용은 바로 아래 표에 쓴다. 한글은 글꼴마다 폭이 달라 상자 안에 넣으면 줄이 어긋나기 때문이다.
- **라벨:** 화면에 보이는 문구는 `「」`로 감싼다. 예: 「실행...」.
- **단축키:** Windows 기준으로 쓴다.

## 2. 공통 UX 원칙 (프로토타입에서 배운 것)

| # | 원칙 | 왜 (프로토타입에서 일어난 일) |
| --- | --- | --- |
| U1 | 사용자에게 보이는 단위는 **BPM 프로세스**다. 파일을 여는 메뉴·버튼을 두지 않는다 | `.bpmn` 파일을 직접 열면 어느 BPM 프로세스에 속하는지 잃어버렸다 |
| U2 | 내부 id는 숨기고 이름과 한국어 종류를 먼저 보인다. id는 툴팁에 | id가 앞에 나오면 사용자가 무엇인지 알아보지 못했다 |
| U3 | 고를 수 없는 선택지는 **그 자리에 이유를 쓴다.** 툴팁에 숨기지 않는다 | 회색 버튼 세 개의 이유가 툴팁에만 있어 아무도 몰랐다 |
| U4 | 문맥 메뉴는 **지금 고른 항목의 동작만** 보인다 | 회색 항목이 섞인 긴 메뉴가 어지러웠다 |
| U5 | 실행 버튼은 실행 중에 **중지 버튼**이 된다 (모든 실행 방식에서) | 7분 동안 같은 셀을 읽는 태스크를 앱을 죽여서만 멈출 수 있었다 |
| U6 | 판정은 세 갈래: 「통과」 / 「실패」 / 「비교 안 함」 | 기대 결과가 비어 있는데 「통과」로 보였다 |
| U7 | **색만으로 뜻을 전하지 않는다.** 색 옆에 항상 글자 | 트레이 점 색만으로는 상태를 구분하지 못했다 |
| U8 | 서버에 닿지 못하면 **"모른다"고 쓴다.** 추측해서 "새 화면" 등으로 말하지 않는다 | 오프라인일 때 등록된 화면을 새 화면이라고 안내했다 |
| U9 | 되돌릴 수 없는 동작은 경고 창 + **기본 단추는 취소**. 서버가 409(다른 것이 참조 중)를 주면 두 번째 확인 후에만 강제한다 | 화면 삭제가 다른 화면의 경로를 말없이 끊었다 |
| U10 | 업무 값은 기본으로 **접어 둔다.** 목록에는 키만, 값은 펼쳐야 보인다 | 실행 기록·결재 목록에 개인정보가 그대로 보였다 |
| U11 | 저장 안 한 변경은 「저장」 / 「저장 안 함」 / 「취소」로 묻는다. 적용 안 한 속성 편집은 「적용」 / 「버리기」 / 「머무르기」 | 다른 요소를 누르는 순간 편집이 사라졌다 |
| U12 | 빈 상태 문구는 **다음에 할 일**을 말한다. 예: 「BPM 프로세스가 없습니다. 파일 → 새 BPM 프로세스...로 만드세요.」 | 빈 화면에서 무엇을 할지 몰랐다 |
| U13 | 실패는 **한 줄 요약 먼저**, 상세(스택 등)는 그 아래 | 스택 맨 끝에서 원인을 찾아야 했다 |
| U14 | 버튼은 **영향을 주는 영역의 오른쪽 위**에 둔다. 할 일이 없는 버튼은 비활성. 영역 제목·단계 번호·불필요한 「확인」 버튼을 두지 않는다 | 화면 등록 탭에서 버튼 위치가 흩어져 순서를 헷갈렸다 |
| U15 | 상주 앱은 창을 닫아도 계속 돈다. 그래도 **메뉴에 「종료」가 항상 있다** | OS가 트레이를 숨기면 끌 방법이 없었다 |
| U16 | 결재(업무)와 확인(실행 중 막힘)은 **창 제목부터 다르게** 보인다 | 둘 다 "HITL"이라 누가 답해야 하는지 헷갈렸다 |
| U17 | 진행 중 작업은 화면을 멈추지 않는다. 느린 일은 배경에서 하고, 결과는 상태 줄·알림으로 | 등록 중 창이 굳었다 |

## 3. 공통 상태 표기

같은 상태는 모든 앱에서 같은 글자·같은 색으로 보인다. 색 이름은 상태 토큰이다. **원본은 `design/tokens.json`의 `status_map`** 이고, 이 표와 다르면 토큰 파일이 맞다. 색값·구성요소·문구 규칙은 [스타일 가이드](../07-style-guide.md).

| 대상 | 상태 (화면 표기) | 색 토큰 |
| --- | --- | --- |
| 실행·노드 | 대기 / 실행 중 / 기다리는 중(서버) / 완료 / 실패 / 재생됨 / 취소됨 | neutral / active / waiting / done / failed / replayed / neutral |
| Bot (BPM 프로세스 실행) | 대기 / 대기열 N번째 / 실행 중 / 결재 대기 / 확인 대기 / 오류 / 실행 불가(사전 점검) | neutral / waiting / active / waiting / waiting / failed / failed |
| Bot UI | 연결됨 / 연결 끊김 / 등록 전 / 키 폐기됨 / 키 만료 / 비활성 | done / warning / neutral / failed / failed / neutral |
| Bot UI 실행 자리 | 비어 있음 / 실행 중 · 대기 N건 / 셀렉터 등록 중 | neutral / active / active |
| 실행 위치 | PC / 서버 | 글자로만 표시 (색 없음) |
| 서버 실행기 | 동작 / 일시 중지 / 정리 중 / 오류 / 오프라인 | done / neutral / active / failed / warning |
| 확장 | 켜짐 / 꺼짐 / 호환 안 됨 / 필요하지만 없음 | done / neutral / warning / failed |
| Worker 프로세스 | 실행 중 / 꺼 둠 / 예약됨 / 요청 처리 중 / 셀렉터 등록 중 / 다시 띄우는 중 / 멈춤 / (Studio에서 볼 때) Bot UI가 꺼져 있음 | done / neutral / active / active / active / warning / failed / warning |
| 수행 모드 | 자율 수행 / 결정 수행 | 글자로만 표시 (색 없음) |
| API 키 (Center·서비스 앱) | 사용 중 / 만료 / 폐기됨 | done / warning / neutral |
| 서비스 앱 키 참조 (Bot UI·Studio) | 정상 / 없음(등록 필요) / 거부됨 / 만료 / 폐기됨 / 확인 전 | done / failed / failed / warning / failed / neutral |
| 패키지 | 후보 / 승인됨 / 지원 종료 / 철회 / 로컬만 | waiting / done / warning / failed / neutral |
| 서명·준비·온라인·UI 세션·배치 결정 | `tokens.json` `status_map` 참고 | — |
| 결재 | 대기 / 답함 / 시간 초과 / 회수됨 (실행하는 쪽이 답을 거절하면 다시 「대기」 + 안내 띠) | waiting / done / warning / neutral |
| 작업 | 대기 / 전달됨 / 대기열 / 수락 / 거절 / 만료 / 취소됨 | neutral / active / waiting / done / failed / warning / neutral |
| 로케이터 | 사용 중(active) / 검증 전(unverified) / 대체됨(deprecated) | done / waiting / neutral |
| 서비스 앱 | 정상 / 저하 / 응답 없음 / 확인 전 | done / warning / failed / neutral |
| 사전 점검 | 정상 / 경고 / 실행 불가 | done / warning / failed |

캔버스 노드 표시(Studio): 실행 중 = active 외곽선, 완료 = done 외곽선, 실패 = failed 외곽선 + 옅은 채움, 재생됨 = replayed 점선.

## 4. 전체 흐름 (화면 순서)

새 업무 하나가 만들어져 운영되기까지 거치는 화면이다.

0. **준비 (서버)** — 서버에서 첫 Admin 키를 넣고(`chk-center admin-keys bootstrap`, [ADM](admin.md)), 운영자가 Center 콘솔에서 내장·사내 서비스 앱 주소를 등록한다([CON-07](center-console.md#con-07-리소스-신규)). 외부 확장은 Admin 서명과 함께 등록한다. 서버 Bot을 쓸 거면 서버 실행기용 Center API 키를 발급해 서버 실행기에 넣는다 (M7).
1. **준비 (PC)** — 운영자가 Bot UI용 Center API 키를 발급하고([CON-11](center-console.md#con-11-center-api-키-신규)), 설치 담당자가 Bot UI 설정에 넣는다([BUI-03](bot-ui.md#bui-03-설정등록)). 서비스 앱 관리자가 서비스 앱 키를 발급하고([SVC-02](service-app-console.md#svc-02-api-키)), Bot UI 「서비스 앱 키」에 참조 이름으로 넣는다([BUI-10](bot-ui.md#bui-10-서비스-앱-키)).
2. **UI 셀렉터 등록** (화면 조작이 필요할 때) — 등록 담당자가 UI 자동화 확장의 유틸리티로 화면 요소를 등록한다. [BUI-06](bot-ui.md#bui-06-ui-셀렉터-등록)
3. **BPM 프로세스 만들기** — 설계자가 Studio에서 새 BPM 프로세스를 만들고 실행 위치를 정한다 — 기본은 서버, 화면 조작·현장 확인이 필요하면 PC ([ADR-0016](../decisions/0016-server-first.md)). 사용할 서비스 앱마다 키 참조 이름을 정한다. [STU-05](studio.md#stu-05-새-bpm-프로세스), [STU-06](studio.md#stu-06-bpm-프로세스-정보)
4. **그리기** — BPMN을 그리고 태스크마다 속성을 채운다. UI 태스크는 등록된 화면·요소를 고르고, 서비스 앱 태스크는 리소스 탐색기의 작업을 고른다. [STU-01](studio.md#stu-01-메인-창), [STU-03](studio.md#stu-03-리소스-탐색기), [STU-13](studio.md#stu-13-ui-태스크-편집기-신규), [STU-14](studio.md#stu-14-서비스-앱-태스크-편집기-신규)
5. **시험** — 시험 케이스를 만들고 자율 수행으로 실행한다 (UI 태스크는 같은 PC의 Bot UI가 띄운 Worker 프로세스가 처리). AI 태스크는 학습되어 재생 명세가 생기고, 결정 수행(재생)으로 운영과 같은 방식을 미리 확인한다. [STU-07](studio.md#stu-07-시험-케이스), [STU-08](studio.md#stu-08-실행-대화상자), [STU-09](studio.md#stu-09-실행-표시와-결과)
6. **올리기** — 패키지로 Center에 올린다 (후보 상태). 패키지에는 키 값이 없고 참조 이름만 있다. [STU-01](studio.md#stu-01-메인-창) 파일 메뉴, [CON-02](center-console.md#con-02-bot-현황)
7. **승인·배포** — Admin이 승인에 서명하고, PC Bot은 Bot UI에, 서버 Bot은 서버 실행기에 배포 서명한다 (서버는 M7). [ADM](admin.md)
8. **적용** — PC: Bot UI가 하트비트로 배포를 받아 Bot을 설치하고 사전 점검(키 참조·확장 포함)을 한다 ([BUI-04](bot-ui.md#bui-04-bot-탭-실행대기열설치된-bot), [CON-03](center-console.md#con-03-bot-ui-현황)). 서버: 서버 실행기가 배포를 받는다 ([CON-12](center-console.md#con-12-서버-실행-신규-m7)).
9. **작업 지시** — 운영자가 콘솔에서 작업을 만들거나, 외부 시스템(연동용 키)·감시 모드·일정·메시지로 시작된다. [CON-05](center-console.md#con-05-작업-지시)
10. **실행** — PC: Bot UI가 Bot을 결정 수행으로 실행한다. 한 PC에서 실행 중인 Bot은 하나이고 나머지는 대기열에서 기다린다 ([ADR-0014](../decisions/0014-one-bot-per-pc.md), [BUI-01](bot-ui.md#bui-01-트레이), [BUI-09](bot-ui.md#bui-09-로컬-런타임-탭-worker-프로세스-등)). 서버: 서버 실행기가 여러 건을 동시에 실행한다 ([CON-12](center-console.md#con-12-서버-실행-신규-m7)).
11. **결재** — 결재자가 콘솔 결재함 또는 현장 PC 창에서 답한다. [CON-04](center-console.md#con-04-결재함), [CMN-01](#5-공용-창-cmn-01-결재--확인-창)
12. **확인** — 운영자가 실행 로그·Bot 현황을, 서비스 앱 관리자가 셀렉터 상태·사용 기록을 본다. [CON-01](center-console.md#con-01-실행-로그), [CON-02](center-console.md#con-02-bot-현황), [UIA-02](service-app-console.md#uia-02-셀렉터), [SVC-03](service-app-console.md#svc-03-사용-기록)

## 5. 공용 창 CMN-01: 결재 / 확인 창

Studio 시험 실행과 Bot UI의 Bot 실행에서 같은 창을 쓴다 (`packages/qt`). 항상 위에 뜬다.

```
+--------------------------------------------------+
| [T] title                                        |
+--------------------------------------------------+
| [D] description                                  |
| [R] review data (resizable, read-only)           |
| [F] form fields                                  |
| [E] error line                                   |
+--------------------------------------------------+
|                              [OK]   [Cancel]     |
+--------------------------------------------------+
```

| 영역 | 결재 (업무) | 확인 (실행 중 막힘) |
| --- | --- | --- |
| [T] 제목 | 폼 제목, 없으면 「결재 요청」 | 「실행 확인 요청 — <태스크 이름>」 |
| [D] 설명 | 폼 설명 | 에이전트·Worker의 질문 한 줄 + 오류 문구(있으면) |
| [R] 검토 자료 | 폼의 「표시 변수」만. 문자열은 글자로, 목록은 글머리표로 (JSON 따옴표·`\n` 그대로 보이지 않게) | UI 태스크 전환이면: 화면, 요소, 시도한 로케이터와 실패 사유 표 |
| [F] 입력 | 폼 필드: 참/거짓 → 체크, 숫자 → 숫자 상자, 선택지 → 콤보, 그 밖 → 한 줄 입력. 필수는 ` *` | 한 줄 「응답 입력」, 또는 선택 단추(「계속」/「중단」/「직접 처리했음」) |
| [E] 오류 | 검증 오류를 빨간 글자로. 창은 닫히지 않는다 | 같음 |
| 단추 | 폼이 있으면 「보내기」 / 「취소」(= 중단으로 답함). 폼이 없으면 「승인」 / 「반려」 + 「메모」 한 줄 (C6 `decision`) | 「계속」 / 「중단」 (+ 응답 입력) |

- 시간 초과: 창을 닫고 로그에 「결재 요청이 시간 초과로 취소되었습니다.」를 남긴다.
- 시험 케이스의 「결재 자동 응답」이 있으면 창을 띄우지 않는다.
- 결재가 Center로 올라간 경우(원격 결재) Bot UI는 창을 바로 띄우지 않고 트레이 알림 「결재가 Center 결재함으로 올라갔습니다 — 여기서 답하려면 누르세요」를 띄운다. 알림이나 BUI-04 「지금 실행」 줄의 「결재 창 열기」를 누르면 CMN-01이 열린다. 현장에서 먼저 답하면 Center 요청은 회수된다.

## 7. 열린 질문

- 콘솔 쓰기 권한: 로그인(OIDC) 전까지 관리자 토큰을 입력한 세션에서만 쓰기 버튼을 보인다 (제안). 결재자 신원은 그동안 「자칭」으로 표시한다.
- 서비스 앱 관리 콘솔의 로그인: 처음에는 앱별 관리자 토큰, 나중에 Center와 같은 OIDC로 묶는다 (제안).
- 데스크톱 화면 등록(Windows UIA)의 수집 화면은 S1 스파이크 뒤에 BUI-06에 추가한다.
