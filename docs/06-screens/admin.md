# Admin 화면 설계

Admin은 서명 키를 가지고 패키지 승인·배포·철회에 서명한다. 서명은 토큰이 새도 배포를 못 하게 하는 마지막 관문이라, 서버(콘솔)에서 하지 않고 관리자 PC에서 한다.

**서명하는 입구는 둘이고 서명하는 코드는 하나다** ([ADR-0089](../decisions/0089-admin-ui.md)) — 명령줄 `chk-admin`과 창 `chk-admin-ui`(Admin UI)가 있다. 둘 다 확인 문구·봉투·서명할 키 고르기를 Qt를 모르는 `admin/ops.py`에서 받는다. 개인키는 명령 한 번, 또는 단추 한 번 동안만 열리고 닫힌다. 창의 첫 판은 키(ADM-01), 외부 확장(ADM-04), Center 연결(ADM-05)이다. 승인·배포(ADM-02·03)는 아직 명령줄과 Center 콘솔(CON-06·CON-03·CON-05)이 한다.

## 명령 (첫 릴리스)

| 명령 (가안) | 하는 일 | 확인 문구 |
| --- | --- | --- |
| `chk-admin keys new` | 서명 키 생성 (암호문으로 보호, OS 사용자 폴더에 저장) | 키 id 출력 |
| `chk-admin keys register --signed-by <기존 키>` | 새 공개키를 **기존 Admin 키의 서명**으로 Center에 등록 (C2 `admin_key`) | 「<키 id>를 <기존 키 id>의 서명으로 추가합니다」 |
| (서버에서) `chk-center admin-keys bootstrap <public.pem>` | Admin 키가 하나도 없을 때만 첫 키를 넣는다. 서버 셸에서 실행 | |
| `chk-admin keys list` / `revoke <key_id>` | 목록 / 철회 (C2 `admin_key_revoke` 서명) | 목록의 상태는 「등록됨」·「등록 안 됨」·「철회됨」이고, **Center에 닿지 못하면 「알 수 없음」**이다(모르는 것을 「등록 안 됨」으로 말하지 않는다). 철회는 「이 키로 서명한 승인·배포가 모두 무효가 됩니다. 계속할까요?」. 마지막 키는 철회할 수 없다 |
| `chk-admin pending` | 승인 대기(후보) 패키지 목록: id, 버전, 종류, 올린 이, 사전 점검 요약, 필요한 리소스 누락 | |
| `chk-admin approve <id> <버전>` | 패키지 승인 서명 → Center에 올림 | 해시·사전 점검 요약을 보이고 「승인할까요?」 |
| `chk-admin deploy <id> <버전> --bot-ui <Bot UI> [--from --until]` | PC 배포 서명 → Center에 올림 | 대상 Bot UI·유효 기간 확인 |
| `chk-admin deploy <id> <버전> --server [<서버 실행기 id>] [--max-concurrency 5] [--from --until]` | 서버 배포 서명 (실행 위치가 「서버」인 BPM 프로세스만, M7). id를 비우면 **전체(`*`)** — PC에는 전체 대상이 없다(ADR-0046). `--max-concurrency`는 서버 배포에만, 적지 않으면 기본 | 대상(전체/그 실행기)·동시 실행 상한·유효 기간 확인. **돈다** |
| `chk-admin deployments [--bot-ui <이름>] [--bpm-process <id>]` | 활성 배포 목록 (배포 id, 대상, Bot, 버전, 유효 기간). CON-03 「배포」의 배포 id와 같다 | |
| `chk-admin revoke-deploy <배포 id>` | 배포 철회 서명 | |
| `chk-admin revoke-package <id> <버전>` | 패키지 승인 철회 서명 (C2 `package_revoke`) — 그 패키지의 배포가 모두 무효 | 「배포 N개가 무효가 됩니다」 |
| `chk-admin sign-extension <정의 파일> [--out] [--register]` | 외부 확장 정의 승인 서명 (C2 `extension`) → 봉투 파일. 운영자가 CON-07에 함께 올린다. **`--register`면 그 자리에서 Center에 정의와 봉투를 함께 올린다**(`POST /resources/extensions` — Admin이 운영자도 겸할 때 한 번에 끝낸다. 봉투 파일도 그대로 남는다). **E1·E3을 먼저 로컬에서 돌려** 문제가 있으면 서명하지 않는다 | 해시·허용 호스트·사설망 허용·작업별 수행 모드를 보이고 「서명할까요?」 |
| `chk-admin revoke-extension <id> <버전> [--out]` | 외부 확장 승인 철회 서명 → 봉투 파일. 운영자가 CON-07 상세의 「등록 해제」에 올린다 | 「이 정의를 쓰는 Bot이 실행 불가가 됩니다. 계속할까요?」 |
| `chk-admin deprecate <id> <버전>` | 지원 종료 표시 (서명 없음, 새 배포만 막음). **묻고 기본은 「아니오」**다 — `-y`로 넘긴다 | **돈다** |
| `chk-admin job new <id> --bot-ui <Bot UI> [--version] [--input 이름=값] [--inputs <JSON>] [--until] [--note] [--idempotency-key]` | 작업 만들기 (콘솔 CON-05와 같은 일). **서명이 없다** — 이미 배포된 것을 돌릴 뿐이라 토큰 권한이 관문이다 (C5 권한표) | 대상 Bot UI·입력 개수·만료를 보이고 「작업을 보낼까요?」 |
| `chk-admin job list [--state] [--bot-ui] [--bpm-process]` / `show <작업 id>` | 작업 목록 / 하나 (실행 상태 포함) | |
| `chk-admin job cancel <작업 id>` | 작업 취소. **시작된 것은 멈추지 않는다** (C5) — 「취소를 요청했습니다」로 끝나면 현장의 답을 기다리는 중이다 | 「작업 <id>를 취소할까요?」 |

**서명 키는 고르지 않아도 된다** — 이 PC의 키가 하나면 그것을, 여럿이면 **Center에 등록되어 있고 철회되지 않은 것이 정확히 하나일 때** 그것을 쓰고 어느 키인지 한 줄로 말한다(짐작이 아니라 Center가 받아 줄 키다). 그 밖(Center에 닿지 못함·등록된 것이 없거나 둘 이상)이면 아무 키나 쓰지 않고 `--key <키 id>`로 고르라고 한다 — `chk-admin` 전체의 옵션이라 **명령 앞에** 적는다(`chk-admin --key <키 id> approve …`). 키는 **묻기 전에** 고른다(「서명할까요?」에 답한 뒤에 막히지 않게). `-y`도 명령 앞이다.

명령 이름 접두사 `chk-`는 환경변수 접두사(`CHK_`)와 맞춘 가안이다.

| 명령 (가안) | 하는 일 |
| --- | --- |
| `chk-center admin-keys bootstrap <public.pem>` | Admin 키가 하나도 없을 때만 첫 키를 넣는다 (C2) |
| `chk-runner keys set <참조 이름>` / `list` / `remove <참조 이름>` | 서버 실행기의 서비스 앱 키 값 (서버 Bot의 키 참조, ADR-0015). 값은 서버 OS 비밀 저장소. `list`는 앞자리만 |
| `chk-runner status` | 서버 실행기 상태·용량·실행 중·기다리는 실행 (CON-12와 같은 내용) |

## Admin UI (`chk-admin-ui`)

> 상태: ADM-01·ADM-04·ADM-05·ADM-06이 **돈다** ([ADR-0089](../decisions/0089-admin-ui.md)). ADM-02·ADM-03은 **아직**이다(명령줄로 한다).

- 창은 탭 둘(「키」·「확장」)이다. 맨 위 줄 왼쪽에 **지금 Center 주소·상태**, 그 오른쪽 끝에 「연결 변경」이 있고, 「새로 고침」은 표를 다시 읽는 것이라 **탭 안 표 오른쪽 아래**에 있고, 탭마다 다른 단추 줄은 **탭 상자 밖 아래**에 있고(지금 탭의 줄만 보인다), 창 제목은 「Chaeksas Admin」뿐이다. Center 연결(ADM-05)은 시작할 때와 토큰이 거부될 때 저절로 뜬다.
- 키는 보통 한두 개라 창은 작게 연다(표가 화면을 차지하지 않게).
- 서명은 **누를 때마다 암호를 묻는다.** 창은 암호도 열린 키도 쥐고 있지 않다. 빈 암호는 받지 않고, 틀리면 그렇다고 말한 뒤 아무것도 바꾸지 않는다.
- Center를 부르는 것은 **사람이 누를 때뿐**이다(창을 열 때 한 번, 「새로 고침」, 각 동작). 닿지 못하면 그 자리에서 한 줄로 말하고, 표의 등록 상태는 「알 수 없음」이 된다.
- 되돌릴 수 없는 동작(철회·지우기)은 확인 창을 띄우고 기본 답은 「취소」다.

```
+----------------------------------------------------------+
| [C] Center: url · state                     [Reconnect] |
+----------------------------------------------------------+
| [T] tabs: Keys | Extensions                              |
|                                                          |
|                 [W] tab content                          |
|                                                          |
+----------------------------------------------------------+
| [S] status line                                          |
+----------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| 위 줄 | 「Center  <주소> · <상태>」와 오른쪽 끝 「연결 변경」. 상태는 「연결됨 · Admin 키 N개」 / 「연결됨 · Admin 키 없음」 / 「관리자 토큰이 없습니다」 / 「토큰이 거부되었습니다 …」 / 「닿지 못했습니다 …」 |
| S | 마지막 동작의 결과 한 줄 (「서명하고 등록했습니다 — <id>@<버전>」 등). 키 값·암호·토큰은 넣지 않는다 |

### 시작할 때 (Center 연결 확인)

Admin UI의 모든 일은 Center를 거치므로, 창을 쓰기 전에 **Center 주소와 관리자 토큰이 맞는지 먼저 본다**(일종의 로그인).

| 때 | 하는 일 |
| --- | --- |
| 처음 시작 (저장된 연결이 없음) | 주 창보다 먼저 ADM-05를 띄운다. 「연결」은 **확인된 뒤에만** 저장한다. 창을 닫으면 Admin UI를 닫는다 |
| 두 번째부터 | 저장된 주소·토큰으로 Center에 물어본다. 맞으면 **바로 주 창**이다 |
| 저장된 연결이 맞지 않음 (토큰이 바뀌었거나 지워짐 — 401·403, 주소가 틀림 — 닿지 못함) | 주 창보다 먼저 ADM-05를 띄우고 맨 위에 까닭을 적는다 |
| 쓰는 도중 Center가 토큰을 거부함 (401·403) | 그 자리에서 ADM-05를 띄운다. 연결되면 표를 다시 읽는다. 창을 닫으면 주 창에 남고 등록 상태는 「알 수 없음」이다 |

- Center가 **잠깐 닿지 않는 것**(서버가 꺼짐)도 시작할 때는 ADM-05로 간다. 까닭 줄이 「닿지 못했습니다」라고 말하므로, 주소가 맞으면 Center를 띄운 뒤 「연결」을 누르면 된다.
- **「연결 변경」**: 주로 다른 Center로 바꿀 때 쓴다. **묻지 않고** ADM-05를 바로 띄운다(지금 주소가 채워져 있다). 새 주소·토큰으로 「연결」되어야 바뀌고, 창을 닫으면 **지금 연결 그대로**다(아무것도 지우지 않는다).

### ADM-01 키

```
+----------------------------------------------------------+
| [L] keys table                                           |
+----------------------------------------------------------+
| [B] [New key] [Register] [Revoke] [Delete]     [Refresh] |
+----------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| L | 열: 키 id · 이름 · 만든 날 · Center 상태(「등록됨」·「등록 안 됨」·「철회됨」·「알 수 없음」). 「알 수 없음」은 Center에 닿지 못했을 때다. 등록된 키가 위로 온다 |
| B 「새 키」 | **창 하나**에서 이름·암호·암호 확인을 받는다. 이름이 비었거나 이 PC에 같은 이름이 있으면, 암호가 비었거나 둘이 다르면 창을 닫지 않고 그 칸 아래에 말한다. 만든 뒤 Center에 Admin 키가 없으면 「첫 키로 넣을까요?」를 이어 묻는다 |
| B 「등록」 | 고른 키를 Center에 넣는다(툴팁 「고른 키를 Center에 등록합니다」). 이미 등록된 키에서는 꺼진다. **Center에 Admin 키가 없으면 첫 키(ADM-06)**이고, 있으면 **등록된 다른 키의 서명**(C2 `admin_key`)이다. 서명할 키는 고르게 하고(등록된 것이 하나면 그것), 그 키의 암호를 묻는다 |
| B 「철회」 | 등록된 키를 C2 `admin_key_revoke`로 철회한다. 확인 문구는 CLI와 같다(「이 키로 서명한 승인·배포가 모두 무효가 됩니다」). 서명할 키는 Center에 등록된 이 PC의 키에서 고른다(하나면 그것이다). 마지막 키는 Center가 거부하고, 그 사유를 그대로 보인다 |
| B 「지우기」 | **이 PC의 키 파일만** 지운다(Center의 등록은 그대로 남는다). Center에 등록되어 있고 철회되지 않은 키면 「이 키로는 다시 서명할 수 없습니다」를 한 번 더 묻는다. **Center가 아는 유일한 키는 지우지 않는다**(Admin이 잠긴다). Center에 닿지 못해 모르면 「알 수 없음」으로 말하고 같은 확인을 거친다 |

Center에 Admin 키가 없으면 「등록」은 ADM-06(첫 키)을 연다. Center에 닿지 못하면 동작하지 않고 「Center 연결(주소·관리자 토큰)을 확인할까요?」라고 물어 ADM-05를 연다.

### ADM-04 외부 확장

```
+----------------------------------------------------------+
| [L] external extensions table                            |
+----------------------------------------------------------+
| [B] [Sign and register...] [Revoke...]         [Refresh] |
+----------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| L | Center에 등록된 외부 확장(C7 `type=extension`, 등급 `external`). 열: id · 판 · 이름 · 게시자 · 상태(C7 `status`의 표기). 닿지 못하면 비우고 C 줄이 말한다 |
| B 「서명하고 등록...」 | 정의 파일을 고른다 → CLI `sign-extension`과 **같은 줄**(id·판·이름·등급, 해시, 허용 호스트, 사설망 허용, 작업별 수행 모드)을 보이고 「서명하고 등록할까요?」를 묻는다 → 암호를 묻는다 → 서명해 Center에 올린다(`POST /resources/extensions`). E1·E3 문제가 있으면 **서명 단추가 꺼지고** 문제를 줄마다 보인다. 같은 정의가 이미 있으면 「이미 같은 정의로 등록되어 있습니다」이고 실패가 아니다 |
| B 「철회...」 | 고른 확장의 그 판을 C2 `extension_revoke`로 철회한다. 사유를 받고(기본 「관리자 철회」) CLI와 같은 문구(「이 정의를 쓰는 Bot이 실행 불가가 됩니다」)로 묻는다. **되살릴 수 없다** |

서명할 키는 묻지 않는다 — CLI와 같은 규칙으로 고른다(키가 하나면 그것, 여럿이면 Center에 등록되어 있고 철회되지 않은 하나). 하나로 좁혀지지 않으면 동작을 멈추고 「키」 탭에서 정리하라고 말한다.

### ADM-05 Center 연결

Center를 부르는 모든 동작이 쓰는 연결이다. 화면에는 **필요한 것만** 둔다 — 설명은 툴팁이다.

| 칸 | 내용 |
| --- | --- |
| 까닭 줄 | 저절로 떴을 때만, 맨 위 한 줄(「토큰이 거부되었습니다 …」·「닿지 못했습니다 …」) |
| Center 주소 | 예 `https://center.example.com`. 기본 `http://localhost:8800`. Admin 설정 파일(`settings.json`, 데이터 폴더)에 저장한다 |
| 관리자 토큰 | OS 비밀 저장소(`chaeksas-admin`)에 저장한다. 저장된 것이 있으면 칸은 비어 있고 「저장됨」이 흐리게 보인다. 이름 옆 「?」(칸들의 끝이 어긋나지 않게 이름 쪽에 둔다)에 올리거나 누르면 안내가 뜬다: 「관리자 토큰은 Center 담당자에게 받으세요. 받은 값을 이 칸에 붙여 넣고 「연결」을 누르면 됩니다. 토큰은 이 PC에만 안전하게 저장됩니다.」 — **서버 내부(파일·환경변수 이름)는 적지 않는다**(사용자가 알 수 없는 것이다. 담당자가 보는 곳은 `deploy/.env.example`) |
| 「연결」 | 창 오른쪽 아래, 보통 크기. **단추는 이것 하나다.** `GET /admin-keys`로 확인하고, 「연결됨 …」이면 저장하고 닫는다. 아니면 아래 결과 줄에 까닭을 적고 닫지 않는다. 토큰이 비어 있으면 부르지 않고 「관리자 토큰이 없습니다」 |
| 결과 줄 | 「연결」의 결과 한 줄 |

- 그만두려면 창을 닫는다(「저장」·「취소」 단추는 없다). 시작할 때 닫으면 Admin UI가 닫힌다.
- 환경변수(`CHK_ADMIN__CENTER_URL`·`CHK_ADMIN__ADMIN_TOKEN`)가 있으면 **그 값이 이기고**, 그렇다고 한 줄 적는다.
- 비밀 저장소가 없으면 저장이 분명히 실패하고 창을 닫지 않는다. ASCII가 아닌 글자가 든 토큰은 저장하지 않는다(HTTP 헤더는 ASCII다).
- 명령줄 `chk-admin`도 같은 순서(환경변수 → 설정 파일·비밀 저장소 → 기본값)로 읽는다.

### ADM-06 첫 키 넣기 (서버 셸)

Center에 Admin 키가 **하나도 없을 때 한 번만** 연다. C2는 첫 키를 서버 셸에서만 넣게 한다 — 관리자 토큰이 새도 다른 사람이 제 키를 넣지 못하게 하려는 것이다. 그래서 이 창은 **Center에 들어갈 셸**을 묻는다.

화면에는 **필요한 것만** 둔다 — 설명은 툴팁이다.

```
+----------------------------------------------+
| <name>(<key id>...) -> first Admin key        |
|  Server      [This PC                    v]   |
|  SSH target  [user@host            ] : [22]   |
|  > Advanced                                   |
|  result line                                  |
|  [Put manually...]                    [Put]   |
+----------------------------------------------+
```

| 칸 | 내용 |
| --- | --- |
| 첫 줄 | 「<이름>(<키 id 앞 8자>…)을 첫 Admin 키로 넣습니다.」 툴팁: Center 주소, 서버에서만 넣는 까닭(C2) |
| 서버 | 「이 PC」 / 「SSH」. 「이 PC」는 Center 주소가 루프백일 때만 쓴다. 기본은 저장된 것, 없으면 주소가 루프백이면 「이 PC」 아니면 「SSH」 |
| SSH 대상 : 포트 | 한 줄. **「SSH」를 고를 때만 보인다.** 암호 칸은 없다 — SSH 키·에이전트로 들어간다(툴팁) |
| 고급 ▸ | 접혀 있다. 펴면 「Center 명령」 — 비우면 compose 서비스 `center` 컨테이너를 찾고, docker 없이 띄운 Center면 그 서버에서 Center를 부르는 명령을 적는다. 저장된 명령이 있으면 펴진 채로 연다 |
| 결과 줄 | 「넣기」가 Center를 찾지 못한 까닭 한 줄 |
| 「직접 넣기...」 | 왼쪽 아래. 서버에 들어갈 수 없을 때 — 그 서버에서 칠 명령과 공개키를 따로 띄우고 각각 「복사」(넣은 뒤 「새로 고침」) |
| 「넣기」 | 오른쪽 아래, 단추는 이것 하나다(닫기는 창의 X). 서버 설정을 남기고, 서버에서 Center를 찾아 `chk-center admin-keys bootstrap`을 돌린다(공개키는 stdin). 돌린 뒤 **Center API로 그 키가 Admin 키가 됐는지 확인한다** — 아니면 「셸의 Center와 주소의 Center가 다릅니다」 |

- 찾지 못하면 창을 닫지 않고 그 까닭을 결과 줄에 보인다.
- 서버 셸 칸은 비밀이 아니라 설정 파일에 간다.
