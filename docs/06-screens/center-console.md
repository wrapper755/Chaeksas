# Center 콘솔 화면 설계

Center의 웹 화면. 운영자·결재자가 쓴다. 기본 포트 8501 (설정으로 변경).
콘솔은 DB를 직접 읽지 않고 **Center API만** 부른다. 서비스 앱의 관리 화면은 각 서비스 앱의 **관리 콘솔**에 있고, 콘솔은 리소스 목록에서 그쪽으로 링크만 건다 ([service-app-console.md](service-app-console.md)).
공통 원칙·상태 표기는 [README.md](README.md) §2·§3.

> 구현: **Next.js** (`web/apps/center-console`), 모양은 [스타일 가이드](../07-style-guide.md) ([ADR-0017](../decisions/0017-web-nextjs-design-system.md)). 브라우저는 Center API를 직접 부르지 않고 콘솔 서버(BFF)가 부른다. 이 문서는 화면 구성만 정한다.

## CON-00 공통 틀

```
+----------------------------------------------------------------+
| [N] nav    | [A] top bar: center url | write mode | [Refresh]  |
|            +---------------------------------------------------+
|            | [F] filters (collapsible)                          |
|            | [B] page body                                      |
|            |                                                    |
+----------------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [N] 탐색 | 「실행 로그」(첫 화면) / 「Bot 현황」 / 「Bot UI 현황」 / 「서버 실행」(M7) / 「결재함」 / 「작업 지시」 / 「공통 패키지」 / 「리소스」 / 「Center API 키」 |
| [A] 위 막대 | 「Center: <주소>」, 쓰기 모드 표시(「보기 전용」 / 「관리자」), 「새로 고침」 |
| [F] 필터 | 페이지마다 다름. 접을 수 있다 |
| [B] 본문 | 목록 → 고르면 아래에 상세 |

**쓰기 권한 (제안):** 로그인(OIDC) 전까지는 「관리자」 모드에서만 쓰기 단추(결재 답, 작업 만들기·취소, 패키지 삭제, Center API 키 발급·폐기, Bot UI 비활성화)를 보인다. 관리자 모드는 관리자 토큰을 입력해 켠다. 서명이 필요한 동작(승인·배포·철회)은 콘솔에서 하지 않는다 → Admin.

**오류:** Center에 닿지 못하면 본문 대신 「Center에 연결할 수 없습니다 (<주소>): <이유>」. 리소스 화면에서 서비스 앱에 닿지 못하면 그 줄의 상태만 「응답 없음」.

## CON-01 실행 로그

필터: 「Bot」, 「실행 위치」(전체/PC/서버, 신규), 「Bot UI」, 「상태」((전체)/실행 중/기다리는 중(서버)/완료/실패/취소됨), 「최근 n건」(10~500, 기본 100).

목록 열: 실행 id / 상태 / Bot / 버전 / 실행 위치 / Bot UI 또는 서버 실행기 / 시작 방식(작업·감시·수동·일정·메시지) / 시작 / 끝 / 소요(초) / AI 태스크 / 재생 / UI 태스크 (신규) / 결재·확인 수 / 오류 코드. 빈 상태: 「조건에 맞는 실행이 없습니다.」 아래 「<n>건」.

상세 (목록에서 고름):

| 섹션 | 내용 |
| --- | --- |
| 요약 | 상태, 소요, AI 태스크, 재생, UI 태스크, LLM 단계, 결재·확인 수. 오류 코드가 있으면 경고 |
| 「노드 타임라인」 | 가로 막대(노드별 시작~끝, 색 = 상태). 이어 돌기(재개) 지점은 점선. 아래 표: 노드 / 상태 / 시작 / 끝 / 소요 |
| 「이어 돈 기록」 | 재개가 있을 때만: 이어 돈 횟수, 기다린 시간, 표 |
| 「AI 태스크 단계」 | 순번 / 시각 / 노드 / 단계 / 요약 |
| 「UI 태스크」 (신규) | 노드 / 화면 / 스텝 수 / 폴백 깊이 최대 / 치유 / 전환 여부 → 누르면 UI 자동화 앱 관리 콘솔 UIA-03 상세 (새 탭) |
| 「사람 개입」 | 순번 / 시각 / 종류(결재·확인) / 노드 / 폼 키 |
| 「로그」 | 시각 + 글 |
| 「원본 이벤트」 | 접힌 JSON |

빈 섹션은 「<종류> 이벤트가 없습니다.」 한 줄.

## CON-02 Bot 현황

Bot(BPM 프로세스)·버전별 준비도. 최근 20회 실행 기준. 설명 줄: 「Bot N개, 버전 M개 · 준비도는 최근 20회 실행 기준」.

열: Bot / 버전 / 실행 위치(PC·서버) / 상태(후보·승인됨·지원 종료·철회) / 실행 불가 / 경고 / 성공률(막대) / 재생률(막대) / 확인률(실행당 확인 요청 평균) / 표본 수 / 최근 성공 / 배포된 Bot UI / 필요한 서비스 앱 키 참조.

- 「투입 가능」 같은 판정 열은 두지 않는다. 판단은 관리자 몫.
- 경고 띠: 「사전 점검에 실행 불가 항목이 있는 버전: …」, 「필요한 리소스가 Center에 없는 버전 (배포 시 거부됨): …」(툴팩·UI 화면·서비스 앱 — C7).
- 관리자 모드: 「삭제할 버전」 고르기 + 「삭제...」 → 확인 창(기본 「취소」): 「<Bot> <버전>을 지웁니다. 되돌릴 수 없습니다.」 배포가 참조하면 409 → 이유 표시.
- 빈 상태: 「올라온 Bot이 없습니다. Studio에서 「Center로 올리기」로 올리세요.」

## CON-03 Bot UI 현황

PC마다 하나인 Bot UI의 상태.

열: 온라인(마지막 하트비트 90초 이내 「● 온라인」 / 「○ 오프라인」 — 글자 포함. 오프라인이면 아래 실행·대기열 칸에 「마지막 보고 <시각> 기준」을 붙인다, U8) / Bot UI 이름 / 상태 / OS / 버전 / 마지막 하트비트 / 실행 중(`Bot@노드`, 하나 또는 「없음」) / **대기열**(N건, 신규) / **Worker 프로세스**(버전·상태, 신규) / **런타임**(브라우저·데스크톱 백엔드, 신규) / Center API 키(앞자리, 만료).
설명 줄: 「x/y 온라인」.

상세 (Bot UI를 고름, 신규 확장):
- 「대기열」 (신규): 순서 / Bot / 출처 / 요청 시각 / 만료. Bot UI가 하트비트로 보고한 그대로 (보기 전용; Center 작업은 CON-05에서 취소).
- 「배포」: 이 Bot UI의 활성 배포 목록 (배포 id / Bot / 버전 / 유효 기간 / 준비: 「준비됨」/「서비스 앱 키 없음」/「확장 없음」 — Bot UI가 보고). 배포 id는 복사 단추와 함께 (Admin `revoke-deploy`에 씀).
- 「확장」: 이 PC에 설치된 확장과 켜짐 여부 (C4 `extensions`).
- 「최근 배치 결정」: 시각 / 결과(「✅ 적용」/「⛔ 거부」) / 배포 id / 패키지 / 사유(코드를 글로: `bad_signature` 「서명이 맞지 않음」, `expired` 「유효 기간 지남」, `not_yet` 「아직 시작 전」, `wrong_target` 「다른 PC용」, `hash_mismatch` 「패키지 내용이 다름」, `unsigned_package` 「승인 서명 없음」, `revoked_key` 「서명 키 철회됨」) / 만료. 빈 상태: 「Bot UI가 올린 배치 결정이 아직 없습니다.」
- 관리자 모드: 「비활성화...」(확인 창, 기본 「취소」: 「이 PC에 새 작업·배포를 보내지 않습니다. 실행 중인 Bot은 끝까지 돕니다.」) / 「다시 활성화」 (신규, 비활성화된 Bot UI에는 새 작업·배포를 보내지 않는다. 하트비트는 받아 상태는 계속 보인다 — C4 `disabled`).

## CON-04 결재함

필터: 「상태」(대기/답함/시간 초과/회수됨/(전체)), 「실행하는 곳」(Bot UI·서버 실행기).

열: 상태(아이콘 + 글자) / 제목 / 요청 id / 실행하는 곳(Bot UI 이름 또는 「서버」) / Bot / 변수 키(키만, U10) / 요청 시각 / 시한 / 답한 사람 / 전달됨(실행하는 쪽이 답을 받아 감).
빈 상태: 「해당하는 결재 요청이 없습니다. 필터를 「(전체)」로 바꿔 보세요.」 (필터가 전체면 「기다리는 결재가 없습니다.」)

상세:
- 요약: 상태, Bot UI, Bot, 실행 id(누르면 CON-01).
- 「결재에 필요한 값 (업무 데이터)」 — 접혀 있음. 값이 보이는 유일한 곳.
- 대기가 아니면: 「답: <값> (자칭 — 신원 검증 없음)」, 회수됐으면 「회수됨 — <현장에서 먼저 답함 / 실행이 끝남 / 관리자 회수 / Bot UI 기록 유실>」.
- Bot UI가 답을 받아들이지 못했으면 요청은 다시 「대기」가 되고 위에 「Bot UI가 이전 답을 거절했습니다: <이유> — 고쳐서 다시 답하세요」를 보인다 (C6).
- 실행이 끝나거나 Bot UI가 기록을 잃으면 대기 중 결재는 자동으로 회수된다.
- 대기이고 관리자 모드면 「답하기」:
  - 폼 필드에서 입력 칸을 만든다 (참/거짓 → 체크, 숫자 → 숫자, 선택지 → 고르기, 그 밖 → 글). 폼이 없으면 「승인」 / 「반려」 단추와 「메모」 한 줄 (C6 `decision`).
  - 「답하는 사람 (자칭 — 신원 검증 없음)」 필수. 채워야 「답 보내기」가 켜진다. 콘솔 서버가 이 이름을 행위자로 Center에 보낸다 (C6 `X-CHK-Actor`).
  - 폼과 맞지 않는 답은 Center가 거부하고 칸마다 오류를 보인다.
  - 성공: 「답을 보냈습니다. 실행하는 쪽이 다음 하트비트에 받아 갑니다.」
  - 「회수...」 → 확인 창(기본 「취소」): 「이 결재를 회수합니다. 그 노드에 오류 경계 이벤트가 없으면 실행은 실패로 끝납니다.」 → 「회수」. 결과: 「회수했습니다. 그 노드에 오류 경계 이벤트가 없으면 실행은 실패로 끝납니다.」

## CON-05 작업 지시

필터: 「상태」(대기/전달됨/대기열/수락/거절/만료/취소됨, 여러 개), 「Bot UI」, 「최대」(10~1000).

열: 상태 / 작업 id / 실행 위치 / Bot UI(서버면 「서버」) / Bot(`이름@버전` 또는 「(배포된 버전)」) / 입력 키 / 요청자(사람 또는 「서버 Bot <이름> (실행 id)」 — PC 위임, 누르면 CON-01) / 요청 시각 / 만료 / 실행 id / 실행 상태 / 사유 / 메모.
빈 상태: 「작업 지시가 없습니다. 「새 작업...」으로 만드세요.」

상세: 상태, Bot UI, 실행 id, 실행 상태, 거절 사유. 「입력 (업무 데이터)」 접힘. 「전체 JSON」 접힘(입력 제외).

관리자 모드 (신규 — 프로토타입은 명령줄만):
- 「새 작업」 단추 → 창: 「Bot」, 「Bot UI」(그 Bot이 배포된 Bot UI만, 실행 위치가 서버인 Bot이면 이 칸 대신 「서버 실행기에서 실행 — 동시 실행 상한 <n>」), 「버전」(기본: 배포된 버전), 「입력 변수」(진입 정의가 기대하는 입력을 표로 채움), 「만료」, 「메모」. 배포가 없으면 「이 Bot UI에 유효한 배포가 없습니다」(422 `no_deployment`). 같은 Bot UI에 그 Bot의 배포가 둘 이상이면 「버전」을 고르게 한다.
- 대기·전달됨·대기열 상태 작업의 「취소」. 대기면 바로 「취소됨」. 전달됨·대기열이면 「취소 요청함 — 다음 하트비트에 반영」으로 보이고, Bot UI가 빼내면 「취소됨」. 그사이 이미 시작됐으면 작업은 「수락」 그대로이고 옆에 「취소 못 함 — 이미 시작됨」을 붙인다 (C5).
- 「대기열」 상태 줄에는 「Bot UI 대기열 N번째 — 실행 중 <Bot>」을 보인다. 거절 사유: 「대기열 가득」, 「배포 없음」, 「준비 안 됨」, 「Bot UI 종료」, 「Bot UI 기록 유실」(비정상 종료), 「서버 실행 Bot」.

## CON-06 공통 패키지

Bot이 아닌 패키지(공유 BPM 프로세스, 툴팩). 빈 상태: 「올라온 공통 패키지가 없습니다. Studio의 「공유 BPM 프로세스 Center로 올리기」나 툴팩 업로드로 올리세요.」

열: id / 버전 / 종류 / 이름 / 상태 / 올린 시각 / 올린 이 / 다운로드 수.

상세:
- 요약: 종류, 상태, 다운로드, 설명, 「실행 요구」.
- 「제공 도구」(툴팩): 이름 / 환경 / 설명 / 인자 / 서버.
- 「제공 정의」(공유 BPM 프로세스): 정의 id / 이름 / 파일 / 읽는 변수 / 쓰는 변수 / AI 태스크 / 결재 / 설명.
- 「이 패키지를 쓰는 패키지」: id / 버전 / 종류 / 이름 / 상태 / 관계 / 고정 해시. 없으면 「아직 없습니다.」
- 관리자 모드: 「삭제...」 → 확인 창(기본 「취소」): 「되돌릴 수 없습니다.」 참조되면 409 → 이유.

## CON-07 리소스 (신규)

Bot이 실행에 필요로 하는 바깥 자원의 목록 (계약 C7). 고정 탭 넷(확장·서비스 앱·툴팩·런타임) + **확장이 기여한 자원 종류마다 탭 하나**(예: UI 자동화 확장의 「UI 화면」). 키는 다루지 않는다.

| 탭 | 열 | 상세 |
| --- | --- | --- |
| 「확장」 (신규, [ADR-0018](../decisions/0018-extensions.md)) | 이름 / id / 등급(내장·사내·외부) / 버전 / 연결 방식(C11·HTTP 어댑터·없음) / 기여 요약 / 설치된 Bot UI 수 / 상태 | 기여 지점별 목록, 서버 부분 링크(「서비스 앱」 탭), 외부 확장이면 정의 전체(접힘)와 어댑터의 허용 호스트, 「이 확장을 쓰는 Bot」 |
| 「서비스 앱」 | 앱 이름 / id / 구분(업무·시스템) / 버전 / 상태(정상·저하·응답 없음·확인 전 + 마지막 확인 시각) / API 주소 / **관리 콘솔 주소** / 작업 수 | 작업 목록(이름, 설명, 입력·출력 필드, 지원 수행 모드, 결정 수행 실패 시 폴백 정책). 「이 앱을 쓰는 Bot」(키 참조 이름 포함). 「관리 콘솔 열기」(새 탭) |
| 「UI 화면」 (UI 자동화 확장 기여 — 확장 기여 자원 탭의 예) | 화면 id / 이름 / 요소 수 / 로케이터 상태 요약(사용 중·검증 전·대체됨) / 마지막 등록 | 요소 목록. 「이 화면을 쓰는 Bot」. 「셀렉터 보기」 → UI 자동화 앱 관리 콘솔 UIA-02 (새 탭) |
| 「툴팩」 | id / 버전 / 상태 / 도구 수 | CON-06 상세로 |
| 「런타임」 | 실행하는 곳(Bot UI·서버 실행기) / 이름 / core 버전 / Worker 버전 / 브라우저 / 데스크톱 백엔드 / OS / 확장 | CON-03·CON-12 상세로 |

경고 띠: 「Bot이 요구하지만 없는 리소스: …」 (배포 전 확인용, C7 누락 검사).
빈 상태(탭마다): 「확장」 「설치·등록된 확장이 없습니다.」 / 「서비스 앱」 「등록된 서비스 앱이 없습니다. 「서비스 앱 추가...」로 주소를 넣으세요.」 / 기여 자원 「<확장>이 아직 올린 <자원>이 없습니다.」

관리자 모드: 「확장」 탭 「확장 추가...」 → 외부 확장 정의 파일과 **Admin 서명 봉투**(`chk-admin sign-extension`으로 만든 것)를 함께 올림. C13 검사 결과를 칸마다 보이고, 서명이 검증되면 「등록」. 서명 없이는 등록할 수 없다 (C2 `extension`). 해제도 서명 봉투(`extension_revoke`, `chk-admin revoke-extension`이 만든 파일)가 필요하다: 「해제...」 → 봉투 파일 올리기 → 확인 창(기본 「취소」: 「이 정의를 쓰는 Bot N개가 실행 불가가 됩니다」). 「서비스 앱」 탭: 「주소 바꾸기...」(내장·사내 서비스 앱의 환경별 주소, C7 `PUT` — 클라이언트는 이 주소만 쓴다). 「서비스 앱」 탭 「서비스 앱 추가...」 → 창: 「API 주소」 → Center가 manifest를 읽어 이름·작업을 미리 보여 주고 「등록」. 「등록 해제」(쓰는 Bot이 있으면 막고 목록을 보임). 모든 탭에 「새로 고침」(바로 다시 읽기).

Center는 서비스 앱에서 공개 정보(`/healthz`, `/manifest`, UI 자동화 앱의 셀렉터 없는 카탈로그)만 읽는다. 서비스 앱 키를 갖지 않는다 (C7).

## CON-08 ~ CON-10 (폐기)

UI 자동화 개요·셀렉터·모니터링은 **UI 자동화 앱의 관리 콘솔**로 옮겼다 ([ADR-0013](../decisions/0013-api-keys.md)). → [service-app-console.md](service-app-console.md) UIA-01 ~ UIA-03.

## CON-11 Center API 키 (신규)

Bot UI·Studio·서버 실행기·외부 시스템(연동용)이 Center에 접속할 때 쓰는 키를 발급·폐기한다 ([ADR-0013](../decisions/0013-api-keys.md) §1). 빈 상태: 「발급한 키가 없습니다. 「새 키...」로 Bot UI용 키부터 만드세요.」 서비스 앱 키는 여기서 다루지 않는다 (각 서비스 앱 관리 콘솔).

필터: 「종류」(Bot UI용 / Studio용 / 서버 실행기용 / 연동용), 「상태」(사용 중 / 만료 / 폐기됨).

| 열 | 내용 |
| --- | --- |
| 「이름」 | 사람이 알아볼 이름 (예: 「재무팀 PC-03」) |
| 「종류」 | Bot UI용 / Studio용 / 서버 실행기용 ([ADR-0015](../decisions/0015-run-location.md)) / 연동용 (외부 시스템이 작업을 만들 때, C5) |
| 「연결된 대상」 | Bot UI용·서버 실행기용: 그 키로 등록된 대상(PC·서버 이름, 처음 등록 시각), 아직 안 쓰였으면 「등록 전」 · Studio용: 사용자 이름 · 연동용: 메모(어느 외부 시스템인지)와 최근 만든 작업 수 |
| 「앞자리」 | 앞 16자 (`chk_ctr_` + 무작위 8자). 원문은 보이지 않는다 |
| 「만든 날」 / 「만료」 / 「마지막 사용」 | |
| 「상태」 | 사용 중 / 만료 / 폐기됨 |

관리자 모드:
- 「새 키」 → 창: 이름, 종류, 만료(기본 1년). 「발급」을 누르면 **원문을 한 번만** 보여 준다: 「이 키는 다시 볼 수 없습니다. 지금 복사해 Bot UI 설정(또는 Studio 설정)에 넣으세요」 + 「복사」 단추.
- 「폐기」(확인 창, 기본 단추 「취소」): 「이 키를 쓰는 Bot UI <이름>의 하트비트가 바로 거부됩니다. 실행 중인 Bot은 끝까지 돌지만 기록은 쌓아 둡니다.」
- 「묶음 풀기」(Bot UI용·서버 실행기용, 확인 창, 기본 「취소」): PC를 다시 설치해 같은 키로 다시 등록해야 할 때. 다음 `register`가 새 PC에 묶인다.
- Bot UI용 키 하나는 Bot UI 하나에만 묶인다. 이미 다른 PC가 등록한 키로 다시 등록하려 하면 거부한다 (「이 키는 <PC>에서 쓰고 있습니다」).

## CON-12 서버 실행 (신규, M7)

실행 위치가 「서버」인 BPM 프로세스(서버 Bot)의 실행 상황 ([ADR-0015](../decisions/0015-run-location.md)). 서버 실행기는 Center가 관리한다.

| 섹션 | 내용 |
| --- | --- |
| 「서버 실행기」 | 온라인(「● 온라인」/「○ 오프라인」) / 이름 / 버전 / 실행 중 n / 상한 N / 기다리는 실행 수 / 마지막 하트비트 / Center API 키(앞자리) / 상태(「동작」/「일시 중지」) |
| 「실행 중」 | 실행 id / 서버 Bot / 버전 / 현재 노드 / 시작 / 경과 → 누르면 CON-01 상세 |
| 「기다리는 실행」 | 실행 id / 서버 Bot / 기다리는 것(결재·메시지·타이머·PC 위임 — PC 위임이면 작업 id → CON-05) / 기다린 시간 / 결재면 CON-04 링크. 상한에 세지 않는다 |
| 「대기열」 | 작업 id / 서버 Bot / 요청 시각 / 대기 이유(「전체 상한」/「Bot별 상한 n」) / 만료 |
| 「Bot별 상한」 | 서버 Bot / 배포 버전 / 상한(배포 서명에 들어 있음, 보기 전용) / 지금 실행 수 / 준비(「준비됨」/「서비스 앱 키 없음: <참조>」/「확장 없음」 — C12 `readiness`. 키는 서버에서 `chk-runner keys set`) |

상태 표기: 서버 실행기 「동작」 / 「일시 중지」 / 「정리 중」(draining) / 「오류」 / 「오프라인」 · 대기 이유 「전체 상한」 / 「Bot별 상한 n」 / 「일시 중지」.

관리자 모드: 서버 실행기 「일시 중지...」(확인 창: 「새 실행을 받지 않습니다. 실행 중인 것은 끝까지 돕니다.」) / 「다시 시작」 (C12 `POST /server-runners/{id}/pause`·`resume`), 오프라인 실행기의 「유실 처리...」(확인 창, 기본 「취소」: 「이 실행기의 실행 N건을 실패로 닫고 결재를 회수합니다. 되돌릴 수 없습니다.」, C12 `mark-lost`), 대기열 작업 「취소...」.

빈 상태: 「등록된 서버 실행기가 없습니다. Center API 키(서버 실행기용)를 발급해 서버 실행기 설정에 넣으세요.」
