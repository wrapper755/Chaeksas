# Center 콘솔 화면 설계

Center의 웹 화면. 운영자·결재자·관리자가 쓴다 — 승인·배포·외부 확장 등록도 여기서 한다 ([ADR-0090](../decisions/0090-center-admin-accounts.md)). 기본 포트 8501 (설정으로 변경).
콘솔은 DB를 직접 읽지 않고 **Center API만** 부른다. 서비스 앱의 관리 화면은 각 서비스 앱의 **관리 콘솔**에 있고, 콘솔은 리소스 목록에서 그쪽으로 링크만 건다 ([service-app-console.md](service-app-console.md)).
공통 원칙·상태 표기는 [README.md](README.md) §2·§3.

> 구현: **Next.js** (`web/apps/center-console`), 모양은 [스타일 가이드](../07-style-guide.md) ([ADR-0017](../decisions/0017-web-nextjs-design-system.md)). 브라우저는 Center API를 직접 부르지 않고 콘솔 서버(BFF)가 부른다. 이 문서는 화면 구성만 정한다.

## CON-00 공통 틀

```
+----------------------------------------------------------------+
| [N] nav    | [A] top bar: center url | write mode | [Refresh]  |
|            +---------------------------------------------------+
|            | [F] filters (collapsible)                          |
|            | [B] page body                                      |
|            |                                                    |
+----------------------------------------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| [N] 탐색 | 「실행 로그」(첫 화면) / 「Bot 현황」 / 「Bot UI 현황」 / 「서버 실행」(M7) / 「결재함」 / 「작업 지시」 / 「가상 직원」 / 「공통 패키지」 / 「배포」 / 「리소스」 / 「Center API 키」 / 「관리자 계정」(**관리자에게만** 보인다) |
| [A] 위 막대 | 「Center: <주소>」(**Bot UI·Studio가 적을 주소** — `CHK_CONSOLE__CENTER_PUBLIC_URL`, 없으면 콘솔이 부르는 주소. 콘솔이 컨테이너 안에서 부르는 `http://center:8800`은 PC에서 닿지 않아 보이지 않는다), 「<아이디> · <역할>」(역할은 「관리자」 / 「보기 전용」)과 「로그아웃」, 「새로 고침」 |
| [F] 필터 | 페이지마다 다름. 접을 수 있다 |
| [B] 본문 | 목록 → 고르면 아래에 상세 |

**로그인과 쓰기 권한** ([ADR-0090](../decisions/0090-center-admin-accounts.md)): 콘솔은 **관리자 계정**으로 들어온다. 쓰기 단추(승인·배포·철회, 결재 답, 작업 만들기·취소, 패키지 삭제, Center API 키 발급·폐기, Bot UI 비활성화, 계정 관리)는 역할이 「관리자」인 계정에만 보인다. 「보기 전용」 계정은 읽기만 한다. 봉투가 필요한 일(승인·배포·외부 확장)도 누르기만 하면 되고 **Center가 서버의 키로 서명한다** — 화면에 키·암호가 나오지 않는다. 기록의 「누가」는 로그인한 계정 아이디다.

로그인 화면:

```
+------------------------------+
| [T] title                    |
| [U] username                 |
| [P] password                 |
| [E] error line               |
|                    [Sign in] |
+------------------------------+
```

| 영역 | 내용 |
| --- | --- |
| T | 「Center 콘솔」 |
| U·P | 「아이디」·「비밀번호」. **칸은 이 둘뿐이다** — 역할은 계정이 정한다 |
| E | 틀리면 「아이디나 비밀번호가 맞지 않습니다」(어느 쪽이 틀렸는지 가르지 않는다). 다섯 번 연달아 틀리면 「로그인을 여러 번 틀렸습니다 — 5분 뒤에 다시 하세요」. 비밀번호를 바꾼 뒤 돌아왔으면 「비밀번호를 바꿨습니다…」 |
| 「로그인」 | 오른쪽 아래, 단추는 이것 하나다 |

- 로그인은 **12시간** 간다. 끝나면 다시 로그인 화면이다.
- 첫 관리자는 설치하는 사람이 서버의 설정에 정한다 — 화면은 그것을 말하지 않는다(서버 내부는 적지 않는다).

**오류:** Center에 닿지 못하면 본문 대신 「Center에 연결할 수 없습니다 (<주소>): <이유>」. 리소스 화면에서 서비스 앱에 닿지 못하면 그 줄의 상태만 「응답 없음」.

## CON-01 실행 로그

> 상태: **돈다** (섹션 전부). 필터 다섯(「상태」·「Bot」·「실행 위치」·**「Bot UI」**·「최근 n건」), 목록 열 전부, 상세의 요약·노드 타임라인·AI 태스크 단계·**「UI 태스크」**·**「이어 돈 기록」**·사람 개입·로그·원본 이벤트. **UIA-03 링크도 돈다** (「화면」 칸 — 아래).

필터: 「Bot」, 「실행 위치」(전체/PC/서버), 「Bot UI」(전체 + 등록된 PC 목록), 「상태」((전체)/실행 중/기다리는 중(서버)/완료/실패/취소됨), 「최근 n건」(10~500, 기본 100).

목록 열: 실행 id / 상태 / Bot / 버전 / 실행 위치 / 실행한 쪽(Bot UI·서버 실행기·Studio) / **Bot UI**(어느 PC) / 시작 방식(작업·감시·수동·일정·메시지) / 시작 / 끝 / 소요(초) / AI 태스크 / 재생 / UI 태스크 / 결재·확인 수 / 오류 코드. 빈 상태: 「조건에 맞는 실행이 없습니다.」 아래 「<n>건」.

- 셈 열(AI 태스크·재생·UI 태스크·결재·확인)은 **`run_finished`가 세어 보낸 것**이다 (C3) — **도는 중에는 「—」**다. 0으로 보이면 「아무것도 없었다」로 읽힌다.
- 「Bot UI」는 C3 `RunInfo.bot_ui_id`이고 **Center가 읽을 때 채운다** — 보낸 **키**가 묶인 PC다 (C3 소유 → C4 키 묶기). 보내는 쪽이 제 id를 적지 않는다 (신원은 키다). **Studio가 보낸 기록에는 없다**(묶인 PC가 없다) — 「—」로 보이고 그 이유를 아래 한 줄로 적는다 (U3).
- 고를 거리(PC 이름)는 CON-03과 **같은 `GET /bot-uis`**에서 온다. **그 목록을 못 받아도 좁히기는 돈다** — 이름 대신 id를 보이고 그렇게 말한다.

상세 (목록에서 고름):

| 섹션 | 내용 |
| --- | --- |
| 요약 | 상태, 소요, AI 태스크, 재생, UI 태스크, LLM 단계, 결재·확인 수. 오류 코드가 있으면 경고 |
| 「노드 타임라인」 | 가로 막대(노드별 시작~끝, 색 = 상태). 이어 돌기(재개) 지점은 점선. 아래 표: 노드 / 상태 / 시작 / 끝 / 소요 |
| 「이어 돈 기록」 | **기다림이 있을 때만**: 이어 돈 횟수, 기다린 시간 합, 표(무엇을 / 노드 / 기다리기 시작 / 기한 / 이어 감 / 기다린 시간 / 깨운 까닭). C3 `run_waiting`·`run_resumed`를 **짝지은** 것이다 — 아래 |
| 「AI 태스크 단계」 | 순번 / 시각 / 노드 / 단계 / 요약 |
| 「UI 태스크」 | 노드 / 화면 / 결과(성공·전환·실패) / 스텝 수 / 폴백 깊이 최대 / 치유. C3 `ui_session`을 읽는다 ([ADR-0041](../decisions/0041-extension-run-events.md)). **「화면」이 그 앱의 관리 콘솔로 가는 링크다** — 아래 |
| 「사람 개입」 | 순번 / 시각 / 종류(결재·확인) / 노드 / 폼 키 |
| 「로그」 | 시각 + 글 |
| 「원본 이벤트」 | 접힌 JSON |

빈 섹션은 「<종류> 이벤트가 없습니다.」 한 줄.

### 「이어 돈 기록」 (서버 실행)

C3 `run_waiting`과 `run_resumed`를 **짝지어** 기다림 한 번을 한 줄로 만든다. 두 줄은 **서버 실행만 남긴다** (C3 — PC Bot은 기다리는 동안에도 실행 자리를 쥐고 있어 `node_state: waiting`만으로 뜻이 통한다). 그래서 PC 실행에서는 **섹션이 아예 보이지 않는다** — 늘 비는 섹션을 그리면 PC 실행 상세마다 뜻 없는 한 줄이 선다.

- **「기다린 시간」은 보낸 쪽이 센 것**(`after_s`)이다 — 셈을 받는 쪽이 다시 하지 않는 이 화면의 규칙 그대로다. 그 칸이 없는 줄(옛 기록)만 두 줄의 시각 차로 메운다.
- **짝 없이 남은 마지막 줄도 보인다.** 빼면 「무엇을 기다리느라 멈춰 있나」가 화면에서 사라진다 (CON-12는 **지금 기다리는 것**만 알고, 지나간 기다림은 여기에만 있다). 도는 실행이면 「기다리는 중」이고, **끝난 실행이면 「이어 가지 않음」**이다 — 기다리다 취소되거나 마감으로 닫힌 것이라 「기다리는 중」이라고 적으면 끝난 실행이 아직 멈춰 있는 것처럼 보인다.
- 「기한」은 타이머만 있다 (C3 선택 칸). **지난 기한이 보일 수 있다** — 깨우기는 주기마다 쓸어서 하므로 기한은 「그 시각 이후」다 ([ADR-0061](../decisions/0061-waking-runs-whose-timer-is-due.md)).
- 「깨운 까닭」은 답·메시지·시각이 됨·실행기 재시작·결재 회수다. **열린 문자열**이라 모르는 값은 글자 그대로 보인다.

### 「UI 태스크」의 관리 콘솔 링크 (UIA-03)

「화면」 칸의 `page_id`를 그 화면을 가진 **앱의 관리 콘솔 주소**로 잇는다. **실행 기록에는 앱이 없고**(C3 `ui_session`은 `page_id`만 가진다) C7이 이미 둘을 잇는 칸을 들고 있어, 콘솔 서버(BFF)가 리소스 목록 둘을 읽어 맞춘다.

| 걸음 | 읽는 것 |
| --- | --- |
| `page_id` → 어느 확장인가 | C7 기여 자원 (`?type=contributed&resource_type=ui_page`) — 항목의 `id`가 `page_id`이고 `extension_id`가 그 확장이다 |
| 확장 → 콘솔 주소 | C7 서비스 앱 (`?type=service_app`) — `extension_id`가 같은 앱의 `console_url` |

- **링크는 콘솔 주소 그대로**다. UIA-03으로 바로 보내지 않는다 — 확장마다 어느 화면이 「모니터링」인지는 **그 확장의 `console.pages`가 아는 것**이고(ADR-0042), Center 콘솔이 그 경로를 적으면 플랫폼 화면에 확장 이름이 들어온다. 운영자는 콘솔에서 탭 하나를 더 누른다.
- **못 이으면 글자만 보인다** (U3) — 그 `page_id`가 카탈로그에 없거나(아직 등록되지 않은 화면), 그 확장의 서버 부분이 Center에 등록되지 않았거나, `console_url`이 비어 있으면 **줄은 그대로 보이고 링크만 없다**. 왜 없는지는 섹션 아래 한 줄로 적는다.
- 바깥 주소라 새 탭으로 연다 (CON-07의 「관리 콘솔 열기」와 같다).

## CON-02 Bot 현황

Bot(BPM 프로세스)·버전별 준비도. 최근 20회 실행 기준. 설명 줄: 「Bot N개, 버전 M개 · 준비도는 최근 20회 실행 기준」.

열: Bot / 버전 / 실행 위치(PC·서버) / 상태(후보·승인됨·지원 종료·철회) / 실행 불가 / 경고 / 성공률(막대) / 재생률(막대) / 확인률(실행당 확인 요청 평균) / 표본 수 / 최근 성공 / 배포된 Bot UI / 필요한 서비스 앱 키 참조.

- 「투입 가능」 같은 판정 열은 두지 않는다. 판단은 관리자 몫.
- 경고 띠: 「사전 점검에 실행 불가 항목이 있는 버전: …」, 「필요한 리소스가 Center에 없는 버전 (배포 시 거부됨): …」(확장·서비스 앱·확장 기여 자원 — C7).
- 관리자: **「승인」 열** — 줄마다 그 판의 상태로 할 수 있는 것만 보인다 ([ADR-0090](../decisions/0090-center-admin-accounts.md) — Center가 서명한다). 모두 확인 창이고 기본은 「취소」다.

  | 상태 | 단추 | 확인 문구 |
  | --- | --- | --- |
  | 후보 | 「승인...」 | 「승인하면 이 판을 배포할 수 있습니다. 승인한 사람으로 이 계정이 남습니다.」 |
  | 승인됨 | 「승인 철회...」·「지원 종료...」 | 철회: 「이 판의 배포가 모두 무효가 되고 현장에서 실행 불가가 됩니다. 되돌릴 수 없습니다.」 / 지원 종료: 「새 배포만 막습니다. 이미 배포된 것은 그대로 돕니다. 다시 승인하면 풀립니다.」 |
  | 지원 종료 | 「승인...」·「승인 철회...」 | 위와 같다 |
  | 철회 | 없음(「—」) | 되살아나지 않는다 |

  배포는 이 화면에 두지 않는다 — 「배포」(CON-15) 한 곳이다.
- 관리자: 「삭제할 버전」 고르기 + 「삭제...」 → 확인 창(기본 「취소」): 「<Bot> <버전>을 지웁니다. 되돌릴 수 없습니다.」 배포가 참조하면 409 → 이유 표시.
- 빈 상태: 「올라온 Bot이 없습니다. Studio에서 「Center로 올리기」로 올리세요.」

> 상태: **돈다** (`app/bots`). **집계는 Center에 두지 않는다** — 패키지(C5)·실행 요약(C3)·보고된 준비 상태(C4)를 **콘솔에서 묶는다**(Center에 집계 표를 두면 실행이 올 때마다 낡고 어느 쪽이 원본인지 흐려진다, CON-01의 셈 열과 같은 결). 실행 요약은 **Bot마다** 묻는다 — 한 번에 받으면 판이 많은 Bot의 옛 판이 잘린다. 셈은 **끝난 실행**만 세고(도는 중인 실행의 셈 칸은 `null`이다, C3) 표본이 없으면 **「—」**다(0%로 보이면 「다 실패했다」로 읽힌다). 비율은 **글자 + 막대**다 (색만으로 뜻을 전하지 않는다, 스타일 가이드 §7).
>
> 「확인률」은 C3 요약의 **`confirmations`**(확인만 센 수)로 잰다 — 결재는 빼고 센다. 그 칸은 **선택 칸**이라 보내지 않은 옛 기록은 **분모에서도 빠진다**(0으로 세면 확인률이 조용히 낮아진다). 아무도 보내지 않았으면 **「—」**다.
>
> 「배포된 Bot UI」는 **살아 있는 PC 배포의 `target.id`를 겹치지 않게 센 수**다 — **PC 배포에 전체(`*`) 대상이 없으므로**([ADR-0046](../decisions/0046-no-wildcard-pc-deployment.md)) 봉투 하나가 PC 하나를 가리키고, 이 수는 어림이 아니다. 건수는 **툴팁**에 둔다 — 같은 판을 같은 PC에 두 번 배포하면(옛 배포가 살아 있는 채) 건수가 PC 수보다 커, 「왜 수가 적나」의 답이 그 자리에 있어야 한다. **등록된 Bot UI와 맞춰 보지 않는다**: 가리킨 PC가 아직 등록하지 않았으면 그것은 **보여야 하는 어긋남**이다(잘못 서명한 배포가 0대로 숨으면 아무도 못 찾는다). 어느 PC가 정말 있는지는 CON-03이 말한다. 그 옆의 「실행 불가」는 **그 판을 실행 불가로 보고한 PC 수**다 (C4 `readiness`) — 어느 PC가 왜 막혔는지는 CON-03에 있다.
>
> 「재생률」은 **AI 태스크 중 재생된 비율**이다 (`replayed_tasks / ai_tasks`) — AI 태스크가 없는 버전은 「—」다.

## CON-03 Bot UI 현황

PC마다 하나인 Bot UI의 상태.

> 상태: **목록과 상세가 돈다** (M5 조각 4). 이름을 누르면 `/bot-uis/<id>`가 열리고 대기열·배포·확장·최근 배치 결정과 관리자 비활성화가 있다. 「배포」의 유효 기간은 **연도까지** 적는다 — 내일 끝나는 배포와 내년에 끝나는 배포가 같아 보이면 안 된다.

열: 온라인(마지막 하트비트 90초 이내 「● 온라인」 / 「○ 오프라인」 — 글자 포함. 오프라인이면 아래 실행·대기열 칸에 「마지막 보고 <시각> 기준」을 붙인다, U8) / Bot UI 이름 / 상태 / OS / 버전 / 마지막 하트비트 / 실행 중(`Bot@노드`, 하나 또는 「없음」) / **대기열**(N건, 신규) / **Worker 프로세스**(버전·상태, 신규) / **런타임**(브라우저·데스크톱 백엔드, 신규) / Center API 키(앞자리, 만료).
설명 줄: 「x/y 온라인」.

### 승인 대기 (초안, [ADR-0092](../decisions/0092-keys-are-issued-and-delivered-by-center.md))

> 상태: **초안** — 코드 아직. 지금은 CON-11에서 키를 발급해 현장에 건넨다.

**등록 요청이 있을 때만** 목록 위에 보인다 (C5 §등록 승인, `type=bot_ui`). 띠: 「승인을 기다리는 PC N대」.

| 열 | 내용 |
| --- | --- |
| 「요청 코드」 | `ABCD-EFGH` — 크게. 현장 Bot UI 화면(BUI-03·트레이)에 뜬 것과 같아야 한다 |
| 「PC 이름」 / 「OS」 / 「버전」 | 요청이 보낸 그대로 |
| 「요청한 곳」 | 요청이 온 주소 |
| 「요청 시각」 / 「남은 시간」 | 24시간에서 줄어든다 |
| 「이 PC의 자리」 | 이미 등록된 PC면 「<Bot UI 이름>을 이어받음」, 아니면 「새 PC」 |
| (관리자 계정) | 「승인...」 / 「거절...」 |

- 「승인...」 → 확인 창(기본 「취소」). 맨 위에 **「현장 화면의 요청 코드가 ABCD-EFGH인지 확인하세요.」** 칸은 「이름」 하나(기본은 요청의 PC 이름). 이미 등록된 PC면 한 줄 더: 「이 PC는 이미 「<이름>」으로 등록되어 있습니다. 승인하면 그 자리(배포·실행 기록)를 이어받고 옛 키는 폐기됩니다.」 「승인」을 누르면 줄이 사라진다. 현장이 다음에 물을 때(10초 안팎) 키를 받아 등록하면 그 PC가 목록에 나타난다 — 24시간 안에 등록하지 않으면 그 키는 폐기된다.
- 「거절...」 → 창: 「사유」(선택, 200자). 현장 화면에 그대로 보인다.
- 보기 전용 계정은 표만 보고 단추가 없다.
- 요청 코드는 **글자로만** 맞춘다 — 같은 이름의 PC가 둘이면 코드가 가른다. 결정한 요청은 표에서 빠지고 「누가·언제」는 C5 `decided_by`에 남는다.
- 상태 표기는 `status_map` 「등록 요청」(대기·승인됨·거절됨·만료)이다.

> 미정: `status_map`에 「등록 요청」 무리가 아직 없다. 토큰부터 더한다 (`docs/07-style-guide.md`).

상세 (목록에서 Bot UI 이름을 누름 — 따로 열린다, 신규 확장):
- 요약의 「버전」: `Bot UI <판> · core <판> · Worker <판>` 다음에 **어디서 도는지** — 묶은 것이면 「묶음 <커밋 앞 12자> · <묶은 때>」, 아니면 「개발 체크아웃」 (C4 `versions.build`, [ADR-0067](../decisions/0067-build-stamp.md)). 목록의 「버전」 열은 판만 보인다(태그 없이 묶은 것은 판에 `+g<커밋>`이 붙어 거기서 드러난다).
- 「대기열」 (신규): 순서 / Bot / 출처 / 요청 시각 / 만료. Bot UI가 하트비트로 보고한 그대로 (보기 전용; Center 작업은 CON-05에서 취소).
- 「배포」: 이 Bot UI의 활성 배포 목록 (배포 id / Bot / 버전 / 유효 기간 / 준비: 「준비됨」/「서비스 앱 키 없음」/「확장 없음」 — Bot UI가 보고). 배포 id는 「배포」(CON-15)의 그 줄로 가는 링크다 — 철회는 거기 한 곳에서 한다.
- 「확장」: 이 PC에 설치된 확장과 켜짐 여부 (C4 `extensions`).
- 「최근 배치 결정」: 시각 / 결과(「✅ 적용」/「⛔ 거부」) / 배포 id / 패키지 / 사유(코드를 글로: `bad_signature` 「서명이 맞지 않음」, `expired` 「유효 기간 지남」, `not_yet` 「아직 시작 전」, `wrong_target` 「다른 PC용」, `hash_mismatch` 「패키지 내용이 다름」, `unsigned_package` 「승인 서명 없음」, `revoked_key` 「서명 키 철회됨」) / 만료. 빈 상태: 「Bot UI가 올린 배치 결정이 아직 없습니다.」
- 관리자 계정: 「비활성화...」(확인 창, 기본 「취소」: 「이 PC에 새 작업·배포를 보내지 않습니다. 실행 중인 Bot은 끝까지 돕니다.」) / 「다시 활성화」 (신규, 비활성화된 Bot UI에는 새 작업·배포를 보내지 않는다. 하트비트는 받아 상태는 계속 보인다 — C4 `disabled`).

## CON-04 결재함

> 상태: **돈다** (M5 조각 5). 목록·상세·답하기·회수까지. 「답하기」는 **일반 폼 + 서버 액션**이라 JS 없이도 보내지고, 폼과 맞지 않는 답은 Center가 칸 이름과 함께 돌려주어 그 칸에 보인다. 아직 현장에서 올라오는 결재가 없다 — 엔진·실행기 연결은 다음 조각이다.
>
> **담당자와 대리 답** ([ADR-0080](../decisions/0080-approval-assignees.md)·[ADR-0081](../decisions/0081-answering-on-behalf.md)): 결재마다 그림이 정한 담당자가 보이고 그것으로 거른다. **콘솔은 담당자로 막지 않는다** — 관리자는 누구의 결재든 답할 수 있다(답한 사람은 로그인한 계정이다, ADR-0090). 대리 답용 키로 들어온 답은 「누가」와 「어느 키로」를 함께 보인다.

필터: 「상태」(대기/답함/시간 초과/회수됨/(전체)), 「실행하는 곳」(Bot UI·서버 실행기), 「담당」(이름 한 칸 — 비우면 전체. 그 이름이 담당자에 있는 결재만, C6 `?assignee=`).

열: 상태(아이콘 + 글자) / 제목 / 요청 id / 실행하는 곳(Bot UI 이름 또는 「서버」) / Bot / 변수 키(키만, U10) / 요청 시각 / 시한 / 담당(이름들, 없으면 「—」) / 답한 사람(대리 답이면 「<이름> · <키 이름>」) / 전달됨(실행하는 쪽이 답을 받아 감).
빈 상태: 「해당하는 결재 요청이 없습니다. 필터를 「(전체)」로 바꿔 보세요.」 (필터가 전체면 「기다리는 결재가 없습니다.」)

상세:
- 요약: 상태, Bot UI, Bot, 실행 id(누르면 CON-01), 담당(없으면 「담당자 없음 — 콘솔에서만 답합니다」), 요청한 쪽(그 실행을 시작한 작업의 `requested_by` — 작업 없이 시작했으면 줄이 없다).
- 「결재에 필요한 값 (업무 데이터)」 — 접혀 있음. 값이 보이는 유일한 곳.
- 대기가 아니면: 「답: <값> (<답한 사람> · <시각>)」 — 대리 답이면 「답: <값> — <이름>, 「<키 이름>」 키로 대리 답 (이름은 그 키를 쓰는 쪽이 확인)」, 회수됐으면 「회수됨 — <현장에서 먼저 답함 / 실행이 끝남 / 관리자 회수 / Bot UI 기록 유실>」.
- Bot UI가 답을 받아들이지 못했으면 요청은 다시 「대기」가 되고 위에 「Bot UI가 이전 답을 거절했습니다: <이유> — 고쳐서 다시 답하세요」를 보인다 (C6).
- 실행이 끝나거나 Bot UI가 기록을 잃으면 대기 중 결재는 자동으로 회수된다.
- 대기이고 관리자 계정이면 「답하기」:
  - 폼 필드에서 입력 칸을 만든다 (참/거짓 → 체크, 숫자 → 숫자, 선택지 → 고르기, 그 밖 → 글). 폼이 없으면 「승인」 / 「반려」 단추와 「메모」 한 줄 (C6 `decision`).
  - 「답하는 사람: <아이디>」 한 줄 — **로그인한 계정**이다 ([ADR-0090](../decisions/0090-center-admin-accounts.md)). 고칠 칸은 없다.
  - 담당자가 있으면 같은 줄에 「담당: <이름들>」을 보인다. **막지 않는다** — 담당이 아니어도 관리자는 답할 수 있다 (ADR-0080).
  - 폼과 맞지 않는 답은 Center가 거부하고 칸마다 오류를 보인다.
  - 성공: 「답을 보냈습니다. 실행하는 쪽이 다음 하트비트에 받아 갑니다.」
  - 「회수...」 → 확인 창(기본 「취소」): 「이 결재를 회수합니다. 그 노드에 오류 경계 이벤트가 없으면 실행은 실패로 끝납니다.」 → 「회수」. 결과: 「회수했습니다. 그 노드에 오류 경계 이벤트가 없으면 실행은 실패로 끝납니다.」

## CON-05 작업 지시

필터: 「상태」(대기/전달됨/대기열/수락/거절/만료/취소됨, 여러 개), 「Bot UI」, 「최대」(10~1000).

열: 상태 / 작업 id / 실행 위치 / Bot UI(서버면 「서버」) / Bot(`이름@버전` 또는 「(배포된 버전)」) / 입력 키 / 요청자(사람 또는 「서버 Bot <이름> (실행 id)」 — PC 위임, 누르면 CON-01) / 요청 시각 / 만료 / 실행 id / 실행 상태 / 사유 / 메모.
빈 상태: 「작업 지시가 없습니다. 「새 작업...」으로 만드세요.」

상세: 상태, Bot UI, 실행 id, 실행 상태, 거절 사유. 「입력 (업무 데이터)」 접힘. 「전체 JSON」 접힘(입력 제외).

관리자 계정 (신규 — 프로토타입은 명령줄만):
- 「새 작업...」 단추 → 화면 `/jobs/new`. **두 걸음이고 JS 없이 돈다**: 먼저 「Bot」 → 「Bot UI」(그 Bot이 배포된 Bot UI만 — **PC 배포는 대상이 하나씩이라 풀 것이 없다**, [ADR-0046](../decisions/0046-no-wildcard-pc-deployment.md). 실행 위치가 서버인 Bot이면 이 칸 대신 「서버 실행기에서 실행 — 동시 실행 상한 <n>」 — M7) → 「버전」을 고르고 「고르기」(주소에 남는다). 그다음 칸들: 「입력 변수」(**매니페스트의 `inputs`**(C1)로 칸을 그린다 — 타입마다 칸 종류, 필수는 `*`, 설명은 칸 아래. 아래에 「그 밖의 입력 (한 줄에 하나, 이름 = 값)」), 「만료」(비우면 없음), 「메모」, 「작업 만들기」. 「버전」은 같은 Bot UI에 그 Bot의 배포가 **둘 이상일 때만** 고르게 하고, 하나면 「(배포된 버전) <버전>」으로 보이며 비워 보낸다. 고를 Bot UI가 없으면 「이 Bot이 배포된 Bot UI가 없습니다」, 배포가 없으면 「이 Bot UI에 유효한 배포가 없습니다」(422 `no_deployment`). 만들면 그 작업의 상세로 가서 「작업을 만들었습니다. Bot UI가 다음 하트비트에 받아 갑니다.」
- 대기·전달됨·대기열 상태 작업의 「취소」. 대기면 바로 「취소됨」. 전달됨·대기열이면 「취소 요청함 — 다음 하트비트에 반영」으로 보이고, Bot UI가 빼내면 「취소됨」. 그사이 이미 시작됐으면 작업은 「수락」 그대로이고 옆에 「취소 못 함 — 이미 시작됨」을 붙인다 (C5).
- **「수락」(실행 중) 작업도 대상이 서버 실행기면 취소할 수 있다** ([ADR-0063](../decisions/0063-stopping-a-running-server-run.md)): 확인 창(기본 「취소」) 「도는 실행을 멈춥니다. 한 일은 되돌리지 않습니다 — 이미 보낸 메일·웹훅은 그대로입니다.」 → 「중지」. 그다음 「중지 요청함 — 다음 하트비트에 반영」으로 보이고, 실행기가 닫으면 「취소됨」이다. **PC 대상이면 단추를 끄고** 「실행 중인 PC Bot은 현장에서 멈춥니다 (Bot UI 「중지」)」를 적는다 — 화면을 만지는 중일 수 있어서다 (ADR-0014).
- 「대기열」 상태 줄에는 「Bot UI 대기열 N번째 — 실행 중 <Bot>」을 보인다. 거절 사유: 「대기열 가득」, 「배포 없음」, 「준비 안 됨」, 「Bot UI 종료」, 「Bot UI 기록 유실」(비정상 종료), 「서버 실행 Bot」.

## CON-06 공통 패키지

Bot이 아닌 패키지(지금은 공유 BPM 프로세스뿐이다 — 도구 묶음은 패키지가 아니다, [ADR-0050](../decisions/0050-no-toolpack-kind.md)). 빈 상태: 「올라온 공통 패키지가 없습니다. Studio의 「공유 BPM 프로세스로 내보내기...」로 만든 패키지를 올리세요.」

열: id / 버전 / 종류 / 이름 / 상태 / 올린 시각 / 올린 이 / 내려받은 횟수.

상세:
- 요약: 종류, 상태, 설명, 「실행 요구」, 「내려받기」(`<n>회 · 마지막 <시각>`, 한 번도 없으면 「아직 없음」).
- 「제공 정의」(공유 BPM 프로세스): 정의 id / 이름 / 파일 / 읽는 변수 / 쓰는 변수 / AI 태스크 / 결재 / 설명.
- 「이 패키지를 쓰는 패키지」: id / 버전 / 종류 / 이름 / 상태 / 관계 / 고정 해시. 없으면 「아직 없습니다.」
- 요약의 「승인」: 승인한 계정과 시각 (사람이 서명하던 때의 승인은 계정 대신 서명 키 id), 아직이면 「아직」.
- 관리자: CON-02와 **같은 승인 단추**(상태별 「승인...」·「승인 철회...」·「지원 종료...」)와 「삭제...」 → 확인 창(기본 「취소」): 「되돌릴 수 없습니다.」 참조되면 409 → 이유.

> 상태: **돈다.** 목록·상세·「실행 요구」·「이 패키지를 쓰는 패키지」(C5 `dependents`)·관리자 「삭제...」까지. 목록은 `GET /packages`를 한 번 읽어 **콘솔에서 Bot 아닌 종류만** 가린다. 「삭제...」는 CON-07 「등록 해제...」와 같은 확인 창이라 **JS가 필요하다**(되돌릴 수 없는 동작은 확인 창을 거치게 두었다) — 참조되면 409 `in_use`이고 **아무것도 지워지지 않은 채** 막은 배포·패키지가 그 자리에 보인다.
>
> 「제공 정의」는 매니페스트의 `provides`(C1)를 그린다. `provides`가 없으면 그 칸은 「매니페스트에 없습니다」라고 말한다 — **빈 표로 두지 않는다**(「제공하는 것이 없다」와 「적히지 않았다」는 다르다).
>
> 「내려받은 횟수」는 C5 `download_count`다 — Center가 **관문을 지나 파일을 내어 줄 때** 센다(막힌 요청은 세지 않는다). **같은 곳이 다시 받아도 센다** — 「몇 곳이 쓰나」는 「이 패키지를 쓰는 패키지」와 배포 목록이 말한다. **「제공 도구」는 없다** — `provides.tools`가 계약에서 사라졌다 (ADR-0050).

## CON-07 리소스 (신규)

Bot이 실행에 쓰는 바깥 기능의 목록이다 (계약 C7). 관리자가 여기서 묻는 것은 하나다. **「이 기능을 Bot이 지금 쓸 수 있나? 안 되면 내가 무엇을 하나?」**

확장은 BPM 프로세스에서 통신 방식·주소·키·호출 형식을 일일이 정하지 않고 **이름 하나로 가리켜 쓰게** 하려고 둔 틀이다. 운영 화면도 같은 틀을 지킨다. 그 기능이 안에서 어떻게 도는지(서비스 앱인지 외부 앱인지, 무엇을 기여하는지, 어떤 로컬 런타임을 띄우는지)는 보이지 않는다. 키는 Center가 발급해 내려 주므로([ADR-0092](../decisions/0092-keys-are-issued-and-delivered-by-center.md)) 이 화면에 「키를 발급하러 가라」는 할 일도 없다.

**칸을 두는 기준:** 사람이 그것을 보고 **고치거나**, **판단하거나**, **문제를 풀 때 쓰는** 것만 둔다. 그 밖의 것은 다른 화면이 이미 쓰고 있으면 그쪽에 두고(Studio·CON-03), 쓰는 곳이 없으면 두지 않는다.

> 상태: **화면 문서만 바뀌었다 — 코드는 아직 옛 모양이다.** 지금 콘솔에는 고정 탭 셋(「확장」·「서비스 앱」·「런타임」)과 기여 자원 탭이 있다. 「확장」 탭은 등급·연결 방식·기여 요약을, 「서비스 앱」 탭은 작업 목록·수행 모드를 보인다. 계약(C7 `GET /resources`의 네 종류)은 그대로이고, 콘솔 서버(BFF)가 그것을 맞춰 이 모양으로 그린다. 외부 앱 키를 넣는 자리는 ADR-0092의 C7 변경이 들어와야 돈다.
>
> 미정: 「할 일」을 확장 정의의 선언(서버 주소·키·설정)에서 지으려면 **Center가 모든 확장의 정의를 가져야 한다.** 지금 Center는 외부 확장의 정의만 갖고, 내장·사내 확장은 서비스 앱 manifest와 현장 보고로 짐작한다. 그 전까지 「할 일」은 Center가 가진 것으로 지어서 빠지는 항목이 있을 수 있다. C7·C13을 함께 고칠 일이다.

탭: 「기능」(기본)과, 확장이 기여한 자원 종류마다 탭 하나(예: 「UI 화면 (N)」). 「서비스 앱」·「런타임」 탭은 없다.

경고 띠(맨 위): 「Bot이 요구하지만 쓸 수 없는 기능: …」 (배포 전 확인용, C7 누락 검사). 항목을 누르면 그 기능의 줄로 간다.

### 「기능」 목록

한 줄이 기능(확장) 하나다. **쓸 수 없는 것이 맨 위**다.

| 열 | 내용 |
| --- | --- |
| 「이름」 | 확장 이름. 누르면 상세 |
| 「쓸 수 있나」 | 「쓸 수 있음」 / 「쓸 수 없음」 / 「확인 전」 |

### 관리자 동작

- 「기능 추가 (외부)」 (목록 아래) → **외부 확장 정의 파일 하나**를 올리고 「등록」. 검사를 지나면 Center가 C2 `extension` 봉투에 서명해 둔다 ([ADR-0090](../decisions/0090-center-admin-accounts.md)). 걸리면 C13 위반을 칸마다 보인다. 키를 받는 앱이면 다음 화면이 곧바로 「키 넣기...」다.
- 「서비스 앱 추가...」 (목록 아래) → 창: 「API 주소」 → Center가 manifest를 읽어 **이름과 어느 기능의 서버인지**를 미리 보여 주고 「등록」. 등록하면 그 기능의 줄에 붙는다.
- 「주소 넣기...」 (줄의 할 일) → 「서비스 앱 추가...」와 같은 창이다. 읽은 manifest의 `extension.id`가 **그 줄의 기능과 다르면 등록하지 않고** 까닭을 보인다.
- 「키 넣기...」 → 창: 키 한 칸(가려서 받는다). 「저장」하면 Center가 암호화해 두고, 쓰는 Bot이 배포된 곳에 내려 준다. 창을 닫으면 원문은 화면 어디에도 남지 않는다.
- 「등록 해제...」 → 확인 창(기본 「취소」). 이때 **쓰는 Bot**을 보인다. 서비스 앱은 쓰는 Bot이 있으면 막는다(C7 `in_use`). 외부 기능은 막지 않고 「이 기능을 쓰는 Bot N개가 실행 불가가 됩니다. 되살릴 수 없습니다.」라고 말한다 — Center가 `extension_revoke` 봉투에 서명한다.
- 모든 탭에 「새로 고침」(바로 다시 읽기).

### 기여 자원 탭

기여 자원 탭의 칸은 카탈로그의 **공통 칸**(자원 id·이름·요약·기여한 기능·마지막 갱신·쓰는 Bot)뿐이다. `data`는 확장 고유 내용이라 Center도 콘솔도 해석하지 않는다 (C13 §5). 요약은 `summary` 한 줄로 오고, 자세한 것은 그 확장의 관리 콘솔에서 본다. 카탈로그를 읽지 못하면 **빈 목록이 아니라 띠로 말한다** — 「없다」와 「못 읽었다」는 다르다. 빈 상태: 「<기능>이 아직 올린 <자원>이 없습니다.」

| 탭 | 열 | 상세 |
| --- | --- | --- |
| 「UI 화면」 (UI 자동화 확장 기여 — 기여 자원 탭의 예) | 화면 id / 이름 / 요약 / 마지막 등록 | 「이 화면을 쓰는 Bot」. 「셀렉터 보기」 → UI 자동화 앱 관리 콘솔 UIA-02 (새 탭) |

Center는 서비스 앱에서 공개 정보(`/healthz`, `/manifest`, UI 자동화 앱의 셀렉터 없는 카탈로그)만 읽는다 (C7).

UI 자동화 개요·셀렉터·모니터링은 **UI 자동화 앱의 관리 콘솔**로 옮겼다 ([ADR-0013](../decisions/0013-api-keys.md)). → [service-app-console.md](service-app-console.md) UIA-01 ~ UIA-03.

## CON-11 Center API 키 (신규)

Bot UI·Studio·서버 실행기·외부 시스템(연동용·대리 답용)이 Center에 접속할 때 쓰는 키를 발급·폐기한다 ([ADR-0013](../decisions/0013-api-keys.md) §1). 빈 상태: 「발급한 키가 없습니다. 「새 키...」로 Bot UI용 키부터 만드세요.」 서비스 앱 키는 여기서 다루지 않는다 (각 서비스 앱 관리 콘솔).

필터: 「종류」(Bot UI용 / Studio용 / 서버 실행기용 / 연동용 / 대리 답용), 「상태」(사용 중 / 만료 / 폐기됨).

| 열 | 내용 |
| --- | --- |
| 「이름」 | 사람이 알아볼 이름 (예: 「재무팀 PC-03」) |
| 「종류」 | Bot UI용 / Studio용 / 서버 실행기용 ([ADR-0015](../decisions/0015-run-location.md)) / 연동용 (외부 시스템이 작업을 만들거나 **메시지를 넣을 때** — C5·[C12](../03-contracts/C12-server-runner-center.md) §메시지) / 대리 답용 (연동하는 쪽이 **사람 대신 결재에 답할 때만** — 담당인 결재만 읽고 답한다, C6·[ADR-0081](../decisions/0081-answering-on-behalf.md)) |
| 「연결된 대상」 | Bot UI용·서버 실행기용: 그 키로 등록된 대상(PC·서버 이름, 처음 등록 시각), 아직 안 쓰였으면 「등록 전」 · Studio용: 사용자 이름 · 연동용: 메모(어느 외부 시스템인지)와 최근 만든 작업 수 · 대리 답용: 메모(어느 연동인지) |
| 「앞자리」 | 앞 16자 (`chk_ctr_` + 무작위 8자). 원문은 보이지 않는다 |
| 「만든 날」 / 「만료」 / 「마지막 사용」 | |
| 「상태」 | 사용 중 / 만료 / 폐기됨 |

관리자 계정:
> 초안 ([ADR-0092](../decisions/0092-keys-are-issued-and-delivered-by-center.md)): **Bot UI용·서버 실행기용 키는 여기서 발급하지 않는다** — 등록 승인(CON-03·CON-12 「승인 대기」)이 만든다. 목록에는 그대로 보이고 「연결된 대상」에 「승인으로 발급」이 붙는다. 「새 키」의 종류는 Studio용·연동용·대리 답용만 남는다(Studio용은 로그인으로 바뀌는 다음 조각에서 빠진다). 「묶음 풀기」는 **승인이 만든 키에는 없다** — PC를 다시 설치했으면 새 등록 요청을 승인하면 그 자리를 이어받는다. 아래 글은 지금 코드의 모양이다.

- 「새 키」 → 창: 이름, 종류, 만료(기본 1년). 「발급」을 누르면 **원문을 한 번만** 보여 준다: 「이 키는 다시 볼 수 없습니다. 지금 복사해 Bot UI 설정(또는 Studio 설정)에 넣으세요」 + 「복사」 단추.
- 종류가 「대리 답용」이면 창에 한 줄을 더 보인다: 「이 키를 가진 쪽은 결재 담당자의 이름을 대면 그 사람 대신 답할 수 있습니다. 사람 확인은 그쪽이 합니다.」
- 「폐기」(확인 창, 기본 단추 「취소」): 「이 키를 쓰는 Bot UI <이름>의 하트비트가 바로 거부됩니다. 실행 중인 Bot은 끝까지 돌지만 기록은 쌓아 둡니다.」
- 「묶음 풀기」(Bot UI용·서버 실행기용, 확인 창, 기본 「취소」): PC를 다시 설치해 같은 키로 다시 등록해야 할 때. 다음 `register`가 새 PC에 묶인다. **그 PC 자리도 함께 놓인다** — 키를 잃어 새 키를 발급한 경우, 새 키가 그 PC를 등록하면 같은 Bot UI 자리를 이어받는다 (실행 기록·배포가 그대로 산다, C4 「키 묶기」).
- Bot UI용 키 하나는 Bot UI 하나에만 묶인다. 이미 다른 PC가 등록한 키로 다시 등록하려 하면 거부한다 (「이 키는 <PC>에서 쓰고 있습니다」).
- **거꾸로도 하나다** — 이미 등록된 PC를 **다른 키**로 등록하려 하면 거부한다 (「이 PC는 이미 「<이름>」으로 등록되어 있습니다」). 같은 PC가 두 줄로 보이지 않게 하는 것이고, 바꾸려면 옛 키의 「묶음 풀기」가 먼저다. 키 하나가 혼자서 남의 PC 자리를 가져갈 수 없다.

## CON-12 서버 실행 (신규, M7)

실행 위치가 「서버」인 BPM 프로세스(서버 Bot)의 실행 상황 ([ADR-0015](../decisions/0015-run-location.md)). 서버 실행기는 Center가 관리한다.

**목록과 상세로 나눈다** (CON-03과 같은 결) — 실행기가 여럿일 수 있고, 아래 「실행 중」·「기다리는 실행」·「Bot별 상한」은 **실행기 하나의 것**이라 열에 실행기 이름이 없다. 한 화면에 쌓으면 그 세 표에 「서버」 열을 더해야 하고, 그러면 실행기가 하나인 흔한 경우에 쓸데없는 열이 남는다.

**「대기열」만 목록 쪽에 둔다.** 서버 작업은 **내려가기 전까지 어느 실행기에도 묶이지 않는다** (C12 — 대기열은 Center가 가진다). 상세에 넣으면 같은 작업이 실행기마다 모두 보여 「어디서 도는 건가」를 거짓으로 말한다.

### 목록 (`/server-runners`)

| 열 | 내용 |
| --- | --- |
| 「온라인」 | 「● 온라인」/「○ 오프라인」 (마지막 하트비트가 3분 안인가 — C12) |
| 「이름」 | 누르면 상세 |
| 「상태」 | 「동작」/「일시 중지」/「정리 중」/「오류」/「오프라인」 |
| 「실행 중 / 상한」 | `n / N` (`capacity`). **기다리는 실행은 세지 않는다** (ADR-0054 §5) |
| 「기다리는 실행」 | 건수 |
| 「대기열」 | Center가 센 건수 (C12 `queued`) |
| 「OS」 / 「버전」 / 「마지막 하트비트」 | |
| 「Center API 키」 | 앞자리와 만료 (**연도까지** — CON-03과 같다) |

**「승인 대기」** — 등록 요청이 있을 때만 목록 위에 보인다. **CON-03 「승인 대기」와 같은 표·같은 창**이고 `type=server_runner`만이다 (C12 §등록 요청과 승인, 초안 — [ADR-0092](../decisions/0092-keys-are-issued-and-delivered-by-center.md)). 다른 것은 하나다: 요청 코드는 서버 실행기의 **시작 로그**에 있으므로 확인 창의 첫 줄이 「서버 실행기 로그의 요청 코드가 ABCD-EFGH인지 확인하세요.」다.

머리글에 「n/m 온라인」. 그 아래 **「대기열」 표** — 작업 id / 서버 Bot / 요청 시각 / 대기 이유(「전체 상한」/「Bot별 상한 n」) / 만료. 작업 id를 누르면 CON-05 상세로 간다.

### 상세 (`/server-runners/<id>`)

| 섹션 | 내용 |
| --- | --- |
| 「서버 실행기」 | 목록의 값 + 확장(C12 `extensions`) · 보고하지 못한 실행 기록 수(`unsent_events`) · 최근 배치 결정 |
| 「실행 중」 | 실행 id / 서버 Bot / 버전 / 현재 노드 / 시작 / 경과 → 누르면 CON-01 상세 |
| 「기다리는 실행」 | 실행 id / 서버 Bot / 기다리는 것(결재·메시지·타이머·PC 위임 — PC 위임이면 작업 id → CON-05) / 기다린 시간 / 결재면 CON-04 링크. 상한에 세지 않는다 |
| 「Bot별 상한」 | 서버 Bot / 배포 버전 / 상한(배포 서명에 들어 있음, 보기 전용. **적혀 있지 않으면 「기본」** — 계약의 기본값을 화면에 베껴 적지 않는다) / 지금 실행 수 / 준비(「준비됨」/「서비스 앱 키 없음: <참조>」/「확장 없음」 — C12 `readiness`. 키는 서버에서 환경변수 `CHK_SERVER_RUNNER__SVC__<참조>`로 준다) |

**「Bot별 상한」의 줄은 배포가 정한다** (C5 활성 배포 — 이 실행기 것과 전체 `"*"` 것). 실행기가 아직 준비 상태를 올리지 않은 Bot도 **보여야** 하고(「배포는 했는데 왜 안 도나」가 이 화면에서 풀려야 한다 — CON-03과 같은 결), 거꾸로 `readiness`로 줄을 지으면 그 Bot이 아예 사라진다. 보고가 없는 줄의 「준비」는 「보고 없음」이다.

「기다리는 것」은 C12 `waiting[]`의 짝 칸으로 적는다 — 결재면 `request_id`, **메시지면 메시지 이름과 상관 키**, 타이머면 울릴 시각(**연도까지**). 모르는 `waiting_for`는 그대로 보인다 (열린 문자열이다).

**PC 위임도 보인다** ([ADR-0062](../decisions/0062-pc-delegation.md)) — 기다리는 것은 「PC 위임 \<작업 id\>」이고 링크는 **그 작업**(CON-05)으로 간다. 그 줄의 요청자는 「서버 Bot \<실행 id\>」라 거기서 서버 실행으로 되돌아올 수 있다.

상태 표기: 서버 실행기 「동작」 / 「일시 중지」 / 「정리 중」(draining) / 「오류」 / 「오프라인」 · 대기 이유 「전체 상한」 / 「Bot별 상한 n」 / 「일시 중지」.

관리자 계정: 서버 실행기 「일시 중지...」(확인 창: 「새 실행을 받지 않습니다. 실행 중인 것은 끝까지 돕니다.」) / 「다시 시작」 (C12 `POST /server-runners/{id}/pause`·`resume`), 오프라인 실행기의 「유실 처리...」(확인 창, 기본 「취소」: 「이 실행기의 실행 N건을 실패로 닫고 결재를 회수합니다. 되돌릴 수 없습니다.」, C12 `mark-lost` — **온라인이면 단추를 끄고 까닭을 적는다**), 대기열 작업 「취소...」(CON-05와 같은 길). **도는 실행을 멈추는 것도 CON-05의 그 길이다** — 멈추는 손잡이는 **작업 하나**이고(서버 실행은 작업으로만 시작된다, C12) 여기 따로 두지 않는다 ([ADR-0063](../decisions/0063-stopping-a-running-server-run.md)).

빈 상태: 「등록된 서버 실행기가 없습니다. Center API 키(서버 실행기용)를 발급해 서버 실행기 설정에 넣으세요.」 대기열이 비면 「기다리는 작업이 없습니다.」

## CON-13 가상 직원 (신규)

사람이 아닌 업무 주체 — 접수 Bot과 감독자를 묶는다 ([ADR-0085](../decisions/0085-virtual-worker-resource.md), C5 §가상 직원). **일괄은 접수 Bot 실행 한 번**이고(ADR-0079) 화면은 Center가 읽을 때 이어 붙인 것을 보인다 — 콘솔이 세지 않는다.

### 목록 (`/virtual-workers`)

| 열 | 내용 |
| --- | --- |
| 「이름」 | 누르면 상세 |
| 「id」 | `vw:` 없이 id만 |
| 「접수 Bot」 | 패키지 id |
| 「감독자」 | 이름들, 없으면 「—」 |
| 「상태」 | 「사용 중」 / 「멈춤」 (`status_map` 「가상 직원」). **멈춤은 새 작업을 막지 않는다** — 막는 것은 배포다 |

빈 상태: 「등록한 가상 직원이 없습니다.」 — 관리자 계정이면 아래에 「새 가상 직원」 폼(id·이름·감독자(쉼표로)·접수 Bot)이 있다. 등록이 거부되면 Center의 사유를 그대로 보인다 — 「결재 없는 일괄 기동이 있습니다 (B16)」이면 그 판과 메시지를 함께 보인다.

### 상세 (`/virtual-workers/<id>`)

- 요약: 이름, id, 접수 Bot, 감독자, 상태, 만든 날·바꾼 날.
- 「최근 일괄」 표 (최근 20개):

| 열 | 내용 |
| --- | --- |
| 「일괄」 | 접수 실행 id — 누르면 CON-01 |
| 「상태」 | 그 실행의 상태 (`status_map` 「실행·노드」) |
| 「시작」 | 시각 |
| 「기동한 건」 | 자식 실행 수와 상태별 수 (「3 — 완료 2 · 실패 1」) |
| 「결재」 | 열린 일괄 결재가 있으면 「대기」와 CON-04 링크, 없으면 「—」 |

- 빈 상태: 「아직 일괄이 없습니다. 접수 Bot이 실행되면 여기 보입니다.」
- **감독자와 결재 담당자는 다른 칸이다** — 담당자는 그림이 정한다(C14 `assignees`). 상세는 그 차이를 맞춰 보지 않는다.
- 관리자 계정: 「멈추기」 / 「다시 쓰기」(상태만 바꾼다), 「등록 해제...」(확인 창, 기본 「취소」): 「등록만 지웁니다. 실행·작업 기록은 남습니다.」

## CON-14 관리자 계정 (신규)

콘솔에 들어오는 사람 ([ADR-0090](../decisions/0090-center-admin-accounts.md), C5 §관리자 계정). **관리자에게만** 탐색에 보인다.

> 상태: **돈다** (`app/accounts`).

```
+--------------------------------------------------------+
| [H] title · count                        [New account] |
| [L] accounts table                                     |
+--------------------------------------------------------+
```

| 열 | 내용 |
| --- | --- |
| 「아이디」 | |
| 「역할」 | 「관리자」 / 「보기 전용」 |
| 「상태」 | 「사용 중」 / 「멈춤」 (`status_map` 「관리자 계정」) |
| 「마지막 로그인」 | **연도까지**, 없으면 「—」 |
| 「만든 이」 | 「<만든 계정> · <때>」 (첫 관리자는 「설치」) |
| (끝 칸) | **자기 줄**은 「비밀번호 바꾸기...」 하나. **남의 줄**은 「...」 — 펼치면 「관리자로 바꾸기...」·「보기 전용으로 바꾸기...」 / 「멈추기...」·「다시 쓰기」 / 「비밀번호 새로 정하기...」 |

- 「새 계정...」 → 창: 「아이디」(도움말 「영문 소문자·숫자·.·_·- 3~32자」), 「처음 비밀번호」(도움말 「12자 이상, 영문과 숫자를 모두 넣습니다.」), 「역할」(기본 관리자), 「만들기」. 규칙에 어긋나면 Center의 까닭을 창 안에 보이고 닫지 않는다.
- 「멈추기...」 → 확인 창(기본 「취소」): 「그 계정은 바로 로그아웃되고 다시 들어올 수 없습니다. 기록에 남은 이름은 그대로입니다. 「다시 쓰기」로 되돌릴 수 있습니다.」 「다시 쓰기」는 묻지 않는다(되돌릴 수 있고 해가 없다, U9).
- 역할 바꾸기는 확인 창 「그 계정은 다시 로그인해야 합니다.」
- 「비밀번호 새로 정하기...」 → 창에 새 비밀번호 한 칸. 지금 비밀번호를 묻지 않는다(관리자가 정해 준다). 그 계정은 다시 로그인해야 한다.
- 「비밀번호 바꾸기...」(자기) → 창: 「지금 비밀번호」·「새 비밀번호」·「새 비밀번호 확인」. 바꾸면 로그인 화면으로 간다.
- **계정은 지우지 않는다** — 기록의 「누가」가 가리킬 곳이 남아야 한다. **마지막 관리자를 멈추거나 보기 전용으로 바꾸려 하면** Center가 막고 「마지막 남은 관리자는 … 다른 관리자를 먼저 만드세요」를 그 줄에 보인다.

## CON-15 배포 (신규)

배포를 **만들고 철회하는 한 곳**이다 ([ADR-0090](../decisions/0090-center-admin-accounts.md) — 옛 ADM-03). CON-03·CON-12의 배포 줄은 여기로 잇기만 한다 (같은 단추는 한 곳). 봉투는 Center가 서명한다.

> 상태: **돈다** (`app/deployments`, `app/deployments/new`).

### 목록 (`/deployments`)

머리글: 「살아 있는 배포 N건 · 철회된 것도 보기」(누르면 전체 — 철회된 것도 행이 남는다, C5). 관리자면 오른쪽에 「새 배포...」.

| 열 | 내용 |
| --- | --- |
| 「배포 id」 | CON-03에서 이 줄로 온다 |
| 「Bot@버전」 | |
| 「대상」 | PC 이름(등록 기록이 없으면 id 그대로), 서버면 「서버 (전체)」 / 「서버 <실행기 이름>」 |
| 「상태」 | 「활성」 / 「예약」(시작 전) / 「만료」 / 「철회됨」 (`status_map` 「배포」) |
| 「유효 기간」 | 「<시작 또는 즉시> ~ <끝 또는 무기한>」, **연도까지** |
| 「동시 실행」 | 서버 배포만. 적지 않았으면 「기본」 |
| 「누가」 | 배포한 계정. 철회됐으면 「철회 <계정>」. 사람이 서명하던 때의 배포는 「—」 |
| 「배포한 때」 | |
| (끝 칸) | 관리자에게 「철회...」 → 확인 창(기본 「취소」): 「현장은 다음 하트비트에 이 Bot을 내립니다. 도는 실행은 끝까지 갑니다. 되돌릴 수 없습니다 — 다시 쓰려면 새로 배포하세요.」 |

빈 상태: 「배포가 없습니다.」 + 관리자면 「승인된 Bot을 「새 배포...」로 배포하세요.」

### 새 배포 (`/deployments/new`)

**두 걸음이고 JS 없이 돈다** (CON-05 「새 작업」과 같은 결):

1. 「Bot@버전 (승인된 것)」을 고르고 「고르기」 (주소에 남는다). 승인된 것이 없으면 「승인된 Bot이 없습니다. 「Bot 현황」에서 먼저 승인하세요.」
2. 그 판의 실행 위치로 대상 칸이 갈린다.
   - **PC**: 「대상 — Bot UI (여럿 고를 수 있습니다)」 — 등록된 Bot UI마다 체크 칸(이름 · 「● 온라인」/「○ 오프라인」). **비활성 PC는 없다**. 고른 PC마다 배포가 하나씩 생긴다 (PC 배포에 전체 대상은 없다, ADR-0046). 없으면 「등록된 Bot UI가 없습니다. PC에서 Bot UI를 한 번 연결해야 배포할 수 있습니다.」
   - **서버**: 「실행기」(「전체」 + 등록된 실행기), 「동시 실행 상한 (비우면 기본)」.
   - 공통: 「시작 (비우면 즉시)」, 「끝 (비우면 무기한)」, 「배포」.
3. 되면 목록으로 가서 「배포 N건을 만들었습니다. 현장은 다음 하트비트에 받아 설치합니다.」 Center가 거부하면(대상·리소스 누락·지원 종료 등, C5) 그 까닭을 이 화면 위에 보인다. 여러 PC 중 일부가 먼저 됐으면 「먼저 만든 배포 n건은 남았습니다」를 붙인다.
