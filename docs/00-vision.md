# 00. 비전과 범위

## 한 문장

업무 담당자가 **BPMN으로 BPM 프로세스를 그리면**, Center가 그것을 현장 PC의 **Bot UI**에 **Bot**으로 배포하고, 각 단계의 실제 일(웹·데스크톱 화면 조작, 문서 읽기, 판단, 서버 API 호출)은 **AI·Worker·서비스 앱이 수행**하며, 사람은 **정해진 지점에서만 결재·확인**한다.

## 핵심 원칙: 지도 · 운전사 · 실행 · 손

| 역할 | 담당 | 정하는 것 | 넣지 않는 것 |
| --- | --- | --- | --- |
| 지도 | BPMN | 순서, 분기, 결재, 마감, 감사 기록 | 셀렉터, 클릭 좌표, 프롬프트 요령 |
| 운전사 | AI (AI 태스크, 서비스 앱의 LLM) | 각 단계 목표에 도달하는 방법, 도구 선택, 실패 시 복구 | 업무 순서, 승인 규칙 |
| 실행 | Bot UI가 Bot(BPM 프로세스)을 실행 (개발 중에는 Studio) | 태스크를 차례로 수행하며 운전사·손·서비스 앱을 부른다 | 화면 조작 자체 |
| 손 | Worker 프로세스 (실행 중인 Bot이 REST로 요청) | 요청받은 화면 요소를 결정적으로 조작, 셀렉터 자기 치유 | 업무 판단, 업무 흐름 |

프로토타입 4개 모두에서 유지된 가장 중요한 설계 규칙이다 ([ADR-0008](decisions/0008-map-driver-hands-boundary.md), [ADR-0012](decisions/0012-bot-ui.md)).
BPM 프로세스가 호출하는 서버 기능은 **서비스 앱**으로 늘려 간다. 같은 BPM 프로세스도 Studio에서는 **자율 수행**(AI가 방법을 찾고 학습), Bot에서는 **결정 수행**(학습된 대로)으로 돈다 ([ADR-0010](decisions/0010-service-apps.md)).

## 누가 쓰는가

| 사용자 | 하는 일 | 주로 쓰는 것 |
| --- | --- | --- |
| BPM 프로세스 설계자 | BPM 프로세스를 그리고, 시험 실행으로 학습시키고, 패키지로 올린다 | Studio + Bot UI (Windows) |
| 화면 등록 담당자 | 자동화 대상 화면의 요소(버튼·입력칸)를 등록·검증한다 | Bot UI의 「UI 셀렉터 등록」 (Windows) |
| 운영 관리자 | 패키지 승인·배포, Bot UI 상태 확인, 작업 지시, 실행 이력 조회, Center API 키 발급 | Center 콘솔, Admin |
| 서비스 앱 관리자 | 서비스 앱 API 키 발급, 앱 상태·사용 기록 확인 | 각 서비스 앱 관리 콘솔 |
| 업무 결재자 | Bot이 올린 결재 요청에 답한다 | Center 콘솔 결재함 (또는 현장 PC의 결재 창) |
| 현장 PC 사용자 | Bot UI를 켜 두고, 필요하면 확인 요청에 답한다 | Bot UI (Windows) |

## 대표 시나리오 (프로토타입에서 검증된 것)

새 플랫폼의 기능 범위와 인수 시험의 기준으로 쓴다. 자세한 내용은 [reference/lessons-learned.md](reference/lessons-learned.md).

| # | 시나리오 | 확인하는 능력 | 프로토타입 결과 |
| --- | --- | --- | --- |
| 1 | 신규 거래처 등록 심사 | 포함 게이트웨이, 조건별 검토 켜기 | 케이스 3/3 통과 |
| 2 | 입사 첫날 온보딩 | 하위 프로세스, 묶음 마감 타이머, 수동 작업 | 케이스 3/3, 재생 3/3 |
| 3 | 세금계산서 발행 | 웹에서 조회 → 데스크톱 앱에 입력 (웹 + 데스크톱) | 케이스 2/2, 재생 2/2 |
| 4 | 계약서 조항 검토 | Call Activity, 변수 매핑, 같은 절차 반복 | 진행 중이었음 |

> 제안: 새 플랫폼의 첫 번째 끝-끝 목표는 **시나리오 3을 Windows 현장 PC에서** 돌리는 것이다. UI 태스크(Worker)·데스크톱 조작(UIA)·BPMN·Center 배포·Bot UI를 한 번에 확인할 수 있다.

## 만드는 것 (범위)

1. **Studio** — BPM 프로세스 편집(BPMN), 시험 실행, 학습, 패키지 빌드. Windows 데스크톱 앱.
2. **Center** — 패키지 레지스트리, Bot UI 등록·상태, 배포, 작업 지시, 결재 창구, 실행 이력, 리소스 목록, Center API 키. Linux 서버. 웹 화면은 **Center 콘솔**.
3. **Bot UI** — 항상 떠 있는 트레이 기반 GUI 프로그램. Bot(BPM 프로세스) 다운로드·실행, Worker 프로세스 실행 관리, 유틸리티로 UI 셀렉터 등록 관리. Windows 주.
3-1. **서버 실행기** — 실행 위치가 「서버」인 BPM 프로세스(「서버 Bot」)를 여러 건 동시에 실행. **업무 대부분은 여기서 돈다** (서버 우선, [ADR-0016](decisions/0016-server-first.md)). PC Bot은 UI 조작·현장 확인·PC 전용 자원이 필요할 때만. Center가 배포·작업·관리. Linux 서버, M7.
4. **Worker** — Bot UI가 관리하는 화면 없는 서버 프로세스. 실행 중인 Bot이 REST로 UI 자동화를 요청하면 등록된 화면 요소를 조작하고, 실패하면 치유를 요청한다. Windows 주.
5. **확장** — BPM 프로세스에 공통 기능을 더하는 묶음 (VS Code의 확장처럼). 내장(이 저장소)·사내(다른 저장소)·외부(정의 파일만, 외부 앱) 등급. UI 자동화가 첫 내장 확장이다 ([ADR-0018](decisions/0018-extensions.md)).
   **서비스 앱**은 확장의 서버 부분이다 — BPM 프로세스가 API 키로 호출하는 서버 앱들(대부분 LLM 앱). 앱마다 관리 콘솔(키 발급 포함)을 가진다. 첫 번째는 **UI 자동화 앱**(화면·요소·로케이터 레지스트리, 실행 계획, 치유 제안). Linux 서버.
6. **Admin** — 서명 키 관리, 패키지 승인·배포 서명.
7. **공통 계약 패키지** — 위 구성요소가 주고받는 모든 데이터 모델의 단일 원본.

## 만들지 않는 것 (비범위)

- 범용 BPM 제품과의 호환. BPMN 2.0 파일 형식은 따르되, 실행 엔진은 우리 것 하나.
- 사람이 실시간으로 화면을 원격 조종하는 기능.
- 비밀 값 보관 서버. Center는 서비스 앱 키 같은 비밀을 저장하지 않는다 (Bot UI·Studio PC의 OS 비밀 저장소 사용). 패키지에도 비밀을 넣지 않는다.
- 멀티 테넌시 (조직 하나 기준). 필요해지면 ADR로 다시 연다.
- macOS 지원.

## 성공 기준

> 제안: 아래는 첫 릴리스(M6) 기준이다. 숫자는 논의로 확정한다.

- 시나리오 1~4가 Windows 현장 PC에서 Center 배포를 거쳐 끝까지 돈다.
- 등록된 화면에서 셀렉터가 깨지면 사람 개입 없이 치유되고, 3회 성공 후 승격된다.
- 새 개발자가 Windows PC에서 `docs/04-setup.md`만 보고 1시간 안에 Studio·Bot UI(+ Worker 프로세스)를 띄운다.
- 모든 구성요소 간 통신이 `docs/03-contracts/`의 명세와 일치한다 (계약 테스트로 확인).
- 모든 화면이 `docs/06-screens/`의 설계와 일치한다.

## 열린 질문

| 질문 | 상태 |
| --- | --- |
| 제품 이름 "Chaeksas"를 사용자 화면에도 쓰는가, 저장소 이름만인가? | 미정 |
| 배포 단위의 화면 이름 | **확정: 설계 화면 "BPM 프로세스", 운영 화면 "Bot"** ([ADR-0012](decisions/0012-bot-ui.md)) |
| 서비스 앱 키를 어디에 지정하나 | **확정: BPM 프로세스 속성에 키 참조, 값은 Bot UI·Studio 비밀 저장소** ([ADR-0013](decisions/0013-api-keys.md) §3) |
| PC 한 대에서 Bot 여러 개를 동시에 돌리는가 | **확정: 아니다. 실행 중인 Bot은 하나, 나머지는 Bot UI 대기열** [ADR-0014](decisions/0014-one-bot-per-pc.md) |
| 결재를 기다리는 Bot이 실행 자리를 놓는가 | **확정: PC Bot은 끝날 때까지 기다린다** (실제 업무와 같음). 동시 실행·상태 저장이 필요한 업무는 실행 위치를 「서버」로 ([ADR-0015](decisions/0015-run-location.md)) |
| 서버 실행 BPM 프로세스의 운영 화면 이름 | **확정: 「서버 Bot」, PC 쪽은 「Bot」** ([ADR-0016](decisions/0016-server-first.md)) |
| 업무 대부분을 어디서 돌리나 | **확정: 서버 (기본값). PC는 사람·화면이 필요할 때만** ([ADR-0016](decisions/0016-server-first.md)) |
| 서버 Bot이 화면 조작 한 부분만 PC Bot에 맡기는가 (PC 위임) | 제안: Call Activity로 PC BPM 프로세스를 부르면 Center 작업으로 PC에 맡기고 기다림 ([ADR-0016](decisions/0016-server-first.md) §3) |
| 서버 앱 분류 이름 | **확정: "서비스 앱", 첫 번째는 "UI 자동화 앱"** ([ADR-0010](decisions/0010-service-apps.md)) |
| 결정 수행이 실패하면 자율 수행으로 넘어가는가? | 기본은 넘어가지 않고 실패. 앱·작업별 예외는 manifest 정책 ([ADR-0010](decisions/0010-service-apps.md)) |
| 무인 실행: 로그인한 사용자 없이 Bot UI가 Windows 서비스로 Bot을 돌리는가? UI 태스크는 화면이 있는 로그인 세션이 필요하므로 서비스 모드에서는 쓸 수 없다 | **나중에 검토** (첫 릴리스는 로그인 세션의 트레이 앱으로 실행) |
