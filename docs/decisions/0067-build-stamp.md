# ADR-0067. 산출물의 판은 빌드가 찍고, 앱은 그것을 읽어 올린다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-10-17) |
| 날짜 | 2026-10-17 |
| 관련 | [ADR-0024](0024-desktop-packaging-extensions.md)(묶기), 계약 C4 `versions`·C12 `versions`, `packaging/build.py`, `.github/workflows/desktop.yml` |

## 배경

M8-A로 Studio·Bot UI가 실행 파일로 묶인다. 그런데 **묶은 Bot UI는 제 판을 모른다** —
`importlib.metadata`로 `chaeksas-bot-ui`·`chaeksas-core`의 판을 읽는데, PyInstaller는 그
dist-info를 넣지 않는다(훅은 **확장의** dist-info만 넣는다). 그래서 묶은 앱은 C4 `versions`를
`0.0.0`으로 올린다. 서버 실행기는 `"0.1.0"`이 코드에 적혀 있다.

그리고 패키지 판은 워크스페이스 열두 멤버가 모두 `0.1.0`이고 아무도 올리지 않는다 — 그 값으로는
**현장 PC가 어느 산출물인지** 알 수 없다. 「판 올리기」(M8-A 다음 거리)를 정하려면 Center가
먼저 그것을 알아야 한다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 패키지 판을 올려 쓴다 (dist-info만 넣는다) | 손댈 곳이 적다 | 멤버 열둘의 판을 **사람이** 맞춰 올려야 한다. 같은 판으로 두 번 묶으면 가를 수 없다 |
| B. **빌드가 찍는다** — 태그면 태그, 아니면 `<패키지 판>+g<커밋>` | 판의 출처가 하나다(태그). 태그 없이 묶은 것이 **이름에서** 드러난다 | 찍은 파일을 읽는 자리가 하나 더 생긴다 |
| C. 실행 파일의 Windows 버전 리소스에 넣는다 | 탐색기 「속성」에 보인다 | Windows에만 있고 앱이 제 리소스를 읽기 번거롭다. Linux 묶음은 못 한다 |

## 결정

**B를 쓴다.**

### 1. 판은 빌드가 정한다

`packaging/build.py --version <판>`이 이긴다. 없으면:

- **지금 커밋에 `v*` 태그가 딱 붙어 있으면** 그 태그에서 `v`를 뗀 것 (`v0.2.0` → `0.2.0`).
- 아니면 **`<chaeksas-core의 판>+g<커밋 12자>`**, 고치다 만 파일이 있으면 `.dirty`를 붙인다
  (PEP 440의 로컬 판 — `0.1.0+g13bca23d0e1f.dirty`). **태그 없이 묶은 것을 태그로 착각하지 않는다.**

판은 PEP 440 공개 판 모양(`1.2.3`, `1.2.3rc1` …)이어야 하고 아니면 빌드가 멈춘다 — 「판 올리기」가
판을 **견주어야** 하기 때문이다. 산출물 워크플로는 태그로 돌 때 `--version`을 넘긴다(얕은 체크아웃에서
태그를 찾느라 헤매지 않는다).

### 2. 찍는 자리는 실행 파일 옆 `chaeksas-build.json` 하나다

`{schema, version, commit, built_at}`. 실행 파일 옆이라 **사람이 열어 볼 수 있다**. Studio·Bot UI가
같은 이름을 쓴다. 이것은 **보안 관문이 아니다** — `versions`는 원래 현장이 스스로 말하는 값이다.

그리고 빌드는 **`chaeksas-core`와 그 앱의 dist-info를 넣는다**(`--copy-metadata`) — 그래야 묶은
앱에서도 `core`의 판이 `0.0.0`이 되지 않는다.

### 3. 읽는 자리는 `core.build_info` 하나다

- `stamp()` — 묶인 앱이고 그 파일이 있으면 찍힌 것, 아니면 `None`.
- `product_version(배포판 이름)` — 찍힌 판 > 그 배포판의 dist-info > `0.0.0`.

C4 `versions.bot_ui`·`worker`(Worker는 같은 실행 파일로 뜬다)는 **찍힌 판**이고, `versions.build`
(`{commit, built_at}`)가 **묶은 것에서 돈다**는 표시다 — **없으면 묶지 않은 것**(소스·`uv sync`)에서
돈다. C12는 칸을 더하지 않는다 — **서버 실행기는 묶지 않는다**(소스에서 돈다). 코드에 적힌 판만
dist-info로 바꾼다.

### 4. 빌드가 되읽어 확인한다

`--selftest`가 찍힌 것을 결과에 싣고, 빌드는 **묶은 앱이 읽은 판이 자기가 찍은 판과 같은지** 본다.
다르면(파일이 안 들어갔거나 앱이 다른 자리를 읽으면) **빌드를 실패시킨다** — 현장에서 `0.0.0`을
보고서야 아는 일을 빌드에서 막는다.

## 결과

- 쉬워지는 것: CON-03이 PC마다 **어느 산출물인지**(판·커밋·묶은 때)와 **개발 체크아웃인지**를
  보인다. 「판 올리기」가 견줄 값이 생긴다.
- 어려워지는 것: 판을 올리려면 **태그를 민다** — 패키지 판(`pyproject.toml`)은 태그 없이 묶은
  것의 앞자리로만 쓰인다.
- 다시 볼 조건: 서버 실행기를 묶어 내보내게 되면(이미지·설치 파일) C12에도 `build`를 더한다.
  Windows 「속성」에 판이 필요해지면 버전 리소스를 **같은 값으로** 더 찍는다(C).
