# ADR-0034. 서비스 앱의 모델 연결 — 모델 클라이언트를 맨 아래 패키지로 내리고, 주소·키는 서비스 앱 설정이 갖는다

| 항목 | 값 |
| --- | --- |
| 상태 | 제안 |
| 날짜 | 2026-10-05 |
| 관련 | [ADR-0027](0027-llm-connection.md)(모델 연결), [ADR-0018](0018-extensions.md)(확장), [ADR-0033](0033-desktop-app-and-window.md)(데스크톱 화면), 계약 C8·C11, CLAUDE.md §5, 인수 시험 FX-05 |

## 배경

UI 자동화 앱(서비스 앱)에는 모델이 하는 일이 둘 있다. 지금은 둘 다 422로 분명히 막혀 있다.

- **치유(`heal`, C8):** 찾지 못한 요소를 스냅샷에서 다시 찾아 로케이터를 제안한다.
- **목표로 계획(`plan`의 `goal`, C8):** 자연어 목표 한 줄로 스텝을 짓는다 (STU-13). 데스크톱 AI 태스크 예제 FX-05가 이것을 기다린다.

모델을 부르는 코드는 `core.llm`에 있다 (ADR-0027 — OpenAI 호환 `/v1/chat/completions`, `httpx`). 그런데 **서비스 앱은 `core`를 import할 수 없다** (§5 — 확장의 service·worker와 `service_kit`은 `core`를 모른다. `tests/test_import_direction.py`가 막는다). `core`는 BPMN 실행 엔진이고 서비스 앱은 서버에서 혼자 도는 HTTP 앱이라서, 이 방향은 지켜야 한다.

그래서 코드를 짜기 전에 「서비스 앱이 무엇으로 모델을 부르나」와 「주소·키를 누가 갖나」를 정해야 한다.

## 선택지

모델 클라이언트를 어디에 두나.

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. **새 맨 아래 패키지** `chaeksas-llm`(`chaeksas.llm`)로 내린다. `core`와 `service_kit`이 둘 다 그것을 쓴다 | 한 벌. 의존 방향이 그대로다 (`llm`은 `httpx`만 안다). 어댑터 모양(ADR-0027 §1)을 그대로 쓴다 | 워크스페이스 멤버가 하나 는다. `core.llm`을 옮기는 작업 |
| B. `extension_api`에 둔다 | 멤버가 늘지 않는다. 둘 다 이미 의존한다 | `extension_api`는 확장과 플랫폼 사이의 **약속**이다. HTTP 클라이언트가 들어가면 약속이 무거워지고 버전이 자주 오른다 |
| C. `service_kit`에 따로 하나 더 쓴다 | 바로 된다 | 두 벌이 갈라진다 (재시도·사용량 기록·오류 분류) |
| D. 모델을 **PC 쪽(Worker·Bot UI)**이 부르고 서비스 앱은 검증만 한다 | 서비스 앱에 모델 설정이 없어도 된다 | 모델 주소·키가 PC마다 퍼진다. 화면 정보(스냅샷)를 다루는 일이 C8 경계를 넘는다. 서버 우선(ADR-0016)과 맞지 않는다 |

주소·키를 누가 갖나.

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| E. **서비스 앱 설정**(환경변수 `CHK_SVC_<앱>__LLM__*`)이 갖는다 | 다른 비밀과 같은 자리 (C11 관리자 토큰처럼). 앱마다 다른 모델을 쓸 수 있다 | 앱마다 설정한다 |
| F. 부르는 쪽(Bot)이 요청에 실어 보낸다 | 설정이 한 곳 | 키가 요청을 타고 다닌다. 원칙상 안 된다 |

## 결정

**A + E.** (제안 — 구현할 때 확정한다)

1. **`packages/llm`(`chaeksas.llm`)** 을 맨 아래에 둔다. `core.llm`의 `LlmError`·`ToolSpec`·`ToolCall`·응답 모양·`OpenAiCompatibleLlm`·`NoLlm`을 옮긴다. 의존은 `httpx`뿐이고 **`contracts`도 모른다** (모델 대화는 계약이 아니다). `core.llm`은 그것을 다시 내보내고 **도구 루프·결과 검증·궤적(ADR-0027 §3~5)은 `core`에 남긴다** — 그것은 BPMN 실행의 일이다.
2. **`service_kit`이 모델 설정을 준다.** `CHK_SVC_<앱>__LLM__BASE_URL`·`__MODEL`·`__API_KEY`(비밀은 환경변수만, §5). 설정이 없으면 어댑터는 `NoLlm`이고 모델이 필요한 작업은 **503 `llm_unavailable`** 로 분명히 막는다 (422 `mode_unsupported`는 결정 수행에서 `goal`을 보낸 경우로만 남긴다). 관리 콘솔 상태(`/admin/v1/status`)에 모델 연결 여부를 보인다 (키 값은 보이지 않는다).
3. **사용량은 응답에 싣는다.** 서비스 앱은 C3 이벤트를 직접 쓰지 않으니, 치유·계획 응답에 `llm_usage`(`model`·`input_tokens`·`output_tokens`)를 실어 보내고 Worker·수행기가 실행 기록에 남긴다 (금액은 넣지 않는다, ADR-0027 §6).
4. **모델에 보내는 것은 가린 스냅샷뿐이다** (원칙 6). Worker가 입력한 값을 가린 뒤 보낸다 (지금 데스크톱·웹 스냅샷이 이미 그렇게 한다). 서비스 앱은 받은 스냅샷을 저장하지 않는다.
5. **제안은 Worker가 로컬에서 검증한 뒤에만 쓴다** (C8 그대로). 모델이 틀려도 사다리 규칙(하나여야 쓴다)이 막는다.

### 이 ADR이 정하지 않는 것

- 치유·목표 계획의 **프롬프트와 응답 모양** — 구현 조각에서 C8을 먼저 고친다.
- 데스크톱 AI 태스크(`domain: desktop`, FX-05)가 화면을 **보는** 방법(UIA 트리 줄글 / 화면 캡처) — FX-05를 다룰 때 따로 쓴다.
- 벤더 네이티브 어댑터 — ADR-0027 §1 그대로, 필요할 때 더한다.

## 결과

- 쉬워지는 것: 모델을 부르는 코드가 한 벌이다. 서비스 앱마다 모델을 고를 수 있다. `core` 경계가 그대로다.
- 어려워지는 것: 워크스페이스 멤버가 하나 는다 (`tests/test_workspace.py`의 `MEMBERS`, `tests/test_import_direction.py`에 `llm`이 아무것도 import하지 않는다는 줄을 더한다). `core.llm`을 쓰는 곳(Bot UI·Studio·서버 실행기)의 import가 바뀐다 — 다시 내보내기로 당분간 그대로 둔다.
- 다시 볼 조건: 서비스 앱이 도구 루프까지 필요해지는 경우(그때는 루프도 `llm`으로 내릴지 본다), 사내 게이트웨이가 OpenAI 호환이 아닌 경우.
