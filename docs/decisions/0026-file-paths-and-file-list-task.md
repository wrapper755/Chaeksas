# ADR-0026. 파일은 실행 폴더로 묶고, 파일 목록은 식이 아니라 태스크로 둔다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-04 |
| 관련 | [ADR-0025](0025-expression-language.md) §식에 두지 않는 것, [C14](../03-contracts/C14-bpmn-extensions.md) §파일 경로·파일 목록·파일 출력, M3 조각 3b |

## 배경

ADR-0025가 `파일목록(패턴)`을 식에서 뺐다 — 디스크를 읽으므로 결정 수행(재생)이 같은 값을 내지 못한다. 그러면서 「C14에 없는 공백이라 M3 조각 3에서 계약에 더한다」고 적어 두었다. 업무 예제 두 곳(BX-01 청구서 폴더, FX-04 폴더 감시)이 그 함수를 쓰고 있어, 태스크가 생기기 전에는 두 예제가 첫 스크립트에서 멈춘다.

같이 정해야 할 것이 하나 더 있다. C14는 파일 출력의 `path`가 「출력 폴더 기준 상대 경로」라고만 적었고 **출력 폴더가 무엇인지, 그 밖을 가리키면 어떻게 되는지**는 비어 있었다. 읽는 쪽(파일 목록)은 `/share/invoices` 같은 공유 폴더를 봐야 하므로 쓰기와 같은 규칙으로 묶을 수 없다. BPM 프로세스는 현업이 Studio에서 그리는 그림이고 Center를 거쳐 남의 PC에서 돈다 — 「아무 경로나 읽고 쓴다」로 두면 그림 하나가 그 PC의 파일 전체에 닿는다.

## 선택지

### 파일 목록을 어디에 두나

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 식 도우미로 되돌린다 | 예제를 고치지 않아도 된다 | ADR-0025를 뒤집는다. 재생이 깨지고, 조건식 한 줄이 디스크를 읽는다 |
| B. **`serviceTask` + `chk:fileList`** | 노드라서 실행 기록에 남고, 결정 수행에서 다시 밟을지 재생할지 고를 수 있다. 허용 경로를 한곳에서 본다 | 예제를 고쳐야 한다 (조각 3f), 그림에 노드가 하나 는다 |
| C. 프로세스 입력으로 받는다 (`파일목록`을 사람·일정이 채움) | 엔진이 디스크를 모른다 | 폴더를 감시하는 업무(FX-04)가 성립하지 않는다 |

### 경로를 어디까지 허용하나

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| D. 무엇이든 (OS 권한만 믿는다) | 규칙이 없다 | 배포된 그림 하나가 PC의 모든 파일에 닿는다. 「어디에 썼는지」를 아무도 모른다 |
| E. 전부 출력 폴더 안으로 | 가장 안전하다 | 읽을 수가 없다 — 업무가 보는 공유 폴더는 밖에 있다 |
| F. **쓰기는 출력 폴더, 읽기는 출력 폴더 + 실행하는 쪽이 허용한 폴더** | 쓰기는 완전히 묶이고, 읽기는 운영자가 PC마다 정한다. 웹훅의 허용 호스트와 같은 태도다 | 허용 폴더 설정이 하나 는다 (Bot UI 설정은 M5) |

## 결정

**B + F.**

1. **파일 목록은 `serviceTask` + `chk:fileList`다** (`folder`·`pattern`·`recursive`·`sort`·`limit`·`store_as`·`count_as`). `store_as`는 필수다 — 결과를 받을 길이 그것뿐이다.
2. **실행 폴더는 둘이다.** 실행하는 쪽(Bot UI·Studio 시험 실행·서버 실행기)이 정해서 엔진에 준다.
   - **출력 폴더** — 실행 하나가 파일을 쓰는 곳이자 **상대 경로의 기준**.
   - **읽기 허용 폴더** — 파일 목록이 들여다볼 수 있는 곳 (여럿). 주지 않으면 출력 폴더만 읽는다.
3. **쓰기는 출력 폴더 안만, 읽기는 그 둘 안만.** 경로는 **풀어서**(`Path.resolve()`) 판정한다 — `..`도 심볼릭 링크도 풀린 뒤의 자리로 본다.
4. **그 밖을 가리키면 실행 오류**(`path_denied`)이고 **오류 경계로 받지 않는다.** 그림·설정이 잘못된 것이라 고쳐야 하지, 업무 흐름으로 우회할 일이 아니다. 반대로 **폴더가 없거나 읽을 수 없는 것은 업무 실패**(`TASK_FAILED`)라서 경계가 받는다 — 공유 폴더가 안 붙은 날이 있다.
5. **`pattern`에는 경로 구분자를 쓸 수 없다.** 폴더는 `folder`로만 정한다. 패턴으로 폴더를 거슬러 올라가는 길을 열지 않는다.
6. **변수에 들어가는 경로는 BPM 프로세스가 적은 그대로**다 — 파일 목록은 `folder`에 이어 붙인 것, 파일 출력은 채운 `path` 그대로. 엔진이 푼 절대 경로를 업무 값·보고서에 새로 섞지 않는다 (`/home/runner/...`가 보고서에 찍히는 것을 막는다). 푼 경로는 엔진 안에서만 쓴다 (메일 첨부를 어댑터에 넘길 때 등). **실행 기록에는 경로를 남기지 않는다** — 파일 이름에 거래처·사람 이름이 들어간다 (원칙 6).
7. **차례는 정해져 있다** — `sort`의 기본은 이름순이다. 디스크가 주는 순서를 그대로 쓰면 같은 폴더에서도 실행마다 결과가 달라진다.

## 결과

- **쉬워지는 것:** 「이 Bot이 어느 폴더를 보나」를 배포 전에 말할 수 있다 (C1 매니페스트·Studio 실행 전 검사로 가져갈 자리). 파일을 읽고 쓰는 코드가 `core.files` 한 곳이라 OS별 경로 문제(`pathlib`, UTF-8, 구분자)도 한곳이다.
- **포기하는 것:** 그림만으로는 아무 폴더나 읽지 못한다 — 새 공유 폴더를 보려면 운영자가 허용 폴더를 늘려야 한다. 이것은 의도한 번거로움이다.
- **우리가 지는 것:** 허용 폴더를 Bot UI 설정(M5)·Studio 시험 실행 설정(M3 조각 3e)에 노출해야 한다. 그때까지는 부르는 쪽이 코드로 준다.
- **다시 볼 조건:** ① 업무가 **쓰기**도 공유 폴더로 해야 한다고 밝혀지면 (그때는 「쓰기 허용 폴더」가 따로 생긴다), ② 실행 하나가 다른 실행이 만든 파일을 읽어야 하면 (출력 폴더가 실행마다 따로라서 지금은 못 한다), ③ 결정 수행에서 파일 목록을 **다시 읽지 않고 재생**하기로 하면 (지금은 늘 다시 읽는다).
