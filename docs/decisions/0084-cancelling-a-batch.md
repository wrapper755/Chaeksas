# ADR-0084. 일괄 취소는 **접수 실행 취소**이고, 맡겨 둔 자식은 작업 취소 규칙대로 거둔다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-20 |
| 관련 | [ADR-0079](0079-virtual-worker-is-an-intake-bot.md), [ADR-0082](0082-batch-start.md)(일괄 기동), [ADR-0062](0062-pc-delegation.md) §5(위임 거두기), [ADR-0063](0063-stopping-a-running-server-run.md)(시작된 서버 실행 멈추기), [C5](../03-contracts/C5-packages-deployments-jobs.md) 「취소」, [C12](../03-contracts/C12-server-runner-center.md) §PC 위임, 바깥 요청서 W6 |

## 배경

일괄(접수 Bot 실행 한 번)을 **승인한 뒤에** 멈추고 싶을 때 무엇이 일어나야 하는지 정해 두지 않았다. 요청서는 「시작 안 된 자식은 취소하고 시작된 것은 그대로 두는 C5 규칙을 따를지」를 물었고, 보류·재개가 필요한지도 물었다.

승인 **전**에는 결재 회수(`admin_withdraw`)로 충분하다 — 그림의 오류 경계가 받거나 실행이 실패로 끝나고, 기동은 하나도 일어나지 않는다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| **A. 접수 실행을 취소한다 — 지금 있는 길 그대로** | 새 API가 없다. 서버 실행이 취소되면 실행기가 맡긴 위임을 거두고(ADR-0062 §5), 그 작업의 취소는 C5 규칙(`cancel_outcome`)이 **대상 종류로** 가른다 | 끝난 자식은 되돌리지 않는다(되돌리기는 업무다) |
| B. 「일괄 취소」 API를 따로 둔다 | 한 번에 보인다 | 일괄은 자원이 아니다(ADR-0079) — 같은 일을 하는 두 번째 길이다 |

## 결정

**A.** 일괄 취소는 **접수 실행의 작업을 취소하는 것**(C5 `DELETE /jobs/{id}`, 서버 대상이라 시작된 것도 202)이다. 그때 일어나는 일은 이미 있는 규칙들의 합이다.

| 자식의 상태 | 결과 | 근거 |
| --- | --- | --- |
| 이미 끝난 건 | 그대로 남는다 — 되돌리지 않는다 | 되돌리기는 업무이고 그림이 그린다 |
| 맡겨졌는데 아직 시작 안 됨 | 취소된다 (`cancelled`) | C5 「취소」 표 |
| 시작된 **서버** 자식 | 취소된다 — 엔진 취소가 곧 `cancelled` 기록이다 | ADR-0063 |
| 시작된 **PC** 자식 | 끝까지 간다 — 결과는 받는 쪽이 없어 버려진다 | C5 — 화면을 만지는 중일 수 있다 |
| 아직 맡기지 않은 건 | 맡겨지지 않는다 — 반복이 **차례로** 돌기 때문이다 | ADR-0082 §2 |

- **보류·재개는 두지 않는다.** 필요해지면 접수 Bot 그림에 메시지 받기(`receiveTask`)로 그린다 — 지도는 BPMN이다(ADR-0008). 플랫폼의 멈춤은 운영자의 실행기 일시 중지(C12)뿐이다.

## 결과

- 이 결정으로 쉬워지는 것: 연동하는 쪽(대화 창구)은 일괄 취소를 **작업 취소 한 번**으로 나른다 — 일괄 id(접수 실행)에서 작업 id를 읽으면 된다. 새 계약이 없다.
- 어려워지거나 포기하는 것: 끝난 건은 남는다. 시작된 PC 자식은 멈추지 않는다.
- 다시 볼 조건: ① 반복이 병렬이 되면(09-gaps §3-15) — 맡겨 둔 것이 여럿이 되고 그 모두를 거둔다(실행기가 기다림 전부를 읽으므로 규칙은 같다). ② 보류·재개를 그림으로 그리기 어렵다는 업무가 나오면.
