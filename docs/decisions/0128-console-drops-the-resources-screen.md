# ADR-0128. Center 콘솔의 리소스 화면(CON-07)을 없앤다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-11-01 |
| 관련 | 화면 CON-07·CON-11·CON-01, 계약 C7·C15(바뀌지 않는다), [ADR-0122](0122-consumer-folder.md), [ADR-0123](0123-folder-keys.md), [ADR-0124](0124-no-api-key-page.md) |

## 배경

CON-07은 「기능」 목록(프로세스가 부르는 바깥 기능을 지금 쓸 수 있나, 할 일), 「일꾼 폴더」(폴더 파일마다 결과와 키 상태, 줄 끝 「...」로 키 폐기), 「콘솔에서 발급한 연동 키」(ADR-0123 전에 발급한 키)를 보였다. 그런데 일꾼과 연동용·대리 답용 키는 **사람이 승인하지 않고 폴더 파일로 저절로 들어온다**(ADR-0122·0123). 사용자가 compose로 돌려 보고 이 화면이 보여 줄 필요도, 여기서 폐기를 부를 필요도 없다고 했다. 「기능」 목록까지 포함해 화면을 통째로 걷기로 했다(사용자 결정, 2026-11-01).

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 화면 통째로 없앤다 | 메뉴 하나가 준다. 승인 없이 들어오는 것을 보여 주는 칸이 남지 않는다 | 「기능을 지금 쓸 수 있나·할 일」을 볼 자리가 없다. 새어 나간 일꾼·연동 키를 콘솔에서 바로 끊는 길이 없다 |
| B. 일꾼 폴더·키 칸만 걷고 「기능」 목록은 남긴다 | 진단 자리가 남는다 | 사용자가 화면 자체가 필요 없다고 했다 |

## 결정

**A — CON-07을 없앤다.** 메뉴 「배포·자원 › 리소스」, `/resources`와 그 아래 상세(기능·옛 서비스 앱·확장 주소)를 걷는다.

- **Center API는 그대로다** — C7 `GET /resources…`(Studio STU-03·STU-14가 읽는다)·`GET /resources/consumer-folder`, C15 `GET /consumers`·`GET /external-topics`는 읽는 길로 남는다. 배포를 막는 누락 검사(C7 `missing_resources`)도 Center에 그대로 있다.
- **일꾼·폴더 키를 끊는 길은 폴더다** — 파일을 빼고 Center를 다시 띄우면 그 키가 폐기된다(ADR-0122). 콘솔에는 그 「키 ...」 자리가 없다(ADR-0124 표의 CON-07 두 줄을 대체한다). 예전에 콘솔에서 발급한 연동용·대리 답용 키는 콘솔에서 보이지 않는다 — 끊어야 하면 Center API(C7 `DELETE /center-keys/{id}`)로 한다.
- CON-01 실행 상세 「외부 작업」의 토픽은 링크 없이 글이다.

## 결과

- 이 결정으로 쉬워지는 것: 콘솔 메뉴가 줄고, 사람이 손댈 것이 없는 목록을 지켜보지 않는다.
- 어려워지거나 포기하는 것: 「바깥 기능을 지금 쓸 수 있나」를 콘솔에서 보지 못한다 — 일꾼이 멈춘 것은 실행이 외부 작업에서 기다리는 것(CON-01)과 Center 로그로 안다. 새어 나간 일꾼 키를 콘솔에서 바로 끊지 못한다. 서비스 앱 관리 콘솔(C11 `console_url`)로 가는 링크가 Center 콘솔에서 사라진다.
- 다시 볼 조건: 운영자가 「왜 이 프로세스가 바깥 기능을 못 부르나」를 콘솔에서 찾아야 하는 일이 잦아지면 진단 자리(기능 목록)를 다시 둘지 정한다 — 그때는 화면 문서를 먼저 고친다.
