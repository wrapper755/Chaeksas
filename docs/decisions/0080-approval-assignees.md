# ADR-0080. 결재 담당자는 **이름 목록**이고, 콘솔은 그것으로 거르기만 한다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-20 |
| 관련 | [ADR-0079](0079-virtual-worker-is-an-intake-bot.md)(일괄 결재 — 담당자 = 감독자), [ADR-0081](0081-answering-on-behalf.md)(대리 답 — 담당자일 때만 받는다), [C14](../03-contracts/C14-bpmn-extensions.md) `chk:approval`, [C6](../03-contracts/C6-approvals.md), 화면 CON-04 |

## 배경

C6 결재에는 **누가 답할 사람인지**가 없다. 콘솔 결재함은 모든 결재를 한 목록으로 보이고, 연동하는 쪽(대화 창구)은 「내 결재함」을 제 설정 파일 규칙으로 흉내 낸다 — Center 밖에 두 번째 담당 규칙이 생긴다. 일괄 결재(ADR-0079)는 **감독자**가 답해야 하고, 대리 답(ADR-0081)은 「그 사람이 담당자인가」를 물을 칸이 있어야 막을 수 있다.

Chaeksas에는 아직 사용자·조직 모델이 없다. 콘솔이 답한 사람으로 적는 이름도 **자칭**이다(C6 「행위자」, OIDC 전).

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| **A. 이름 문자열 목록** — 그림이 적거나 변수로 주고, C6에 풀어 싣는다 | 사용자 모델 없이 된다. 콘솔의 「자칭」과 같은 수준이라 뜻이 어긋나지 않는다. 사용자 모델이 생기면 이름이 계정으로 바뀔 뿐 칸은 남는다 | 이름 철자가 곧 신원이다 — 오타는 그냥 「담당자가 아니다」가 된다 |
| B. 역할·그룹 (`재무팀장`) | 사람이 바뀌어도 그림이 그대로다 | 역할 → 사람을 푸는 **조직 모델**이 필요하다. 지금 없다 |
| C. 담당자 칸 없이 연동하는 쪽이 거른다 (지금) | 할 일이 없다 | Center 밖의 담당 규칙 — 대리 답이 막을 근거가 없다 |

## 결정

**A — 결재 담당자는 이름 목록이고, 그림(C14)이 정하고 실행하는 쪽이 풀어 C6에 싣는다.**

1. **C14 `chk:approval.assignees`**는 **이름 배열**(글자 그대로) 또는 **변수 이름 하나**다 — `expires`(ISO 기간 또는 변수 이름)와 같은 결이다. 변수의 값은 이름 하나(글자) 또는 이름 목록이다. 비우면 **담당자 없음**이고 지금과 같다(누구나 콘솔에서 답한다). 검사는 B2가 본다(배열이면 빈 글자가 없고, 글자 하나면 변수 이름 규칙).
2. **실행하는 쪽이 결재를 만들 때 푼다.** 이름은 앞뒤 공백을 걷고 NFC로 맞추며, 빈 것과 겹치는 것은 버린다(`contracts.approvals.normalize_assignees` 하나). 변수 값의 모양이 틀리면(수·사전 등) **실행 오류**다 — 식 오류와 같은 갈래라 오류 경계로 받지 않는다(고쳐야 할 그림의 버그다).
3. **C6 `ApprovalCreateRequest.assignees[]`**(선택, 기본 빈 목록). 본문의 일부라 **멱등 대조에 들어간다**(같은 `request_id`에 다른 담당자는 409). 담당자 이름은 업무 값이 아니라 사람 이름이라 **30일 삭제 대상이 아니다**(`answered_by`와 같다).
4. **`GET /approvals?assignee=<이름>`** — 그 이름이 `assignees`에 있는 결재만. 비교는 같은 정규화를 거친 **글자 그대로**다.
5. **`ApprovalInfo.requested_by?`** — 그 실행을 시작한 **작업**의 `requested_by`. Center가 **읽을 때** 실행의 작업에서 붙이고 저장하지 않는다(`bot_ui_of`·`dependents`와 같은 결). 작업 없이 시작한 실행(Bot UI 수동·일정·감시)은 비어 있다.
6. **관리자 토큰(콘솔)은 담당자로 막지 않는다.** 콘솔의 이름은 자칭이라 막아도 증명이 아니고, 관리자 토큰은 이미 모든 결재에 답할 수 있다. 콘솔은 담당자를 **보이고 거른다**(CON-04 「담당」 칸·거르기). **막는 것은 대리 답(ADR-0081) 하나**다.
7. **현장 결재(`where=field`)에도 실어 CMN-01이 보인다. 막지 않는다** — 현장은 화면 앞 사람이 답한다. 확인(`manualTask`)에는 담당자가 없다.
8. **실행 기록(C3)에는 싣지 않는다.** 사람 이름을 실행 기록에 더 늘리지 않는다 — 담당자는 C6에서 읽는다.

## 결과

- 이 결정으로 쉬워지는 것: 「내 결재함」을 Center가 거른다 — 연동하는 쪽의 설정 파일 규칙이 필요 없다. 일괄 결재의 감독자가 그림에 남는다. 대리 답이 막을 근거가 생긴다.
- 어려워지거나 포기하는 것: 이름 철자가 신원이다. 사람이 바뀌면 그림(또는 그 변수를 채우는 자리)을 고쳐야 한다. 콘솔에서는 여전히 누구나 답한다(관리자 토큰).
- 다시 볼 조건: ① 사용자 모델(OIDC)이 생기면 — 이름을 계정 id로 바꾸고 콘솔도 담당자로 막을지 다시 본다. ② 「재무팀장」 같은 역할로 적고 싶다는 업무가 나오면 — 조직 모델을 먼저 정한다. ③ 가상 직원(W3)이 감독자 목록을 가지면 — 그 목록을 그림이 변수로 받는 길(`assignees: "감독자"`)을 W3 ADR에서 정한다.
