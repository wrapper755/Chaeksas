# ADR-0035. UI 태스크의 목표로 계획 — 모델은 값의 이름만 보고, 앱이 계획을 거르고, 수행기가 값을 채운다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-05 |
| 관련 | [ADR-0034](0034-service-app-model-connection.md)(모델 연결), [ADR-0033](0033-desktop-app-and-window.md)(스텝 값 템플릿), [ADR-0027](0027-llm-connection.md) §4(모델이 틀리면 업무 실패), [ADR-0008](0008-map-driver-hands-boundary.md)(시맨틱 키), 계약 C8·C10·C14, 화면 STU-13 |

## 배경

C8 `plan`은 자율 수행에서 `goal`(목표 한 줄)과 `values`(쓸 값)를 받아 모델이 스텝을 세운다고 적혀 있다. STU-13에도 「스텝 대신 목표로 실행」이 있다. 그런데 셋이 정해져 있지 않다.

- **값.** 「공급자 등록번호를 넣고 상신」의 등록번호는 업무 값이다. `values`에 값을 실어 보내면 업무 값이 UI 자동화 앱과 모델로 나간다 (원칙 6).
- **결과.** 스텝을 손으로 적으면 읽기 스텝마다 결과 변수를 적는다. 모델이 세운 스텝은 어느 변수에 담나.
- **언제 세우나.** Worker는 세션을 열 때 계획을 받는다 (ADR-0033). 화면을 보기 전이다.

## 선택지

값을 어떻게 넘기나.

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 값을 `values`에 실어 보낸다 | 모델이 값을 보고 판단한다 | 업무 값이 앱·모델로 나간다 (원칙 6 위반) |
| B. **이름만** 보낸다. 모델은 스텝 값을 `{이름}` 템플릿으로 쓰고 수행기가 채운다 | 업무 값이 나가지 않는다. 손으로 적은 스텝과 **같은 채우기**(ADR-0033)를 쓴다 | 값을 보고 고르는 일(「금액이 크면 결재란 체크」)은 못 한다 — 그것은 BPMN 게이트웨이의 일이다 |

모델의 계획이 틀리면.

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| C. Worker가 돌려 보고 실패한다 | 앱이 단순하다 | 없는 요소·틀린 동작을 화면에서야 안다. 조작이 반쯤 된 뒤에 멈춘다 |
| D. **앱이 거른다** — 등록된 요소·그 요소가 할 수 있는 동작·값 규칙·이름 규칙. 어긋나면 422 | 화면에 손대기 전에 멈춘다 | 거르는 규칙을 앱이 들고 있어야 한다 |

## 결정

**B + D.**

1. **모델은 값의 이름만 본다.** UI 태스크(목표 모드)는 쓸 값의 이름을 목표 안에 `{이름}`으로 적는다 (`{신청.이름}`처럼 사전 안의 값도 된다). 수행기가 목표에서 이름을 모아 `values`로 보낸다 — **이름의 목록**이고 값이 아니다. 모델은 스텝 `value`에 그 템플릿을 쓰거나, 목표에 글자로 적힌 것(설계자가 쓴 말)을 쓴다.
2. **결과 변수는 태스크가 정한다.** 목표 모드 UI 태스크는 `results: [이름]`을 적는다. 모델은 읽기 스텝의 `result`를 그 이름 중에서만 고른다.
3. **계획은 화면의 시맨틱 정보로 세운다.** 등록된 요소(키·이름·설명·역할·할 수 있는 동작·선행 입력)가 재료다. 스냅샷은 쓰지 않는다 — 계획은 세션을 열 때(화면을 보기 전) 받는다.
4. **앱이 계획을 거른다.** 다음 중 하나라도 어긋나면 422 `goal_plan_invalid`(`detail.reasons`)이다.
   - 키가 그 화면에 등록돼 있다.
   - 동작이 그 요소의 `catalog.actions` 안이다 (적혀 있을 때).
   - 값 규칙이 C10 `check_step`과 같다.
   - 템플릿은 `values`의 이름만 쓴다.
   - `result`는 `results`의 이름만 쓰고 읽기 스텝에만 단다.
   - 스텝은 1개 이상 30개 이하다.
5. **틀린 계획은 업무 실패다** (`TaskFailed` — 오류 경계가 받는다). 모델은 가끔 틀린다는 ADR-0027 §4와 같은 판단이다. 모델이 없으면 503 `llm_unavailable`이고 다시 해도 풀리지 않는다.
6. **흐름:** 수행기 → Worker 세션 열기(`goal`·`values`·`results`) → Worker가 계획을 받으며 `goal`을 싣는다(**캐시하지 않는다**) → 세션 정보 `planned_steps`로 수행기에 돌려준다 → 수행기가 템플릿을 채워 **하나씩** 보낸다 (손으로 적은 스텝과 같은 길이다. 다시 뜬 Worker·전환 규칙도 같다).
7. **결정 수행에서는 세우지 않는다** (C8 그대로 — 결정 수행은 LLM을 몰래 부르지 않는다). 목표만 있는 UI 태스크를 결정 수행에서 만나면 `TaskFailed`(`ui_goal_needs_autonomous`)다.
   > 미정: Studio가 자율 수행에서 세운 계획을 스텝으로 굳혀 결정 수행에서도 돌게 하는 것(「계획을 스텝으로」). AI 태스크의 재생(ADR-0028)과 같은 자리를 쓸지 따로 정한다.

## 결과

- 쉬워지는 것: 업무 값이 앱·모델로 나가지 않는다. 모델이 세운 스텝도 손으로 적은 스텝과 같은 길을 탄다 (채우기·사다리·치유·보고·다시 뜬 Worker 규칙).
- 어려워지는 것: 목표에 값의 이름을 `{이름}`으로 적어야 모델이 그 값을 쓸 수 있다. 계획에 쓴 모델의 사용량은 지금 Worker에서 끝난다 (C11 `usage`가 실행 기록까지 가지 않는다).
- 다시 볼 조건: 값을 보고 골라야 하는 업무가 잦을 때, 화면을 본 뒤 계획을 다시 세워야 하는 경우(여러 화면을 넘나드는 목표).
