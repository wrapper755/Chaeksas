# ADR-0008. 역할 경계: BPMN = 지도, AI = 운전사, Bot = 실행, Worker = Bot이 쓰는 손

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-10-01) · 역할 이름(실행·손) 일부 대체됨([ADR-0012](0012-bot-ui.md)) |
| 날짜 | 2026-10-01 |
| 관련 | `docs/00-vision.md`, `docs/02-glossary.md` 태스크 종류, ADR-0009, ADR-0010 |

## 배경

프로토타입 두 묶음은 같은 원칙을 각자 발견했다.
- 프로토타입 Studio·Bot: "BPM = 내비 지도 + 교통 규칙, LLM 그래프 = 자율주행 운전사". 셀렉터를 BPMN에 넣지 않고, 업무 순서를 프롬프트에 넣지 않는다.
- 프로토타입 UI 자동화 서버: BPM은 셀렉터 대신 시맨틱 키를 넘기고, 실행 중에는 LLM을 부르지 않는다.

그러나 웹 자동화는 두 벌이 되었다.
- 프로토타입 Studio·Bot은 LLM이 셀렉터를 매번 만들고, 실패하면 궤적 단위로 다시 학습했다.
- 프로토타입 UI 자동화 서버는 로케이터를 그래프로 관리하고, 치유도 로케이터 단위로 했다.

처음 제안은 지도·운전사·손 세 역할이었다. 검토에서 **실행 주체(Bot)를 따로 세우고, Worker는 Bot이 쓰는 손**으로 정리했다.

## 결정

| 역할 | 담당 | 가진 것 | 가지지 않는 것 |
| --- | --- | --- | --- |
| 지도 | BPMN | 순서, 분기, 결재, 마감 | 셀렉터, 좌표, 프롬프트 요령 |
| 운전사 | AI (에이전트, 서비스 앱의 LLM) | 목표에 도달하는 방법, 도구 선택, 경로 복구 | 업무 순서, 승인 규칙 |
| 실행 | **Bot** | BPM 프로세스 실행: 지도를 따라 태스크를 차례로 수행하고, 운전사·손·서비스 앱을 부른다 | 화면 조작 자체, 셀렉터 |
| 손 | **Worker (Bot이 사용)** | 등록된 화면 요소의 결정적 조작, 로케이터 치유 검증 | 업무 판단, 프로세스 흐름 |

- 등록된 화면은 **UI 태스크**(화면 + 시맨틱 키 + 동작)로, Bot이 Worker에 요청해 조작한다.
- 등록되지 않은 화면은 AI 태스크의 탐색 도구로 조작한다.
  - > 미정: 탐색으로 학습한 화면을 UI 자동화 앱에 등록하는 흐름은 M4에서 정한다.
- 치유는 두 단계로 나눈다: 로케이터 치유는 Worker·UI 자동화 앱, 경로(순서·도구) 치유는 운전사.
- Studio에서 개발 목적으로 프로세스를 실행할 때도 같은 역할을 쓴다. 이때 Studio가 실행 역할을 맡는다 (자율 수행, [ADR-0010](0010-service-apps.md)).

## 결과

- 쉬워지는 것: 반복 업무가 LLM 없이 결정적으로 돈다. 셀렉터 변경이 BPMN에 영향을 주지 않는다. 누가 무엇을 하는지(흐름·판단·실행·조작) 코드 경계가 분명하다.
- 어려워지는 것: 두 경로(등록/탐색)를 모두 유지해야 한다.
- 다시 볼 조건: 탐색 경로의 사용 비중이 매우 낮으면 탐색 도구를 축소.
