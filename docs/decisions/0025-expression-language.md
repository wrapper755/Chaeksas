# ADR-0025. 식 `chk-expr`는 직접 만든 AST 검사기로 돌리고, 템플릿은 `{변수}`만 둔다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-04 |
| 관련 | 스파이크 [`spikes/s6-expr/`](../../spikes/s6-expr/README.md), [C14](../03-contracts/C14-bpmn-extensions.md) §식, M3 로드맵 「식 도우미 목록 확정」 |

## 배경

C14는 게이트웨이 조건·스크립트·호출 입력을 「안전한 식 언어(Python 식 문법의 부분집합)」로 쓴다고만 적고, **도우미 함수 목록은 M3으로 미뤄** 두었다. 엔진·DMN·매핑·템플릿이 모두 이것 위에 서므로 M3의 첫 조각으로 정한다.

재는 자리는 이미 있다 — 업무 예제 50개가 식을 **201곳**에서 쓴다 (스크립트 74, 조건 36, `serviceCall.input` 50, `rule.input` 16, `call.input` 12, `dataOutput` 13). 추측하지 않고 그 201곳으로 후보를 재었다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. `eval()`에 `__builtins__`를 비워 넘긴다 | 코드가 가장 짧다 | **막을 수 없다.** 던더 한 줄로 빠져나간다. 막을 문법을 열거할 수 없어 「무엇이 허용되는지」를 문서로 적을 수도 없다 |
| B. `simpleeval` | 널리 쓰이고 식은 잘 된다 (평가 14/14, 막음 7/7) | **대입문을 다루지 않는다** — 스크립트 74곳이 안 된다. 결국 우리가 대입·템플릿·오류 메시지를 감싸야 하고, 의존성은 늘어난다 |
| C. `asteval` | 대입문·여러 줄을 다룬다 | 실측 결과 **내포·조건식 미지원**(예제의 14곳), 사전을 점으로 읽지 못하고, `open('/etc/passwd')`가 **새어 나갔다** |
| D. 직접 만든 AST 검사기 | 허용 목록이 코드이자 문서(파싱 193/201·평가 14/14·막음 7/7). 사전 점 접근·대입문·한국어 오류 메시지를 우리가 정한다. 의존성 없음 | 우리가 들고 있어야 한다 (≈300줄). 파이썬 문법이 늘면 허용 목록을 다시 봐야 한다 |

## 결정

**D — `ast`로 파싱하고 허용한 노드만 직접 걸어 값을 낸다** (`chaeksas.core.expr`). `eval`·`exec`을 쓰지 않는다.

1. **두 개의 작은 언어로 나눈다.**
   - **식 `chk-expr`** — 조건·매핑·DMN 입력·`loop.over`. 값 하나를 낸다.
   - **스크립트** — `scriptTask`의 본문. **대입문만** 여러 줄 (`변수 = 식`). 오른쪽은 식이다.
   - **템플릿** — `dataOutput.path`·`template`, `email.to`·`subject`·`body`. 텍스트에 `{변수}`를 끼운다. **중괄호 안은 변수 이름 하나만** 쓸 수 있고 식은 쓸 수 없다. 예제의 중괄호 86곳이 전부 이름 하나였고, 템플릿에 식을 허용하면 「어디까지가 식인가」를 사람이 매번 물어야 한다. `{{`·`}}`는 중괄호 한 개로 읽는다.
2. **허용하는 문법** (이 밖은 파싱 단계에서 거부): 상수·변수·산술·비교·논리·`not`, 조건식(`a if c else b`), 목록·사전·집합·튜플, 첨자·조각, **목록·사전·집합 내포**, 함수 호출(허용 목록만), 점 접근(아래), f-문자열. 람다·`for`·`while`·`import`·`with`·`:=`·`del`·`global`·클래스·함수 정의는 없다. **인자 펼치기(`*`·`**`)도 없다** — 몇 개를 넘기는지 글로 셀 수 없으면 호출 모양을 미리 볼 수 없고(C14 B15), `**`는 그냥 두면 조용히 버려졌다.
3. **점은 사전의 키를 읽는다.** `결과.지급`은 `결과['지급']`이다 (예제가 그렇게 쓴다). 사전이 아닌 값에 점을 쓰면 오류다 — **파이썬 객체의 속성은 읽을 수 없다.** 밑줄로 시작하는 이름은 점으로도 첨자로도 읽을 수 없다.
4. **도우미 함수는 순수 함수만.** 결정 수행(재생)이 같은 값을 내야 하므로, 디스크·환경·네트워크를 읽는 함수는 식에 두지 않는다. 목록은 §도우미 함수.
5. **없는 값:** 선언한 입력에 값이 없으면 `None`이다 (C14 §6). **선언하지 않은 이름을 읽으면 실행 오류**이고, 템플릿도 같다. 검사 B11이 미리 어림으로 잡는다.
6. **오류는 어디서 틀렸는지 말한다.** 식 본문·노드 id·틀린 자리를 한 줄로 붙인다 (`[Task_Reconcile] 모르는 변수다: 지급대상`). 실행 기록(C3)에는 **식 본문만** 남고 값은 남지 않는다 (계약 원칙 6).

## 도우미 함수

플랫폼이 주는 것은 이 목록뿐이다. 늘릴 때는 **세 곳**을 함께 고친다 — 이 표, `core.helpers`(구현), 예제 생성기의 인자 표(`docs/08-business-examples/_source/exdsl.py`의 `HELPER_ARITY` — 생성기는 표준 라이브러리만 쓰므로 구현을 import하지 못한다). 셋이 어긋나면 pytest가 잡는다.

| 묶음 | 이름 | 뜻 |
| --- | --- | --- |
| 내장 | `len` `sum` `min` `max` `round` `abs` `sorted` `zip` `dict` `list` `set` `str` `int` `float` `bool` | 파이썬과 같다. `sorted`는 키 없이, 또는 `sorted(목록, '열')` |
| 날짜 | `오늘()` `지금()` `어제()` `이번달()` `지난달()` `이번주표기()` `지난주표기()` | 실행 시작 시각 기준 (`YYYY-MM-DD`·ISO 8601·`YYYY-MM`·`YYYY-Www`) |
| 날짜 | `날짜더하기(날짜, 일수)` `달더하기(달, 개월)` `기간(시작, 끝)` | 문자열 날짜를 다룬다. `기간`은 `{"from":…, "to":…}` |
| 표 | `합계(목록, 열)` `평균(목록, 열)` `세기(목록)` | 사전 목록의 한 열을 더한다·센다 |
| 표 | `표를사전(목록, 열)` `묶기(목록, 열)` `펼치기(목록)` `쪼개기(목록, 크기)` | 목록을 사전으로, 열로 묶기, 한 겹 펴기, 묶음으로 쪼개기 (`쪼개기`는 묶음 단위 반복에 쓴다 — BX-35가 VOC를 50건씩 나눈다) |
| 표 | `골라내기(목록, 열, 값)` `열뽑기(목록, 열)` | 거르기·한 열만 뽑기 (내포로도 되지만 자주 쓴다) |
| 수 | `나누기(a, b)` `비율(a, b)` | **0으로 나누면 0**이다 (식에서 실행이 멈추지 않게) |
| 검사 | `빈칸없음(줄, 열목록)` `범위벗어남(값, 아래, 위)` | 업무 검증에 자주 나온다 |

> `오늘`·`지금`·`run_id`는 **변수**다 (C14 §9). `오늘()`·`지금()`은 함수로도 쓸 수 있게 둔다 — 예제가 둘 다 쓴다 (같은 값이다).
>
> BPMN·JSON에서 온 소문자 `true`·`false`·`null`도 값으로 받는다 — 흐름 조건에 `true`라고 적은 예제가 있고, 손으로 적는 사람이 자연히 소문자로 쓴다 (`core.helpers.JSON_LITERALS`).
>
> **호출 모양은 값 없이 미리 본다** (C14 B15, 2026-10-08에 더함). `parse()`·`parse_script()`가 이 표에 있는 이름의 호출마다 인자 수와 키워드 이름을 서명과 맞춰 본다 — 문법만 보던 때는 `세기(전체, '주제')`가 검사·시험을 모두 지나 **실행할 때야** 터졌다. 목록 밖의 이름(툴팩)과, 인자를 몇 개든 받거나 서명을 들여다볼 수 없는 파이썬 내장은 건너뛴다.

### 식에 두지 않는 것 (예제가 쓰지만 도우미가 아니다)

스파이크에서 드러난 것이다. 예제를 비틀지 않고 여기 적는다 (CLAUDE.md §3-6).

| 예제가 쓰는 것 | 왜 안 되나 | 어디로 가는가 |
| --- | --- | --- |
| `파일목록(패턴)` | 디스크를 읽는다 — 재생이 같은 값을 못 낸다 | **파일 목록 태스크**가 필요하다. C14에 없는 공백이라 M3 조각 3에서 계약에 더한다 |
| `설정(이름, 기본값)` | 환경을 읽는다 | BPM 프로세스 입력(`chk:process.inputs`)으로 받는다 |
| `대사규칙(...)` `전표자료(...)` | 업무 로직이다 | AI 태스크·서비스 앱·툴팩 |
| `대사표양식(...)` `아침보고양식(...)` 등 「양식」류 | 서식 만들기다 | `dataOutput.template`·`email.body` 템플릿, 또는 표 서식 도우미 하나로 모은다 |

이 표의 예제 쪽 수정(`_source/spec_*.py`)은 **M3 조각 3**에서 한다 — 그 태스크·템플릿이 생긴 뒤에 해야 하고, 지금 고치면 예제가 실행되지 않는 상태로 남는다.

## 결과

- **쉬워지는 것:** 허용 목록이 코드 한 곳(`ALLOWED`·`HELPERS`)이라 「무엇을 쓸 수 있나」를 Studio 도움말·검사 B11이 같은 출처에서 읽는다. 의존성이 늘지 않아 Windows 설치 파일도 그대로다. 오류 메시지를 한국어로 쓰고 노드 id를 붙일 수 있다.
- **포기하는 것:** 파이썬 문법을 전부 쓰지 못한다 (람다·반복문·객체 속성). 식이 길어지면 스크립트·AI 태스크로 보내야 한다.
- **우리가 지는 것:** 파이썬이 새 문법을 더하면 허용 목록을 다시 본다. `ast` 노드 이름이 바뀌면 시험이 깨지므로 pytest가 그것을 지킨다.
- **다시 볼 조건:** ① 식에 반복문·함수 정의가 필요해지면 (그때는 식이 아니라 다른 것이어야 한다), ② DMN(FEEL)과 식을 같은 언어로 쓰고 싶어지면, ③ 도우미가 30개를 넘으면 (업무별 툴팩으로 갈라야 한다).
