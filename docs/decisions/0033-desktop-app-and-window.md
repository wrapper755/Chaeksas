# ADR-0033. 데스크톱 화면은 앱 이름과 창 조건으로 찾고, Worker는 계획을 먼저 받아 백엔드를 고른다

| 항목 | 값 |
| --- | --- |
| 상태 | 제안 |
| 날짜 | 2026-10-05 |
| 관련 | [ADR-0020](0020-windows-desktop-backend.md)(UIA 라이브러리), [ADR-0021](0021-worker-dpi-capture.md)(DPI), [ADR-0023](0023-bot-ui-process-supervision.md)(잠금 화면), 계약 C8·C9·C10·C14, 인수 시험 BX-04·BX-17 |

## 배경

Worker의 화면 조작은 `Backend` 뒤에 있고 지금은 브라우저(Playwright)뿐이다. 데스크톱 세션을 열면 503 `browser_unavailable`이고, M4 인수 묶음의 남은 예제(BX-04·BX-17)가 이것 때문에 빨갛다.

데스크톱 백엔드를 만들려면 **세션이 어느 앱·어느 창을 만지는지** 알아야 하는데 계약에 그 칸이 없다.

- 웹은 화면 등록(C9)에 `url_pattern`이, 세션 열기(C10)에 `start_url`이 있다. 데스크톱에는 대응하는 것이 없다.
- C14 `chk:defaults.desktop.app`(「띄울 앱 이름」)은 있지만 **엔진이 확장 태스크에 넘기지 않는다.** C14는 기본값이 「모든 AI·UI 태스크」에 간다고 적고 있다.
- 예제는 앱을 **이름**으로만 적는다(BX-17 「ERP Client」). 실행 파일 경로는 PC마다 다르다. BX-04는 이름도 없이 화면(`accounting.taxbook.sheet`)만 가리킨다.
- Worker는 세션을 열 때 **화면부터 열고 계획을 나중에** 받는다. 데스크톱은 어느 창인지가 계획(화면 정의)에 있으니 이 순서로는 열 수 없다.

## 선택지

창을 어디서 알아내나.

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 화면 등록(C9)에 창 조건을 둔다. 계획(C8)이 싣는다 | 화면 = 창이라는 뜻과 맞다. 앱 이름이 없는 예제(BX-04)도 된다. 등록이 사람(BUI-06)의 일이라 조건을 사람이 정한다 | 계약 세 개(C8·C9·C10)를 고친다 |
| B. UI 태스크(C14)에 창 조건을 적는다 | 계약 하나 | 셀렉터 같은 물리 정보가 BPM 프로세스에 들어간다 (ADR-0008 — 경계를 넘는 것은 시맨틱 키뿐) |
| C. 앞에 있는 창을 그냥 쓴다 | 가장 쉽다 | 사용자가 다른 창을 보고 있으면 엉뚱한 창에 입력한다 (S1에서 사용자 탭을 건드릴 뻔했다) |

앱을 어떻게 띄우나.

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| D. 이름 → 실행 명령은 **그 PC의 Worker 설정**, 창이 이미 있으면 띄우지 않고 붙는다 | 경로가 BPM 프로세스·레지스트리에 들어가지 않는다 (PC마다 다르다) | 설정 화면이 필요하다 |
| E. 실행 명령을 레지스트리에 둔다 | 설정이 한 곳 | PC마다 경로가 다르면 틀린다 |

## 결정

**A + D.**

### 계약

- **C9:** 데스크톱 화면에 `app`(앱 이름, 선택)과 `window`(창 조건, **데스크톱이면 필수**)를 둔다. `window`는 `title`(정규식, 부분 일치), `class_name`(정확히), `process`(실행 파일 이름, 대소문자 무시) 중 **하나 이상**이다. 등록은 다른 칸처럼 **덮어쓰지 않고 준 것만 바꾼다**.
- **C8:** 계획이 그 화면의 `app`·`window`를 싣는다.
- **C10:** 세션 열기에 `app`(UI 태스크의 `desktop.app`)을 둔다. 주지 않으면 계획의 `app`을 쓴다. 새 오류는 둘이다.
  - `app_not_running`(409): 창이 없고 띄우는 방법도 설정돼 있지 않다.
  - `window_ambiguous`(409): 조건에 맞는 창이 여럿이다.
- **C14:** `chk:defaults`의 `web`·`desktop`은 **확장 태스크 속성의 기본값**으로도 넘어간다(태스크에 적은 값이 이긴다). 엔진이 그렇게 넘긴다.

- **UI 태스크 스텝 값의 템플릿:** `value`의 `{변수}`·`{변수.키}`를 수행기가 실행 시점 변수로 채운다. 지금까지 아무도 채우지 않아 `{신청.이름}`이 글자 그대로 입력되고 있었다 (FX-15는 입력값을 확인하지 않아 초록이었다). 사전 안의 값(`{건.품목}`)은 예제가 반복 항목을 쓰는 방식이라 받는다 — 식이 아니라 경로다. 모르는 이름이면 업무 실패다.

### Worker

- 세션을 열 때 **계획을 먼저** 받고, 계획의 `platform`으로 백엔드를 고른 뒤 연다. 계획이 없으면(등록 세션 등) 지금처럼 웹이다. 시작 주소도 열 때 한 번에 준다(전처럼 열고 다시 이동하지 않는다).
- 백엔드는 **둘을 묶은 경로 백엔드** 하나다. 세션이 쓰는 쪽으로 보낸다. 분석·직접 고르기·표시는 지금처럼 브라우저만이다 (C10 상태 그대로).
- **앱 띄우기:** 조건에 맞는 창이 있으면 그 창에 붙는다. 없으면 Worker 데이터 폴더의 `desktop-apps.json`에서 그 이름의 실행 명령을 찾아 띄우고 창이 생길 때까지 기다린다(기본 30초). 그래도 없으면 `app_not_running`이다.
  > 미정: 그 설정을 Bot UI 화면(BUI-03 「확장별 설정」)에서 고치는 것. 지금은 파일이다.
- **찾기:** 붙은 창 **안에서만** 찾는다 (다른 창을 건드리지 않는다). 전략은 C8 그대로(`automation_id`·`class_name`·`control_name` + `control_type`), `control_name`은 `exact`가 아니면 부분 일치다. 맞은 수를 세고 **하나여야** 쓴다(사다리 규칙 그대로).
- **입력(`fill`):** ADR-0020대로 **포커스 → 키 입력**이다. 키 입력은 `SendInput` 유니코드라 한글·`{ } ( ) + ^ %`가 원문 그대로 간다. 값을 읽을 수 있는 칸이면 **다시 읽어 맞는지 확인**한다. 다르면(이모지처럼 키 입력으로 안 들어가는 글자) `ValuePattern.SetValue`로 넣고 또 확인한다. 그래도 다르면 그 스텝은 실패다 — **들어갔다고 치지 않는다.**
- **누르기(`click`):** `Invoke` 패턴이 있으면 그것으로, 없으면 화면 좌표로 누른다. 좌표로 누를 때는 그 점의 최상위 창이 **붙은 앱의 프로세스**인지 먼저 본다 (S4 — 잠금 화면·다른 앱을 누르지 않는다). 창이 아니라 프로세스로 보는 것은 펼친 목록·대화상자가 같은 앱의 다른 최상위 창이기 때문이다.
- **고르기(`select`):** 펼친 뒤 항목을 `Invoke`·`SelectionItem`으로 고르고, 칸의 값이 바뀌지 않으면(Qt 콤보 상자) 그 항목을 눌러 본다. 어느 길이든 **고른 뒤 값을 다시 읽어** 확인한다.
- **잠금:** 조작 전에 WTS 잠금을 본다. 잠겨 있으면 C10 `session_locked`(503, 재시도 가능)다 (ADR-0023).
- **DPI:** 데스크톱 백엔드를 만들 때 프로세스가 Per-Monitor v2인지 확인하고, 아니면 선언한다 (ADR-0021).
- **치유 스냅샷:** 붙은 창의 UIA 트리를 줄글로 떠서 보낸다. 입력한 값은 가린다(원칙 6). 현재 주소(`current_url`)는 `desktop:<앱 이름>`이다 — 창 제목에는 문서 이름 같은 업무 값이 들어 있을 수 있다.

## 결과

- 쉬워지는 것: 데스크톱 화면도 웹처럼 「등록 → 계획 → 사다리 → 보고」로 돈다. 실행 파일 경로가 BPM 프로세스·레지스트리에 들어가지 않는다. 앱 이름 없이 화면만 가리키는 예제도 돈다.
- 어려워지는 것: 계약 넷(C8·C9·C10·C14)이 함께 바뀐다. Worker가 띄운 앱은 Worker의 Job 안에 있어 Worker가 다시 뜨면 함께 꺼진다 (ADR-0023). 데스크톱 화면의 분석·직접 고르기(BUI-06)는 아직 없다 — 등록은 사람이 사다리를 적어 넣거나 시험이 한다.
- 다시 볼 조건: 사내 앱에서 창 조건 셋으로 창을 가르지 못하는 경우, Worker가 띄운 앱을 Worker와 따로 살려야 하는 경우, 데스크톱 화면 등록(BUI-06 분석)을 만들 때.
