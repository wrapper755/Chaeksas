# ADR-0095. 폐기된 Center API 키는 관리자가 목록에서 지울 수 있다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-10-25) |
| 날짜 | 2026-10-25 |
| 관련 | 계약 C7 §Center API 키 관리, 화면 CON-11, C4·C12 「키 묶기」, [ADR-0092](0092-keys-are-issued-and-delivered-by-center.md) |

## 배경

`DELETE /center-keys/{id}`는 이름과 달리 **폐기**다 — 행을 남겨 「누가 언제 썼나」를 보게 했다. 그런데 승인으로 들이는 길(ADR-0092·0093)이 생기자 다시 승인할 때마다 옛 키가 폐기되어 쌓이고, 시험 삼아 만든 연동 키도 남는다. CON-11에는 다시 쓸 수 없는 줄이 늘어만 간다. 관리자는 「폐기한 것은 내가 판단해 지우겠다」고 했다.

키 행을 가리키는 것은 넷이다: Bot UI·서버 실행기 행의 `key_id`(키 묶기), 실행 기록·결재의 `owner_key_id`(C3·C6 소유), 회전의 `successor_id`. 모두 키 행이 없을 때를 이미 다룬다 — 앞자리·만료는 「—」로 보이고, 폐기된 키는 어차피 인증을 지나지 못한다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 지우지 않고 기본 목록에서 숨긴다 | 기록이 온전하다. 계약이 그대로다 | 관리자가 원한 「지우기」가 아니다. 표는 계속 커진다 |
| B. 쓴 적 없는 폐기 키만 지운다 | 「누가 보냈나」가 끊기지 않는다 | 승인으로 들인 키는 거의 다 쓴 키라 지울 수 있는 것이 없다 |
| C. **폐기된 키는 관리자가 지운다** | 관리자의 판단대로 목록을 정리한다 | 그 키의 이름·앞자리·폐기 시각이 사라진다 |

## 결정

**C로 한다.** 새 경로 `POST /center-keys/{key_id}/purge`(관리자 토큰)가 **폐기된 키의 행**을 지운다. 폐기되지 않은 키는 409 `not_revoked`다 — 쓰는 키를 한 번에 없애지 않고 「폐기 → 삭제」 두 걸음을 거친다. 만료된 키도 먼저 폐기한다.

- 지우는 것은 `center_keys`의 그 행 하나다. 실행 기록·결재·작업은 그대로 두고 `owner_key_id`는 글자로 남는다(CON-01의 「Bot UI」 열은 키 묶기로 풀므로 영향이 없다).
- 그 키가 묶여 있던 PC·서버 자리는 **놓인 자리**가 된다 — 「묶음 풀기」와 같다. 같은 기계를 새 키가 등록하거나 다시 승인하면 그 자리(배포·실행 기록)를 이어받는다.
- 되돌릴 수 없으므로 CON-11 확인 창은 기본 단추가 「취소」이고 그 키의 이름·앞자리·연결된 대상을 보인다.

## 결과

- 쉬워지는 것: CON-11이 지금 쓰는 키와 관리자가 남기기로 한 키만 보인다.
- 포기하는 것: 지운 키의 이름·앞자리·폐기 시각. CON-03·CON-12의 「Center API 키」 칸에서 그 키를 가리키던 줄은 「—」가 된다.
- 다시 볼 조건: 「누가 언제 키를 지웠나」를 감사해야 할 일이 생기면 관리자 동작 기록을 따로 둔다.
