# ADR-0042. 확장이 플랫폼 화면에 칸을 기여한다 — 데스크톱은 위젯, 웹 콘솔은 화면

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-09 |
| 관련 | [C13](../03-contracts/C13-extension-manifest.md) `console.pages`·`bot_ui.utilities`, [ADR-0018](0018-extensions.md), [ADR-0024](0024-desktop-packaging-extensions.md), [ADR-0017](0017-web-nextjs-design-system.md), 화면 BUI-09·UIA-01~03·STU-03, [09-gaps](../09-gaps.md) §4-2·§4-4·§4-7 |

## 배경

같은 모양의 공백이 **셋** 떠 있고, 셋 다 「확장이 아는 것을 플랫폼 화면이 그려야 한다」다.

| 공백 | 화면 | 지금 |
| --- | --- | --- |
| §4-2 | BUI-09 「최근 UI 세션」 (시각·요청한 쪽·**화면**·결과·**폴백 깊이**·**치유**) | Worker가 `recent_sessions[]`로 준다. Bot UI가 읽지 않는다 |
| §4-7 | UIA-01·02·03 (서비스 앱 콘솔의 UI 자동화 화면 셋) | `console.pages` 기여가 있는데 **호출자가 `tests/`뿐**이고, 콘솔에는 세 줄이 **손으로 베껴** 꺼진 채 있다 |
| §4-4 | STU-03 리소스 탐색기의 「UI 화면」 뿌리 | `studio.resource_views` 기여가 있는데 호출자가 `tests/`뿐이다 |

M6 조각 1에서 BUI-09의 「예약」·「밀린 보고」를 붙일 때 이 경계가 드러났다. 런타임 상태 본문에서
**뜻을 아는 칸만**(`reserved_for`·`unsent_reports`) 읽고 「최근 UI 세션」 표는 떼어 냈다 — 그
표의 열이 **UI 자동화의 말**이기 때문이다. 플랫폼 코드와 콘솔에 「UI 화면」이라는 말이 없다는
규칙(ADR-0018)을 지키려면, 플랫폼이 그 표를 그릴 수는 없다.

그런데 셋을 각각 다르게 풀면 **길이 셋** 생긴다. 한 번 정해 둔다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 확장이 **그리는 코드**를 기여한다 (데스크톱=위젯, 웹=화면 모듈) | 플랫폼이 **뜻을 모른다** — 열 이름·단위·배지를 확장이 정한다. 선례가 있다: `bot_ui.utilities`(창), `studio.editors`(STU-13·14 탭) — 규약이 하나다 | 외부 확장은 **코드를 기여할 수 없다**(C13 E1) — 외부는 이 길을 못 쓴다. 웹은 번들에 들어가야 해서 **모노레포 안 확장만** 된다 |
| B. 데이터 + **표 모양 선언**을 기여한다 (열 이름·타입을 JSON으로) | 외부 확장도 쓸 수 있다. 코드를 싣지 않아 설치 파일이 얇다 | 계약에 **화면 문법**이 들어온다 — 열·정렬·배지·링크·접기…. 한 번 열면 끝이 없고, 결국 못 그리는 화면이 생겨 확장이 다시 코드를 요구한다. 표 하나는 되지만 UIA-02(차트·경고 띠·좁히기)는 안 된다 |
| C. 플랫폼이 그린다 (확장별 분기) | 제일 빨리 만든다 | **ADR-0018을 깬다.** Bot UI 코드에 「화면·폴백 깊이·치유」가 들어가고, 다음 확장이 다른 칸을 요구하면 또 분기한다 |

## 결정

**A — 확장이 그리는 코드를 기여한다.** 표면마다 모양이 다르므로 셋을 이렇게 가른다.

### 1. 데스크톱 (Bot UI·Studio) — 위젯 기여

C13에 `bot_ui.panels`를 더한다. `bot_ui.utilities`와 **같은 꼴**이고 다른 것은 「창이 아니라
플랫폼 화면의 한 칸」이라는 점이다.

```json
{"id": "recent-ui-sessions", "label": "최근 UI 세션",
 "surface": "bot_ui.runtimes", "runtime": "worker",
 "entry": "ui_automation.client:RecentSessionsPanel"}
```

- `surface`는 **플랫폼이 미리 정한 자리 이름**이다 (`bot_ui.runtimes` = BUI-09 런타임 칸 아래).
  모르는 `surface`는 **조용히 무시한다** — 새 Bot UI의 자리를 옛 Bot UI가 모를 수 있다.
- `entry`는 `QWidget`을 만드는 호출 가능한 것이고, **규약은 STU-13·14 편집기와 같다**
  (`refresh()`만 더 받는다 — 플랫폼이 주기마다 부른다). 패널은 자기가 타이머를 만들지 않는다.
- **플랫폼은 칸 안을 모른다.** 못 그리면(예외) 그 칸만 접고 사유를 보인다 — 화면 전체가
  깨지지 않는다 (「없는데 된 척」하지 않는다).
- `runtime`을 적으면 그 런타임이 **떠 있을 때만** 보인다. Worker가 꺼져 있을 때 빈 표를 보이는
  것보다 칸이 없는 것이 정직하다.

### 2. 웹 콘솔 (서비스 앱 콘솔) — `console.pages`를 실제로 읽는다

`console.pages`는 **이미 계약에 있다.** 콘솔이 손으로 베낀 `APP_PAGES`를 버리고 그 기여를 읽게
한다. 화면 모듈은 **모노레포 안 내장·사내 확장만** 올릴 수 있다 — Next.js 번들에 들어가야 하기
때문이다. 외부 확장은 C13대로 **자기 콘솔 링크만** CON-07에 보인다 (코드 기여 금지, E1).

- `module`은 `web/` 워크스페이스 안의 경로이고, 콘솔이 **빌드 시점 레지스트리**로 잇는다
  (동적 `import()`를 바깥 주소로 열지 않는다 — ADR-0017의 「브라우저가 토큰·주소를 모른다」를
  깨지 않게).
- `href` 타입을 고정 셋(`"/status" | "/keys" | "/usage"`)에서 푼다.

### 3. Studio 리소스 뿌리 (STU-03) — 선언만으로 된다

`studio.resource_views`는 **코드가 아니라 선언**이다 (`{id, label, resource_type,
creates_task_type}`). 목록은 Center 리소스 목록(C7)에서 오고 **모양이 하나**이므로 플랫폼이
그려도 확장의 말을 알지 않는다 — 「UI 화면」은 `label`로 들어오는 **글자**다. 여기는 B로 간다.
**기여가 코드를 요구하지 않는 자리에는 코드를 들이지 않는다.**

## 결과

- 이 결정으로 쉬워지는 것: 공백 셋이 **같은 규약**으로 풀린다. 확장을 더해도 플랫폼 코드가
  안 바뀐다. BUI-09 「최근 UI 세션」·UIA-01~03·STU-03을 만들 수 있다.
- 어려워지거나 포기하는 것: **외부 확장은 플랫폼 화면에 칸을 못 만든다** (1·2 모두 코드를
  요구한다). 외부는 선언으로 되는 자리(3)와 자기 콘솔 링크만 갖는다 — 외부 코드를 우리 앱
  안에서 돌리지 않는다는 결정(C13 E1)의 값이다. 웹 화면은 **모노레포에 들어와야** 올라간다 —
  사내 확장을 따로 배포할 수 없다.
- 다시 볼 조건: 사내 확장을 **모노레포 밖에서** 배포해야 하거나(그러면 웹 쪽은 iframe·웹
  컴포넌트 같은 다른 길을 봐야 한다), 외부 확장이 화면을 꼭 기여해야 하는 업무가 생기면.
  그때도 **코드를 받는 것이 아니라** B(선언)를 어디까지 늘릴지부터 본다.
