# ADR-0043. 사람이 끈 확장은 앱마다 제 설정에 두고, 「흠이 있다」와 다르게 적는다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-10 |
| 관련 | [ADR-0018](0018-extensions.md), C4, C13, 화면 STU-15·BUI-11, `docs/09-gaps.md` §4-5·§4-8 |

## 배경

확장 호스트는 확장을 **켜거나 켜지 않거나** 둘뿐이다 (`LoadedExtension.enabled`는 「흠이 없다」는
뜻이고, 흠은 E1·E3~E6 검사와 정의 읽기 실패다). 그런데 STU-15·BUI-11 두 화면이 모두 사람이
직접 끄고 켜는 단추를 적어 두었고, 상태 표기에도 「꺼짐」이 「호환 안 됨」과 따로 있다
(`design/tokens.json`의 `status_map` 「확장」).

「사람이 껐다」는 **세 번째 상태**다. 흠이 있는 확장은 고쳐야 할 것이고, 꺼 둔 확장은 멀쩡한데
일부러 쓰지 않는 것이다. 둘을 한 칸(`enabled`)에 밀어 넣으면 화면도 Center도 어느 쪽인지
모르고, 「고치세요」와 「켜세요」 중 틀린 쪽을 안내하게 된다.

정해야 할 것이 셋이다 — **끈 목록을 어디에 두는가**, **꺼진 확장이 기여를 내는가**,
**Center에 무엇으로 보고하는가**.

## 선택지

### 끈 목록의 자리

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 앱마다 제 설정 (Studio ↔ Bot UI 따로) | 개발 도구의 실험이 현장 실행을 건드리지 않는다. 지금의 「앱끼리 설정을 공유하지 않는다」와 같은 결 | 한 PC에서 두 번 꺼야 한다 |
| B. PC에 한 자리 (공유) | 「이 PC에서 이 확장을 안 쓴다」가 한 번에 통한다 | **개발자가 Studio에서 끈 것이 그 PC의 예약된 Bot을 조용히 실행 불가로 만든다.** Studio가 Bot UI 데이터 위치에 의존하게 된다 |

### 꺼진 확장의 기여

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| C. 기여를 아예 내지 않는다 (목록에서만 보인다) | 「꺼짐」의 뜻이 하나다. 태스크 종류·편집기·런타임·점검이 한꺼번에 사라진다 | 사전 점검이 「종류가 없다」와 「꺼 뒀다」를 따로 말해 줘야 한다 |
| D. 기여는 내되 수행만 막는다 | 팔레트가 그대로다 | 「꺼 뒀는데 왜 팔레트에 있나」, 「왜 실행할 때만 죽나」 — 늦게 실패한다 |

## 결정

**A와 C다.** 끈 목록은 **앱마다 제 설정**에 두고, 꺼진 확장은 **기여를 하나도 내지 않는다.**

- 자리는 Studio가 `Settings.disabled_extensions`, Bot UI가 제 `Settings`의 같은 이름 칸이다.
  **id만** 적는다 (판은 적지 않는다 — 올려도 꺼 둔 채로 있는 것이 사람의 뜻이다).
- 호스트는 `ExtensionHost(off=[...])`로 받는다. 플랫폼 코드가 「어느 확장을 끌 만한가」를 알지
  못하게 **부르는 쪽이 목록을 준다** (ADR-0018).
- `LoadedExtension.off`가 「사람이 껐다」, `problems`가 「흠이 있다」이고 **둘은 섞이지 않는다.**
  `enabled`는 여전히 「지금 쓰이는가」(흠이 없고 꺼지지도 않았다)라서 부르는 쪽은 그대로다.
- **겹침(E4·E8)은 꺼지지 않은 것들 사이에서만 본다.** 꺼진 확장은 아무것도 기여하지 않으므로
  이름을 쥐고 있지 않는다. 껐던 것을 다시 켰을 때 겹치면 그때 **그쪽이** 켜지지 않고 「호환 안
  됨」으로 사유를 보인다 — 먼저 켜져 돌던 쪽이 계속 돈다 (ADR-0018의 「나중에 온 쪽이 진다」).
- **사전 점검은 따로 말한다.** 그림이 쓰는 태스크 종류의 주인이 **깔려 있는데 꺼져 있으면**
  `extension_turned_off`이고 고치는 길은 「켜세요」다. 깔려 있지 않으면 지금처럼
  `task_types_unsupported`이고 고치는 길은 「그 확장이 깔린 판으로 올리세요」다. 한 칸으로
  뭉치면 **틀린 안내**가 나간다 — 켜면 될 일에 Bot UI를 다시 깔라고 한다.
- **Center에는 C4 `ExtensionState.off`로 보고한다** (새 선택 칸, 기본 `false`). `enabled`의 뜻은
  그대로 두고 칸을 하나 더한다 — 뜻을 바꾸면 옛 Bot UI가 보낸 값을 Center가 달리 읽는다
  (계약 README 원칙 3). CON-03·CON-07은 `off`가 참이면 「꺼짐」, 아니면 「호환 안 됨」이다.

## 결과

- **쉬워지는 것:** 화면 둘이 같은 개념을 그린다 — STU-15와 BUI-11이 각자 제 앱의 목록을 쓰면
  되고 서로를 기다리지 않는다. 운영자가 CON-03에서 「꺼 둔 것」과 「깨진 것」을 가른다.
  사전 점검의 안내가 사람이 **실제로 할 수 있는 일**을 가리킨다.
- **어려워지거나 포기하는 것:** 한 PC에서 Studio와 Bot UI를 **따로** 꺼야 한다. 「이 PC 전체」
  스위치는 없다 — 둘을 한 번에 끄려는 사람은 두 창을 열어야 한다.
- **다시 볼 조건:** 한 PC에서 둘을 함께 꺼야 하는 일이 운영에서 실제로 나오면 (예: 사고 대응
  중 확장 하나를 PC 단위로 즉시 꺼야 한다) PC 한 자리를 다시 본다. 그때도 Studio가 Bot UI 설정을
  **쓰는** 것이 아니라, 둘 다 읽는 **제3의 자리**를 두는 쪽을 먼저 본다.
- 서버 실행기(M7)도 같은 칸을 제 설정에 둔다 — 그때 C12가 `ExtensionState`를 그대로 쓴다.
