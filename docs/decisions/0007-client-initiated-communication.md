# ADR-0007. 통신은 항상 현장 PC → 서버

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-10-01) |
| 날짜 | 2026-10-01 |
| 관련 | `docs/01-architecture.md` §3, 계약 C4·C8·C10 |

## 배경

현장 PC는 방화벽·NAT 뒤에 있는 경우가 많다. 프로토타입 두 묶음은 모두 이 방향을 이미 따르고 있었다.
- 프로토타입 Bot: 하트비트 응답에 배포·작업·결재가 실려 내려옴
- 프로토타입 Worker: "연결은 항상 Worker → 서버"

반면 프로토타입 UI 자동화 서버에는 서버가 작업을 배분하는 lease 경로도 있었다. 갱신·영속화 없이 기본값 꺼짐 상태로 남아 있었다.

## 결정

- 서버는 현장 PC로 먼저 연결하지 않는다. 지시는 **하트비트 응답**으로 내려간다.
- 작업 배분은 Center의 작업(`job`) 하나로 한다. 서비스 앱에는 작업 배분(lease) 기능을 두지 않는다.
- Bot → Worker는 같은 PC의 127.0.0.1 로컬 HTTP만 쓴다. Worker는 미리 떠 있는 트레이 앱이다 ([ADR-0009](0009-worker-deployment-form.md)).
- 실행 중(hot path)에는 서버를 부르지 않는다. 서버가 없어도 캐시·로컬 큐로 계속 동작한다. (서비스 앱 태스크는 예외: 서버 호출 자체가 그 태스크의 일이다.)

## 결과

- 쉬워지는 것: 현장 PC 네트워크 설정 불필요, 서버 재시작에 강함.
- 어려워지는 것: 지시 전달 지연 = 하트비트 주기 (프로토타입 30초). 즉시성이 필요하면 롱폴링을 추가로 검토.
- 다시 볼 조건: 실시간 원격 제어가 범위에 들어오면.
