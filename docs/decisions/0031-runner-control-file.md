# ADR-0031. Bot UI와 실행기는 **파일 한 벌**로 주고받는다 (stdin 파이프가 아니라)

| 항목 | 값 |
| --- | --- |
| 상태 | 수락. **「올라오는 길은 하나」에 [ADR-0038](0038-approval-request-channel.md)이 예외를 더함** (값이 필요한 결재 요청은 요청 파일로) |
| 날짜 | 2026-10-05 |
| 관련 | [ADR-0023](0023-bot-ui-process-supervision.md)(실행기 = 자식 프로세스, 「stdin으로 stop」을 이 ADR이 바꾼다), [ADR-0014](0014-one-bot-per-pc.md)(PC 한 대에 Bot 하나), [C3](../03-contracts/C3-run-events.md)(실행 이벤트), [C6](../03-contracts/C6-approvals.md)(결재), 화면 BUI-04·CMN-01, M3 조각 4a |

## 배경

ADR-0023은 실행기를 Bot UI의 자식 프로세스로 두고 「**stdin으로 `stop` 한 줄**(협조 중지)」이라고 적었다. 그때는 멈추기만 생각했다.

실행기가 실제로 Bot을 돌리게 되니 **올라오는 길**과 **내려가는 길**이 더 필요하다.

- 올라오는 것: 지금 어느 노드인가(BUI-04 「지금 실행」), **결재·확인 요청**(CMN-01), 끝났는가.
- 내려가는 것: 중지, 그리고 **결재 답**.

결재는 사람이 몇 분~며칠 걸린다. 그동안 실행기는 자리를 쥔 채 기다린다 (ADR-0014).

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| **A. 파일 한 벌** — 올라오는 것은 **실행 기록**(C3 `runs/<run_id>.jsonl`), 내려가는 것은 **제어 파일**(`runs/<run_id>.control.jsonl`) | 올라오는 길을 **새로 만들지 않는다** — C3 이벤트가 이미 노드 상태·결재 요청을 담는다. 재시작해도 남고 사람이 들여다볼 수 있다. OS를 타지 않는다 | 폴링이다 (기본 0.2초). 파일이 두 개 는다 |
| B. stdin·stdout 파이프 | 즉시 전달, 폴링 없음 | **올라오는 길이 두 개**가 된다 (기록 파일 + 파이프)이고 둘이 어긋날 수 있다. 자식이 멈추면 파이프가 막혀 Bot UI가 같이 멈춘다 (GUI 스레드에서 읽으면 더 나쁘다). Windows에서 비차단 읽기가 번거롭다. 죽으면 중간 상태가 사라진다 |
| C. 로컬 HTTP (실행기가 서버) | 구조가 또렷하다 | 포트 하나를 더 연다 (Worker에 이어 둘째). 토큰·수명 관리가 또 는다. 결재 하나 주고받자고 서버를 띄운다 |

## 결정

**A — 올라오는 것은 실행 기록, 내려가는 것은 제어 파일.** ADR-0023의 「stdin으로 stop」을 이것으로 바꾼다 (실행기를 **띄우고 끝내는** 방식과 Job Object는 그대로다).

1. **올라오는 길은 C3 실행 기록 하나뿐이다.** 실행기는 `runs/<run_id>.jsonl`에 쓰고, Bot UI는 그것을 읽어 「지금 실행」·결재 요청·끝남을 안다. **같은 파일이 Center로도 간다** (ADR-0007·조각 3g) — 화면과 Center가 같은 것을 본다.
2. **내려가는 길은 `runs/<run_id>.control.jsonl`** — 한 줄에 하나씩 덧붙인다.
   - `{"kind": "stop"}` — 협조 중지. 실행기는 지금 노드를 마치고 `run_finished(status: cancelled)`를 남기고 끝낸다. 유예가 지나면 Bot UI가 Job 나무째 끝낸다 (ADR-0023 그대로).
   - `{"kind": "answer", "request_id": …, "answer": {…}, "answered_by": …}` — 결재·확인 답 (C6).
   - **읽은 자리는 `.control.sent`에 남긴다** — 다시 읽어 두 번 답하지 않는다 (실행 기록의 `.sent`와 같은 수법).
3. **값은 제어 파일에만 있다.** 결재 답은 업무 값이라 **실행 기록에 담기지 않는다** (원칙 6 — C3 `human_answered`에는 값이 없다). 제어 파일은 그 PC 안에만 있고 Center로 가지 않는다.
4. **폴링 간격은 0.2초**다. 사람을 기다리는 동안에도 같은 간격으로 돈다 — 실행기는 한 번에 하나이고(ADR-0014) 파일 하나를 보는 비용은 무시할 만하다.
5. 끝나면 제어 파일을 지운다. 실행 기록은 남는다 (Center로 가야 한다).

## 결과

- 이 결정으로 쉬워지는 것: **Bot UI가 실행기에 매이지 않는다** — 멈춘 실행기 때문에 화면이 멈추지 않고, Bot UI를 다시 켜도 기록을 읽어 이어 본다. 올라오는 길이 하나라 「화면에는 있는데 기록에는 없다」가 생기지 않는다. 시험이 쉽다 (파일 두 개를 쓰고 읽으면 된다).
- 어려워지거나 포기하는 것: 즉시성이 아니라 **0.2초 안에** 전해진다. 결재 답을 누르고 실행이 이어지기까지 그만큼 걸린다 (사람은 못 느낀다). 파일이 둘 는다.
- 다시 볼 조건: 한 PC에서 여러 실행기를 돌리게 되면(ADR-0014를 뒤집으면) 파일 수가 는다 — 그때 다시 본다. 폴링이 눈에 띄게 느리면 간격을 설정으로 뺀다.
