# ADR-0091. `auth`가 없는 외부 앱은 키를 받지 않는 앱으로 친다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-25 |
| 관련 | 계약 C1·C13·C14, [ADR-0013](0013-api-keys.md), [ADR-0018](0018-extensions.md), [ADR-0060](0060-pinning-external-definitions.md) |

## 배경

외부 확장 정의가 `requires_keys: [{purpose: "run"}]`을 적고 `service.adapter.auth`는 적지 않을 수 있었다.
어댑터는 `auth`가 없으면 키를 싣지 않는다(실을 자리가 없다). 그런데 C14 B7·사전 점검·BUI-10·STU-06은
「서비스 앱을 부르면 키 참조가 있고 그 값이 이 PC에 있어야 한다」고 보아, **보내지도 않을 키**를 넣으라고
막았다. 사람은 아무 값이나 넣어야 Bot이 돌았다. 실제 사용(외부 앱 하나를 로컬 주소로 붙인 Bot)에서 드러났다.

모순은 두 겹이다 — 정의가 스스로 어긋났고(「키가 필요하다」 + 「키를 싣지 않는다」), 플랫폼은 키를 받지 않는
앱을 가를 말이 없었다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 그대로 두고 사람이 아무 값이나 넣는다 | 고칠 것이 없다 | 쓰이지 않는 비밀이 저장소에 쌓이고, 「무엇을 넣으라는 건가」를 아무도 답하지 못한다 |
| B. `requires_keys`가 키를 받는지 정한다 (`run`이 없으면 키 없음) | 정의가 「필요」를 직접 말한다 | 어댑터가 실제로 쓰는 것은 `auth`라 둘이 또 갈라질 수 있다 |
| C. **`auth`가 정한다** — 없으면 키를 받지 않는 앱. `run` 키를 적고 `auth`가 없으면 정의 검사가 거부 | 키를 쓰는 자리 하나(어댑터)와 판단이 같다. 어긋난 정의는 등록 전에 막힌다 | 이미 등록된 어긋난 정의는 다음 판을 올릴 때 고쳐야 한다 |

## 결정

**C. 외부 확장(`http-adapter`)에서 키를 받는지는 `service.adapter.auth`가 정한다.** 판단은 `contracts.extension.takes_key()` 하나다.

1. **정의 검사(E3)** — `requires_keys`에 `purpose: run`이 있는데 `adapter.auth`가 없으면 422 `adapter_invalid`
   (`service.adapter.auth` 칸 사유). Center 등록(CON-07)과 STU-15 「정의 파일 열기...」가 같은 `validate()`를 쓴다.
   실행하는 쪽의 봉투 검증(E6)은 E3를 다시 돌리지 않으므로 **이미 등록된 정의는 그대로 돈다** — 다음에 올릴 때 막힌다.
2. **키를 받지 않는 앱은 키를 묻는 자리에서 모두 빠진다.**
   - C14 B7 — `validate(..., keyless_apps=…)`. 어느 앱이 그런지는 계약이 스스로 모르므로(정의는 Center에 있다)
     부르는 쪽이 준다. 주지 않으면 지금처럼 모든 앱에 키 참조를 요구한다 — **모르는 것으로 풀어 주지 않는다**.
   - C1 — `requires.service_apps[].key_ref`는 **선택**이다. 빌드가 키를 받지 않는 앱에는 적지 않는다.
     사전 점검(`core.preflight`)·BUI-10·만료 묻기는 모두 `key_apps_of()`로 매니페스트를 읽으므로 따로 고치지 않는다.
   - STU-06 키 표 — 그 앱의 줄을 두지 않는다(적어 둔 참조가 있으면 「쓰는 노드 없음」처럼 지울 수 있는 줄로 남는다).
3. **Studio가 아는 길은 STU-14의 고를 거리(Center 목록)다** — 외부 앱 줄이 `auth` 유무를 들고 온다. Center에 닿지
   못하면 모른다 → 키를 요구하는 쪽(지금 그대로)으로 둔다.

## 결과

- 쉬워지는 것: 키를 받지 않는 외부 앱을 부르는 Bot이 쓰지 않을 비밀 없이 돈다. 어긋난 정의는 등록 전에 이유와 함께 막힌다.
- 어려워지는 것: **키를 받는지는 빌드 때 본 정의가 정한다.** 정의가 나중에 `auth`를 얻으면 다시 빌드해야 하고, 그 전에는
  어댑터가 「키 참조가 없다」(`key_missing`)로 업무 실패를 낸다. 정의 고정(ADR-0060)이 그 변화를 배포 전에 드러내는 길이다.
  이미 등록된 어긋난 정의(`run` 키 + `auth` 없음)는 그대로 돌지만 새 판을 올리려면 둘 중 하나를 고쳐야 한다.
- 다시 볼 조건: C11 서비스 앱에도 키를 받지 않는 앱이 필요해지면(C11은 키 발급·검증이 공통 계약이라 지금은 없다).
