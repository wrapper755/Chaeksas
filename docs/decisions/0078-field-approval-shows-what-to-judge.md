# ADR-0078. 현장 결재도 **본문을 요청 파일에 쓰고**, 결재 창이 그것을 읽는다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-20 |
| 관련 | [ADR-0038](0038-approval-request-channel.md)(요청 파일 — 이 ADR이 「현장 결재는 쓰지 않는다」를 넓힌다), [ADR-0031](0031-runner-control-file.md)(제어 파일), [C6](../03-contracts/C6-approvals.md), [C3](../03-contracts/C3-run-events.md), 화면 CMN-01·BUI-04 |

## 배경

UserTask가 현장(`where=field`)에서 답해질 때, Bot UI의 결재 창(CMN-01)이 **결재자가 판단할 것을 보이지 않았다.**

- 제목 자리에 `chk:approval.title` 대신 `<Bot 이름> — <노드 id>`, 설명 자리에 `<Bot id>의 결재 요청입니다.`가 떴다.
- **검토 자료(`show`)가 비어 있었다.** 결재자는 금액·거래처를 보지 못한 채 「승인」을 누르게 된다 — 사람이 끼어드는 뜻이 사라진다.

까닭은 ADR-0038과 같다. Bot UI가 읽는 것은 C3 실행 기록뿐이고 거기에는 값이 없다(원칙 6). 폼은 패키지 BPMN에서 다시 읽으면 되지만, `review`와 식으로 채운 제목(`{변수}`)은 **실행 중에만 생기고 실행기 자식 프로세스 안에만** 있다. ADR-0038은 Center로 올릴 결재만 요청 파일에 쓰게 했고, 현장 결재는 「올릴 이유가 없다」며 쓰지 않았다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| **A. 현장 것은 따로 둔 요청 파일** (`runs/<run_id>.field-requests.jsonl`), 같은 C6 본문 | 엔진이 짓는 본문 하나를 그대로 쓴다. **올리는 길이 현장 결재를 나를 수 없다**(다른 파일이다). 치우는 규칙이 요청 파일과 같다 | 파일이 하나 더 는다 |
| B. 지금 요청 파일 한 벌에 모두 쓰고 올릴 때 `where`로 거른다 | 파일이 그대로 | C6 본문에 `where`가 없다 — 줄을 감싸거나 기록과 대조해야 하고, **한 번 거르기를 잊으면 현장 결재가 Center에 올라간다** |
| C. 제어 파일처럼 Bot UI가 실행기에 묻는다 | 디스크에 값이 덜 남는다 | 실행기가 묻는 말을 받을 창구가 없다 (ADR-0031이 소켓·포트를 접었다) |
| D. 그림의 `show` 이름만 보이고 값은 보이지 않는다 | 새 파일 없음 | 결재자가 판단할 수 없다 — 문제가 그대로다 |

## 결정

**A — 현장 결재·확인도 C6 본문을 요청 파일에 쓰되, 올릴 파일과 가른다.**

1. 실행기는 새로 생긴 사람 요청마다 `core.requests.create_request()`로 본문을 짓는다. `where=center`면 `runs/<run_id>.requests.jsonl`(ADR-0038, Bot UI가 올린다), 아니면 **`runs/<run_id>.field-requests.jsonl`**에 쓴다. 확인(`confirmation`)도 후자로 간다.
2. **현장 요청 파일은 아무 데도 올라가지 않는다.** Bot UI의 결재 창만 `Running.body_of(request_id)`로 읽는다. Center로 올라간 결재도 현장에서 답할 수 있으므로(ADR-0038) 창은 **두 파일을 모두** 본다.
3. 창은 본문의 `title`·`description`·`form`·`review`를 그대로 싣는다. **본문이 아직 없으면**(기록 줄이 먼저 쓰인다) 지금처럼 그림에서 폼만 읽어 승인·반려라도 할 수 있게 한다.
4. **끝나면 지운다** — 실행기가 끝날 때, 그리고 실행기가 죽었을 때를 위해 Bot UI의 `cleanup()`이. 검토 자료에는 업무 값이 있다.
5. 실행 기록 전송은 이 파일도 건너뛴다(`run_id` 뒤에 `.`이 붙은 이름은 C3가 아니다).

## 결과

- 이 결정으로 쉬워지는 것: 현장 결재자가 콘솔(CON-04)과 **같은 것**을 보고 답한다. 본문을 짓는 자리가 엔진 하나로 남는다.
- 어려워지거나 포기하는 것: 실행 중에는 현장 결재의 검토 자료가 PC 디스크에 있다 (Center 결재와 같은 정도다).
- 다시 볼 조건: 실행기와 Bot UI 사이에 묻고 답하는 창구가 생기면 파일 없이 넘길 수 있다.
