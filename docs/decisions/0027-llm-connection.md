# ADR-0027. AI 태스크는 OpenAI 호환 HTTP를 **우리 루프로** 직접 부른다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-04 |
| 관련 | 스파이크 [`spikes/s7-llm/`](../../spikes/s7-llm/NOTES.md), [C14](../03-contracts/C14-bpmn-extensions.md) §태스크 종류(AI 태스크), [ADR-0008](0008-map-driver-hands-boundary.md)(운전사), [ADR-0010](0010-service-apps.md)(수행 모드), [ADR-0024](0024-desktop-packaging-extensions.md)(설치 파일), M3 조각 3c |

## 배경

C14는 AI 태스크(`serviceTask` + `chk:aiTask`)의 **속성**을 정했지만(`goal`·`domain`·`tools`·`results`·`limits`), **무엇으로 모델을 부르는지**는 비어 있었다. ADR-0008은 「운전사 = AI」가 목표에 도달하는 방법과 도구를 고른다고만 했고, ADR-0010은 「결정 수행은 LLM을 쓰지 않거나 최소」라고 못 박았다. 엔진·재생·도구 화이트리스트가 모두 이 위에 서므로 조각 3c에서 정한다.

추측하지 않고 업무 예제 50개의 AI 태스크 **31곳**을 세었다 (스파이크 §1). 셋이 드러났다.

- **18곳은 도구가 아예 없다** — 「물어보고 구조화된 답을 받는다」 한 번이다.
- 도구는 **6종, 12곳**뿐이고 전부 우리가 만들 로컬 도구다 (PDF·엑셀·CSV·OCR·HTTP). 바깥 생태계의 도구 묶음이 필요하지 않다.
- 결과는 거의 늘 **필드 1~2개의 JSON**이다 (1개가 22곳).

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| **A. OpenAI 호환 HTTP를 우리 루프로** | 의존성이 **늘지 않는다** (`httpx`는 이미 `core`에 있다 — 7패키지·4 MB). 도구 선택·화이트리스트·결과 검증·**궤적 기록**을 우리가 정한다. vLLM·Ollama·Azure·OpenRouter·사내 게이트웨이가 모두 같은 경로다 | 벤더 네이티브 기능(Anthropic Messages의 고유 필드 등)은 어댑터를 더 써야 쓴다. 루프를 우리가 들고 있어야 한다 |
| B. 벤더 SDK (`openai`·`anthropic`) | 벤더 기능을 그대로 쓴다 | **설치 파일이 커진다** — 하나당 14~15패키지·45~47 MB, 둘이면 90 MB가 넘는다. **궤적을 주지 않아** 재생용 기록은 결국 우리가 적어야 한다 (스파이크에서 실측) |
| C. 에이전트 프레임워크 (`langchain`·`pydantic-ai`) | 도구 루프·구조화 출력이 이미 있다 | **무겁다** — `langchain` 39패키지·63 MB, `pydantic-ai` **99패키지·219 MB**. 얻는 것은 우리가 어차피 해야 하는 일이고, 판이 바뀌면 적어 둔 궤적이 쓸모없어진다 |
| D. LLM을 **서비스 앱**으로 빼고 AI 태스크는 그 앱을 부른다 (C11) | 엔진이 모델을 모른다. 키·한도가 서버 한 곳에 | **`domain: desktop`·`web`이 성립하지 않는다** — 도구가 현장 PC의 화면·파일을 만지므로 도구 한 번마다 서버 왕복이고, 서버가 끊기면 못 돈다 |

## 결정

**A — OpenAI 호환 `/v1/chat/completions`를 `httpx`로 직접 부르고, 도구 루프는 `core`가 들고 있는다.**

1. **어댑터 뒤에 둔다.** 보내기(`core.senders`)·서비스 앱(`core.services`)과 **같은 모양**이다 — `RunEnv.llm`에 끼운다. 기본은 `NoLlm`이고 **부르지 않고 실패한다** (조용히 넘어가면 AI가 안 돈 채로 업무가 흘러간다). 내장 구현은 `OpenAiCompatibleLlm` 하나이고, 벤더 네이티브가 필요해지면 어댑터를 하나 더 둔다.
2. **주소·키·모델 이름은 BPMN에 적지 않는다** (C14 기본 규칙 8). 실행하는 쪽(Bot UI 설정·Studio 설정·서버 실행기)이 설정과 비밀 저장소에서 꺼내 어댑터에 넣는다. BPM 프로세스는 `goal`·`domain`·`tools`·`results`만 말한다.
3. **루프는 `core`가 돈다** — 모델이 「도구를 불러라」 하면 **허용 목록(`chk:aiTask.tools`) 안의 도구만** 부르고, 결과를 다시 넣는다. 허용 밖 도구를 부르면 **실행 오류**다 (그림·모델이 잘못된 것이라 오류 경계로 받지 않는다). 단계 수는 `limits.max_steps`로 막는다.
4. **마지막 답은 JSON이어야 하고, `results: {이름: 타입}`대로 검증한다.** 빠졌거나 타입이 다르면 `TaskFailed`다 — 오류 경계가 받을 수 있는 업무 실패다 (모델이 가끔 틀리는 것은 흔한 일이고, 흐름으로 대처할 거리가 된다).
5. **자율 수행은 궤적을 적어 둔다** — 도구 이름·인자·결과 요약과 마지막 답. 결정 수행은 그것을 **모델 없이** 되밟는다 (재생). 저장 방식은 [ADR-0028](0028-replay-memory.md).
6. **사용량은 C3 `llm_usage`로 남긴다** (`model`·`input_tokens`·`output_tokens`). **금액은 넣지 않는다** (Center가 가격표로 계산). 단계는 `agent` 이벤트로 남기고 **값은 담지 않는다** (원칙 6).

## 결과

- **쉬워지는 것:** 설치 파일이 그대로다 (의존성 0 추가). 「무엇을 부를 수 있나」가 코드 한 곳(`core.llm`)이고, 모델을 바꾸는 일이 `base_url`·`model` 설정 하나다 — 사내 게이트웨이·로컬 모델(Ollama·vLLM)도 같은 길이다. 시험은 스텁 서버 없이 `RecordingLlm`으로 돈다.
- **포기하는 것:** 벤더 네이티브 기능과 프레임워크의 기성 도구 생태계. 프롬프트 캐싱·배치 같은 벤더 고유 기능이 필요해지면 어댑터를 더 써야 한다.
- **우리가 지는 것:** 도구 루프·재시도·토큰 집계를 우리가 들고 있다 (대신 재생이 가능해진다). OpenAI 호환 규격이 바뀌면 따라가야 한다.
- **다시 볼 조건:** ① 벤더 네이티브 기능이 업무에 필요해지면 (그때는 어댑터를 더하지, 프레임워크로 갈아타지 않는다), ② 도구가 **20종을 넘어** 생태계의 도구 묶음을 쓰는 편이 싸지면, ③ 긴 멀티턴 대화가 필요해지면 (지금 예제는 한두 번 왕복이다).
