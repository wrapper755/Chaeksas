# ADR-0072. 데스크톱 「직접 고르기」는 훅 없이 커서와 Ctrl을 읽고, 「표시」는 Bot UI가 테두리 창을 띄운다

| 항목 | 값 |
| --- | --- |
| 상태 | 대체됨([ADR-0114](0114-remove-ui-automation.md)) — 원래 수락 |
| 날짜 | 2026-10-18 |
| 관련 | 스파이크 `spikes/s11-desktop-pick/`, C10 §5, BUI-06, [ADR-0021](0021-worker-dpi-capture.md), [ADR-0033](0033-desktop-app-and-window.md), 09-gaps §7-3 |

## 배경

BUI-06은 데스크톱 창에서도 「분석」으로 담는다(#162). 브라우저에 있는 「직접 고르기」(사람이 누른 요소를 담는다)와 「표시」(고른 줄을 화면에 테두리로)는 덧씌운 스크립트가 하는 일이라 데스크톱에는 자리가 없었다. 누른 자리를 알려고 전역 마우스 훅을 걸면 **다른 앱의 입력을 가로채는** 프로그램이 되고, Worker는 화면 없는 REST 서버라 테두리를 그릴 창도 없다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 전역 마우스 훅(`SetWindowsHookEx`)으로 클릭을 받는다 | 브라우저와 같은 몸짓(누른다) | 모든 앱의 입력을 가로챈다 — 보안 제품이 막고, 사람이 그 클릭이 업무 앱에 갔는지 모른다. 훅에는 메시지 루프가 필요하다 |
| B. **훅 없이 읽는다** — 사람이 요소 위에 커서를 두고 Ctrl을 누르면, 화면이 비워 가져갈 때 커서 아래 요소(`ControlFromCursor`)와 Ctrl 상태(`GetAsyncKeyState`)를 읽는다 | 입력을 가로채지도 막지도 않는다. 이미 도는 「비워 가져오기」(400ms)에 얹힌다 | 몸짓이 다르다(누르지 않고 올려 둔다). Ctrl을 아주 짧게 누르면 놓친다 |
| 표시 1. Worker가 화면 DC에 직접 그린다 | Worker 하나로 끝 | 다음 다시 그리기에 지워지고, 화면 없는 서버가 화면을 만지는 일이 늘어난다 |
| 표시 2. **Worker는 사각형만 주고 Bot UI가 Qt 테두리 창을 띄운다** | 그리기는 이미 화면이 있는 쪽(Qt)이 한다. 입력은 통과시킨다(`WindowTransparentForInput`) | 두 프로세스의 좌표를 맞춰야 한다 — UIA는 물리 픽셀(ADR-0021), Qt는 논리 픽셀 |

## 결정

**고르기는 B, 표시는 2로 한다.** 스파이크가 배율 100%에서 둘 다 맞는 것을 보았다.

1. **고르기**: 데스크톱 등록 세션에서 `pick`을 켜면 Worker가 붙은 창의 컨트롤 줄을 한 번 읽어 둔다(겹침 거르기에 쓴다 — 「분석」과 **같은 규칙**). 화면이 `pick/events`로 비워 가져갈 때마다 **Ctrl이 눌려 있으면** 커서 아래 요소를 읽어, 등록할 만한 종류가 나올 때까지 **조상으로 올라가고**(표 안의 칸 → 표), **붙은 창의 것이 아니면 버린다**. 같은 요소를 누르고 있는 동안 두 번 담지 않는다. **Esc가 눌려 있으면 끝낸다**(`picking: false`). 입력은 **읽기만** 한다.
2. **표시**: 데스크톱 세션의 `highlight`는 사다리를 차례로 찾아 **정확히 하나**면 그 요소의 사각형(물리 픽셀, `rect: [left, top, right, bottom]`)을 함께 돌려준다. Bot UI가 그 자리에 **잠깐(1.5초) 테두리 창**을 띄운다 — 논리 좌표는 그 화면의 `devicePixelRatio`로 나눈 값이고, 창은 입력을 통과시킨다.
3. 브라우저의 둘은 그대로다(덧씌운 스크립트).

## 결과

- 쉬워지는 것: 데스크톱 화면도 브라우저처럼 고르고 확인한다. Worker가 다른 앱의 입력을 가로채지 않는다.
- 어려워지거나 포기하는 것: 몸짓이 「누르기」가 아니라 「올려 두고 Ctrl」이다(안내 줄이 그렇게 말한다). 400ms보다 짧은 Ctrl은 놓친다. 배율 125%·150%·모니터 여럿은 사람이 보아야 한다(스파이크가 보지 못했다).
- 다시 볼 조건: 배율이 다른 화면에서 테두리가 어긋난다는 말이 나오면 좌표 변환을 그 화면 기준으로 다시 본다. 「올려 두기」가 불편하다는 말이 많으면 A를 다시 보되 훅은 고르는 동안만 건다.
