# ADR-0068. 설치 프로그램은 Inno Setup이고 사용자별로 깐다 — 서명 없이 시작한다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-10-17) |
| 날짜 | 2026-10-17 |
| 관련 | [ADR-0024](0024-desktop-packaging-extensions.md)(묶기 — 「설치 프로그램 종류는 미정」을 여기서 닫는다), [ADR-0023](0023-bot-ui-process-supervision.md)(자동 시작·로그인 세션), [ADR-0067](0067-build-stamp.md)(판), 스파이크 S4(MSIX 가상화) |

## 배경

M8-A로 Studio·Bot UI가 onedir 폴더로 묶이고(Windows Bot UI 160MB·Studio 600MB), 묶은 앱이 판을
찍고 로컬 런타임을 띄우는 것까지 빌드가 본다. 남은 것은 그 폴더를 **현장 PC에 넣는 길**이다 —
지금은 사람이 zip을 풀어야 하고, 제거·덮어쓰기가 없어 「판 올리기」를 얹을 바탕이 없다.

현장 사정은 셋이다: 일괄 배포를 GPO(MSI)로 할 필요가 없다, 현장 사용자에게 관리자 권한이 있다고
가정하지 않는다, **코드 서명 인증서가 없다**.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. **Inno Setup**, 사용자별 | 관리자 권한 없이 깔린다. 조용한 설치·같은 `AppId` 덮어쓰기·실행 중인 앱 닫기가 내장이다. 스크립트 한 파일, 한국어 화면이 공식으로 있다 | GPO 소프트웨어 설치로는 못 뿌린다(Intune·SCCM은 조용한 설치 인자로 된다) |
| B. WiX(MSI) | GPO·Intune·SCCM이 기본으로 받는다 | 사용자별 MSI는 함정이 많다. XML·컴포넌트 GUID·사용자 정의 동작이 무겁다. 지금 필요 없는 것(GPO)을 위해 낸다 |
| C. NSIS | A와 비슷하다 | A보다 나은 점이 없고 스크립트 문법이 오래됐다 |
| D. MSIX | 자동 업데이트 내장 | **S4: 파일·레지스트리 가상화로 작업 스케줄러·다른 프로세스가 설치 자리를 못 본다** (ADR-0024가 적어 두었다). 서명이 필수다 |
| E. zip만 | 할 일이 없다 | 제거가 없어 자동 시작 등록이 남는다. 실행 중인 폴더를 갈아끼울 수 없다 |

## 결정

**A를 쓴다.** 설치 스크립트는 `packaging/installer/chaeksas.iss` **하나**이고 앱마다 다른 값은
`packaging/build.py --installer`가 `/D`로 넘긴다.

### 1. 설치 파일은 둘이다 — Studio와 Bot UI

받는 사람(설계자 PC ↔ 현장 PC)이 다르고 크기가 네 배 다르다 (ADR-0024 「따로 묶는다」와 같은 까닭).
`AppId`는 앱마다 **고정한 GUID**다 — 바꾸면 덮어쓰기가 아니라 **두 번째 설치**가 된다.

### 2. 사용자별이다 — 관리자 권한을 묻지 않는다

`PrivilegesRequired=lowest`, PC 전체 설치로 넘어가는 길도 열지 않는다. 자리는
`%LOCALAPPDATA%\Programs\Chaeksas\<앱>`이고 **고르게 하지 않는다**(자리가 하나여야 덮어쓰기와
「판 올리기」가 단순하다). Bot UI는 원래 로그인 세션에서 돌고(ADR-0023) 데이터도 사용자 자리에 있다.

### 3. 덮어쓸 때 옛 `_internal`을 먼저 지운다

onedir은 파일이 수천 개다. 덮어쓰기만 하면 **새 판에서 빠진 파일이 남아** 옛 모듈·옛 dist-info가
섞인다(엔트리 포인트가 옛 확장을 다시 찾을 수 있다). 그래서 `_internal`을 지운 뒤 깐다. 실행 중이면
Restart Manager로 **닫고** 깐다(`CloseApplications`).

### 4. 자동 시작은 앱이 걸고, 설치 프로그램은 제거할 때 지우기만 한다

자동 시작은 지금처럼 BUI-03 토글이 작업 스케줄러에 건다(`autostart.py`). 제거하면 그 작업을 지운다
(`schtasks /Delete`) — 이름은 `autostart.TASK_NAME` 한 자리에서 빌드가 넘긴다(베끼면 이름을 바꿀 때
지우지 못한 작업이 남는다). **사용자 데이터는 지우지 않는다** — 보내지 못한 실행 기록·설치한 Bot이
거기 있다. 설치 자리와 데이터 자리가 원래 다르므로 따로 할 일이 없다.

### 5. 서명 없이 시작한다

인증서가 없다. 그래서 **SmartScreen이 「Windows의 PC 보호」를 띄운다**(「추가 정보 → 실행」).
설치 안내(`docs/04-setup.md`)에 그 화면을 적는다. PyInstaller 실행 파일은 백신 오탐이 잦은데,
서명이 그것을 줄여 주므로 오탐이 현장에서 실제로 막히면 인증서를 다시 본다.

### 6. 빌드가 설치까지 해 본다 (CI에서만)

`build.py --installer --check-install`이 만든 설치 파일을 **조용히 설치**하고, **설치된** 실행 파일로
`--selftest`(판·확장·Bot UI는 런타임 기동까지)를 돌리고, **조용히 제거**해 자리가 비는 것까지 본다.
`--check-install`은 **같은 `AppId`의 설치를 덮으므로** 사람 PC에서는 쓰지 않는다 — 산출물 워크플로만
쓴다.

## 결과

- 쉬워지는 것: 현장 PC에 개발 체크아웃 없이 넣는다 (M6의 사람 몫 둘). 조용한 설치·덮어쓰기가 있어
  「판 올리기」는 **설치 파일을 받아 조용히 돌리는 것**으로 얹을 수 있다.
- 어려워지는 것: GPO로는 못 뿌린다. 서명이 없어 처음 설치할 때 사람이 경고를 한 번 넘겨야 한다.
- 다시 볼 조건: 회사가 GPO 배포를 요구하면 B(WiX)를 같은 폴더로 더한다. 백신 오탐이 현장을 막으면
  인증서를 산다. PC 전체 설치(여러 사용자가 한 PC)가 필요해지면 2를 다시 본다.
