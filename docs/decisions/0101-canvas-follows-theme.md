# ADR-0101. Studio 캔버스 그림도 창의 테마를 따른다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-28 |
| 관련 | STU-01·STU-10, [ADR-0073](0073-studio-settings-only-what-is-used.md) 결정 1(일부 대체), [ADR-0022](0022-studio-canvas.md), `design/tokens.json` |

## 배경

ADR-0073은 「어둡게」를 골라도 캔버스 그림은 밝게 두었다. bpmn-js의 선·글자 기본색이 검정이라 어두운 바탕에서 읽히지 않는다는 까닭이었다. 그런데 써 보니 어두운 창 한가운데 흰 판이 떠 있어 **다른 프로그램을 끼워 넣은 것처럼** 보였다. 사용자가 캔버스도 같은 테마로 바꿔 달라고 했다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 밝게 둔다 (지금) | 손댈 것이 없다 | 어두운 창에서 캔버스만 따로 논다 |
| B. 렌더러 설정에 색 값을 넣고 테마가 바뀌면 그림을 다시 읽는다 | bpmn-js가 정식으로 받는 설정이다 | 다시 읽으면 실행 취소 기록과 「저장 안 한 변경」 판단이 끊긴다 |
| C. 렌더러 기본색을 **CSS 변수**로 두고 변수 값만 바꾼다 | 다시 그리지 않고 한 번에 바뀐다. 실행 취소가 그대로다 | 렌더러가 inline `style`로 색을 쓴다는 것에 기댄다(bpmn-js 18.31.0에서 확인) |

## 결정

**C를 쓴다. 캔버스 그림도 창의 테마를 따른다.**

1. 두 페이지(`index.html`·`view.html`)가 bpmn-js를 만들 때 `bpmnRenderer`의 `defaultFillColor`·`defaultStrokeColor`·`defaultLabelColor`를 `var(--chk-surface)`·`var(--chk-line)`·`var(--chk-text)`로 준다. 변수가 아직 없을 때는 bpmn-js 기본값(흰색·검정)이 쓰인다.
2. 팔레트·문맥 메뉴·선택 윤곽은 bpmn-js의 `--bio-*` 변수를 쓴다. 테마가 들어온 뒤에만(`html[data-chk-theme]`) 그 변수를 같은 `--chk-*`로 덮는다.
3. 색 값은 페이지에 적지 않는다. `canvas.py`의 `CANVAS_TOKENS`가 변수 이름과 토큰을 짝지어 두고, 페이지가 뜰 때와 앱 팔레트가 바뀔 때(`apply_theme`, 「시스템 따름」의 OS 전환 포함) `window.chkTheme`로 넣는다. 페이지가 뜨기 전의 바탕(`QWebEnginePage.setBackgroundColor`)도 같은 색이다.
4. `apply_theme`은 고른 값을 **팔레트보다 먼저** 적는다. 팔레트 변경을 받은 위젯이 `chaeksas.qt.theme.current()`로 새 테마를 묻기 때문이다.
5. 색은 그림(XML)에 들어가지 않는다. 사람이 DI에 직접 색을 적은 요소는 그 색이 이긴다(bpmn-js 규칙 그대로).

## 결과

- 쉬워지는 것: 어두운 테마에서 창 전체가 한 벌로 보인다. 테마를 바꿔도 편집 상태가 남는다.
- 포기하는 것: 어두운 테마에서 사람이 DI에 검정 같은 색을 적은 요소는 읽기 어려울 수 있다. 지금 업무 예제에는 그런 요소가 없다.
- 다시 볼 조건: bpmn-js 판을 올렸는데 렌더러가 색을 inline `style` 대신 표시 속성(`fill="…"`)으로 쓰게 되면 `var()`가 먹지 않는다. 그때는 B로 간다.
