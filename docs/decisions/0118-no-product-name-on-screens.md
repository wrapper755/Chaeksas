# ADR-0118. 화면에 「Chaeksas」를 쓰지 않는다 — 웹 콘솔의 머리는 BPM 흐름 마크다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-31 |
| 관련 | [00-vision](../00-vision.md) §열린 질문, [07-style-guide](../07-style-guide.md) §6-1, 화면 CON-00·SVC-00, [ADR-0017](0017-web-nextjs-design-system.md) |

## 배경

Center 콘솔 탐색 맨 위에 「Chaeksas」가 적혀 있었다. Chaeksas는 **저장소(프로젝트) 이름**이고 제품 이름이 아니다 —
00-vision의 열린 질문 「제품 이름을 사용자 화면에도 쓰는가」가 미정인 채 콘솔에만 먼저 들어가 있었다. 사용자가 바깥
시연(NowView)에서 콘솔을 띄우며 「프로젝트 이름이지 상품 이름이 아니다」라고 짚었고, 그 자리를 **BPM을 나타내는 그림**으로
채우기를 원했다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 흐름 그림 + 「Center」 글자 | 무엇의 콘솔인지 글로도 말한다 | 위 막대·로그인·탭 제목이 이미 「Center 콘솔」이라 겹친다 |
| B. 정사각 분기 아이콘 + 「Center 콘솔」 | 탭 아이콘으로 작아도 읽힌다 | BPMN 기호 하나(게이트웨이)만으로는 「업무 흐름」이 덜 보인다 |
| C. **흐름 그림만** (시작 → 태스크 → 분기 → 끝) | 이름 없이 「BPM」이 보인다. 이름이 정해지지 않아도 고칠 것이 없다 | 그림만으로는 어느 콘솔인지 모른다 — 툴팁·`aria-label`로 말한다 |

## 결정

**사용자 화면에 「Chaeksas」를 쓰지 않는다.** 웹 콘솔 둘(Center 콘솔·서비스 앱 관리 콘솔)의 탐색 맨 위·로그인 제목 위·
브라우저 탭 아이콘에 **BPM 흐름 마크**(C)를 둔다.

- 마크는 BPMN 요소 넷을 한 줄로 이은 것이다 — 시작 이벤트(빈 원) → 태스크(채운 둥근 네모) → 배타 게이트웨이(빈 마름모) →
  끝 이벤트(굵은 원). 색은 브랜드 색 `primary` 하나다 (스타일 가이드 §2-1 「브랜드 색은 `primary` 하나」).
- **원본은 `design/bpm-mark.svg` 하나**이고(`currentColor`) 생성기 `scripts/gen_tokens.py`가 웹 구성요소 `BpmMark`와
  콘솔마다 탭 아이콘 `app/icon.svg`(밝게·어둡게 `primary`)를 짓는다. 탭 아이콘은 SVG라 색을 변수로 받지 못해 값을 적어야
  하는데, 손으로 적으면 토큰과 어긋나므로 생성한다 (Qt의 화살표·점 SVG와 같은 결).
- 그림만 있는 자리라 **이름은 툴팁·`aria-label`**이 말한다 — Center 콘솔은 「Center 콘솔」, 서비스 앱 콘솔은 그 앱 이름.
  서비스 앱 콘솔은 **앱 이름 글자를 남긴다**(한 벌로 여러 앱을 그리므로 어느 앱인지가 글로 보여야 한다) — 마크는 그 앞에 붙는다.
- 메타데이터 설명의 「Chaeksas」도 뺀다. 코드·저장소·패키지 이름(`chaeksas.*`, `@chaeksas/*`)은 그대로다 — 화면 글이 아니다.

## 결과

- 쉬워지는 것: 제품 이름이 정해져도 화면을 고치지 않는다. 시연에서 저장소 이름이 보이지 않는다.
- 포기하는 것: Center 콘솔 탐색 맨 위에 글이 없다 — 어느 콘솔인지는 위 막대·탭 제목·툴팁이 말한다.
- 아직 하지 않은 것: 데스크톱(Studio·PC 실행기·Tool UI)의 창 아이콘·트레이 아이콘은 그대로다. 같은 원본에서 짓는 것은
  그 화면을 고칠 때 정한다.
- 다시 볼 조건: 제품 이름이 정해지면 마크 옆에 그 이름을 둘지 다시 본다. 탭 아이콘이 16px에서 읽히지 않는다는 말이
  나오면 탭 아이콘만 따로 그린다(원본을 둘로).
