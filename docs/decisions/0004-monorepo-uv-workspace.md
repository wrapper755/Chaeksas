# ADR-0004. 저장소 하나, uv 워크스페이스

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-10-01) · 폴더 구성은 ADR-0017(`web/`)·ADR-0018(`extensions/`)이 보완 |
| 날짜 | 2026-10-01 |
| 관련 | `docs/01-architecture.md` §7 |

## 배경

프로토타입은 저장소 4개였다. 그래서 두 가지 비용이 들었다.
- 계약 변경이 매번 두 저장소에 걸쳤다.
- 프로토타입 Center는 프로토타입 Studio·Bot 저장소의 **로컬 절대경로**(`git = "file:///home/..."`)와 git 태그로 계약 패키지를 가져왔다. 다른 PC에서는 이 경로가 깨진다.

프로토타입 UI 자동화 서버와 프로토타입 Worker는 둘 다 최상위 패키지 이름이 `src`라서 한 환경에 함께 설치할 수 없었다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 저장소 하나, uv 워크스페이스 | 계약 변경이 한 커밋. clone 한 번 | 저장소가 커짐. 서버·클라이언트 의존성이 한 lock 파일에 |
| B. 앱별 저장소 + 계약 저장소 | 배포 단위가 명확 | 버전 맞추기, 여러 번 clone |

## 결정

**A.** 루트 `pyproject.toml`은 패키지가 아닌 워크스페이스 루트이고, 멤버는 `packages/*`, `apps/*`, `services/*`이다 (서비스 앱은 [ADR-0010](0010-service-apps.md)).

- 모든 import 패키지 이름은 고유하게 짓는다 (예: `chaeksas_contracts`, `chaeksas_worker`). `src`라는 이름은 쓰지 않는다.
- 앱별 선택 의존성(PySide6, Playwright, Neo4j 드라이버)은 해당 앱 `pyproject.toml`에만 둔다. 서버 설치에 Qt가 딸려 오지 않게 한다.

## 결과

- 쉬워지는 것: 계약·앱 동시 변경, 통합 테스트, 새 PC 준비.
- 어려워지는 것: 서버만 배포할 때 필요한 멤버만 설치하는 절차가 필요 (`uv sync --package`).
- 다시 볼 조건: 외부 팀이 일부 앱만 따로 개발하게 되면.
