# ADR-0063. 도는 서버 실행은 **작업 취소로** 멈춘다 — PC는 그대로 거절한다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-10-15) |
| 날짜 | 2026-10-15 |
| 관련 | [ADR-0014](0014-one-bot-per-pc.md), [ADR-0015](0015-run-location.md), [ADR-0054](0054-server-run-state-and-concurrency.md), [ADR-0062](0062-pc-delegation.md) §5, 계약 C4·C5·C12, 화면 CON-05·CON-12 |

## 배경

**도는 실행을 멈출 길이 schema 1에 없다.** C5의 취소 표가 `accepted`(실행이 시작된 작업)를
409 `already_started`로 돌려보내고, C4가 「실행 중인 Bot을 멈추는 것은 schema 1 범위 밖」이라고
적어 두었다. 그래서 운영자가 **몇 시간 도는 서버 실행**이나 **잘못 지시한 작업**을 멈출 수 없다.

ADR-0062 §5가 그것을 먼저 건드렸다 — 「서버 실행이 취소되면 그 위임 작업도 거둔다」. 코드는
있다(실행기가 `cancel_jobs`를 따라 실행을 닫고 맡긴 PC 작업을 거둔다). **그런데 그 가지를
켜 줄 길이 없다**: Center가 `accepted` 작업의 취소를 받아 주지 않아 `cancel_jobs`에 실리지
않는다. 코드가 닿을 수 없는 자리에 있고, 위임한 PC 작업은 **받을 쪽 없이** 돌아 버린다.

**현장은 이미 멈출 수 있다** — BUI-04 「중지」가 자식 프로세스에 제어 파일로 중지를 넣고
유예를 기다려 `cancelled`를 기록에 남긴다 (ADR-0023·0031). 멈출 수 없는 것은 **Center에서**다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. `DELETE /jobs/{id}`를 **서버 대상에서만** `accepted`에도 연다 (202 + `cancel_requested`) | 길이 하나다 — 취소 지시(`cancel_jobs`)·ack(`cancelled`/`cancel_refused`)·상태 옮기기가 **이미 있고 실행기가 이미 따른다**. 가르는 기준은 **대상 종류 하나**이고 PC의 거절 이유(ADR-0014)는 그대로 남는다 | C5 취소 표가 대상 종류를 보게 된다 (지금은 상태만 본다). 「시작된 작업의 취소는 거절」이라는 한 줄이 **두 줄**이 된다 |
| B. 실행을 가리키는 새 경로 (`POST /server-runners/{id}/runs/{run_id}/stop`, 관리자 토큰, CON-12) | CON-12에 단추를 두기 자연스럽다. C5 작업 규칙을 건드리지 않는다 | **멈추는 손잡이가 둘이 된다**(작업 ↔ 실행) — 작업 상태(`cancel_result`)와 실행 기록을 두 길이 고치고, 어느 쪽이 「취소했다」인지 화면이 갈라진다. 서버 실행은 **작업으로만** 시작되므로(메시지 시작도 작업이 된다, C12) 작업이 이미 유일한 손잡이다 |
| C. 아무것도 하지 않고 ADR-0062 §5의 거두기 코드를 지운다 | 더 적은 코드 | 운영자가 **도는 실행을 멈출 수 없다**가 남는다. 위임한 PC 작업이 받을 쪽 없이 도는 것도 그대로다 |
| D. PC까지 함께 연다 | 한 규칙이 된다 | **UI 자동화 도중 끊으면 화면이 반쯤 바뀐 채 남는다.** 기록에는 `cancelled`가 남지만 되돌릴 수 없는 것은 되돌려지지 않는다 — 현장 사람이 BUI-04에서 멈추는 것은 **그 사람이 화면을 보고 있어서** 다르다 |

## 결정

**A를 쓴다.** `DELETE /jobs/{id}`는 `accepted` 작업에도 **대상이 서버 실행기일 때** 202로
답하고 `cancel_requested`를 세운다. **PC 대상은 그대로 409 `already_started`다.**

### 1. 가르는 것은 대상 종류 하나다 (C5)

- 판정은 계약이 쥔다 — `cancel_outcome(state, target_type)` 한 함수다 (부르는 쪽이 상태를 따로
  고르면 문서의 표와 갈라진다). 표에 줄 하나가 늘 뿐 **코드 자리는 그대로**다.
- **PC가 거절하는 까닭을 그대로 적는다** — PC 실행은 자리를 끝까지 쥐고(ADR-0014) 화면을
  만지는 중일 수 있다. 서버 실행은 **화면을 만지지 않는다**(C1 R2가 UI 태스크를 막는다) —
  엔진 취소가 곧 `cancelled` 기록이고 되돌릴 수 없는 바깥 일(메일·웹훅)은 이미 지나간 것뿐이다.
- `pending`·`dispatched`·`queued`는 **바뀌지 않는다**.

### 2. 멈추는 쪽은 이미 돈다 (C12·ADR-0054)

- 실행기가 하트비트의 `cancel_jobs`를 받아 그 실행에 중지를 넘긴다. **기다리는 실행도 그
  자리에서 닫힌다** — 스레드를 놓았으므로 깃발만 세워 두면 볼 사람이 없다 (ADR-0054 §5).
- 끝난 방식은 **기록에서 읽는다** — 엔진은 성공만 `DONE`으로 앉히고 **취소도 `FAILED`**라,
  상태로 가르면 작업 ack가 `cancelled`를 잃는다 (C3 「취소는 실패가 아니다」).
- **이미 끝나 가던 실행은 `cancel_refused`다** — 현장이 옳다 (C5의 그 규칙 그대로).
- 맡긴 PC 위임도 **함께 거둔다** (ADR-0062 §5) — 거둘 작업은 **기다림이 걷히기 전에** 읽는다.

### 3. 실행기가 오프라인이면 기다린다

취소 요청은 `cancel_requested`로 남고 **돌아오면 반영된다**. 돌아오지 않는 실행기는 CON-12
「유실 처리」가 닫는다 (C12 — 그 길은 그대로다). **Center가 혼자 작업을 `cancelled`로 적지
않는다**: 그 실행이 정말 멈췄는지는 현장만 안다 (`dispatched`·`queued`와 같은 결).

## 결과

- 쉬워지는 것: 운영자가 **도는 서버 실행을 멈출 수 있다** (CON-05의 「취소」 한 자리에서).
  ADR-0062 §5의 거두기 가지가 **켜진다** — 위임한 PC 작업이 받을 쪽 없이 돌지 않는다.
- 어려워지거나 포기하는 것:
  - C5의 취소 표가 **대상 종류를 본다.** 「시작된 작업의 취소는 거절」이 PC에만 남는다 —
    읽는 사람이 두 줄을 봐야 한다.
  - **PC는 여전히 Center에서 멈출 수 없다.** 현장 사람만 BUI-04에서 멈춘다. 그 비대칭이
    화면 글에 드러나야 한다 (CON-05가 「이미 시작됨」을 PC에서만 말한다).
  - 멈춘 실행이 **어디까지 했는지**는 기록이 말하지만 **바깥으로 나간 일은 되돌리지 않는다**
    (보내기는 멱등이 아니다 — ADR-0059). 취소는 「더 하지 않는다」이지 「되돌린다」가 아니다.
- 다시 볼 조건:
  - PC 실행도 Center에서 멈춰야 할 일이 생기면 (예: 현장에 사람이 없는 PC) **D를 다시 본다** —
    그때 정할 것은 「UI 세션을 어떻게 닫나」다 (C10 세션·ADR-0014 자리).
  - 「멈춤」과 「일시 중지」를 실행 단위로 구분하고 싶어지면 (지금은 실행기 단위 `pause`뿐이다)
    그때 연다.
