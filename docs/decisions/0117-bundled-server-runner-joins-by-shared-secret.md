# ADR-0117. 함께 배포된 서버 실행기는 들이기 비밀로 바로 승인되고, 콘솔은 재시작만 한다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-31 |
| 관련 | 계약 C12(§등록 요청과 승인·`HeartbeatResponse.restart`·운영 API), 화면 CON-02 「서버」 탭, [ADR-0092](0092-keys-are-issued-and-delivered-by-center.md), [ADR-0100](0100-server-runner-secrets-dir.md), [ADR-0054](0054-server-run-state-and-concurrency.md), `deploy/compose.yaml` |

## 배경

`deploy/compose.yaml`은 Center와 서버 실행기를 **같이** 띄운다 (ADR-0100). 그런데 실행기는 PC 실행기처럼 등록 요청을
보내고 기다려서, 운영자가 콘솔 「승인 대기」에서 로그의 요청 코드를 맞춰 보고 눌러야 들어왔다. 같은 사람이 같은 파일로
함께 띄운 프로그램을 따로 승인하는 것은 할 일이 아니다. 사용자가 「같이 배포되는 프로그램인데 승인 절차가 필요 없는 것
아닌가, 상태 정보와 재시작 정도면 된다」고 짚었다.

요청 코드를 맞춰 보는 까닭은 「이 요청이 정말 내가 띄운 그 기계인가」를 사람이 확인하는 것이다(ADR-0092). compose로
같이 띄운 실행기는 **설치하는 사람이 이미 그 확인을 쥐고 있다** — 두 컨테이너에 같은 값을 주는 사람이 그 사람이다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 같은 망(도커 네트워크)에서 온 요청은 승인 | 설정이 없다 | 주소로 신원을 정한다 — 같은 망의 다른 컨테이너·역방향 프록시 뒤의 요청을 가르지 못한다 |
| B. 실행기에 환경변수 키(`CENTER_API_KEY`)를 미리 준다 | 코드가 그대로다 | 관리자가 키를 따로 발급해 `.env`에 옮겨야 하고, 공개키가 없어 회전하지 않는다 (ADR-0100이 버린 길) |
| C. **들이기 비밀** — `.env`의 같은 값을 Center와 실행기에 주고, 맞으면 요청을 받는 자리에서 승인 | 승인·봉함·키 회전·비밀 폴더가 지금 코드 그대로다. 다른 호스트의 실행기는 지금처럼 승인을 기다린다 | `.env`에 비밀이 하나 는다 |

## 결정

**C.** 그리고 콘솔에는 **재시작**을 둔다.

1. **들이기 비밀** — Center `CHK_CENTER__SERVER_RUNNER_JOIN_TOKEN`, 실행기 `CHK_SERVER_RUNNER__JOIN_TOKEN`. 실행기는
   등록 요청에 헤더 `X-CHK-Join-Token`으로 싣는다(본문이 아니다 — 요청 본문은 「승인 대기」를 위해 저장된다). Center는
   값을 상수 시간으로 견주고 맞으면 **평소의 승인 함수를 그대로** 불러 응답에 봉한 키를 싣는다. 키 묶기·이어받기·회전·
   비밀 폴더가 승인 버튼과 같은 길이다. 「누가 승인했나」는 `join_token`이다.
2. **헤더가 있는데 맞지 않으면 403 `join_token_invalid`** — 대기 줄로 떨어뜨리지 않는다. 틀린 설정이 조용히 「승인 대기」가
   되면 운영자는 「자동으로 들어온다더니 왜」를 로그에서 찾아야 한다. 틀린 시도는 줄을 남기지 않으므로 지키는 것은 비밀의
   길이다 — `.env.example`이 무작위 32바이트를 만드는 한 줄을 적어 둔다. 헤더가 없으면 지금과 같다 — 다른 호스트에 따로 띄운 실행기는 승인을 기다린다.
3. **compose는 이 값을 필수로 받는다** (`:?` — 세션 비밀과 같은 결). 비우면 compose가 뜨지 않고 무엇을 넣을지 말한다.
4. **재시작** — 콘솔 「서버」 탭 실행기 줄의 「재시작」 → `POST /server-runners/{id}/restart`가 요청 시각을 적고, 하트비트
   답에 `restart: true`를 싣고 **그때부터 작업을 싣지 않는다**. 실행기는 새 작업을 받지 않고(`status: draining`), 자리를
   쥔 실행이 끝나고 올릴 ack가 없으면 끝 코드 0으로 **스스로 끝난다**. 다시 띄우는 것은 감독하는 쪽이다(compose
   `restart: unless-stopped`) — 콘솔에 Docker 소켓을 주지 않는다. 기다리는 실행은 저장소에 있어 이어 간다 (ADR-0054).
   Center는 그 실행기가 **다시 등록할 때** 표시를 지운다(응답 하나를 잃어도 다음 하트비트가 다시 싣는다).

## 결과

- 쉬워지는 것: `docker compose up` 한 번이면 실행기가 들어온다. 서버 탭에서 할 일은 상태를 보고 재시작하는 것뿐이다.
- 포기하는 것: `.env`를 읽는 사람은 실행기 키를 얻을 수 있다 — 그 사람은 이미 세션 비밀·관리자 토큰을 쥐고 있다.
  감독 없이 손으로 띄운 실행기에 「재시작」을 누르면 끝나기만 한다(콘솔 단추 툴팁이 말한다).
- 다시 볼 조건: 실행기를 여러 호스트에 올려 비밀을 나눠 주기 어려워지면, 호스트마다 다른 들이기 비밀(한 번 쓰고 버리는
  것)을 다시 본다.
