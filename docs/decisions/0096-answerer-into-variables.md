# ADR-0096. 결재에 답한 사람을 그림이 고른 변수에 넣는다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-25 |
| 관련 | 계약 C14·C6·C3, [ADR-0080](0080-approval-assignees.md)·[ADR-0081](0081-answering-on-behalf.md)·[ADR-0090](0090-center-admin-accounts.md), 바깥 요청 NowView R1 |

## 배경

결재 뒤 서비스 태스크가 바깥 업무 시스템에 「누가 확인했나」를 적어야 하는 그림이 생겼다(NowView SC01 — 원천 `verified_by`, 업무 완료자, 감사 이력).
`answer_variables`는 폼 칸만 변수로 만들고, 답한 사람은 C3 `human_answered.answered_by`와 C6에만 있다. 그림에서는 읽을 수 없다.
폼에 「확인자」 칸을 두면 대신할 수는 있지만, 그러면 이름이 둘이 된다 — Center가 담당자와 맞춰 본 이름(ADR-0081)과 사람이 폼에 스스로 적은 이름.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 폼에 「확인자」 칸 (지금 할 수 있는 것) | 바꿀 것이 없다 | 사람이 스스로 적은 이름이다. 대리 답이면 Center가 대조한 이름과 다를 수 있다 |
| B. 늘 정해진 변수에 넣는다 (`answered_by`) | 그림에 적을 것이 없다 | 그림이 모르는 이름이 생겨 B11 분석이 그 이름을 모른다. 결재가 둘이면 서로 덮어쓴다 |
| C. **그림이 변수 이름을 고른다** (`answered_by_as`·`answered_via_as`) | 결재마다 이름이 따로 있다. 생기는 변수를 검사가 안다(`produced_vars`) | 칸이 둘 는다 |

## 결정

**C를 고른다.** C14 `chk:approval`에 선택 칸 둘을 더한다.

- `answered_by_as: "<변수 이름>"` — 엔진이 답을 넣을 때 **답한 사람**을 그 변수에 적는다. 값은 C3 `human_answered.answered_by`에 남는 것과 **같다**(`core.engine.answerer_variables` — 따로 짓지 않는다).
- `answered_via_as: "<변수 이름>"` — 대리 답이면 **그 키 이름**(C6 `answered_via`), 아니면 `None`.
- **반려여도 채운다** — 누가 반려했는지도 업무 사실이다. 회수·만료는 답한 사람이 없으므로 채우지 않는다(그 길은 오류 경계로 간다).
- **확인(`manualTask`)에도 적을 수 있다.** 현장 확인은 Bot UI의 표시 이름이 들어가고 `via`는 늘 `None`이다.
- 이름 규칙은 B2가 본다. 생기는 변수는 `produced_vars`가 세어 B11이 안다.

`answered_by`에 들어가는 값은 실행하는 쪽이 이미 엔진에 넘기던 이름이다. 새로 짓는 곳은 없다.

| 답한 곳 | 들어가는 이름 |
| --- | --- |
| Center 콘솔 (CON-04) | 그 관리자 계정의 이름 (ADR-0090) |
| 대리 답 (`X-CHK-On-Behalf-Of`) | 그 헤더의 이름 — Center가 담당자와 대조한 것. `answered_via`는 대리 답용 키 이름 |
| Bot UI 현장 창 (CMN-01) | Bot UI의 표시 이름 |
| Studio 시험 실행 | 케이스의 `answered_by[노드 id]`, 적지 않았으면 「시험 케이스」 (`CASE_ANSWERER`) |

Studio에는 「Studio 사용자」가 없다(Studio 키의 이름은 PC를 말한다 — ADR-0093). 그래서 지어내지 않고 **케이스가 적는다**. 결재 답·위임 결과를 케이스가 적는 것과 같은 결이다.

요청서는 `answered_by_into`를 제안했다. 이름을 `_as`로 바꾼 것은 C14가 「결과가 들어갈 변수」를 이미 `store_as`·`count_as`로 부르기 때문이다(`collect_into`는 반복이 **모으는** 목록이라 뜻이 다르다).

## 결과

- 이 결정으로 쉬워지는 것: 결재 뒤 기록 작업이 서비스 호출 입력에 `{"verified_by": "확인자"}`처럼 쓴다. 대리 답이든 콘솔이든 같은 길이다.
- 어려워지거나 포기하는 것: 옛 엔진은 이 칸을 모른다(모델이 모르는 칸을 보관하므로 읽기는 되지만 변수를 만들지 않는다). 그 변수를 읽는 그림은 옛 엔진에서 「모르는 이름」으로 멈춘다.
- STU-04 결재 편집기에는 칸을 아직 두지 않았다. 편집기가 다루지 않는 칸은 그대로 남기므로(STU-04) 그림에 적은 것은 지워지지 않는다.
- 다시 볼 조건: 사용자 모델(OIDC)이 생겨 이름 대신 계정 id를 넘기게 되면, 이 변수에 무엇을 넣을지 다시 본다(ADR-0080 「다시 볼 조건 ①」과 함께).
