# ADR-0074. STU-13의 「이 스텝까지 시험」과 「계획 굳히기」는 Studio 시험 실행과 같은 길로 Worker를 부른다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-18 |
| 관련 | STU-13, BUI-08, C10, C13 예약 설정 키, [ADR-0008](0008-map-driver-hands-boundary.md), [ADR-0013](0013-api-keys.md), [ADR-0014](0014-one-bot-per-pc.md), [ADR-0035](0035-ui-goal-planning.md), [ADR-0073](0073-studio-settings-only-what-is-used.md), 09-gaps §7-6 |

## 배경

STU-13(UI 태스크 편집기)에 둘이 「아직」이었다.

- **「이 스텝까지 시험」** — 표의 1번부터 고른 스텝까지를 실제 화면에 돌려 본다. 09-gaps는 「BUI-08이 돌리므로 Studio → Bot UI로 넘기는 길이 없다(앱끼리 부르지 않는다)」를 먼저 정할 것으로 적었다.
- **계획 굳히기** — 목표로 계획(ADR-0035)은 자율 수행에서만 돈다. Bot(결정 수행)으로 내보내려면 앱이 세운 스텝을 표에 적어야 하는데, 세운 스텝(C10 `planned_steps`)은 수행기 안에서 쓰이고 사라졌다.

대조해 보니 **Studio 시험 실행은 이미 Bot UI를 거치지 않는다** — UI 태스크 수행기가 Bot UI가 띄운 Worker에 **직접** 붙는다(자리는 `runtime.json`·토큰 파일, 키는 STU-10 「서비스 앱 키」). C10도 필요한 것을 다 갖고 있다: `caller.type = studio`, `report: false`(보내지 않는다), `goal`로 열면 `planned_steps`를 돌려준다. 막힌 것은 편집기가 그 자리와 키를 **받지 못한다**는 것 하나였다 — 편집기 문맥은 Worker 자리 없이, 비밀 없이(ADR-0073 결정 2) 만들어졌다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. Studio가 Bot UI에 시험을 넘긴다 | BUI-08 화면을 그대로 쓴다 | 앱끼리 부르는 길을 새로 만든다. Bot UI가 꺼져 있으면 안 된다(Worker는 떠 있어도) |
| B. 두 기능을 걷고 「시험 실행(케이스)」·BUI-08로 보낸다 | 고칠 것이 없다 | 스텝 몇 줄을 보려고 케이스를 짓는다. 굳히기는 갈 곳이 없다 |
| C. **편집기에 시험 실행과 같은 문맥을 준다** — Worker 자리 + Studio 비밀 창고, 그리고 「BPM 프로세스 설정을 따름」을 풀 키 참조 | 길이 이미 있다(C10을 고치지 않는다). 시험 실행과 **같은 Worker·같은 키**를 본다 | 편집기가 키를 풀 수 있게 된다 |

## 결정

**C로 한다.**

1. **Studio는 확장 편집기에 시험 실행과 같은 문맥을 준다** — 설정은 그 확장의 Studio 칸 + 예약 키(`runtime.<id>.*`·`service.base_url`), 비밀은 `StudioSecrets`다. ADR-0073 결정 2의 「편집기에는 비밀을 주지 않는다」는 이것으로 바뀐다. **설계(고르기)에는 여전히 키가 필요 없다** — 고를 것은 공개 카탈로그에서 오고 셀렉터는 Worker 안에만 있다(ADR-0008). 키는 사람이 「시험」·「계획 세워 보기」를 누를 때만 쓰인다.
2. **예약 키 `service.key_ref`를 더한다** (C13, 머리 `service.`는 이미 예약이라 E7이 그대로 지킨다) — Studio 편집기에만, **열린 BPM 프로세스의 `chk:process.service_keys`가 이 확장에 준 참조**다. 태스크의 `key_ref`가 비면(「BPM 프로세스 설정을 따름」) 이것을 쓴다 — 엔진과 같은 순서다. 값은 **물을 때마다** 지금 열린 BPM 프로세스에서 읽는다(편집기는 한 번 만들어 다시 쓴다). 실행하는 쪽(Bot UI·서버 실행기)은 채우지 않는다 — 수행기는 `TaskContext.key_ref`를 받는다.
3. **「이 스텝까지 시험」** — 1번부터 고른 줄까지를 `caller: studio`·`mode: deterministic`·**`report: false`**로 연 세션에서 하나씩 보낸다. 값의 `{이름}`은 **누를 때 사람에게 묻는다**(케이스가 없다). 결과는 편집기의 「시험 결과」 상자에만 쓰고 **읽은 값도 거기에만** 보인다(원칙 6 — 보고하지 않는다). 전환에서 멈추고 실패라고 하지 않는다. **끝나면 세션을 닫는다** — Worker의 UI 세션은 하나라(ADR-0014) 쥐고 있으면 Bot UI의 Bot이 기다린다.
4. **계획 굳히기** — 목표로 계획을 켰을 때 「계획 세워 보기」가 `mode: autonomous`·`goal`·값 **이름**·결과 이름으로 세션을 열어 `planned_steps`를 받고 **스텝을 돌리지 않고 닫는다**. 받은 스텝을 상자에 보이고, 「스텝으로 굳히기」가 그것을 표에 넣고 **목표로 계획을 끈다** — 그래야 결정 수행이 그 스텝을 돈다(ADR-0035: 결정 수행은 목표로 계획하지 않는다). 굳힌 스텝은 다른 스텝과 같고 같은 검사(STU-13 [W])를 받는다. 받은 계획은 편집기 안에만 있고 **그림에 몰래 적지 않는다**(사람이 눌러야 적는다).
5. 단추는 **Studio 밖·고른 줄 없음·목표로 계획 켬**일 때만 끄고 툴팁으로 까닭을 말한다. 키 참조·키 값·Worker 자리가 없으면 누른 그 자리에서 **아무것도 열기 전에** 「시험 결과」 상자에 까닭을 쓴다(키는 STU-10 「서비스 앱 키」, Worker는 Bot UI) — 키를 보려고 고칠 때마다 OS 비밀 저장소를 두드리지 않는다.

## 결과

- 쉬워지는 것: 스텝 몇 줄을 케이스 없이 그 자리에서 돌려 본다. 자율 수행으로 세운 계획을 Bot으로 내보낼 수 있다. BUI-08(등록 담당자 키로 보는 셀렉터 시험)과 STU-13(개발용 키로 보는 태스크 시험)이 갈린다.
- 어려워지거나 포기하는 것: 확장 편집기가 Studio 비밀 창고에서 키를 풀 수 있다 — 같은 확장의 수행기가 이미 같은 프로세스에서 같은 키를 쓰므로 새로 열리는 문은 아니다. 시험이 끝나면 세션을 닫으므로 화면을 이어서 보려면 다시 돌린다.
- 다시 볼 조건: 「이어서 보기」(세션을 열어 두기)가 자주 필요하다는 말이 나오면 BUI-08처럼 「열어 두기」를 두되 Bot UI 대기열과의 충돌을 먼저 정한다. 외부 확장의 편집기가 생기면(지금은 코드 기여 불가, E1) 비밀을 주는 범위를 다시 본다.
