# ADR-0016. 서버 우선: 업무 대부분은 서버 BPM 프로세스, PC Bot은 사람·화면이 필요할 때만

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-10-01) — §3 "PC 위임"은 **제안** |
| 날짜 | 2026-10-01 |
| 대체 | ADR-0015 §1의 기본값(`pc`) → 기본값 `server` |
| 관련 | ADR-0014, ADR-0015, 계약 C1·C5·C12, 화면 STU-04·STU-05·STU-06, BUI-04, CON-05·CON-12 |

## 배경

ADR-0015에서 실행 위치(PC / 서버)를 나눴고, 기본값을 PC로 두었다. 실제 업무에서는 **대부분의 작업이 서버 BPM 프로세스로 돌고**, 현장 사용자 확인이 필요하거나 UI 등 시스템 특성을 타는 경우에만 PC Bot을 쓰는 것이 맞다.

## 결정

### 1. 실행 위치 기본값은 「서버」

- 새 BPM 프로세스의 실행 위치 기본값은 **서버**다 (C1 `run_location` 기본 `server`).
- **PC를 고르는 경우** (이 중 하나라도 해당할 때만):
  1. UI 태스크가 있다 (화면 조작)
  2. 웹·데스크톱 환경 AI 태스크가 있다
  3. 현장 PC 앞 사람의 확인·결재가 필요하다 (「현장」 결재 위치, 실행 중 확인)
  4. 그 PC에만 있는 자원이 필요하다 (설치된 업무 프로그램, 로컬 파일·장치, 사내망 PC 인증서 등)
- Studio는 위 조건을 자동으로 찾아, 실행 위치가 「서버」인데 해당 태스크가 있으면 「실행 전 검사」에서 오류와 함께 **「실행 위치를 PC로 바꾸기」** 또는 **「이 부분을 PC BPM 프로세스로 나누기」(§3)** 를 제안한다.

### 2. 확정한 세부값 (ADR-0015의 제안 항목)

| 항목 | 확정 |
| --- | --- |
| 운영 화면 이름 | 서버에서 도는 것은 **「서버 Bot」**, PC에서 도는 것은 **「Bot」** |
| 동시 실행 상한 기본값 | 서버 실행기 전체 **10건**, BPM 프로세스 하나당 **5건** (둘 다 설정·배포로 바꿀 수 있음) |
| 일정 | 첫 릴리스(M6)는 PC 실행만. `run_location` 속성과 Studio 검사는 처음부터. 서버 실행은 **M7** |
| 서버 구현 방식 | BPM 업무 흐름대로 동작하고 여러 BPM 프로세스가 동시에 돌기만 하면 된다. 세부 구현은 M7 스파이크·ADR에서 정한다 |

> 주의: M6까지는 서버 실행기가 없으므로, 그동안 Studio의 기본값은 서버로 두되 Center가 서버 배포를 받지 않는다 (「서버 실행은 M7부터」). 이때 만든 서버 BPM 프로세스는 Studio에서 시험 실행만 한다.

### 3. 제안 — PC 위임: 서버 BPM 프로세스가 PC Bot에 일부를 맡긴다

서버 업무 흐름 중 화면 조작이나 현장 확인이 필요한 한 부분 때문에 전체를 PC로 돌리면, 서버 우선 원칙이 깨진다. 그래서 그 부분만 PC BPM 프로세스로 떼어 맡긴다.

```
서버 Bot (서버 실행기)
  ├─ AI 태스크, 서비스 앱 태스크 ...
  ├─ Call Activity → PC BPM 프로세스 「ERP 화면 입력」   ← PC 위임
  │     서버 실행기 → Center: 작업 생성 → Bot UI 대기열 → PC Bot 실행 → 결과
  │     (서버 Bot은 상태를 저장하고 기다림, 동시 실행 상한에 세지 않음)
  └─ 결과로 이어서 진행
```

| 항목 | 제안 |
| --- | --- |
| 표현 | 서버 BPM 프로세스의 Call Activity가 실행 위치 「PC」인 BPM 프로세스를 부르면 PC 위임이다 (새 태스크 종류를 만들지 않는다) |
| 대상 PC | 「배포된 Bot UI 중 아무 곳」(대기열이 가장 짧은 곳) / 「지정한 Bot UI」 / 「입력 변수로 정함」(예: 담당자 PC) |
| 기다림 | 서버 Bot은 상태를 저장하고 기다린다. PC 쪽은 ADR-0014대로 하나씩, 끝날 때까지 |
| 결과·실패 | PC Bot의 출력이 Call Activity 출력으로 돌아온다. 실패·거절·시간 초과는 오류 경계 이벤트로 |
| 기록 | 작업 요청자가 「서버 Bot <이름> (실행 id)」로 남아, 콘솔에서 서버 실행 ↔ PC 실행을 오갈 수 있다 |
| 일정 | M7 (서버 실행과 함께) |

## 결과

- 쉬워지는 것: 업무 대부분이 PC 수와 무관하게 서버에서 동시에 돈다. PC는 사람·화면이 필요한 일에만 쓰여 대기열이 짧아진다.
- 어려워지는 것: 서버 실행이 M7이라, 첫 릴리스 전까지는 서버 BPM 프로세스를 운영에 올릴 수 없다 → 서버 실행을 앞당길지는 M6 진행을 보고 다시 판단한다. PC 위임에는 Center 작업과 서버 실행의 연결(C5·C12)이 필요하다.
- 다시 볼 조건: PC 위임이 많아져 PC 대기열이 병목이 되면, PC 배정 규칙(담당자·부서별 PC 묶음)을 ADR로 연다.
