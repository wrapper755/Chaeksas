# ADR-0124. 콘솔의 API 키 화면을 없애고 키 동작은 그 키가 가리키는 화면에 둔다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 · **표의 CON-07 두 줄(일꾼·폴더 키, 예전에 발급한 연동 키)은 [ADR-0128](0128-console-drops-the-resources-screen.md)이 대체한다** — 리소스 화면이 없어져 그 키 동작은 콘솔에 없다 |
| 날짜 | 2026-11-01 |
| 관련 | 화면 CON-03·CON-07·CON-11·CON-12, 계약 C7(바뀌지 않는다), [ADR-0092](0092-keys-are-issued-and-delivered-by-center.md), [ADR-0093](0093-studio-is-let-in-by-approval.md), [ADR-0095](0095-deleting-revoked-center-keys.md), [ADR-0117](0117-bundled-server-runner-joins-by-shared-secret.md), [ADR-0122](0122-consumer-folder.md), [ADR-0123](0123-folder-keys.md) |

## 배경

CON-11 「API 키」는 키를 발급·폐기하는 화면이었다. 그런데 이제 키는 모두 콘솔 밖에서 들어온다 — PC 실행기·Studio는
등록 승인(ADR-0092·0093), 서버 실행기는 함께 배포된 비밀(ADR-0117), 일꾼·연동용·대리 답용은 일꾼 폴더의 파일
(ADR-0122·0123). 화면에는 앞자리가 비고(폴더 키) 「등록 전」인 줄, 파일을 바꿀 때마다 폐기된 채 남은 같은 이름의
줄만 쌓였다. 사용자가 「발급을 하지 않는데 보여 줄 이유가 있나」라고 물었다(2026-11-01). 남는 쓸모는 **새어 나간 키를
바로 끊는 폐기** 하나다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 화면을 폐기하는 자리로만 줄인다 | 키를 한눈에 본다 | 볼 거리가 없는 화면이 남는다. 키를 보려면 대상과 키를 머리로 잇는다 |
| B. **화면을 없애고 폐기를 그 키가 가리키는 화면에 둔다** | 「이 PC·이 일꾼의 키를 끊는다」가 그 대상 옆에서 끝난다. 메뉴가 준다 | 키 목록을 한꺼번에 보는 곳이 없다 |

## 결정

**B.** CON-11과 메뉴의 「관리 › API 키」를 없애고, 「...」(폐기·묶음 풀기·삭제 — 규칙은 그대로, `components/KeyMenu.tsx` 하나)를
Bot 상세(CON-03)·Studio 탭 줄(CON-03)·서버 실행기 상세(CON-12)·일꾼 폴더 줄(CON-07)에 둔다.

1. 콘솔에서 키를 **발급하지 않는다**(「새 키...」를 걷는다). Center API(`POST /center-keys`, C7)는 그대로다 — 자동화·시험이 쓴다.
2. 일꾼 폴더 줄과 키는 **이름·종류·앞자리 없음**으로 잇는다(폴더 키는 원문을 몰라 앞자리가 비어 있다, ADR-0123). 같은 이름이
   여럿이면 사용 중인 것, 없으면 가장 최근 것이다.
3. 예전에 콘솔에서 발급한 연동용·대리 답용 키(앞자리가 있는 것)는 일꾼 폴더 아래 「콘솔에서 발급한 연동 키」에 **있을 때만** 보인다 —
   사라지면 끊을 길이 없다.
4. 키의 이력은 CON-16 「앱 로그」가 말한다.

## 결과

- 쉬워지는 것: 메뉴 「관리」가 「관리자 계정」 하나가 된다. 끊는 자리가 대상 옆이라 어느 키인지 헷갈리지 않는다.
- 포기하는 것: 모든 키를 한 표로 훑어보기. 필요하면 C7 `GET /center-keys`를 직접 부른다.
- 다시 볼 조건: 콘솔에서 키를 다시 발급해야 하는 종류가 생기면(그때는 그 종류를 쓰는 화면에 둔다).
