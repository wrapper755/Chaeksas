# ADR-0127. 업무 자리는 **Studio가 올릴 때 고르고 매니페스트에 실린다** — Center는 승인할 때 확인만 한다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-11-01) |
| 날짜 | 2026-11-01 |
| 관련 | [ADR-0125](0125-organization-and-work-placement.md)(§3 「승인할 때 관리자가 고른다」와 §5의 그 부분을 이 ADR이 대체한다 — 나머지는 그대로다), [ADR-0090](0090-center-admin-accounts.md), 계약 C1·C2·C5·C16, 화면 STU-12·CON-02·CON-06 |

## 배경

ADR-0125는 업무 자리(회사 공통 / 부서 공통 / 개인)를 **Center에서 승인할 때 관리자가 고르고** 서명하지 않기로 했다. 조각 2를 짓기 시작하자 사용자가 방향을 바로잡았다. **Center에서는 승인만 하고, 정보는 Studio에서 올릴 때 고른다. Center에서는 확인만 한다.**

업무 자리는 「이 BPM 프로세스가 누구의 일인가」다. 그것을 아는 것은 그 업무를 설계하고 올리는 쪽이고, 관리자는 그것이 맞는지 보고 승인한다 — 다른 요구 사항(실행 위치·확장·위임)이 매니페스트에 실려 승인되는 것과 같은 결이다.

## 선택지

**어디에 싣나**

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| **A. 매니페스트(C1)에 — 서명된다** | 관리자가 확인한 그대로 고정된다. 「무엇을 승인했나」에 자리가 들어간다. 다른 요구 사항과 같은 자리라 새 길이 없다 | 자리를 바꾸려면 판을 올려 다시 올리고 다시 승인한다 |
| B. 올리기 요청의 칸으로 — 서명 밖 | 판을 올리지 않고 다시 올려 바꾼다 | 승인한 뒤에도 자리가 바뀔 수 있다 — 관리자가 확인한 것이 남지 않는다 |

**Center의 확인**

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| **A. 승인 창·상세에 보여 주기만** | 「확인만」 그대로다. 자리를 고르지 않은 BPM 프로세스도 회사 공통으로 승인할 수 있다 | 고르지 않고 올린 것을 Center가 막지 않는다 |
| B. 자리 없는 것은 승인 못 하게 | 빠뜨린 것을 막는다 | 회사 공통 업무는 고를 것이 없는데 늘 고르게 한다 |

## 결정

**A · A — 업무 자리는 Studio가 「Center로 올리기」에서 고르고 매니페스트에 실려 서명된다. Center는 올릴 때 검사하고, 승인할 때는 보여 주기만 한다.**

### 1. 매니페스트 (C1 `place`)

```json
{"id": "buy.request", "version": "1.2.0", "kind": "bpm_process",
 "place": {"scope": "department", "department": "purchasing"}}
```

- 모양은 C16 `Place` 그대로다(`scope` + 그에 맞는 `department`·`staff`). **회사는 적지 않는다** — 올린 Studio의 회사다(Studio는 회사 소유다, ADR-0125 §2).
- 비우면 **회사 공통**이다. `process_lib`에는 적지 않는다(C1 검사 — 공유 BPM 프로세스는 부품이다).
- 자리는 **판마다** 있다(매니페스트가 판마다이므로). 작업은 그 작업이 도는 판의 자리를 쓴다. 자리를 바꾸려면 판을 올린다.
- 서명된 매니페스트에 들어가므로 승인 뒤에는 바뀌지 않는다.

### 2. Studio — 올리기 확인 창에서 고른다

- STU-12 「Center로 올리기...」를 누르면 확인 창이 뜨고 **「회사」**(이 Studio의 회사, 글로만)와 **「업무 자리」**(회사 공통 / 부서 ▾ / 직원 ▾)를 보인다. 목록은 **그 Studio 키로 Center에서 읽은 제 회사의 부서·직원**이다(C16 읽기 — Studio 키는 제 회사 것만 읽는다).
- 고른 자리는 작업 폴더 기록(`process.json`)에 남아 다음 올리기에 미리 골라져 있다. 빌드(`packaging.build_manifest`)가 그것을 매니페스트로 옮긴다 — 「내보내기」도 같은 값을 싣는다.
- Center에 닿지 못하면 목록을 그리지 못한다 — 그때는 「회사 공통」만 고를 수 있고 그렇게 말한다(올리기 자체도 Center가 필요하다).

### 3. Center — 올릴 때 검사하고 승인할 때 보여 준다

- **올릴 때**(`POST /packages`): 자리의 부서·직원이 **올린 Studio의 회사 안에** 있어야 한다 — 아니면 422 `place_outside_company`(없는 id도 같다). 모르는 `scope`는 422 `input_invalid`. 그 회사·부서·직원이 멈춰 있어도 받는다(돌 때 `owner_stopped`가 막는다).
- **승인할 때**: 본문이 없다(지금 그대로). CON-02·CON-06의 「승인...」 확인 창과 프로세스 상세에 **「회사」·「업무 자리」를 글로 보인다**. 바꾸는 칸은 없다 — 틀렸으면 승인하지 않고 Studio에서 판을 올려 다시 올린다.
- `PUT /packages/{id}/place`·승인 본문의 `place`(ADR-0125 §3)는 **두지 않는다**. 저장소의 업무 자리 표(`process_places`, 22판)는 23판에서 지운다 — 자리는 매니페스트에서 읽는다.

## 결과

- 이 결정으로 쉬워지는 것: 관리자가 승인한 것에 「누구의 일인가」가 들어 있다. Center에 고르는 화면이 없다. 자리를 정하는 사람이 업무를 아는 사람이다.
- 어려워지거나 포기하는 것: 자리를 바꾸려면 판을 올려 다시 승인한다. Studio가 올리기 전에 Center의 조직을 읽어야 한다. 22판이 가상 직원의 접수 BPM 프로세스에 지어 둔 자리는 23판에서 사라진다(그 패키지들은 자리 없음 = 회사 공통이 된다).
- 다시 볼 조건: ① 자리를 판을 올리지 않고 바꿔야 하는 업무가 잦아지면 — 서명 밖 칸(선택지 B)을 다시 본다. ② 같은 판을 두 자리에 두어야 하면.
