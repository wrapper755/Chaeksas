# ADR-0044. 캔버스 드롭은 내부 렌더 위젯에서 가로채고, 자리만 캔버스에 넘긴다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-11 |
| 관련 | 스파이크 `spikes/s9-canvas-drop/`, [ADR-0022](0022-studio-canvas.md), STU-03·STU-01, `docs/09-gaps.md` §4-4 |

## 배경

STU-03 리소스 탐색기에서 캔버스로 **끌어다 놓기**가 남아 있었다 (§4-4). 지금은 문맥 메뉴
「캔버스에 추가」와 더블클릭이고, 만드는 일은 캔버스 명령 하나(`createTask`)가 해서 실행
취소도 한 걸음이다 — 드래그도 **그 명령을 그대로** 써야 한다.

막힌 곳은 Qt 쪽이다. 캔버스는 `QWebEngineView`(ADR-0022)이고 그 안은 Chromium이라 드래그를
**스스로 처리한다**. 뷰에 `dropEvent`를 달면 불리지 않는다는 말이 있어 먼저 확인했다
(`spikes/s9-canvas-drop/`): 사실이었다 — 드래그 이벤트는 뷰가 아니라 **내부 렌더 위젯**
(`focusProxy()`)으로 가고, 그 위젯은 `__init__`에 **아직 없다**.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 내부 렌더 위젯에 이벤트 필터 (`ChildAdded`로 생길 때 단다) | 드롭 자리를 Qt 좌표로 **그대로** 받는다. 페이지를 고치지 않는다 | Qt 내부 구조(자식이 뒤에 생긴다)에 기댄다 |
| B. HTML5 드래그로 페이지에 넘긴다 (`text/plain`을 Chromium이 받게) | Qt 내부에 기대지 않는다 | **드래그를 시작하는 쪽이 Qt 트리다** — Qt → 페이지로 custom MIME을 넘길 길이 없고, `text/plain`에 실으면 그림 안 글상자에 글자가 떨어진다 |
| C. 드래그 대신 「캔버스에 추가」만 둔다 (지금) | 할 일이 없다 | 설계자가 기대하는 동작이고 화면 문서가 이미 적고 있다 |

## 결정

**A.** 캔버스는 `ChildAdded`를 보고 내부 렌더 위젯이 생길 때 거기에 이벤트 필터를 달아,
**우리 MIME 형식일 때만** 드롭을 받는다. 받은 것은 해석하지 않고 **글과 자리**(`payload`,
`x`, `y`)로 올려 보내고, 뜻을 아는 쪽(메인 창 → `center_actions`)이 풀어 **「캔버스에 추가」와
같은 길**로 노드를 만든다.

- **캔버스는 무엇이 떨어졌는지 모른다.** 받을 형식은 부르는 쪽이 알려 준다
  (`accept_drops_of(...)`) — 캔버스 코드에 「리소스」라는 말이 없다 (ADR-0022의 결).
- **뜻을 푸는 것은 `resources.py`다** — `Create` ↔ MIME 글을 그 모듈의 순수 함수 둘이
  오간다(Qt 없이 시험한다). 트리가 싣고 드롭이 푼다.
- **만드는 길은 하나다.** 드래그도 `createTask`를 부르고, 다른 것은 **자리뿐**이다
  (`at`을 주면 그 자리, 주지 않으면 지금처럼 빈자리를 찾는다). 두 길이 갈리면 실행 취소가
  한쪽에서만 한 걸음이 된다.
- **좌표에 `devicePixelRatio`를 넣지 않는다.** 내부 위젯이 뷰를 꽉 채우고(스파이크 ⑤) Qt의
  드롭 위치와 페이지의 CSS 픽셀이 모두 장치 독립 픽셀이라 그대로 쓴다. 다이어그램 좌표로
  바꾸는 일은 **JS가** `viewbox()`로 한다 (축척·스크롤을 아는 쪽이 하나다).
- **받지 않은 드롭은 가던 길로 보낸다** — `eventFilter`가 `False`를 돌려주면 페이지 안의
  bpmn-js 팔레트 드래그와 바깥에서 끌어 온 파일이 그대로 Chromium으로 간다.
- **열린 정의가 없으면 받지 않는다** — 「캔버스에 추가」와 같은 관문이고 같은 한 줄을 말한다.

## 결과

- **쉬워지는 것:** STU-03의 네 뿌리가 한 자리에서 드래그를 얻는다 (뿌리마다 코드가 없다 —
  `Create`를 싣는 것이 하나다). 확장이 기여한 뿌리도 그대로 끌 수 있다.
- **어려워지거나 포기하는 것:** Qt 내부 구조에 기댄다 — PySide6가 렌더 위젯을 다르게 만들면
  드롭이 **조용히** 안 된다. 그래서 시험이 「필터를 달았다」가 아니라 **진짜 드롭 이벤트를
  보내 노드가 생기는 것**까지 본다. 페이지 안으로 끌어 **스텝 사이에 끼우는** 것(연결선 위에
  놓기)은 하지 않는다 — bpmn-js의 `dragging`에 들어가야 하고, 그것은 다른 조각이다.
- **다시 볼 조건:** PySide6 판을 올려 드롭이 오지 않으면(시험이 잡는다), 또는 페이지 안쪽
  드래그와 겹쳐 bpmn-js 팔레트가 망가지면.
