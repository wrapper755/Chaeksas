# ADR-0089. Admin UI를 짓는다 — 키·Center 연결·외부 확장부터, 서명은 누를 때마다 암호를 묻고 키를 버린다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-23 |
| 관련 | [ADR-0076](0076-no-admin-window-yet.md)(이것이 대체한다), 화면 `admin.md`(ADM-01·04·05·06), C2 서명 봉투, C13 E6, `apps/admin`(`chk-admin`·`chk-admin-ui`), [ADR-0013](0013-api-keys.md) |

## 배경

ADR-0076은 Admin 창을 짓지 않고 서명을 `chk-admin` 하나에 남겼다. 그리고 다시 볼 조건 ①로 「Admin이 명령줄을 쓰지 않는 사람으로 바뀌어 **서명이 미뤄지는 일**이 생기면」을 적어 두었다.

그 일이 생겼다. 외부 확장(NowView SC01) 하나를 등록하려던 Admin이 다음 단계에서 모두 막혔다.

- 키가 여럿이라 `--key`를 골라야 했다. `--key`는 서브명령 **앞**에 와야 하는데, 오류 문구는 그 자리를 말하지 않았다.
- `keys list`는 Center에 닿지 못했는데도 「등록 안 됨」이라고 거짓으로 말했다.
- 첫 키를 Center에 넣으려면 서버 셸에서 명령을 쳐야 했다. compose로 띄운 Center라면 그 명령이 컨테이너 안이다.
- Center 주소와 관리자 토큰을 셸마다 환경변수로 넣어야 했다.
- 봉투를 따로 콘솔에 올려야 했다.

CLI 쪽 흠(앞의 둘과 「봉투를 따로 올린다」)은 같은 날 고쳤다. 그래도 Admin의 말은 「설치할 때마다 이걸 할 수는 없다」였다. 명령줄 자체가 장벽이다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. CLI만 다듬고 설치 스크립트를 준다 | 서명 코드가 한 벌이고 공격면이 그대로다 | 키를 만들고 지우고 고르는 일이 여전히 명령이다. 다시 볼 조건 ①이 그대로 남는다 |
| B. **PySide6 Admin UI를 짓는다.** 첫 판은 키(ADM-01), Center 연결(ADM-05), 외부 확장(ADM-04)이다 | 지금 막힌 일을 모두 누르기로 푼다. 고르기(키·서명할 키·확장)가 화면에 보인다 | 서명 PC에 Qt가 들어온다. 서명하는 길이 둘이 된다 |
| C. 서명을 웹 콘솔로 옮긴다 | 어디서나 된다 | 「서명이 서버에서 일어나지 않는다」는 관문(C2)을 버린다 |

## 결정

**B로 한다.** Admin UI(`chk-admin-ui`, `apps/admin`)를 짓고, ADR-0076이 정해 둔 두 조건을 지킨다.

1. **누를 때마다 암호를 묻고, 서명 뒤 키를 버린다.** 창은 암호도 열린 개인키도 쥐고 있지 않는다. 서명은 함수 한 번 안에서 열고 서명하고 끝난다. CLI의 「명령 한 번」이 창의 「누름 한 번」이 된다.
2. **확인 문구와 서명은 CLI와 같은 함수다.** 정의 검사(E1·E3)와 보여 줄 줄(해시·허용 호스트·사설망·작업별 수행 모드), 봉투 내용, 서명할 키 고르기는 Qt를 모르는 `admin/ops.py`에 두고 `cli.py`와 창이 함께 부른다. 그래서 확인 문구가 두 벌로 갈라지지 않는다.
3. **Center 연결(ADM-05, 주소·토큰)과 첫 키의 서버 셸(ADM-06)은 다른 창이다.** 연결은 Center를 부르는 모든 동작이 쓰고, 셸은 Center에 Admin 키가 없을 때 한 번만 쓴다.
4. **첫 판은 지금 막힌 일만 한다.** 키 만들기·지우기·Center 등록·철회, Center 주소와 토큰, 외부 확장 서명·등록·철회다. 승인 대기(ADM-02)와 배포(ADM-03)는 다음 판이다. 그동안 그 둘은 CLI와 콘솔이 한다.
5. **Center 연결은 저장한다.** 주소는 Admin 설정 파일(`settings.json`, 데이터 폴더)에 둔다. 관리자 토큰은 OS 비밀 저장소(`chaeksas-admin`)에 둔다(비밀은 설정 파일에 넣지 않는다, CLAUDE.md §5). 읽는 순서는 **환경변수가 먼저**다(개발·CI). CLI의 `Center.from_env()`도 같은 순서로 읽으므로, 창에서 한 번 넣으면 CLI도 환경변수 없이 돈다.
6. **첫 키(부트스트랩)는 「서버 셸」로 넣는다 — 이 PC든 SSH든.** C2는 첫 키를 서버 셸에서만 넣게 한다. 창은 그 셸을 **연결 정보로 가진다**(ADM-06 「서버 셸」).
   - **이 PC**: Center 주소가 루프백일 때만 쓴다. 주소가 다른 곳을 가리키면 이 PC의 Center는 그 Center가 아니다.
   - **SSH**: `ssh` 명령(OpenSSH — Windows 10 이상에 들어 있다)을 `BatchMode=yes`로 부른다. 그래서 **암호를 묻지 않고 받지도 않는다.** SSH 키나 에이전트로 들어갈 수 있어야 하고, 안 되면 그렇다고 말한다. SSH 접속은 곧 서버 셸이므로 C2 규칙 그대로다.
   - 그 셸에서 Center를 찾는 법은 둘이다. 비워 두면 compose 서비스 `center` 컨테이너를 찾아 **컨테이너 안에서** 돌린다(하나일 때만 — 둘이면 고르지 않는다). 「Center 명령」을 적었으면 그 명령으로 돌린다(`uv run chk-center` 같은, docker 없는 설치).
   - 공개키는 **stdin으로** 건넨다(서버에 파일을 들이지 않는다).
   - **넣은 뒤 Center API로 확인한다.** 주소의 Center가 그 키를 Admin 키로 알아야 성공이다. 다른 Center에 넣었다면(셸과 주소가 서로 다른 서버) 그렇다고 말한다.
   - 셸이 없거나 찾지 못하면 그 서버에서 칠 명령과 공개키를 보이고 「복사」만 둔다.
   - **API(네트워크)로 첫 키를 넣는 길은 만들지 않는다.** 관리자 토큰이 새면 누구나 제 키를 Admin으로 넣을 수 있게 되기 때문이다.
7. **지우기는 이 PC의 키 파일만 지운다.** Center에서 철회하는 일과 다르다. Center에 등록되어 있고 철회되지 않은 키를 지우면 그 키로는 다시 서명할 수 없다. 그래서 그 경우는 한 번 더 묻고, 기본 답은 「취소」다. 그것이 Center가 아는 **유일한** 키라면 지우지 않는다. 지우면 Admin이 잠긴다(새 키를 넣을 서명자가 없다).
8. 설치 파일(PyInstaller)은 이번 판에 묶지 않는다. 지금은 `uv run chk-admin-ui`로 띄운다.

## 결과

- 쉬워지는 것: Admin이 명령을 외우지 않는다. 키가 여럿이어도 Center가 아는 키가 화면에 보인다. 외부 확장은 파일 하나를 골라 「서명하고 등록」 한 번으로 끝난다. CLI도 저장된 연결을 읽어 환경변수가 필요 없다.
- 어려워지거나 포기하는 것: 서명 PC에 PySide6(Essentials)가 들어온다. 서명하는 입구가 둘이다. 그래서 둘이 갈라지지 않게 `ops.py`를 함께 쓰는 것을 시험이 지킨다.
- 다시 볼 조건: ① 승인·배포도 미뤄지면 ADM-02·03을 짓는다. ② 서명을 하드웨어 키로 옮기면 「누를 때마다 암호」가 「누를 때마다 터치」로 바뀐다. ③ Admin UI를 서명 PC에 설치 파일로 깔아야 하면 `packaging/build.py`에 셋째 묶음을 더한다.
