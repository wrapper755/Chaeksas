# ADR-0030. AI 태스크의 도구는 **core가 가진 내장 넷**으로 시작하고, PDF는 `pypdf`를 쓴다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-05 |
| 관련 | 스파이크 [`spikes/s8-doc-tools/`](../../spikes/s8-doc-tools/NOTES.md), [ADR-0027](0027-llm-connection.md)(모델에 닿는 길), [ADR-0026](0026-file-paths-and-file-list-task.md)(파일 경로), [ADR-0018](0018-extensions.md)(확장), [ADR-0024](0024-desktop-packaging-extensions.md)(설치 파일), [C14](../03-contracts/C14-bpmn-extensions.md) §태스크 종류(AI 태스크), M3 조각 3c-2 |

## 배경

ADR-0027이 AI 태스크의 루프를 `core`에 두었지만 **도구는 빈 사전**이었다 (`RunEnv.tools`). 모델이 「`pdf_text_tool`을 불러라」 해도 「이 PC에 그 도구가 없다」로 끝난다. M3 인수 묶음 24개 중 6개가 도구를 요구하므로(`pdf_text_tool` 3, `http_request_tool` 3, `excel_parser_tool` 1, `csv_parser_tool` 1) 지금 정한다.

두 가지가 열려 있었다. ① **누가 도구를 가지나** — `RunEnv.tools`의 주석은 「확장이 더한다」였는데, 그러면 PDF를 읽으려고 확장을 깔아야 한다. ② **PDF 글자 뽑기를 무엇으로 하나** — 우리에게 없는 의존성이다.

②는 재 보았다 (스파이크). 업무 PDF는 포털·회계 프로그램·한글 워드가 뽑아 준 것이라 **만든 쪽을 고를 수 없어서**, 같은 글을 생성기 둘로 만들어 후보 둘에 넣었다.

## 선택지

### 누가 도구를 가지나

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| **A. `core`에 내장 넷, 그 위는 확장** | 평범한 문서 업무가 **아무것도 깔지 않고** 돈다. 넷은 OS를 타지 않고 의존성이 거의 없다 | `core`가 조금 커진다 (PDF 1.7 MB) |
| B. 전부 확장으로 | 플랫폼이 얇다 | 예제 절반이 확장을 요구한다. 「PDF를 읽으려면 확장을 까세요」는 M3 인수 시험을 못 돌린다 |
| C. 전부 `core`에 (OCR·브라우저까지) | 한 번에 다 된다 | OCR·브라우저는 네이티브·OS를 탄다. ADR-0018이 가른 자리를 다시 뭉갠다 |

### PDF 글자 뽑기

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| **A. `pypdf`** | **1.7 MB, 딸려 오는 것 없음.** 표본 둘 다에서 다 뽑았다. 순수 파이썬이라 OS·아키텍처를 안 탄다 | 표 격자를 복원하지 못한다 (어느 후보도 못 한다) |
| B. `pdfminer.six` | 배치 정보가 더 자세하다 | **24.7 MB** — `cryptography`(네이티브 바퀴)·`cffi`·`pycparser`가 딸려 온다. 표본 하나에서 **아무것도 못 뽑았다**(2자) |
| C. `pymupdf` | 빠르고 정확하다 | **AGPL** — 상용 배포가 걸린다. 후보에서 뺐다 |
| D. 안 들인다 (PDF는 서비스 앱으로) | `core`가 안 커진다 | 서버가 없으면 PC 문서 업무가 안 돈다. 파일을 서버로 올려야 해서 「PC 파일은 PC에서」가 깨진다 |

## 결정

**내장 도구 넷을 `core.tools`에 두고(`pdf_text`·`excel_parser`·`csv_parser`·`http_request`), PDF는 `pypdf`를 쓴다.**

1. **도구는 이름 그대로 `RunEnv.tools`에 꽂힌다.** 실행하는 쪽(Studio·Bot UI·서버 실행기)이 `builtin_tools(...)`로 만들어 넣는다. 확장은 거기에 **더한다** — 같은 이름이면 확장이 이긴다 (확장이 더 아는 자리다).
2. **도구는 자기 설명과 인자 모양을 들고 다닌다** (`ToolDef.spec`). 이름만 알려 주면 모델이 인자를 지어낸다 — 실제로 지어냈다. 설명·인자 스키마는 OpenAI 호환 `tools` 필드로 그대로 간다.
3. **파일 도구는 `Workspace`를 거친다** (ADR-0026). 출력 폴더와 읽기 허용 폴더 밖은 `PathDenied`이고, 그것은 **오류 경계로 받지 않는다** (그림·설정이 잘못된 것이다). 파일이 없거나 형식이 아니면 **업무 실패**다.
4. **`http_request_tool`은 읽기만 한다** — `GET`·`HEAD`만, 리다이렉트는 따라가되 횟수를 막고, **본문 길이에 상한**을 둔다. 보내기(메일·웹훅)는 이 도구가 아니라 `chk:send`의 일이다 (어댑터가 막는 자리를 도구로 돌아가지 못하게 한다). 주소는 그림이나 업무 파라미터가 준다.
5. **도구가 돌려주는 것은 글(str)이다** (ADR-0027의 루프 규약). 표는 **JSON 한 덩이**로 돌려준다 — 모델이 다시 쪼개지 않아도 되게. 길면 자르고 **잘랐다고 말한다** (조용히 자르면 모델이 없는 것을 없다고 단정한다).
6. **값은 기록하지 않는다** (계약 원칙 6). 도구 이름·인자 키·결과 **길이**만 궤적에 남고 내용은 남지 않는다.
7. 아직 만들지 않는 둘 — `image_ocr_tool`(OCR은 네이티브다. 확장 또는 서비스 앱), `excel_writer_tool`(쓰기는 `chk:dataOutput`이 이미 한다. 중복을 만들지 않는다).

## 결과

- 이 결정으로 쉬워지는 것: M3 인수 묶음의 문서·API 예제가 **아무것도 깔지 않고** 돈다. 도구가 설명을 들고 다녀 모델이 인자를 지어내지 않는다. `core`의 의존성은 **하나(1.7 MB)만** 는다.
- 어려워지거나 포기하는 것: 스캔 PDF(그림만 있는 것)는 못 읽는다 — 「글자가 없다」로 업무 실패를 올린다. PDF 표의 격자는 복원하지 않는다 (격자가 필요하면 엑셀·CSV로 받는다). `http_request_tool`로는 보낼 수 없다.
- 다시 볼 조건: 스캔 문서가 업무에 자주 나오면 OCR을 확장으로 붙인다. 뽑기가 자꾸 어긋나는 PDF가 쌓이면 후보를 다시 잰다 (`spikes/s8-doc-tools/run.py`가 그대로 돈다). 도구가 넷을 넘어 늘어나면 **그때는 확장으로** 민다 — `core`를 도구 창고로 만들지 않는다.
