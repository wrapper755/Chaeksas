# ADR-0014. PC 한 대에서 실행 중인 Bot은 하나: 나머지는 Bot UI 대기열에서 기다린다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 (2026-10-01) — §5 결재 대기: 끝날 때까지 자리를 쥔다로 확정 (2026-10-01). 범위는 실행 위치가 PC인 BPM 프로세스 ([ADR-0015](0015-run-location.md)) |
| 날짜 | 2026-10-01 |
| 대체 | ADR-0012의 "Bot 실행마다 자식 프로세스(실행기)를 띄워 여러 Bot이 함께 산다"는 제안 |
| 관련 | ADR-0012, 계약 C4·C5, 스파이크 S4, 화면 BUI-01·BUI-04·BUI-06, CON-03·CON-05, STU-08 |

## 배경

ADR-0012에서는 Bot 실행마다 Bot UI의 자식 프로세스(실행기)를 띄워, Bot 하나가 죽어도 "다른 Bot은 산다"고 적었다. 이는 여러 Bot이 한 PC에서 동시에 돈다는 전제다.

실제 구조는 그렇지 않다. Bot은 화면·키보드·마우스·브라우저를 쓰는 업무 자동화라 **한 PC에서 둘이 동시에 돌 수 없다** (화면 포커스, 입력 장치, 로그인 세션, 업무 프로그램 창을 서로 빼앗는다).

## 결정

### 1. 실행 자리는 하나

- PC 한 대(= Bot UI 하나)에서 **실행 중인 Bot은 최대 1개**다. 이를 "실행 자리"라 부른다.
- 실행 자리가 차 있으면 새 실행 요청은 **Bot UI 대기열**에 들어가 차례를 기다린다.
- 대기열에 들어오는 요청: Center 작업 지시, 수동 실행(BUI-04 「지금 실행...」), 감시 모드 트리거, 일정, 메시지 수신(ReceiveTask·메시지 시작 이벤트).

### 2. 대기열 규칙

| 규칙 | 내용 |
| --- | --- |
| 순서 | 들어온 순서 (FIFO). 수동 실행만 「맨 앞에 넣기」를 고를 수 있다 |
| 크기 | 기본 20건 (`CHK_BOT_UI__QUEUE__MAX`). 가득 차면 새 요청은 거절: Center 작업은 「거절 — 대기열 가득」으로 Center에 알린다 |
| 만료 | Center 작업의 만료 시각이 대기 중에 지나면 실행하지 않고 「만료」로 알린다 |
| 감시 모드 | 같은 감시 Bot의 대기 항목은 최대 1건 (트리거가 쌓여도 하나로 합친다). 다른 Bot이 실행 중일 때 감시 Bot은 트리거를 확인하지 않는다 |
| 보이기 | Bot UI 「Bot」 탭(BUI-04)과 트레이(BUI-01)에 실행 중 1건 + 대기 N건. 하트비트로 Center에 보고 → 콘솔 CON-03·CON-05 |
| 취소 | Bot UI에서 대기 항목 「취소」. Center 작업은 콘솔에서도 취소할 수 있다 |
| 종료 시 | Bot UI를 끄면 대기열의 Center 작업은 「거절 — Bot UI 종료」로 돌려보내고, 로컬 요청은 버린다 (경고 창에 건수 표시) |

### 3. 실행기는 하나만, 격리용으로 유지

- Bot 실행은 여전히 Bot UI의 **자식 프로세스(실행기) 하나**에서 돌린다. 목적은 동시 실행이 아니라 **격리**다: Bot이 멈추거나 죽어도 Bot UI(트레이·대기열·Center 연결)는 살아 있고, Bot UI가 실행기를 강제로 끝내고 다음 차례로 넘어갈 수 있다.
- 실행기는 동시에 하나만 있다. S4 스파이크에서 Windows·Linux 자식 프로세스 관리를 확인하고, 과하게 복잡하면 Bot UI 안의 스레드 실행으로 되돌린다 (그래도 실행 자리 하나 규칙은 그대로).

### 4. Worker의 UI 세션도 하나

Worker 프로세스는 같은 PC의 화면을 다루므로 **UI 세션을 한 번에 하나만** 연다. Bot 실행, Studio 시험 실행(설계자 PC), UI 셀렉터 등록이 이 세션을 나눠 쓴다.

| 상황 | 처리 |
| --- | --- |
| Bot 실행 중에 셀렉터 등록 | 등록 창은 열리지만 브라우저 동작 단추는 꺼지고 「Bot 실행 중 — 끝나면 쓸 수 있습니다」 |
| 셀렉터 등록 중에 Bot 차례가 옴 | Bot은 대기열 맨 앞에서 기다리고, 트레이에 「대기 중인 Bot이 있습니다 — 등록을 마치면 실행됩니다」. 등록 창을 닫으면 바로 실행 |
| Bot 실행 중에 Studio 시험 실행 (UI 태스크 있음) | Studio 실행 대화상자(STU-08)에서 「Worker 사용 중 — Bot 실행 중」, 「실행」 단추 꺼짐 |

### 5. 결재·확인 대기 중에도 실행 자리를 쥔다 (확정)

Bot은 결재(현장 창이든 Center 결재함이든)나 확인을 기다리는 동안에도 실행 자리를 쥐고, **완료될 때까지 기다린다.** 실제 업무에서 담당자가 일을 하다 결재를 기다리는 것과 같은 형태다. 결재 폼의 시간 제한을 넘으면 시간 초과로 처리한다. 실행 상태를 저장하고 자리를 놓는 방식은 PC에서는 만들지 않는다.

화면이 필요 없고 여러 건을 동시에 돌려야 하는 업무는 실행 위치를 「서버」로 정한다 ([ADR-0015](0015-run-location.md)).

## 결과

- 쉬워지는 것: 화면·입력 충돌이 구조적으로 없다. 실행 순서와 대기 상황을 운영자가 콘솔에서 본다. Worker도 세션 하나만 다룬다.
- 어려워지는 것: 처리량은 PC 대수에 묶인다 (늘리려면 Bot UI를 설치한 PC를 늘린다). 대기열 상태를 하트비트·작업 계약(C4·C5)에 넣어야 한다.
- 다시 볼 조건: 화면을 쓰지 않는 Bot(AI 태스크·서비스 앱 태스크만)의 동시 실행 요구가 생기면, "화면 없는 Bot" 구분을 따로 검토한다.
