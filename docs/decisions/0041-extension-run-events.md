# ADR-0041. 확장은 `TaskOutcome.events[]`로 실행 기록에 남기고, 줄을 쓰는 것은 엔진이다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-09 |
| 관련 | [C3](../03-contracts/C3-run-events.md) `ui_session`, [C13](../03-contracts/C13-extension-manifest.md), `packages/extension_api`, [ADR-0018](0018-extensions.md), [ADR-0031](0031-runner-control-file.md), [09-gaps](../09-gaps.md) §3-2·§4-11 |

## 배경

C3는 `ui_session` 이벤트를 **이미 정의한다** — UI 태스크 한 번이 끝나면 `business_key`·
`page_id`·`result`·`steps`·`fallback_depth_max`·`healed`를 남긴다. 모델(`REQUIRED_DATA_KEYS`)·
요약 집계(`run_log.summarize()`)·문서 예시가 다 있고, CON-01 상세의 「UI 태스크」 섹션과
UIA-03이 그것을 읽기로 되어 있다.

**내보내는 쪽이 없다.** UI 태스크 수행기는 UI 자동화 앱에 C8 보고를 보내지만 C3에는 한 줄도
쓰지 않는다. 그리고 **쓸 길이 없다** — `TaskOutcome`에는 `outputs`와 `usage`(→ `llm_usage`)만
있어서 확장이 실행 기록에 한 줄 남길 자리가 아예 없다.

그래서 이것은 「빠뜨린 코드」가 아니라 **경계 공백**이다. 확장이 C3에 남기는 길을 여는 것은
C3 + C13 + `extension_api`를 한꺼번에 건드리는 일이고, 원칙 6(업무 값을 기록하지 않는다)을
누가 어떻게 지키느냐가 그 모양에 달려 있다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. `TaskOutcome.events[]` — 확장이 **무엇을 남길지만** 주고 엔진이 쓴다 | 확장은 파일·`run_id`·`seq`를 모른다. **거르는 자리가 하나다** — 엔진이 `sanitize()`를 걸어 원칙 6을 지킨다. 실패한 태스크도 `TaskFailed`에 실어 보낼 수 있다. 칸 추가라 `extension_api` 1.x에서 된다 | 태스크가 **끝날 때** 한 번에 올라간다 — 진행 중 이벤트를 흘려 보낼 수 없다 |
| B. 수행기에게 `RunLog`를 넘긴다 (확장이 직접 쓴다) | 진행 중에도 쓸 수 있다 | 확장이 **파일과 `seq`를 안다** — 원칙 6을 거르는 자리가 확장마다 흩어지고, 잘못 쓰면 업무 값이 실행 기록에 남는다. 되돌릴 수 없다(기록은 Center로 간다). `ExtensionContext`에 실행 기록 핸들이 들어가 경계가 두꺼워진다 |
| C. 엔진이 `ui_session`을 만든다 | 확장 API가 안 바뀐다 | **플랫폼이 UI 자동화의 뜻을 알게 된다** — `page_id`·`fallback_depth`는 확장의 말이다 (ADR-0018 위반). 다음 확장이 다른 칸을 요구하면 엔진이 또 바뀐다 |
| D. 남기지 않는다 (현상 유지) | 할 일이 없다 | CON-01 「UI 태스크」 섹션과 UIA-03의 한쪽 출처를 **영구히 포기**한다. C3에 정의만 있고 영원히 빈 이벤트 종류가 남는다 |

## 결정

**A — `TaskOutcome.events[]`를 더하고, 줄을 쓰는 것은 엔진이다.**

```python
@dataclass(frozen=True)
class ExtensionEvent:
    """확장이 실행 기록에 남기고 싶은 것 (C3). **`run_id`·`seq`·`ts`는 엔진이 붙인다.**"""
    kind: str
    data: Mapping[str, Any] = field(default_factory=dict)
```

- **확장은 `kind`와 `data`만 준다.** `run_id`·`seq`·`ts`·`node_id`는 엔진이 채운다 — 확장이
  채우면 두 수가 어긋날 수 있고(토큰이 여럿이다), 확장이 실행의 구조를 알 필요도 없다.
- **엔진이 거른다.** `core.run_log`의 `sanitize()`를 **그대로** 거쳐 쓴다 (원칙 6). 확장을
  믿고 통과시키지 않는다 — 거르는 자리가 하나여야 지켜진다.
- **어긋난 줄은 떨어뜨리고 실행은 이어 간다.** 알려진 `kind`인데 `data` 필수 키가 빠지면
  (`contracts.events.missing_data_keys()`) **그 줄만 버리고 경고로 남긴다.** 업무 실패가
  아니다 — 기록 한 줄 때문에 다 된 업무를 깨지 않는다 (C3 원칙 3 「받는 쪽은 관대하게」, C4
  실행 기록 전송이 거부된 줄을 지나간 것으로 치는 것과 같은 결).
- **실패한 태스크도 남길 수 있다.** `TaskFailed`에 `events`를 실을 수 있게 한다 — UI 태스크가
  전환(사람에게 넘김)으로 끝난 것이 CON-01에서 가장 보고 싶은 줄이다.
- **`extension_api`는 1.2**다 (칸 추가). C13의 `api: ">=1,<2"`를 쓰는 확장은 그대로 돈다.
- 엔진이 **종류를 제한하지 않는다.** C3 `kind`는 열린 문자열이고, 모르는 종류는 Center가
  저장·무시한다. 다만 **알려진 종류라면 그 규칙을 지켜야** 한다 (위의 떨어뜨리기).

## 결과

- 이 결정으로 쉬워지는 것: UI 태스크 수행기가 `ui_session` 한 줄을 남길 수 있고, CON-01
  「UI 태스크」 섹션이 **읽을 것을 갖는다** (09-gaps §3-2·§4-11). 다음 확장도 같은 길을 쓴다 —
  엔진을 고치지 않는다.
- 어려워지거나 포기하는 것: **진행 중 이벤트는 못 남긴다** — 태스크가 끝날 때 한 번이다. 오래
  도는 UI 태스크의 중간 상태를 보려면 다른 길(C8 보고 → UIA-03)을 본다. 그쪽이 원래 그 일을
  하는 자리다.
- 다시 볼 조건: 확장이 **진행 중**에 남겨야 할 것이 생기거나(예: 몇 시간 도는 태스크의 단계
  표시), 한 태스크가 수백 줄을 남기기 시작하면. 그때는 B가 아니라 **엔진이 흘려 보내는
  콜백**(`ctx.emit(event)`)을 본다 — 거르는 자리를 엔진에 남긴 채로.
