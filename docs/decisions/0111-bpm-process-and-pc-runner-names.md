# ADR-0111. 화면 이름을 「BPM 프로세스」·「PC 실행기」로 바꾼다 — 식별자는 그대로 둔다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-30 |
| 관련 | `docs/02-glossary.md` §0·§1, [ADR-0012](0012-bot-ui.md)(대체하지 않는다 — 구조는 그대로다), [ADR-0015](0015-run-location.md), [ADR-0023](0023-bot-ui-process-supervision.md), [ADR-0068](0068-installer-inno-setup-per-user.md) |

## 배경

업무 흐름 하나를 설계 화면에서는 「BPM 프로세스」, 운영 화면에서는 「Bot」이라 불렀다(ADR-0012). 같은 것에 두
이름이 붙어 있어 문서·화면이 「Bot(BPM 프로세스)」처럼 둘을 함께 적어야 했다. PC에서 BPM 프로세스를 내려받아
돌리는 트레이 프로그램은 「Bot UI」였는데, 같은 일을 서버에서 하는 쪽은 「서버 실행기」라 둘이 짝으로 읽히지
않았다. 사용자가 이름을 바꾸기로 했다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. **보이는 이름만 바꾼다** — 용어집·문서·화면 글자·바로가기 | 현장에 깔린 PC 실행기와 Center가 그대로 서로를 알아본다. 계약 판을 올리지 않는다 | 코드 식별자(`bot_ui`·`bot`)와 화면 이름이 갈린다 — 용어집이 대응을 들고 있어야 한다 |
| B. 식별자까지 바꾼다 (계약 칸·API 경로·패키지·실행 파일) | 이름이 한 벌이다 | 계약 판을 올리고 옛 칸·경로를 한동안 함께 받아야 한다. 설치된 현장 PC가 새 Center와 말이 안 통하는 틈이 생긴다 |
| C. 그대로 둔다 | 할 일이 없다 | 두 이름 문제가 남는다 |

Bot UI의 새 이름 후보로 「BPM Launcher」·「Chaeksas 에이전트」도 보았다. 「Launcher」는 띄우기만 하는 것으로
읽히는데, 이 프로그램은 대기열·결재 창·알림·배포 설치도 맡는다. 「에이전트」는 AI 태스크(운전사)와 헷갈린다.

## 결정

**A — 보이는 이름만 바꾼다.**

| 옛 화면 이름 | 새 화면 이름 | 코드 식별자 (그대로) |
| --- | --- | --- |
| Bot | **BPM 프로세스** (서버 BPM 프로세스·PC BPM 프로세스) | `bot`, `bpm_process_id` |
| Bot UI | **PC 실행기** (「서버 실행기」와 짝) | `bot_ui`, `bot_ui_id`, `target.type: bot_ui`, `/api/v1/bot-ui/*`, `chk-bot-ui`, `apps/bot_ui` |
| (Bot UI의) 실행기·실행기 자식 | **실행 프로세스** | `runner`, `chk-bot-runner` |

- 화면 번호(`BUI-*`)와 상태 묶음 이름은 표기만 바뀌고 번호는 그대로다.
- **지나간 기록은 고치지 않는다** — ADR 본문과 계약 문서의 변경 이력 줄은 옛 이름 그대로 둔다.
- 설치 파일의 표시 이름(바로가기·제거 목록)은 「Chaeksas PC 실행기」이고, **`AppId`와 설치 폴더(`BotUI`)·설치 파일
  이름(`ChaeksasBotUI-setup-*.exe`)은 그대로다** — 바꾸면 덮어쓰기가 아니라 두 번째 설치가 된다(ADR-0068).
- 「실행기」를 앞말 없이 쓰면 서버 실행기·PC 실행기를 함께 가리킨다. PC 실행기의 자식은 늘 「실행 프로세스」다.
- 프로토타입 저장소의 이름(「프로토타입 Bot」)은 대응표(`docs/reference/README.md`)에 맞춰 그대로 둔다.

## 결과

- 쉬워지는 것: 업무 흐름의 이름이 한 벌이다. 서버 실행기 ↔ PC 실행기가 짝으로 읽힌다.
- 어려워지거나 포기하는 것: 코드를 읽는 사람은 `bot_ui` = PC 실행기라는 대응을 용어집에서 찾아야 한다.
- 다시 볼 조건: 계약 판을 올릴 다른 까닭이 생기면 그때 식별자도 함께 바꿀지 본다.
