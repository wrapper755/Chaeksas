# ADR-0109. 결정표(.dmn)는 Studio가 파일로 직접 쓰고, 격자는 따로 뜨는 창에서 고친다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-30 |
| 관련 | 계약 C14 §규칙 태스크와 DMN, [ADR-0022](0022-studio-canvas.md), [ADR-0048](0048-installing-shared-packages.md), 화면 STU-04·STU-04a, 09-gaps 7-11 |

## 배경

STU-04의 규칙 태스크 줄은 「결정표 선택·새 결정표·정의(ID·이름·적중 정책)·규칙 격자, 적용 시 .dmn도 저장」을
약속했지만 「JSON」 탭으로 `chk:rule`만 고칠 수 있었다. 결정표를 고치려면 `.dmn`을 손으로 열어야 했다.
`.dmn`은 bpmn-js 캔버스에 실리지 않는다 — ADR-0022의 「XML을 파이썬이 직접 만지지 않는다」는 **캔버스가 쥔 BPMN**의
실행 취소·「저장 안 한 변경」을 지키려는 규칙이라 `.dmn`에는 걸 자리가 없다. 그렇다면 누가 언제 어떻게 쓰는지를
정해야 한다. 결정표 하나를 여러 규칙 태스크가 함께 쓸 수 있다는 점도 함께 본다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 속성 패널 탭에 연결(`chk:rule`), 격자는 따로 뜨는 창이 「저장」으로 파일에 쓴다 | 결정표가 **파일 하나**라는 뜻과 저장 단위가 맞다. 넓은 창이라 5~6열 격자가 찌그러지지 않는다 | 캔버스 실행 취소에 들어가지 않는다. 창이 하나 는다 |
| B. 탭 안에 격자까지, 「적용」 한 번에 `chk:rule`(캔버스)과 `.dmn`(파일)을 함께 | 한 자리 | 좁은 패널에 가로 스크롤. 「적용」의 반쪽만 실행 취소된다 |
| C. 창 하나에 연결·격자 모두 | 한 자리 | 다른 요소 편집기와 결이 달라진다(연결은 모두 탭에서 고친다) |
| D. DMN도 웹 편집기(dmn-js)로 | 표준 편집기 | 배포본 한 벌을 더 들이고(ADR-0029), FEEL 전체를 받아 C14 부분집합 밖을 쓸 수 있게 된다 |

## 결정

**A — 탭에서는 연결을, 따로 뜨는 창(STU-04a)에서는 결정표를 고치고, 창의 「저장」이 `.dmn`을 바로 쓴다.**
사용자가 화면 셋 가운데 골랐다.

1. **쓰는 것은 Studio(파이썬)다** (`studio/dmn_table.py`). 읽기·판정은 지금처럼 `contracts.dmn`이 하고, 격자는
   **글자 그대로**(칸의 원문)를 다룬다 — 판정용 모델은 칸을 해석해 버려 되돌려 쓸 수 없고, 읽기 오류가 난 파일도
   격자로 열어 고칠 수 있어야 하기 때문이다.
2. **고치는 결정표 하나만 바꾸고 나머지는 그대로 둔다.** 같은 파일의 다른 결정, 결정표가 아닌 결정, 결정 요구
   그림(DRD)·DI, 확장 요소, 열의 `inputValues`, 줄의 `annotationEntry`처럼 **편집기가 모르는 것**은 읽은 대로
   남기고, 열·줄·칸의 id도 있던 것은 그대로 쓴다. 네임스페이스 접두사는 원래 파일의 것을 쓴다.
3. **칸 검증은 `contracts.dmn`과 같은 함수다** — 입력 칸은 `parse_cell`, 출력 칸은 `parse_value`(값 하나). 마지막
   관문은 **지어 쓴 XML을 `read_decisions`가 다시 읽는가**다. 그래서 저장한 파일을 실행기가 거부하는 일이 없다.
4. **뜻이 같아야 한다.** 손대지 않고 열어 저장한 결정표는 판정 결과가 같다 — 업무 예제의 결정표 전부를 시험이
   읽은 모델과 판정으로 대조한다(글자로 견주지 않는다).
5. **캔버스 실행 취소에 들어가지 않고 BPMN의 「저장 안 한 변경」과 따로다.** 창을 닫을 때 저장하지 않은 편집이
   있으면 묻는다.
6. **받은 결정표(`libs/*.dmn`)는 읽기 전용으로 연다** (ADR-0048 — 받은 판은 편집 대상이 아니다). 같은 id를
   `process/`에 두면 내 것이 이긴다는 규칙은 그대로다.
7. **있는 결정의 ID는 창에서 바꾸지 않는다** — 다른 규칙 태스크가 id로 가리킨다. ID는 「새 결정표...」에서만 적는다
   (파일은 `process/<id>.dmn`).
8. **격자에는 C14에 있고 `contracts.dmn`이 읽는 것만 둔다** — 적중 정책 넷(`UNIQUE`·`FIRST`·`ANY`·`COLLECT`),
   입력 열(라벨·식 이름·`typeRef`), 출력 열(이름·`typeRef`), 규칙 줄(입력 칸·출력 값·설명). 집계 함수(`aggregation`)·
   다른 적중 정책·FEEL 식은 두지 않는다.

## 결과

- 쉬워지는 것: 규칙 태스크를 JSON 없이 짓고, 결정표를 FEEL 부분집합 밖으로 벗어나지 않게 고친다. 깨진 칸도 그
  자리에서 보인다.
- 어려워지거나 포기하는 것: 결정표 편집은 캔버스 실행 취소로 되돌릴 수 없다(창의 「닫기」가 저장 전의 버리기다).
  dmn-js의 DRD 편집은 없다.
- 다시 볼 조건: 결정 요구 그림(결정 사이 연결)이나 FEEL 식이 C14에 들어오면 D를 다시 본다.
