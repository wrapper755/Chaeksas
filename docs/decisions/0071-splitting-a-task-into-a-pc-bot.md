# ADR-0071. 「PC BPM 프로세스로 나누기」는 노드 하나를 새 PC Bot으로 옮기고 그 자리에 위임 호출을 둔다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-18 |
| 관련 | [ADR-0016](0016-server-first.md) §3, [ADR-0022](0022-studio-canvas.md), [ADR-0062](0062-pc-delegation.md), [ADR-0018](0018-extensions.md), C14 `chk:call.delegate`, STU-06, 09-gaps §7-4 |

## 배경

서버 Bot에 UI 태스크·화면 AI 태스크·현장 결재가 들어 있으면 실행 전 검사가 막는다(B6). 고치는 길로 ADR-0016 §3이 「실행 위치를 PC로 바꾸기」와 함께 「이 부분을 PC BPM 프로세스로 나누기」를 약속했는데, 그때는 PC 위임이 정해지지 않아 화면에 안내 문구만 두었다. ADR-0062로 위임의 모양(`chk:call.delegate` — 대상은 **따로 배포된 PC Bot 패키지**)이 정해졌으므로 나누는 일을 정한다.

걸리는 것은 셋이다. **그림을 파이썬이 만지지 않는다**(ADR-0022 — 실행 취소·「저장 안 한 변경」이 깨진다) 그런데 캔버스에는 지우기·잇기 명령이 없고 여러 개 고르기도 파이썬에 오지 않는다. **변수 이름을 지어내지 않는다**(STU-03) 그런데 확장 태스크가 읽고 쓰는 변수는 플랫폼이 모른다(ADR-0018 — `extension_task_vars`를 주는 확장이 없다). **PC Bot은 다른 패키지**라 다른 작업 폴더에 산다(ADR-0062).

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 고른 **여러 노드의 이어진 묶음**을 잘라 옮기고 흐름을 다시 잇는다 | 한 번에 끝난다 | 캔버스에 고르기·자르기·잇기를 다 들여야 하고, 묶음의 경계(갈림길·경계 이벤트가 걸친 것)를 정하는 규칙이 크다. 틀리면 그림이 조용히 바뀐다 |
| B. **노드 하나**를 새 PC Bot(시작 → 그 노드 → 끝)으로 옮기고, 원래 자리는 그 노드를 **위임 호출로 바꾼다**(흐름·경계 이벤트는 그대로) | 바꾸기가 bpmn-js의 `replaceElement` 하나라 흐름을 다시 이을 일이 없다. 실행 취소가 한 걸음이다 | 이어진 UI 태스크 셋은 Bot 셋이 된다 — 하나로 합치려면 사람이 PC Bot 쪽에서 옮겨 붙인다 |
| C. 파이썬이 두 그림의 XML을 지어 쓴다 | 캔버스를 안 거친다 | ADR-0022를 어긴다 — 열린 그림의 실행 취소가 깨진다 |

## 결정

**B로 한다.** 단위는 **서버에서 못 하는 노드 하나**(`contracts.server_blockers`가 센 것 — B6과 같은 함수)다.

1. **그림은 둘 다 캔버스가 짓는다.** 캔버스 명령을 둘 더한다 — `delegateNode(id, spec)`은 노드를 `bpmn:CallActivity`로 **바꾸고**(`bpmnReplace` — 들어오고 나가는 흐름과 붙은 경계 이벤트가 그대로 남는다) `calledElement`·이름·`chk:call`만 남긴다. **실행 취소는 한 걸음**이다(명령 하나로 묶는다). `appendChain(specs)`은 빈 그림의 시작 이벤트 뒤에 노드들과 끝 이벤트를 **이어 붙인다**(`autoPlace` — 흐름까지 생긴다). 파이썬은 XML을 만지지 않는다.
2. **옮기는 것은 그 노드의 본문 그대로다** — BPMN 종류·이름·`chk:*`를 `properties`로 읽어 `appendChain`에 그대로 넘긴다. 확장 태스크의 `data`를 해석하지 않는다(C13 §5).
3. **입력·출력 이름은 사람이 확인한다.** 창이 **아는 것만 미리 채운다** — `read_vars`·`produced_vars`(B11이 쓰는 것)가 센 이름이다. 확장 태스크처럼 플랫폼이 모르는 것은 **비워 두고 그렇게 말한다**. 짝은 **같은 이름**이다(`input: {이름: 이름}`, `output: {이름: 이름}`) — 이름을 바꾸는 것은 지어내는 것이라 하지 않는다.
4. **PC Bot은 새 작업 폴더**다(같은 그룹, id는 사람이 정하고 기본값은 `<서버 id>-pc`). 그 그림의 `chk:process`는 `run_location: pc`, 확인한 `inputs`(타입은 사람이 고른다, 필수)·`outputs`, 그리고 **옮긴 노드의 확장에 해당하는** 서버의 `service_keys`·`extensions` 줄만 옮긴다(쓰지 않는 키를 사전 점검이 요구하게 하지 않는다).
5. **순서는 「PC 쪽을 다 지은 뒤 서버 쪽을 바꾼다」다.** 먼저 서버 정의를 디스크에 저장하게 하고(관문 `saved_to_disk`), 그 XML을 들고 캔버스에 PC 그림을 지어 **저장**한 다음, 들고 있던 서버 XML을 다시 띄워 노드를 바꾼다. 서버 쪽은 **캔버스에만** 적용된다(STU-04·STU-06과 같은 결 — 파일로 가는 것은 「저장」이다). PC 쪽이 실패하면 서버 그림은 디스크의 것 그대로 돌아온다.
6. **오류 경계·시험 케이스는 만들지 않는다.** 위임이 실패하면 `DELEGATION_FAILED`가 오고, 케이스에 적지 않은 위임은 시험 실행에서 실패한다(ADR-0062 §2) — 끝난 뒤 그 둘을 하라고 **말한다**. 지어 넣으면 사람이 모르는 분기가 생긴다.

## 결과

- 쉬워지는 것: B6 오류에서 고치는 길이 둘 다 돈다(「PC로 바꾸기」·「나누기」). 바꾼 자리는 흐름을 다시 잇지 않으므로 그림이 조용히 달라지지 않는다.
- 어려워지거나 포기하는 것: **이어진 여러 노드를 한 번에** 옮기지 못한다. 확장 태스크의 입력·출력은 사람이 적는다. PC Bot은 **따로 올리고 배포해야** 서버 Bot의 배포가 통과한다(C1 R8 — 바뀌지 않는다).
- 다시 볼 조건: 이어진 UI 태스크를 나누는 일이 잦아 Bot이 잘게 쪼개진다는 말이 나오면 A를 다시 본다(그때는 캔버스에 고르기·자르기를 들인다). 확장이 `extension_task_vars`를 주게 되면 3의 미리 채우기가 확장 태스크까지 넓어진다.
