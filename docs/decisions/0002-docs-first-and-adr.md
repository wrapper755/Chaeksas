# ADR-0002. 문서를 먼저 쓰고, 문서는 저장소 안 Markdown으로 둔다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-01 |
| 관련 | `CLAUDE.md` §3·§4 |

## 배경

프로토타입에서는 코드를 먼저 쓰고 문서를 뒤따라 고쳤다. 그러자 세 가지 문제가 생겼다.
- 문서와 코드가 어긋났다. 예: 하트비트 본문, `X-Bot-Id`, Studio 실행 기록 업로드 여부.
- 계약을 바꿀 때마다 세션 사이에서 협상이 필요했다.
- 다른 PC·다른 OS에서 이어 작업할 근거가 없었다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 코드 먼저, 문서는 나중 | 빠름 | 위 문제 반복 |
| B. 문서 먼저, 외부 문서 도구 | 편집·공유 편함 | 저장소와 따로 놀고, 다른 PC의 Claude Code가 읽지 못함 |
| C. 문서 먼저, 저장소 안 Markdown | clone만 하면 사람·도구가 같은 문서를 봄. 코드와 같은 커밋에 묶임 | 서식이 단순 |

## 결정

**C.** 흐름은 **실험 → 결정(ADR) → 명세(계약) → 구현**.

- 실험은 `spikes/`에서 자유롭게 한다. 끝나면 ADR 한 장.
- 구성요소 간 약속은 `docs/03-contracts/`를, 화면은 `docs/06-screens/`를 먼저 고친다.
- CLAUDE.md는 현재 규칙만 담고 200줄을 넘기지 않는다. 이력은 ADR로 보낸다.
- 외부 문서(Claude Docs 등)는 논의용 초안으로만 쓴다. 확정되면 저장소로 옮긴다.

## 결과

- 쉬워지는 것: Windows·Linux 어느 PC에서든 같은 문서로 작업 재개.
- 어려워지는 것: 작은 실험에도 ADR 한 장의 수고.
- 다시 볼 조건: ADR 작성이 실험보다 오래 걸리는 일이 반복되면, "짧은 ADR"(배경·결정 두 줄) 형식을 추가한다.
