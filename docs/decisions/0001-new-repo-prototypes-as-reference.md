# ADR-0001. 새 저장소로 다시 만들고 프로토타입 4개는 참고용으로 동결한다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-01 |
| 관련 | `docs/reference/` |

## 배경

프로토타입 4개(Studio·Bot, Center, UI 자동화 서버, Worker)를 시행착오식으로 개발했다. 빨리 보고 배우는 데는 좋았지만 문제가 쌓였다.
- 두 묶음(Studio·Bot + Center / UI 자동화 서버 + Worker)이 서로 모른다.
- 웹 UI 자동화가 두 벌이다.
- 계약 관리 방식이 두 가지다.
- Python 버전이 다르다.
- 결정 이력이 작업 지침 파일(CLAUDE.md)에 누적되어 있다 (최대 159KB).

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 기존 4개를 정리·이관해 모노레포로 | 동작하는 코드를 그대로 이어 감 | 옛 가정(Linux 전용, 경로, 용어)을 함께 끌고 옴. 정리 비용이 큼 |
| B. 새 저장소, 기존은 참고 | 처음부터 Windows·계약·용어를 바로 잡음 | 다시 구현하는 시간 |

## 결정

**B.** `Chaeksas` 저장소에 새로 만든다. 프로토타입 4개 저장소는 **수정하지 않고** 참고용으로 남긴다.

- 코드를 가져올 때는 복사한 뒤 새 규칙(CLAUDE.md §5)에 맞게 고치고, 출처(프로토타입 이름 + 파일)를 커밋 메시지에 남긴다.
- 프로토타입 저장소를 import하거나 경로로 의존하지 않는다.
- 새 문서는 프로토타입 이름 대신 내부 용어를 쓴다. 대응표는 `docs/reference/README.md` 한 곳에만 둔다.
- 개발은 프로토타입이 없는 다른 PC에서도 할 수 있어야 한다. 그래서 `docs/reference/`는 원본 코드 없이 읽혀도 뜻이 통하게 쓴다.

## 결과

- 쉬워지는 것: 클라이언트 Windows 주 환경, 단일 계약, 통일된 용어를 처음부터 적용.
- 포기하는 것: 프로토타입에서 이미 된 기능도 새로 확인해야 한다.
- 다시 볼 조건: 특정 모듈(예: BPMN 실행 엔진 연결)을 거의 그대로 옮기는 것이 명백히 싸면, 그 모듈만 이관 ADR을 따로 쓴다.
