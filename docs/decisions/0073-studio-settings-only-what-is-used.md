# ADR-0073. STU-10에는 쓰는 곳이 있는 칸만 둔다 — 「외형」은 테마 하나, 「확장별 설정」은 기여로 짓고, 「메일」·「비밀」·모델 칸 셋은 걷는다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 — 결정 2의 「편집기(STU-13)에는 비밀을 주지 않는다」는 [ADR-0074](0074-ui-task-editor-runs-on-the-worker.md)가 바꿨다. 결정 1의 「캔버스 그림은 밝게 둔다」는 [ADR-0101](0101-canvas-follows-theme.md)이 대체했다 |
| 날짜 | 2026-10-18 |
| 관련 | STU-10, C13 `configuration`, C14 시험 케이스, [ADR-0027](0027-llm-connection.md), [ADR-0050](0050-no-toolpack-kind.md), [ADR-0013](0013-api-keys.md), 09-gaps §7-5 |

## 배경

STU-10 화면 문서는 분류 여덟을 적었는데 넷(외형·메일·확장별 설정·비밀)과 「LLM」의 칸 셋(공급자·temperature·화면 인식 모델)이 「아직」이었다. 칸을 만들기 전에 **그 값을 읽는 코드가 있는가**를 하나씩 보았다.

| 자리 | 그 값을 읽을 곳 |
| --- | --- |
| 테마 | 있다 — `chaeksas.qt.theme.apply_theme(choice=…)`가 처음부터 시스템·밝게·어둡게를 받는다. Studio가 늘 「시스템」으로 불렀을 뿐이다 |
| 캔버스 팔레트(자동/한 줄/두 줄/숨김) | 없다 — bpmn-js가 창 높이에 따라 한 줄·두 줄을 스스로 바꾼다. 「숨김」은 만들 도구가 없는 모델러라 읽기 전용과 같은데, 읽기 전용은 뷰어로만 짓는다(ADR-0051) |
| 메일 | 없다 — Studio 시험 실행은 메일을 **담아 두기만** 한다(C14, 바깥으로 보내지 않는다). 메일 서버 칸은 현장(BUI-03 「보내기」)과 서버 실행기의 것이다 |
| 확장별 설정 | 있다 — C13 `configuration[].scope`가 `studio`를 약속하고 `Extensions.settings_for()`가 그 칸을 **늘 `None`으로** 넘기고 있었다. 확장이 칸을 기여해도 사람이 값을 넣을 자리가 없었다 |
| 비밀 | 없다 — 「툴팩이 쓰는 비밀」 자리였는데 툴팩이 없다(ADR-0050). 확장의 비밀 칸은 「확장별 설정」의 일이다(BUI-03과 같다) |
| 공급자 | 없다 — 모델에 닿는 길은 OpenAI 호환 하나다(ADR-0027) |
| temperature | 없다 — Bot UI·서버 실행기 어디에도 그 칸이 없다. Studio에만 두면 **시험 실행이 현장과 다른 답**을 낸다 |
| 화면 인식 모델 | 없다 — `web`·`desktop` AI 태스크도 같은 모델로 보고(ADR-0037), 치유는 서비스 앱의 `ServiceLlm`이 한다(ADR-0034) |

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 화면 문서대로 칸을 다 만든다 | 문서와 그대로 맞는다 | 저장만 되고 아무도 읽지 않는 칸이 생긴다 — 사람은 바꿨는데 아무 일도 일어나지 않는다 |
| B. 지금처럼 「(아직)」으로 꺼 둔다 | 고칠 것이 없다 | 받쳐 줄 기능이 **앞으로도 오지 않는** 분류가 영영 「아직」으로 남는다 |
| C. **읽는 곳이 있는 것만 켜고, 오지 않을 것은 화면 문서에서 걷는다** | 칸마다 바꾸면 무엇이 바뀌는지 말할 수 있다 | 화면 문서를 고쳐야 한다(이 ADR이 까닭이다) |

## 결정

**C로 한다.**

1. **「외형」은 테마 하나다** — 시스템 따름(기본)·밝게·어둡게. 설정 파일 `theme`에 가고 **「저장」하는 그 자리에서** `apply_theme`를 다시 부른다. 「시스템 따름」을 고른 뒤 밝게로 바꾸면 OS가 테마를 바꿔도 **따라가지 않는다**(전에는 한 번 붙은 신호가 끝까지 따라갔다). **캔버스 그림은 밝게 둔다** — bpmn-js의 선·글자 기본색이 검정이라 어두운 바탕에서 읽히지 않는다. 그림은 문서이고, 창의 나머지가 어두워진다.
2. **「확장별 설정」은 켜진 확장이 기여한 `scope: studio` 칸으로 그 자리에서 짓는다** (BUI-03과 같은 결) — 비밀이 아닌 값은 설정 파일 `extensions`(`{확장: {칸: 값}}`), **비밀 칸은 OS 비밀 저장소**(`chaeksas-studio`의 `ext:<확장>:<칸>`, 환경변수 `CHK_STUDIO__EXT__<확장>__<칸>`이 이긴다)이고 칸에 보이지 않는다. 확장 코드는 비밀이 아닌 값을 `settings`로, 비밀 칸을 `secrets.resolve(<칸>)`으로 받는다(Bot UI 실행기와 같은 순서 — 서비스 앱 키 참조가 먼저). 기여한 확장이 없으면 **분류는 켜 두고** 「Studio 범위의 설정 칸을 기여한 확장이 없습니다」라고 말한다 — 기능이 없는 것이 아니라 칸이 없는 것이다. **편집기(STU-13)에는 비밀을 주지 않는다**(설계에는 키가 필요 없다 — ADR-0008).
3. **「메일」·「비밀」 분류와 「LLM」의 공급자·temperature·화면 인식 모델, 「외형」의 캔버스 팔레트는 화면 문서에서 걷는다.** 다시 넣으려면 **읽는 곳을 먼저** 만든다 — temperature라면 Bot UI·서버 실행기에도 같은 칸이 생길 때다(시험과 현장이 같은 모델 설정을 써야 한다).

## 결과

- 쉬워지는 것: STU-10에 「(아직)」이 남지 않는다. 확장이 Studio 설정 칸을 기여하면 코드 없이 화면에 뜬다. 어두운 테마를 고를 수 있다.
- 어려워지거나 포기하는 것: 모델마다 다른 선택 값(temperature 등)을 Studio에서 줄 길이 없다 — 현장에도 없으므로 같다. 캔버스는 어두운 테마에서도 밝다.
- 다시 볼 조건: Bot UI·서버 실행기에 모델 선택 값이 생기면 Studio도 같은 칸을 둔다. bpmn-js 그림에 어두운 색 규칙을 입힐 수 있게 되면(선·글자·채움을 토큰으로) 캔버스도 테마를 따른다.
