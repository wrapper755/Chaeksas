# ADR-0021. Worker 프로세스는 시작하자마자 Per-Monitor v2 DPI 인식을 선언하고, 캡처는 `mss`로 한다

| 항목 | 값 |
| --- | --- |
| 상태 | 제안 |
| 날짜 | 2026-10-02 |
| 관련 | 스파이크 `spikes/S2-capture-dpi/`, ADR-0020(데스크톱 백엔드 `uiautomation`), ADR-0003, `docs/01-architecture.md` §6, 계약 C8·C10 |

## 배경

Worker 프로세스는 UIA로 요소 위치를 얻고, 화면을 캡처하고(AI 태스크의 화면 이해, 실행 기록), 좌표로 클릭한다. 업무 PC는 125%·150% 배율이 흔하다. 세 좌표계가 어긋나면 오류 없이 틀린 곳을 누른다.
Windows는 프로세스의 **DPI 인식 모드**에 따라 좌표를 가상화하고, 이 모드는 처음 정한 것만 먹는다. S2에서 라이브러리 import만으로 모드가 바뀌는 것을 봤다 — 지금 정하지 않으면 import 순서가 좌표계를 정하게 된다.

## 선택지

S2에서 배율 100·125·150% × Worker 모드 4 × 대상 앱 모드 3을 시험 창으로 판정했다 (자세히: `spikes/S2-capture-dpi/NOTES.md`).

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. Worker는 Per-Monitor v2 인식 (명시) | 세 좌표가 실제 픽셀로 일치. 대상 앱이 비인식이어도 ±1px. 모니터마다 배율이 달라도 맞는 유일한 모드(이론, 미검증) | Worker가 직접 그리는 화면은 없으니 단점이 거의 없다. 모드를 정하는 코드가 다른 import보다 먼저 돌아야 한다 |
| B. System 인식 | 단일 모니터에서는 A와 같은 결과 | 배율이 다른 보조 모니터에서 어긋난다 (Windows 동작상) |
| C. 비인식 (Python 기본) | — | **캡처가 배율만큼 어긋난다** (150%에서 110~151px). UIA·클릭은 맞아서 문제가 늦게 드러난다 |
| D. 정하지 않음 | — | `import uiautomation`·`mss.MSS()`가 몰래 per-monitor로 바꾼다. 순서가 바뀌면 C가 된다 |

캡처 라이브러리: `mss`와 Pillow `ImageGrab`은 모든 조합에서 같은 좌표, 비슷한 속도(전체 화면 35~53ms).

## 결정

**A. Worker 프로세스는 진입점 첫 줄에서 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`를 부르고, 실패하거나 결과 모드가 per-monitor가 아니면 시작하지 않는다.** 설치 파일로 묶을 때는 실행 파일 매니페스트에도 같은 선언(`<dpiAwareness>PerMonitorV2</dpiAwareness>`)을 넣는다 (S5에서 확인).

- Worker 안의 모든 좌표 — UIA 사각형, 캡처 이미지 픽셀, 클릭 좌표, C8·C10에 오가는 좌표 — 는 **가상 화면의 실제 픽셀**이다. 논리 좌표로 바꾸지 않는다.
- 캡처는 `mss`로 한다 (순수 Python + ctypes, 모니터 목록과 가상 화면 원점을 함께 준다). 이미지 처리는 Pillow.
- 요소를 누를 때는 사각형 **가운데**를 쓴다. DPI 비인식 앱은 테두리가 ±1px 어긋날 수 있다. 캡처를 요소 크기로 자를 때 테두리 몇 px 여유를 둔다.
- 시작할 때 실행 기록에 DPI 모드·시스템 DPI·모니터 목록(원점·크기)을 남긴다 — 좌표 문제를 나중에 재현하려고.
- ctypes로 Win32를 부를 때 핸들 반환형·인자형을 항상 적는다 (64비트 핸들이 잘린다).

> 미정: 모니터 두 대·모니터마다 다른 배율에서의 확인. 이 PC는 모니터가 한 대뿐이라 시험하지 못했다. 그 전까지 이 ADR은 「제안」으로 둔다.

## 결과

- 이 결정으로 쉬워지는 것: 좌표가 한 가지(실제 픽셀)라 변환 코드가 없다. AI 태스크가 캡처에서 찾은 위치를 그대로 클릭할 수 있다.
- 어려워지거나 포기하는 것: Worker 진입점은 다른 import보다 먼저 DPI 모드를 정해야 한다 — 실수하기 쉬우니 시작 검사로 막는다. Worker 프로세스가 아닌 곳(Studio·Bot UI의 Qt 화면)은 Qt가 따로 정하므로 이 규칙과 별개다.
- 다시 볼 조건: 다중 모니터 시험에서 pmv2도 어긋나는 경우, RDP 세션·200% 이상 배율에서 다른 결과가 나오는 경우, 캡처 속도가 AI 태스크에 모자란 경우(그때 DXGI 캡처 검토).
