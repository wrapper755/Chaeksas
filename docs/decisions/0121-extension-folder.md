# ADR-0121. 확장 폴더 — Center는 뜰 때 기본 확장과 승인 없는 일꾼을 폴더에서 들인다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-31 |
| 관련 | 계약 C13(§외부 확장 등록·E1~E6), C15(§승인 없는 일꾼·`FolderConsumer`), C7(`ExtensionResource.source`·`GET /resources/extension-folder`), 화면 CON-07, [ADR-0090](0090-center-admin-accounts.md), [ADR-0092](0092-keys-are-issued-and-delivered-by-center.md), [ADR-0102](0102-calling-outside-is-pull.md), [ADR-0117](0117-bundled-server-runner-joins-by-shared-secret.md), `deploy/compose.yaml` |

## 배경

외부 확장 정의는 관리자가 CON-07 「기능 추가 (외부)」에서 파일을 올려야 Center에 들어오고, 그 토픽을 가져가는 일꾼은
요청 코드를 맞춰 보고 승인해야 들어온다 (C13, C15, ADR-0090·0092). 그런데 BPM 패키지와 **함께 배포되는 고정 프로그램**
(예: NowView 일꾼)은 판마다 확장 정의 하나와 일꾼 하나를 들고 다닌다. NowView의 정의는 BPMN ServiceTask의
「External Service」 자리라서 id(= 토픽)를 `external`로 두고 **기본으로** 쓴다. 같은 사람이 같은 배포로 함께 올리는
것을 콘솔에서 손으로 등록·승인하는 것은 할 일이 아니고, 잊으면 일꾼이 들어오지 못한다. 사용자는 배포할 때 파일을
Center 쪽 폴더에 **복사해 두는** 길로 정했고, 이렇게 들인 것은 **Center 안에서 승인·해제 없이** 돌며 지켜볼 것은
로그에서 본다고 정했다 (서버 실행기를 들이기 비밀로 들이는 ADR-0117과 같은 결 — 등록을 사람 손에서 뺀다).

## 선택지

확장 정의:

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 배포 스크립트가 관리자 토큰으로 `POST /resources/extensions`를 부른다 | Center 코드가 그대로다 | 배포에 관리자 토큰이 있어야 하고 Center가 뜬 뒤에 불러야 한다 |
| B. 폴더의 파일에 **봉투(서명)까지** 요구한다 | 「누가 만든 정의인가」를 파일이 말한다 | 서명 키는 Center에만 있어(ADR-0090) 배포 쪽이 봉투를 지을 수 없다 |
| C. **정의만 둔 폴더를 Center가 뜰 때 읽고, 콘솔 등록과 같은 관문을 지나면 Center가 서명한다** | 배포는 파일 복사 하나다. 검사·서명·현장의 재검증(E6)이 콘솔 등록과 같다 | 폴더에 쓸 수 있는 사람을 관리자로 믿는다 |

일꾼의 비밀:

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. Center 환경변수에 일꾼 이름·토픽·토큰 원문 (ADR-0117과 같은 결) | 파일이 늘지 않는다 | Center가 원문을 든다. 일꾼이 늘면 환경변수가 는다 |
| B. **확장 폴더의 `*.consumer.json`에 이름·토픽·토큰 해시** | 확장 정의와 같은 복사 한 번이다. Center는 원문을 모른다 | 배포가 해시를 계산해야 한다 |

## 결정

확장도 일꾼도 **C**·**B** — 환경변수 **`CHK_CENTER__EXTENSIONS_DIR`**(적지 않으면 `<데이터>/extensions`)가 가리키는
폴더(「확장 폴더」)를 **Center가 뜰 때 한 번** 읽는다. **폴더가 원본이다** — 폴더가 들인 것은 콘솔이 등록·승인·해제하지
않는다.

### 기본 확장 (`*.extension.json`)

1. **서명은 Center가 한다 — 파일에는 정의만 있다.** 폴더에 쓸 수 있는 사람은 서버 셸·볼륨을 쥔 사람이고 그 사람은
   이미 `CHK_CENTER__ADMIN_TOKEN`을 정하고 DB를 열 수 있다. 그래서 폴더에 두는 것을 **관리자의 등록**으로 본다.
   관문은 콘솔 등록과 **같은 함수**(`resources.register_extension`)다 — 크기·C13 모양·E1~E4를 지난 정의에만 Center
   키로 `extension` 봉투를 짓고, 현장은 지금처럼 봉투를 다시 검증한다(E6). 「누가」는 `확장 폴더`, 출처는
   `ExtensionResource.source = folder`(저장소 20판 `extensions.source`).
2. **같은 `id`·`version`·같은 내용이면 아무것도 하지 않는다** (다시 떠도 한 번 등록). 콘솔로 먼저 올린 것과 내용이
   같으면 콘솔 등록으로 남는다.
3. **판이 오르면 새 판을 등록한다** — 지금 판은 가장 최근에 등록된 것이다(C7). 옛 판은 그대로 둔다(쓰는 BPM
   프로세스가 고정한 해시가 그 판일 수 있다).
4. **덮어쓰지 않고 되돌리지 않는다.** 같은 판에 다른 내용이면 거절(콘솔 등록과 같은 409 `id_conflict`), 철회된 판이면
   거절(`extension_revoked`), **이미 더 높은 판이 등록돼 있으면 건너뛴다**(`older_than_registered`).
5. **콘솔은 폴더가 들인 확장을 등록·해제하지 않는다** — 그 id로 오는 콘솔 등록·해제는 409 `managed_by_folder`다.
6. **그만 쓰게 하는 길은 파일을 빼고 다시 띄우는 것이다** — 폴더가 들였는데 파일이 없는 id는 그 폴더 판을 모두
   Center가 철회한다(`revoked`, C2 `extension_revoke` 봉투). 철회된 판은 되살아나지 않으니 다시 쓰려면 판을 올린다.
   **거두지 않는 때**: 폴더가 없거나 폴더가 아니다(볼륨이 붙지 않은 것을 「다 뺐다」로 읽지 않는다), 읽지 못한
   정의 파일이 있다(그 파일이 무엇이었는지 모른다).

### 승인 없는 일꾼 (`*.consumer.json`, C15 `FolderConsumer`)

7. 파일은 `{name, topics, token_sha256, manifests?}`다. Center는 **토큰 원문을 모르고** 해시만 받는다 — 일꾼은 원문을
   지금처럼 `Authorization: Bearer`로 싣는다. Center는 뜰 때 그 일꾼을 **처음부터 안다**: 요청 코드·승인 대기가 없고,
   토픽은 파일에 적은 것으로 **고정**이며(가져가기의 토픽이 밖이면 403 `topic_not_granted`), 키에는 만료·회전이
   없다(공개키가 없다). 일꾼의 자리는 **파일 이름**이 정한다(`folder:<이름>`).
8. 토큰 해시가 바뀌면 옛 키를 폐기하고 새 키를 둔다. **폐기된 토큰은 되살아나지 않는다**(`token_revoked`). 파일이
   빠지면 키를 폐기하고 일꾼을 지운다. **읽지 못한 파일도 자리는 지킨다** — 파일이 있는 한 그 일꾼을 지우지 않는다.
9. 일꾼 목록(CON-07 「일꾼」)에는 보이지만 승인 대기에는 뜨지 않는다. 일감 흐름(가져감·끝냄·실패)은 **Center 로그**에
   일꾼 이름·일감 id·토픽·작업·오류 코드로 남는다 — 업무 값은 찍지 않는다(원칙 6).

### 공통

10. **잘못된 파일은 Center를 막지 않는다.** 파일마다 결과(`registered`·`unchanged`·`skipped`·`refused`·`revoked`)와
    사유를 로그에 찍고, 마지막으로 읽은 결과를 `GET /resources/extension-folder`(C7, 읽기)로 준다. CON-07 「확장
    폴더」가 그것을 보인다.
11. **뜰 때만 읽는다.** 파일을 바꾸면 Center를 다시 띄운다 — 배포는 어차피 Center를 다시 띄운다. 기본 자리(`<데이터>/
    extensions`)가 없으면 조용히 지나간다(기본 확장이 없는 Center). 사람이 적은 자리가 없으면 사유를 남긴다.

## 결과

- 쉬워지는 것: 고정 프로그램은 정의 파일과 일꾼 파일을 폴더에 복사하는 것으로 Center에 들어온다. 관리자 토큰도 승인도
  배포에 끼지 않는다. 확장의 관문은 콘솔 등록·현장 검증과 하나다.
- 포기하는 것: 폴더에 쓸 수 있는 사람을 관리자로 믿는다(서버 셸을 쥔 사람이니 이미 그렇다). 폴더가 들인 확장을 콘솔에서
  급히 거둘 수 없다 — 파일을 빼고 Center를 다시 띄운다. 바꾼 파일은 다시 띄워야 들어온다.
- 다시 볼 조건: Center를 여러 벌 띄워 같은 폴더를 함께 읽게 되면, 또는 폴더가 들인 것을 콘솔에서 급히 거둬야 하는
  운영 사고가 생기면.
