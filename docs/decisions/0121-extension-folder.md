# ADR-0121. Center는 뜰 때 확장 폴더의 외부 확장 정의를 콘솔 등록과 같은 관문으로 들인다

| 항목 | 값 |
| --- | --- |
| 상태 | 수락 |
| 날짜 | 2026-10-31 |
| 관련 | 계약 C13(§외부 확장 등록·E1~E6), C7(`ExtensionResource.source`·`GET /resources/extension-folder`), 화면 CON-07, [ADR-0090](0090-center-admin-accounts.md), [ADR-0102](0102-calling-outside-is-pull.md), [ADR-0117](0117-bundled-server-runner-joins-by-shared-secret.md), `deploy/compose.yaml` |

## 배경

외부 확장 정의는 관리자가 CON-07 「기능 추가 (외부)」에서 파일을 올려야 Center에 들어온다 (C13, ADR-0090). 그런데
BPM 패키지와 **함께 배포되는 고정 프로그램**(예: NowView 일꾼)은 판마다 확장 정의 하나를 들고 다니고, 그 정의가
Center에 없으면 일꾼의 manifest·토픽 승인이 되지 않는다. 같은 사람이 같은 배포로 함께 올리는 파일을 콘솔에서 손으로
다시 올리는 것은 할 일이 아니고, 잊으면 일꾼이 들어오지 못한다. 사용자는 배포할 때 정의 파일을 Center 쪽 폴더에
**복사해 두는** 길로 정했다 (서버 실행기를 들이기 비밀로 들이는 ADR-0117과 같은 결 — 등록을 사람 손에서 뺀다).

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. 배포 스크립트가 관리자 토큰으로 `POST /resources/extensions`를 부른다 | Center 코드가 그대로다 | 배포 쪽에 관리자 토큰이 있어야 하고 Center가 뜬 뒤에 불러야 한다 — 순서·비밀이 배포마다 는다 |
| B. 폴더의 파일에 **봉투(서명)까지** 요구한다 | 「누가 만든 정의인가」를 파일이 말한다 | 바깥 봉투를 받는 길은 ADR-0090이 없앴다 — 서명 키는 Center에만 있어 배포 쪽이 봉투를 지을 수 없다 |
| C. **정의만 둔 폴더를 Center가 뜰 때 읽고, 콘솔 등록과 같은 관문을 지나면 Center가 서명한다** | 배포는 파일 복사 하나다. 검사·서명·현장의 재검증(E6)이 콘솔 등록과 같다 | 폴더에 쓸 수 있는 사람을 관리자로 믿는다 |

## 결정

**C.** 환경변수 **`CHK_CENTER__EXTENSIONS_DIR`**가 가리키는 폴더(「확장 폴더」)의 `*.extension.json`을 **Center가 뜰 때
한 번** 읽어 등록한다. 비우면 그 길이 닫힌다(기본).

1. **서명은 Center가 한다 — 파일에는 정의만 있다.** 폴더에 쓸 수 있는 사람은 서버 셸·볼륨을 쥔 사람이고, 그 사람은
   이미 `CHK_CENTER__ADMIN_TOKEN`을 정하고 DB를 열 수 있다. 그래서 폴더에 두는 것을 **관리자의 등록**으로 본다.
   관문은 콘솔 등록과 **같은 함수**(`resources.register_extension`)다 — 크기(256 KB)·C13 모양·E1·E2·E3·E4를 지난
   정의에만 Center 키로 `extension` 봉투를 짓고, 현장은 지금처럼 봉투를 다시 검증한다(E6). 「누가」는 `확장 폴더`다.
2. **같은 `id`·`version`·같은 내용이면 아무것도 하지 않는다**(다시 떠도 한 번 등록). 출처도 처음 등록한 그대로다 —
   콘솔로 먼저 올린 것과 내용이 같으면 콘솔 등록으로 남는다.
3. **판이 오르면 새 판을 등록한다** — 지금 판은 가장 최근에 등록된 것이다(C7). 옛 판은 철회하지 않는다(쓰는 BPM
   프로세스가 고정한 해시가 그 판일 수 있다 — 거두는 것은 관리자의 보안 동작이다, C13).
4. **덮어쓰지 않고 되돌리지 않는다.** 같은 `id`·`version`에 다른 내용이면 거절(콘솔 등록과 같은 409 `id_conflict`), 철회된 판이면 거절
   (`extension_revoked` — 되살아나지 않는다), **이미 더 높은 판이 등록돼 있으면 건너뛴다**(`older_than_registered` —
   옛 파일을 다시 복사했다고 지금 판이 내려가지 않는다). 내리려면 관리자가 높은 판을 철회한다.
5. **폴더에서 사라진 파일은 지우지 않는다.** 등록 해제는 보안 동작이라 사람이 CON-07에서 한다. 파일을 지우는 것은
   「다음에 다시 들이지 않는다」일 뿐이다.
6. **콘솔 등록과 겹치면 규칙이 하나다** — 같은 표·같은 관문이라 2~4가 그대로 걸린다. 폴더가 콘솔 등록을 덮는 일은
   없다(같은 판은 내용이 같아야 하고, 낮은 판은 건너뛴다).
7. **잘못된 파일은 Center를 막지 않는다.** 파일마다 결과(`registered`·`unchanged`·`skipped`·`refused`)와 사유
   (`code`·`message` — 콘솔 등록이 돌려주는 것과 같은 코드, 읽지 못하면 `unreadable`)를 로그에 찍고, 마지막으로 읽은
   결과를 `GET /resources/extension-folder`(C7, 읽기)로 준다. CON-07이 그것을 「확장 폴더」로 보이고, 폴더에서 들인
   확장은 `ExtensionResource.source = folder`로 갈라 보인다(저장소 20판 `extensions.source`).
8. **뜰 때만 읽는다.** 파일을 바꾸면 Center를 다시 띄운다 — 배포는 어차피 Center를 다시 띄운다. 폴더를 지켜보며 돌지
   않는다(언제 등록됐는지가 흐려지고, 쓰는 도중의 파일을 읽는다).

## 결과

- 쉬워지는 것: 고정 프로그램은 정의 파일을 폴더에 복사하는 것으로 Center에 들어온다. 관리자 토큰을 배포에 두지 않는다.
  콘솔 등록·현장 검증과 규칙이 하나라 따로 볼 것이 없다.
- 포기하는 것: 폴더에 쓸 수 있는 사람을 관리자로 믿는다(서버 셸을 쥔 사람이니 이미 그렇다). 바꾼 파일은 다시 띄워야
  들어온다.
- 다시 볼 조건: Center를 여러 벌 띄워 같은 폴더를 함께 읽게 되면(서명 키·DB가 하나라 지금은 아니다), 또는 폴더에서
  뺀 것을 자동으로 거둬야 할 운영 요구가 생기면.
